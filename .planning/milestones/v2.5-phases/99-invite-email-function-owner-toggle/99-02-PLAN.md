<objective>
Build the server-side invite-onboarding Cloud Function (R289/R290/R291 + honoring R293's toggle): a new
`onCall` callable `sendInviteOnboardingEmail` (with a separately-exported testable
`sendInviteOnboardingEmailHandler`) in `functions/src/inviteOnboarding.ts`, re-exported from
`functions/src/index.ts`. It provisions a Firebase Auth account + a `generatePasswordResetLink` set-password
email for non-Google invitees, sends a "sign in with Google" notify email for gmail/googlemail invitees,
creates nothing when the owner toggle is off, and gates every path behind a server-side org-editor caller
check.

This is provisioning + email ONLY (best-effort): the authoritative invite Firestore docs are written by the
client (`TeamView.onInvite`, unchanged; Phase 100 wires the call). This function never writes membership.

Purpose: Give every invited address a working onboarding path — a discoverable set-password flow for
non-Google users (no undocumented "type a password into Sign in" trick), a clean Google-sign-in notice for
Gmail users — reusing the existing Resend send path.
Output: `functions/src/inviteOnboarding.ts` (+ test) and its re-export.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → callable (`request.auth`, `{orgId,email}`) | Untrusted caller identity + arbitrary email cross here; must be re-authorized server-side |
| callable → Firebase Auth (Admin SDK) | Privileged account creation + reset-link generation on behalf of an arbitrary email |
| callable → Resend API | Outbound email to an arbitrary address; From header built from org-supplied name |
| callable → `appConfig/global` read | The owner on/off gate is read here (TTL-cached, coerced) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-99-01 | Elevation of Privilege / Spoofing | `sendInviteOnboardingEmailHandler` caller identity | high | mitigate | Server-side org-editor gate re-verified BEFORE any Auth/Resend call: require `request.auth`, then read `organizations/{orgId}/members/{callerUid}` and require `role === 'editor'` (inline, mirrors `queueServiceMessageHandler`). An arbitrary authenticated user cannot trigger account creation |
| T-99-02 | Information Disclosure | Email enumeration / account-existence probing | medium | mitigate | The org-editor gate (T-99-01) is the primary control — an attacker must be an editor of the org. `assertValidEmailFormat` rejects malformed probes; invitee-facing copy is generic onboarding text that does not reveal prior account state |
| T-99-03 | Tampering | From display-name header injection via a malicious org name | medium | mitigate | Reuse the existing `fromDisplayName` helper (params.ts) which strips CR/LF and quote/backslash chars — no hand-rolled sanitizer |
| T-99-04 | Spoofing (open redirect) | `actionCodeSettings.url` continue-URL | low | accept | Enforced at the platform level by Firebase Auth authorized-domains; the default `SERVICE_SHARE_BASE_URL` is the project's own auto-authorized hosting domain. Recorded as a deploy-time check if a custom domain is ever configured |
| T-99-05 | Denial of Service / Elevation | Mass account-creation abuse by an authorized editor | medium | accept | Primary control is the org-editor gate. The per-org email quota (`checkAndConsumeOrgEmailQuota`) is the available secondary lever but is DEFERRED this phase to avoid the circular-import trap (RESEARCH Pitfall 1); tightening (extract the quota helper into a dep-free module, then apply) is recorded as a future requirement |
| T-99-06 | Tampering (data integrity) | Concurrent-invite race creating duplicate/conflicting accounts | low | mitigate | Catch `auth/email-already-exists` on `createUser` and fall through to the reset-link path (idempotent), mirroring `resolveAdminTarget`'s code-based discrimination |
| T-99-SC | Tampering (supply chain) | npm installs | high | accept | No packages installed this phase — `firebase-admin`/`firebase-functions`/`resend` all pre-exist with no version change (RESEARCH.md Package Legitimacy Audit); no `[ASSUMED]`/`[SUS]` package, no install checkpoint required |

All high-severity threats are mitigated (T-99-01) or carry no attack surface this phase (T-99-SC, no installs); ASVS L1 block-on-high is satisfied.
