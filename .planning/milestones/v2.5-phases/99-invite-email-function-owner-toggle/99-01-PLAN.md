<objective>
Ship the owner-facing on/off switch for invite/onboarding emails (R293's config + UI half): add a global
`onboarding: { emailsEnabled: boolean }` group to the `appConfig/global` config surface (server interface +
default + coerce + merge, and the byte-identical client mirror), and add an Owner Console Configuration-tab
card that toggles it with immediate save.

This plan is the config foundation the Wave 2 Cloud Function reads (`config.onboarding.emailsEnabled`), so it
must land first. It deliberately does NOT include the function itself.

Purpose: An owner can turn onboarding/invite emails on or off from the Owner Console; the default is OFF
(fail-safe until the Resend domain is verified), consistent with every sibling boolean in this config.
Output: `onboarding.emailsEnabled` in both AppConfig mirrors (+ tests) and a new `OnboardingConfigCard.vue`
mounted in `ConfigurationTab.vue`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser (Owner Console) → Firestore `appConfig/global` | A super-admin's toggle write crosses here; rules gate WHO may write |
| Firestore doc → server read (`getAppConfig` coerce) | Untrusted stored value coerced before any consumer trusts it |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-99-07 | Elevation of Privilege / Tampering | `appConfig/global` write via `store.saveField` | medium | mitigate | Writes are already rules-gated to super-admins (Phase 68 rules) from the super-admin-only Owner Console surface; this plan adds NO new write path — it reuses the existing `saveField` setDoc-merge dot-path write |
| T-99-08 | Tampering | `coerceOnboarding` reading a malformed stored flag | low | mitigate | `coerceOnboarding` uses fail-closed `coerceEnableFlag` — only literal `true` enables; any malformed/absent value resolves `false`, so a corrupt doc can never silently turn emails ON |
| T-99-SC | Tampering (supply chain) | npm installs | high | accept | No packages installed this plan — all deps pre-exist (RESEARCH.md Package Legitimacy Audit, zero version changes); no `[ASSUMED]`/`[SUS]` package, no install checkpoint required |
</threat_model>
