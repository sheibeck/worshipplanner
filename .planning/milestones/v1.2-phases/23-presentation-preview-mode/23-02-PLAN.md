<objective>
Build `PresentationViewer.vue`: the full-screen, Teleport-mounted, index-walking presentation
surface, complete with its Fullscreen-API lifecycle, keyboard and on-screen navigation,
auto-hiding chrome, loading and empty states, and projection-scale rendering for every slide
kind the unified slide model produces.

Purpose: this is the only genuinely new component in Phase 23. Every data source it needs already
exists — it consumes the flat `assembledSlideshow` array and does nothing but walk an index.

Output: a self-contained viewer component plus its test suite. Media playback is deliberately NOT
in this plan; plan 23-03 layers it into the same slide canvas.
</objective>

    Create `src/components/PresentationViewer.vue` as a Vue 3 `<script setup lang="ts">` SFC.

    **Public contract.** `defineProps<{ slides: AssembledSlide[]; isLoading?: boolean }>()` captured
    into `const props`. `const emit = defineEmits<{ exit: [] }>()`. No `defineExpose`.

    **Template root.** Wrap everything in `<Teleport to="body">`. Inside it, one root element:
    `<div ref="viewerRoot" tabindex="-1" data-testid="presentation-viewer" @keydown="handleKeydown"
    @mousemove="registerActivity" class="fixed inset-0 z-50 bg-black outline-none flex items-center
    justify-center">`. That single fixed overlay IS the CSS fallback — nothing extra is rendered
    when fullscreen is unavailable. Do not add a separate backdrop layer.

    **State.** `currentIndex` (ref, 0), `chromeVisible` (ref, true), `isTrueFullscreen` (ref, false),
    `viewerRoot` (template ref), `chromeTimer` (a plain module-scope-free `ReturnType<typeof setTimeout> | null`).

    **Computed.** `hasSlides` = `props.slides.length > 0`. `currentSlide` = `props.slides[currentIndex.value] ?? null`.
    `atFirst` = `currentIndex.value <= 0`. `atLast` = `currentIndex.value >= props.slides.length - 1`.
    `progressLabel` = for a `currentSlide` with a defined `section`, the string
    `` `${SERVICE_SECTION_LABELS[section]} · ${currentIndex.value + 1} / ${props.slides.length}` ``
    (the separator is U+00B7 MIDDLE DOT with a single space on each side); with `section` undefined,
    `` `${currentIndex.value + 1} / ${props.slides.length}` ``.

    **Navigation.** `goNext()` returns early when `atLast`, otherwise increments `currentIndex`.
    `goPrev()` returns early when `atFirst`, otherwise decrements. Never modulo, never wrap. Add a
    `watch` on `() => props.slides.length` that clamps `currentIndex` into `0..length-1` so a live
    edit that shortens the show cannot leave the index out of range. There is NO timer that advances
    slides and NO loop — advance is manual only.

    **Keyboard.** `handleKeydown(e: KeyboardEvent)` switches on `e.key`: `'ArrowRight'` and `' '`
    call `e.preventDefault()` then `goNext()`; `'ArrowLeft'` and `'Backspace'` call `goPrev()`;
    `'Escape'` calls `exitPresentation()`. Every branch also calls `registerActivity()`. Bind this
    ONLY via the root element's `@keydown` template binding — never register a key listener on the
    global window object or on the document object. In `onMounted`, call `viewerRoot.value?.focus()`
    so the root actually receives key events.

    **Fullscreen lifecycle.** In `onMounted`, call an async `enterPresentation()` that awaits
    `viewerRoot.value?.requestFullscreen()` inside try/catch: on success set
    `isTrueFullscreen.value = true`; on ANY rejection set it to `false` and return silently — no
    console.error, no toast, no retry. Also in `onMounted`, add
    `document.addEventListener('fullscreenchange', handleFullscreenChange)`, removed in
    `onUnmounted`. `handleFullscreenChange()` emits `exit` only when `isTrueFullscreen.value` is
    true AND `document.fullscreenElement` is null (the `isTrueFullscreen` guard is required: jsdom
    reports `document.fullscreenElement` as undefined, so an unguarded check would exit immediately
    in the rejection path). `exitPresentation()` first attempts `document.exitFullscreen()` inside a
    try/catch when `document.fullscreenElement` is truthy, then emits `exit` exactly once — guard
    with a local `hasExited` boolean so a keydown plus a `fullscreenchange` cannot double-emit.

    **Auto-hiding chrome.** `registerActivity()` sets `chromeVisible.value = true`, clears
    `chromeTimer`, and sets a new 3000ms `setTimeout` that sets `chromeVisible.value = false`. Call
    it once from `onMounted` to arm the first timer. Clear the timer in `onUnmounted`. Bind the class
    `transition-opacity duration-300` plus `opacity-100` when `chromeVisible` else
    `opacity-0 pointer-events-none` onto exactly two elements: the bottom chrome bar and the exit
    button. Slide content must never carry this binding.
