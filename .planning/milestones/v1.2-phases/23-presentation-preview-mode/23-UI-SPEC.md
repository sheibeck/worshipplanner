# Phase 23 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — shadcn does not apply (see note) |
| Preset | not applicable |
| Component library | none (hand-rolled Vue 3 SFCs + Tailwind v4 utility classes) |
| Icon library | inline hand-drawn SVGs, Heroicons-outline style (`viewBox="0 0 24 24"`, `stroke-width="2"`, `fill="none"`, `stroke="currentColor"`) — no icon package installed, matches every prior phase |
| Font | Tailwind default `font-sans` system stack — no custom webfont |

**shadcn gate note:** Vue 3 + Vite project, no `components.json`, shadcn targets React — not applicable (established precedent, Phases 13/16). This phase extends the existing hand-built dark-mode Tailwind design system, specifically `SlideshowPreview.vue` (the inline preview this full-screen viewer scales up from), `AudioPlayer.vue`/`VideoPlayer.vue` (Phase 22, reused as playback primitives), and `CongregationalEditor.vue` (Leader/Congregation color convention, reused verbatim at presentation scale).

**Third theme zone (new — in addition to the two established zones from Phase 13/16):**
1. **App shell (authenticated screens)** — dark, gray-950/gray-900, indigo-600 accent. `ServiceEditorView`'s Music tab (where the "Present Slideshow" entry point lives) stays in this zone.
2. **Public/print surfaces** — light theme (unaffected by this phase).
3. **Presentation viewer (NEW this phase)** — full-screen, pure black canvas, projection-scale typography. Deliberately darker and larger-type than the app shell — see Color and Typography exceptions below. This is a distinct "performance surface" the way public/print is a distinct "output surface"; it must not inherit app-shell chrome padding/type sizes.

---

## Visual Hierarchy / Focal Points

- **Presentation viewer (full-screen, new):** the current slide's own content (lyric lines / scripture text / image / imported text or image) is the sole focal point — centered both axes, full-bleed on a pure-black canvas. All navigation chrome (progress pill, section label, nav chevrons, exit button) is secondary: small, low-opacity, positioned at the screen edges, and auto-hides after inactivity so it never competes with the slide content.
- **Entry point (`ServiceEditorView`, Music tab, dark app shell):** the existing inline `SlideshowPreview` panel is the anchor; the new **"Present Slideshow"** primary CTA lives in that panel's header row (next to the "Slideshow Preview" title), so the volunteer discovers full-screen preview exactly where they already look at the assembled result.

## Spacing Scale

Declared values — reuses the project's existing 8-point scale exactly, no new scale introduced:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps in nav chrome |
| sm | 8px | Progress-pill internal padding, nav-chevron icon padding |
| md | 16px | Chrome element gaps (progress pill ↔ section label ↔ nav buttons) |
| lg | 24px | Chrome inset from screen edge (top-right exit button, bottom-center progress bar) |
| xl | 32px | Vertical gap between an on-slide label (verse/section tag) and the main slide content below it |
| 2xl | 48px | Slide content vertical safe-margin (`py-12`) — content never touches top/bottom edge |
| 3xl | 64px | Slide content horizontal safe-margin (`px-16`) — content never touches left/right edge ("title-safe" projection convention) |

**Exception — touch target floor (44px):** the on-screen prev/next chevron buttons and the exit (×) button are icon-only and must have a minimum 44×44px hit area even though their visible icon is 24px (`h-6 w-6` icon inside a `min-h-11 min-w-11` / `p-2.5` hit target) — accessibility floor for touch devices (tablets running the presentation), not a violation of the 4px-multiple rule since the icon itself stays on-grid.

Exceptions beyond the touch-target floor: none.

## Typography

Three-tier scale for this phase: **existing app chrome** (reused, not new) for peripheral UI, plus a **new presentation content scale** (exactly 4 sizes, 2 weights) for the projected slide content itself.

### Presentation content scale (NEW — applies only inside the full-screen slide canvas)

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label (on-slide tags) | 24px (`text-2xl`) | 600 semibold | 1.3 |
| Body (main projected content) | 48px (`text-5xl`) | 400 regular | 1.4 |
| Heading (secondary prompts) | 36px (`text-4xl`) | 600 semibold | 1.2 |
| Display (song/copyright title) | 60px (`text-6xl`) | 600 semibold | 1.15 |

- **Label** usage: lyric section label (e.g. "Verse 1", "Chorus"), scripture reference, Leader/Congregation speaker tag.
- **Body** usage: lyric lines, scripture text (including congregational reading blocks — see exception below), imported/text-slide body copy.
- **Heading** usage: "Tap to play audio"/"Tap to unmute" overlay prompts, empty-state heading, loading-state heading ("Loading slideshow…").
- **Display** usage: the song title on the copyright/credit slide only — the single largest, most attention-grabbing line in the whole viewer.

**2 weights declared: 400 (regular) and 600 (semibold).** One documented in-content exception, not a third weight: within a **congregational scripture slide**, Leader lines render at Body size (48px) but weight **600** (matching the Leader/Congregation visual distinction already established in `CongregationalEditor.vue`), while Congregation lines stay at Body's default weight **400** — both values are already in the declared 2-weight set.

### Existing app chrome (reused verbatim, not counted against the 4-size budget above)

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Chrome caption | 12px (`text-xs`) | 400 | 1.4 | "Media unavailable" corner notice (deliberately de-emphasized fine print, not projection content) |
| Chrome label | 14px (`text-sm`) | 500 medium (existing T-1 chrome exception, Phase 13) | 1.5 | Progress pill ("Slide 3 of 24"), section-name chip in the progress bar, nav-button `aria-label` visually-hidden text |

**Compliance fine print exception:** CCLI copyright/license-number lines on the copyright slide use the **Chrome caption** row (12px, gray-500), NOT the Body/Display presentation scale — legal fine print is intentionally de-emphasized relative to the song title, matching how `CopyrightSlide` already renders in `SlideshowPreview.vue`'s small-card context, just carried through unscaled.

## Color

### Presentation viewer (full-screen — NEW this phase, distinct from the app shell's gray-950)

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#000000` (pure black, `bg-black`) | The full-screen canvas background — deliberately pure black, not the app shell's `gray-950`. Documented exception (same pattern as Phase 13/16's public-surface light-theme exception): projection best practice — pure black lets images/video bleed seamlessly and avoids a visible gray wash on a projector screen in a dark room. |
| Secondary (30%) | `#111827`/80 (gray-900 at 80% opacity, `bg-gray-900/80 backdrop-blur-sm`) | The bottom chrome bar holding the progress pill + nav chevrons — a translucent scrim so it reads on any slide content behind it without becoming a solid panel |
| Accent (10%) | `#818cf8` (indigo-400, brighter than the app shell's indigo-600 for legibility against pure black) | **Reserved for:** on-slide Label-role tags that borrow the Leader/section-label indigo convention, the active/focus state of nav chevrons, and the "Tap to play"/"Tap to unmute" affordance button (`bg-indigo-600 hover:bg-indigo-500`, matching `AudioPlayer`/`VideoPlayer`'s existing play-affordance button styling exactly) |
| Destructive | not applicable | No destructive actions occur inside the presentation viewer (exiting is non-destructive; no data mutation happens here) |

**Leader/Congregation convention (reused verbatim from `CongregationalEditor.vue`, scaled up):**

| Role | Value | Usage |
|------|-------|-------|
| Leader tag/text | `text-indigo-300` (tag), Body-role text at weight 600 | Leader lines within a congregational scripture slide |
| Congregation tag/text | `text-amber-300` (tag), Body-role text at weight 400, indented (`pl-8`, scaled equivalent of the editor's `pl-4`) | Congregation lines within a congregational scripture slide |

**Degraded/graceful-fallback semantic (reused amber = warning convention, Phase 13/16):**

| Role | Value | Usage |
|------|-------|-------|
| Degraded notice | `text-gray-500` (neutral, NOT red — see rationale below) | "Media unavailable" corner notice on graceful-degradation |
| Muted-playback notice | `text-amber-300` bg `bg-amber-900/40` chip | "Playing muted — tap to unmute" chip after `VideoPlayer`'s autoplay-blocked muted-retry succeeds |

Accent reserved for: **on-slide speaker/section Label tags, nav-chevron active/focus states, and the play/unmute affordance button only** — never applied to the main slide Body/Display text (which must stay neutral white/`gray-100` so arbitrary lyric/scripture/imported content is always legible regardless of color).

**Rationale for gray-500 (not red) on the missing-media notice:** CONTEXT.md's error-handling strategy calls this "graceful degradation," not a failure — the slide still renders correctly with its text/content intact and the show continues uninterrupted. Using red would incorrectly signal a blocking error to the volunteer mid-rehearsal; a quiet gray note is factual without alarming.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA — entry point (`SlideshowPreview.vue` header, Music tab) | **"Present Slideshow"** (indigo-600 primary button, icon: fullscreen-expand glyph) — disabled + `title="Add songs or scripture to build a slideshow to present."` when the assembled slideshow has zero slides |
| Exit affordance (on-screen, top-right of viewer) | Icon-only × button, `aria-label="Exit presentation (Esc)"` |
| Nav — next (on-screen, bottom-right) | Icon-only chevron-right, `aria-label="Next slide (→)"` |
| Nav — prev (on-screen, bottom-left) | Icon-only chevron-left, `aria-label="Previous slide (←)"` |
| Progress indicator (bottom-center chrome bar) | **"{section label} · {N} / {M}"** e.g. "Worship · 3 / 24" — section label omitted (just "**{N} / {M}**") for legacy/ungrouped slides with no section |
| Loading state (slideshow still assembling on open) | Heading: **"Loading slideshow…"** centered, with a small spinner (reuses the existing spin-SVG pattern from `CongregationalEditor.vue`'s fetch button) |
| Empty state (0 slides — only reachable via a race/refresh, since the CTA is disabled) | Reuses `SlideshowPreview.vue`'s existing empty copy verbatim: **"No slides yet — add songs or scripture to see the assembled slideshow."** + a visible "Exit" affordance (no nav controls shown) |
| Autoplay-blocked — audio | **"Tap to play audio"** — centered overlay button, reuses `AudioPlayer.vue`'s existing "Play audio" affordance copy/style, scaled to the Heading role and centered on the slide |
| Autoplay-blocked — video (hard-blocked, muted retry also failed) | **"Tap to play video"** — same pattern as audio, reuses `VideoPlayer.vue`'s existing "Play video" affordance copy |
| Autoplay-blocked — video (muted retry succeeded) | **"Playing muted — tap to unmute"** — small amber chip, bottom-corner of the video area, not a full overlay (the video IS playing, just silently) |
| Graceful degradation — missing/deleted media | **"Media unavailable"** — small gray-500 corner notice (bottom-left, near but visually distinct from the progress bar); slide's own text/image content renders normally, media element is simply omitted |
| Destructive confirmation | none — no destructive actions in this phase |

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | "Present Slideshow" entry with 0 assembled slides | ✅ covered | CTA disabled with explanatory `title`; if reached anyway (race/refresh mid-edit), viewer shows `SlideshowPreview`'s existing empty copy full-screen with only an Exit affordance, no nav controls |
| loading | Slideshow still assembling (`useSlideshowAssembly`'s `isLoading` true, e.g. lyrics still fetching) on viewer open | ✅ covered | Centered "Loading slideshow…" heading + spinner before first slide paints |
| error/degraded | Slide's `audioUrl`/`videoUrl` fails to load (deleted media, 404, expired 2-week retention) | ✅ covered | Player's `@error` skips/removes the media element; slide's own text/image content still renders; small gray-500 "Media unavailable" corner notice shown |
| error/degraded | Browser blocks unattended `play()` on slide entry | ✅ covered | Centered "Tap to play {audio/video}" affordance (audio/video-specific), reusing the existing `autoplay-blocked` event and affordance-button styling from `AudioPlayer`/`VideoPlayer` |
| zero-one-many | Single-slide slideshow (exactly 1 assembled slide) | ✅ covered | Progress reads "1 / 1"; both prev and next nav chevrons are disabled (not hidden, so the chrome bar doesn't reflow); Esc still exits normally |
| zero-one-many | Navigating past the last slide / before the first slide | ✅ covered | **Stop, do not wrap** — next is disabled at the last slide, prev is disabled at the first slide (matches presentation-software convention; wrapping back into the show risks confusing an already-live congregation-facing screen) |
| overflow | Long lyric/imported-text body slide exceeding the viewport at 48px Body size | 🧪 backstop | No dynamic auto-shrink-to-fit specified — text wraps at 48px and may clip/scroll at the viewport edge for unusually long content. Planner should verify against a real long PPTX-imported text slide and decide whether a floor auto-shrink step (e.g. drop to 36px past N characters) is needed; not fully specified here. |
| overflow | Congregational scripture slide with many alternating Leader/Congregation blocks stacked on one slide | 🧪 backstop | Vertical stack (mirroring `CongregationalEditor.vue`'s preview panel, scaled up) may exceed viewport height before wrapping/scrolling behavior is defined — flagged for planner verification against real multi-exchange congregational readings. |
| partial | `ScriptureSlide.readingMode === 'congregational'` but `sections` is empty/undefined | ⚠ unresolved | Not addressed by CONTEXT.md or the existing type contract (`sections?` is optional even in congregational mode). Planner assumption: fall back to rendering the slide as normal (non-congregational) Body text using `.text`, rather than showing a blank/broken slide. |
| navigation edge | Rapid key-repeat (holding →/Space) advancing through several media-carrying slides quickly | 🧪 backstop | Driver must call `.pause()` on the outgoing slide's `AudioPlayer`/`VideoPlayer` ref before advancing so audio/video from a skipped slide doesn't keep playing under the new slide — specified as a requirement here but not exhaustively enumerated for every timing interleaving. |
| long-text | CCLI copyright/compliance block with long author lists or multi-line copyright text | ✅ covered | Fixed at the small 12px Chrome-caption scale (not the projection Body scale); wraps normally, never truncated — CCLI compliance requires the full text to always be present and legible, never clipped. |

## Component-Specific Notes for This Phase

- **New component (suggested name): `PresentationViewer.vue`** — mounted via `Teleport to="body"`, toggled by the "Present Slideshow" button in `SlideshowPreview.vue`'s header. Consumes the flat `assembledSlideshow` array (not the section-grouped `assembledSections`) for sequential index-based navigation; derives the optional section-label chrome from each `AssembledSlide.section` via `SERVICE_SECTION_LABELS`.
- **Enter/exit mechanics:** on open, call `viewerRootEl.requestFullscreen()` (Fullscreen API). If the returned promise rejects (some embedding contexts disallow it, or the user-gesture requirement wasn't met), fall back to a fixed-position full-viewport overlay (`fixed inset-0 z-50 bg-black`) WITHOUT true browser fullscreen — the feature must still work, just without hiding browser chrome. Listen for the native `fullscreenchange` event (in addition to the on-screen × button and Esc keydown) to detect the user pressing the browser's own Esc-to-exit-fullscreen and unmount the viewer in sync.
- **Keyboard handling:** bind `keydown` on the viewer root (not `window`, to avoid leaking listeners when the viewer isn't mounted) for →/Space (next), ←/Backspace (prev), Esc (exit). Prevent default on Space to avoid an incidental page-scroll if the fullscreen fallback path is active.
- **Auto-hiding chrome:** the bottom progress/nav bar and top-right exit button fade to `opacity-0` after ~3s of no `mousemove`/`keydown` activity, and fade back in immediately on any such activity. Slide content itself (Body/Label/Display text) is never affected by this — only the chrome bar and exit button.
- **AudioPlayer/VideoPlayer reuse — chromeless mode:** both existing players render a native `controls` scrubber intended for the inline editor preview context. The presentation viewer needs a **chromeless** rendering (no visible scrubber — playback is driven entirely by the presentation driver's imperative `play()`/`pause()` calls, not user scrubbing) with the play/unmute affordance button as the only visible chrome when needed. Extend both components with an optional boolean prop (e.g. `chromeless`, default `false`) that conditionally omits the `controls` attribute — this keeps the existing inline `SlideshowPreview.vue` usage (which needs visible controls) unaffected.
- **Video-carrying slides — layout priority:** when a slide carries `videoUrl`, the video becomes the dominant visual element (large, `object-contain`, up to ~80% viewport height, centered) with any accompanying text (e.g. a `TextSlide`'s `title`) rendered as a Label-role caption above it — the video needs visible screen real estate, so it takes priority over a large Body-scale text treatment on that slide.
- **Audio-only slides — layout priority:** when a slide carries `audioUrl` but no `videoUrl`, the slide's own content (lyric/scripture/text/image) renders at full normal size as usual; the (chromeless) `AudioPlayer` occupies no visual space unless the autoplay-blocked affordance is showing.
- **Congregational scripture rendering:** reuse `CongregationalEditor.vue`'s preview-panel block structure (Leader lines bold/indigo, Congregation lines regular/amber/indented) exactly, just re-scaled to the Body/Label presentation sizes declared above — do not invent a new visual pattern for Leader/Congregation distinction.
