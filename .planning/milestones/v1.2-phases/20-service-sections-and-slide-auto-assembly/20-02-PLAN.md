<objective>
Build the slideshow auto-assembly engine (R005) as a pure, fully unit-tested TypeScript function —
the highest-risk centerpiece of Phase 20. It walks a service's ordered slots and resolves each into
unified slides (song lyrics from Phase 18, scripture from Phase 19, text placeholders for
prayer/message/hymn), emitting a flat ordered `AssembledSlide[]`. Because it is a pure function of
`service.slots` plus content maps, reordering slots reorders output deterministically — this is the
R006 auto-reorder contract proven at the function layer (the reactive wiring lands in 20-03).

Purpose: Prove slots → slides is correct in isolation before any Vue/reactivity/UI depends on it.
It depends only on the type definitions from 20-01, so it is built and tested with no external I/O.

Output: `src/utils/slideshowAssembler.ts` + an exhaustive test matrix.

This is a TDD plan — write the failing test first (RED), implement to green (GREEN), refactor if needed.
</objective>

  <behavior>
    - assembleSlideshow walks service.slots sorted ascending by position
    - SONG slot with songId present in songLyricsById emits, in order: one CopyrightSlide (from lyrics.copyright), one LyricSlide per section id resolved via the order, one trailing CopyrightSlide
    - Order source precedence: performanceOrderById.get(songId) if non-empty, else lyrics.performanceOrder if non-empty, else lyrics.sections mapped in stored order (research fallback for missing Song.performanceOrder)
    - Section ids in the order that do not resolve to a known lyrics.section are skipped (no throw)
    - SONG slot with songId === null → contributes nothing
    - SONG slot whose songId is absent from songLyricsById (lyrics not loaded) → contributes nothing
    - SCRIPTURE slot with scriptureReadingId present in scriptureReadingsById → emits one AssembledSlide per entry in reading.slides, in stored order, wrapping the existing ScriptureSlide unchanged
    - SCRIPTURE slot with null/absent scriptureReadingId → contributes nothing
    - every emitted AssembledSlide carries slotIndex (the source slot's array index), slotKind, section (copied from slot.section, may be undefined), sourceId (songId or readingId)
  </behavior>
  <action>
    Define `export interface AssemblyInputs` with three maps: `songLyricsById: Map<string, SongLyrics>`,
    `performanceOrderById: Map<string, string[]>`, `scriptureReadingsById: Map<string, ScriptureReading>`.
    Implement `export function assembleSlideshow(service: Service, inputs: AssemblyInputs): AssembledSlide[]`.
    Walk `[...service.slots].sort((a,b) => a.position - b.position)`. For SONG slots resolve copyright + ordered
    lyric-section slides using the precedence chain above (D001 — emit unified LyricSlide/CopyrightSlide, not a new type).
    For SCRIPTURE slots pass `reading.slides` through. Wrap each inner Slide in an AssembledSlide with slotIndex,
    slotKind, `section: slot.section`, and sourceId. Assign each emitted inner slide a running global `position`
    (0-based sequential across the whole assembled array) and a stable `id` (e.g. `${slotIndex}:${localSeq}`). Write the
    RED tests first for song + scripture resolution, then implement to green. Do NOT read from Firestore or any store —
    this function is pure and takes only its arguments.
  </action>
