<objective>
Establish the additive data-model foundation for Phase 20: the four formalized service sections
(D005) as an OPTIONAL `section` field on every service slot, deterministic default section
assignments in `buildSlots()`, and the slide-type extensions (`TextSlide`, `AssembledSlide`,
`AssembledSection`) the assembly engine and preview will consume — all reusing the unified slide
model (D001), never forking it.

Purpose: This is pure, low-risk TypeScript that unblocks the assembly engine (20-02), the reactive
composable (20-03), and the section UI (20-04). Backward compatibility is the governing constraint —
the `section` field is optional so existing Firestore services keep type-checking and rendering with
no migration.

Output: Extended `service.ts` and `slide.ts` type surfaces, updated `slotTypes.ts` factory/template,
and section-default unit tests.
</objective>
