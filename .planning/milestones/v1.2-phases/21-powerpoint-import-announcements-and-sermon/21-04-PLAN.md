<objective>
Build the server-side heart of the phase: the parsePptx onCall Cloud Function and the pure mapAstToSlides mapping that turns an officeparser AST into native (text | image) slide objects. Output: mapAstToSlides + parsePptxBuffer in pptxParser.ts, the parsePptx onCall export in index.ts, and a green Vitest suite covering text-only, image-only, mixed, and corrupted inputs.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → parsePptx onCall | Untrusted client supplies orgId, importId, storagePath and triggers server-side parsing. |
| parsePptx → Firebase Storage | Function downloads a client-uploaded binary and uploads decoded images. |
| .pptx bytes → officeparser | Untrusted archive is decompressed and XML-parsed. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-21-04-01 | Tampering / Elevation of Privilege | client-supplied storagePath/orgId | high | mitigate | storagePath.startsWith(orgs/{orgId}/pptx-imports/) prefix check PLUS an independent Firestore org-membership lookup keyed on request.auth.uid; both proven by handler-path tests. |
| T-21-04-02 | Denial of Service | zip/decompression bomb in a malicious .pptx | high | mitigate | PK magic-byte gate before parsing; onCall memory 1GiB + explicit timeout backstop; upstream 25 MB Storage upload cap (21-02) bounds input size. |
| T-21-04-03 | Tampering / Injection | file claiming to be .pptx but is not | medium | mitigate | Leading-bytes zip-signature validation rejects mis-declared files before officeparser runs; corrupted/non-pptx fixtures assert the friendly-error path. |
| T-21-04-04 | Information Disclosure | extracted-image URLs leaking cross-org | medium | mitigate | Function returns Storage paths (not long-lived signed URLs); client resolves via getDownloadURL under storage.rules org gate (21-02/21-05). |
| T-21-04-05 | Denial of Service (cost) | unbounded Storage growth from retried failed imports | low | accept | Never-delete-on-failure is a locked CONTEXT tradeoff; images tagged with createdAt metadata for Phase 22's 2-week retention sweep. |
