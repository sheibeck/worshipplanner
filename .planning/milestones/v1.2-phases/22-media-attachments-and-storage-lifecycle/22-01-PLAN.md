<objective>
Lay the media-attachment data + upload foundation for Phase 22: extend the unified slide model (D001) and the service-slot model with `audioUrl?`/`videoUrl?`, propagate slot media onto assembled slides, build the `useMediaUpload` composable, and widen `storage.rules` so video-sized media can upload under the org media path.

Media is attached at the **ServiceSlot** level (service-scoped), NOT baked into a shared canonical song (D002) — an announcement video for one Sunday must not follow the song into every service that references it. Assembled slides are ephemeral (`assembleSlideshow` regenerates them with ids like `slotIndex:localSeq`), so the durable home is the slot; `SlideBase.audioUrl/videoUrl` are the render carriers the assembler fills.

Purpose: Every downstream Phase 22 plan (players, editor UI, cleanup function) depends on these fields, this upload composable, and the org media storage path.
Output: Updated slide/service types, assembler propagation, `useMediaUpload.ts`, widened `storage.rules`, and tests.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser client -> Firebase Storage | Authenticated user uploads arbitrary media bytes to an org-scoped path |
| Storage rules -> Firestore | Cross-service `firestore.exists()` membership lookup authorizes the write |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-22-01-01 | Elevation of Privilege | storage.rules media match | high | mitigate | Media write requires `firestore.exists()` org membership, identical to the existing rule; non-member upload denied (rules test (c)). |
| T-22-01-02 | Denial of Service | media upload size | medium | mitigate | 50MB `request.resource.size` cap on the media path; client-side pre-validation in useMediaUpload rejects oversize before bytes leave the browser (rules test (b)). |
| T-22-01-03 | Tampering | non-media org paths | high | mitigate | New media match is path-scoped to `.../media/**`; pptx-imports 25MB cap regression-guarded (rules test (d)). |
| T-22-01-04 | Tampering | slide metadata on failed upload | medium | mitigate | useMediaUpload imports no Firestore API and rejects on error without writing metadata — a failed upload cannot corrupt slide/slot data. |
| T-22-01-SC | Tampering | npm installs | low | accept | No new packages installed; uploadBytesResumable ships in the already-installed firebase package. |
</threat_model>
