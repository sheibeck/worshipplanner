<objective>
Build the reusable audio and video playback components (R013, R014) and render them inside the editor's SlideshowPreview so attached media is visible and playable there. Players enforce the no-loop / stop-at-end contract, expose imperative play()/pause() for Phase 23's play-on-entry driver, and handle browser autoplay-policy rejection gracefully — the phase's primary risk.

Purpose: These components are consumed by the slide-editor attachment UI (22-04) and by Phase 23's presentation mode. They emit the lifecycle + error events that make graceful media skipping possible when a file is missing or deleted by the 2-week cleanup.
Output: AudioPlayer.vue, VideoPlayer.vue, and SlideshowPreview media rendering, all unit-tested.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| media URL -> DOM media element | A Firebase Storage download URL is bound into an `<audio>`/`<video>` src rendered in the app |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-22-02-01 | Tampering | media element src | low | mitigate | src is only ever an org-gated Firebase Storage download URL bound via Vue `:src` (no `v-html`, no dynamic attribute injection); a bad/missing URL raises the element `error` event which re-emits for graceful skipping. |
| T-22-02-02 | Denial of Service | preview list playback | low | mitigate | Players use `preload='none'` and do not auto-play in the scrolling preview, so N media cards do not eagerly fetch N files. |
| T-22-02-03 | Repudiation | autoplay policy failure | medium | mitigate | play() rejection is caught and surfaced (autoplay-blocked event + affordance / muted fallback) rather than swallowed — the failure is observable to the driving layer (Phase 23). |
| T-22-02-SC | Tampering | npm installs | low | accept | No new packages; players use native HTML5 media elements only. |
</threat_model>
