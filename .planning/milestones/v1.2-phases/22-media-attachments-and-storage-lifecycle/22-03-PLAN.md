<objective>
Implement the R015 2-week retention cleanup as a scheduled Firebase Cloud Function that deletes Storage media older than 14 days, keeping small-church storage cost manageable. This is a DESTRUCTIVE, SCHEDULED job, so it is built defensively: a hard path guard restricting deletes to `orgs/{orgId}/media/`, native-`timeCreated` age keying, idempotent-by-age behavior, a dry-run mode, and deletion-count logging. It NEVER touches Firestore — slide metadata and text are out of its reach by construction.

The handler is exported separately from the `onSchedule` wrapper (mirroring the existing `parsePptxHandler` / `parsePptx` split) so it can be unit-tested directly with a mocked bucket. A blocking human-verify checkpoint reviews dry-run output before the real deleter is trusted.

Purpose: Bounds Firebase Storage cost/retention (R015) without risking slide data.
Output: `cleanupExpiredMedia` scheduled function + tested handler in functions/src/index.ts.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| scheduler -> Storage bucket | An unattended scheduled job issues permanent object deletes against the production bucket |
| cleanup job -> Firestore | (Intentionally absent) the job must have NO path to slide metadata/text |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-22-03-01 | Tampering | over-broad deletion | critical | mitigate | MEDIA_PATH_GUARD (`^orgs/[^/]+/media/`) is applied to every candidate before any delete; getFiles prefix is `orgs/`, never the bucket root; pptx-imports + non-media objects are excluded (tests 2-3). Dry-run + blocking human-verify gate before trust. |
| T-22-03-02 | Tampering | slide metadata/text loss | critical | mitigate | Handler imports/calls NO Firestore API — it is structurally incapable of touching slide documents (test asserts getFirestore never called). Deletes Storage objects only. |
| T-22-03-03 | Denial of Service | partial-run failure | medium | mitigate | Per-file delete wrapped in try/catch; run is idempotent by age so the next daily run retries — a failed run never wedges cleanup. |
| T-22-03-04 | Repudiation | silent deletion | medium | mitigate | Deletion count + scanned count + dryRun flag logged each run for auditability. |
| T-22-03-05 | Elevation of Privilege | wrong age key | high | mitigate | Age keyed on native GCS `timeCreated` (server-set), not client-supplied custom metadata that a user could backdate to force-expire another org's media. |
| T-22-03-SC | Tampering | npm installs | low | accept | No new packages; onSchedule ships in installed firebase-functions ^7.2.5, getStorage in firebase-admin ^13. |
</threat_model>
