## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| editor user -> Firebase Storage | Editor selects local files that are uploaded to the org media path |
| slot mutation -> Firestore autosave | audioUrl/videoUrl assigned onto a slot is persisted via the existing service autosave |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-22-04-01 | Elevation of Privilege | attachment control exposure | medium | mitigate | SlotMediaAttachment is rendered behind `authStore.isEditor` and uploads under `authStore.orgId`, which storage.rules independently gates by org membership. |
| T-22-04-02 | Tampering | slide-data loss on failed upload | high | mitigate | Upload is decoupled from autosave; SlotMediaAttachment emits a URL only on success, so a failed upload writes nothing and the slot's other fields are untouched (unit test + human-verify step 6). |
| T-22-04-03 | Repudiation | autoplay policy failure | medium | mitigate | Preview relies on 22-02's players, which surface autoplay-block (muted fallback / affordance) rather than failing silently (human-verify step 5). |
| T-22-04-SC | Tampering | npm installs | low | accept | No new packages; reuses existing composable + components. |
</threat_model>
