<objective>
Add R412 invalidation (per D-R412): when a service is relocked (markAsPlanned — the only moment
the resolved assignment set can change, since Planned services are otherwise Draft-gated), any
prior `confirmed` confirmation whose stable assignment identity `{roleId}_{emailLower}` is no
longer a valid assignment is flipped to `needsReconfirmation`. Confirmations whose assignment is
unchanged are left completely untouched — no stale checkmark, no needless re-confirm.

Purpose: R412 keys invalidation on stable assignment identity, not person identity, so an unlock
-> reassign -> relock cycle never shows a confirmation for an assignment that changed underneath
it, while unrelated roster edits preserve confirmations.
Output: a `reconcileConfirmations` step wired into `markAsPlanned`, plus store tests.
</objective>
