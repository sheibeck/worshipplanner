<objective>
Make any tokenless service self-heal a share link automatically — with no manual "Share Link" click —
by adding ONE idempotent, fail-closed `ensureShareLink` safety-net call to `markAsPlanned`, KEEPING the
existing `createService` creation-time mint, and fixing the emulator seed so seeded services carry a real
token (R421).

Purpose: Deliver the auto-share-link half of the "trivial wins" phase per the owner's RESOLVED decision
(2026-09-07 — "Safety-net + fix seed"). The owner's observed symptom ("link isn't auto-generated unless I
click Share Link") came from SEEDED test data, not an app bug: `createService()` has auto-minted a link at
creation since 2026-08-17, but `functions/seed-emulator-data.mjs` writes its service doc without a token.
This plan closes the gap without touching draft-sharing behavior.
Output: a `markAsPlanned` self-heal + retained `createService` mint in `src/stores/services.ts`, a token
mint in `functions/seed-emulator-data.mjs`, and updated tests in `src/stores/__tests__/services.test.ts`.

RESOLVED SCOPE (owner decision 2026-09-07 — authoritative, supersedes earlier "gate-to-Planned" framing):
1. KEEP the `createService()` mint-at-creation. Do NOT remove it (removing it regresses the 2026-08-17
   empty-`{{service_link}}` fix for messages composed before lock).
2. ADD an idempotent "ensure share link exists" safety net using `ensureShareLink` (NOT
   `maybeRefreshShareLink`), called fail-closed from a natural lifecycle point. This plan uses
   `markAsPlanned()` — the owner-endorsed store-level hook. (The "on service open" view hook was deferred
   to keep this plan store-only and in wave 1, since `src/views/ServiceEditorView.vue` is owned by the
   parallel plan 131-01; see the return note.)
3. FIX the seed so seeded services get a real token (test data matches real data).
4. DROP the "no Draft exposure / gate-to-Planned" framing entirely. Do NOT remove the draft mint; do NOT add
   a ShareView status gate. Draft-sharing behavior is UNCHANGED by this phase.
</objective>
