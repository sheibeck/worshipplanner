(the default) is untouched from Phase 136.

suite left unedited as the regression net).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| localStorage → inline CSS | The per-device `wp:videoKeyColor:v1` value (an untrusted local read) is interpolated into the render root's inline `background` style. |
| Firestore → render branch | `slot.videoOutput.mode` (persisted, editor-authored) selects the Video output's render branch. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-137-01 | Tampering | key-color localStorage read → inline `background` | medium | mitigate | `loadVideoKeyColor` validates `colorHex` against strict `^#[0-9a-fA-F]{6}$` and `enabled` as boolean on read; any malformed/injected value (CSS expression, non-hex) is rejected and falls back to `#FF00FF` — no attacker-controlled string reaches the inline style. Mirrors the existing untrusted-localStorage-read guards (T-91-01/T-114-01). |
| T-137-02 | Tampering | `videoOutput.mode` → render branch | low | mitigate | Branch fires only on strict `=== 'banner'`; any other/tampered value degrades to the unchanged full-screen render (no crash). Null/out-of-range index already resolves to null (T-93-01) — no new crash surface. |
| T-137-03 | Denial of Service | banner render (client) | low | accept | Pure client-side render in a standalone output window; no server surface, no new network call, no shared-resource amplification. |
| T-137-SC | Tampering | npm/pip/cargo installs | low | accept | No new packages introduced this plan (no install task); nothing to audit. |
</threat_model>
