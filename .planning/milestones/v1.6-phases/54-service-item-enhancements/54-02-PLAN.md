<objective>
Give every service item a plain-text notes field beside its selector (R122), in a consistent,
responsive layout that is side-by-side on desktop and stacked on mobile. One additive optional field on
the shared slot base plus one shared input written ONCE in the editor covers all item kinds with zero
per-kind duplication, and rides the existing autosave path.

Purpose: A planner can record who leads an item / who sings which parts, next to the selector, without
the selector consuming the full screen width.
Output (artifacts this plan produces):
- `MediaAttachableSlot.notes?: string` (new slot-level field, schemaless, no migration).
- A `slot-notes-input` editor input + `slot-notes-text` read-only viewer variant, inside a
  `flex flex-col sm:flex-row` wrapper, shared by every kind in ServiceEditorView.vue.
</objective>
