<objective>
Implement R127: give a MISC (Miscellaneous) service item an optional custom label, editable in
both the live service editor and the default-template editor, defaulting to "Miscellaneous" and
exported as the Planning Center item title in place of the hard-coded "Miscellaneous".

Per CONTEXT decision D-01 (R127 — Miscellaneous label model): the label is a DISTINCT compact
"name" input, NOT a second notes box. The existing consolidated notes-canonical field (quick task
260811-vsr) is untouched — MISC keeps its notes/details field AND gains a separate label. Both new
fields are optional and non-destructive; absent value reproduces today's behavior exactly.

Purpose: Let planners name a Miscellaneous item ("Communion", "Offering", "Baptism") instead of the
generic "Miscellaneous", and carry that name into Planning Center.
Output: An optional `label?` on `NonAssignableSlot` and `ServiceTemplateEntry`, a shared
`miscLabel()` helper, and label editing wired through both editors + PC export + print.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| authenticated editor -> slot/template store | planner-supplied `label` text is written to Firestore and read back |
| app -> Planning Center API | the label crosses to an external service as the item title |
| app -> printed/rendered DOM | the label is displayed in the editor, print layout, and read-only views |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-56-01 | Tampering/Injection | label rendered in editor + print + read-only views | low | mitigate | Render via Vue `{{ }}` / `:value` binding only (auto-escaped); never v-html. Plain-text field, same handling as the existing `notes`/`body` fields. |
| T-56-02 | Information disclosure | label sent to Planning Center as the item title | low | accept | Intended behavior (D-01): the planner explicitly chose to export this label. No secret data; PC receives only what the user typed. |
| T-56-03 | Tampering | corrupt/absent `label` read from Firestore | low | mitigate | `miscLabel()` coerces any falsy/whitespace value to "Miscellaneous"; `createSlot`/entry model omit the key entirely when absent, preserving the legacy absent-key shape (no migration). |

No package-manager installs in this phase (no npm/pip/cargo additions), so no supply-chain (T-*-SC) checkpoint applies.
</threat_model>
