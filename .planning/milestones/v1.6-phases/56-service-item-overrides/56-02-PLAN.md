<objective>
Implement R128: let a Scripture service item override the org-wide default Bible version (ESV or NLT)
for just that item, honored wherever that item's scripture TEXT is actually produced. Items with no
override keep using the org default.

Per CONTEXT decision D-01 (R128 — Scripture Bible-version override): add optional
`bibleVersion?: 'ESV' | 'NLT'` to `ScriptureSlot`; absent => org default
(`authStore.settings.bibleVersion`). Effective version everywhere = `slot.bibleVersion ?? orgDefault`.
Do NOT change the org-wide default or the Settings UI — per-item override only.

R128 SLIDE-SIDE SCOPE (traced 2026-08-12; see the Scope Disclosure block below). The projected
slide / preview / print surfaces for a scripture item are REFERENCE-ONLY (they render the typed
reference string, never fetched passage text), so the override has no effect there — documented, not
invented. The genuinely version-dependent passage-fetch surfaces are the Planning Center export
routing and the two editor passage fetches (reference preview + congregational split). Those are the
surfaces this plan wires.

Purpose: A planner can, e.g., read one passage in NLT while the church default is ESV, and have that
choice carry into Planning Center and the editor's fetched text.
Output: `ScriptureSlot.bibleVersion?`, a per-item version selector in the Scripture row, and the
effective version threaded into PC export + ScriptureInput preview + CongregationalEditor.
</objective>

| authenticated editor -> scripture slot store | planner-chosen `bibleVersion` is written to Firestore and read back |
| app -> ESV / NLT passage APIs | the effective version selects which upstream fetch runs |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-56-10 | Tampering | corrupt/unexpected `bibleVersion` value read from Firestore | low | mitigate | Every routing site is a two-way branch `=== 'NLT' ? NLT : ESV`, so any value other than exactly 'NLT' (including a corrupt or absent one) safely defaults to the ESV fetch — no arbitrary code path or injection. The UI selector only ever writes 'ESV' \| 'NLT' \| undefined. |
| T-56-11 | Information disclosure | scripture passage text fetched and sent to Planning Center | low | accept | Pre-existing behavior (quick 260809-vvq); this phase only changes WHICH translation, not whether text is fetched. Public scripture text; no secrets. |
| T-56-12 | Tampering | absent `bibleVersion` must reproduce org-default behavior | low | mitigate | `?? orgDefault` fallback at every consumer; no migration; unset slots are byte-identical to today. |

No package-manager installs in this phase (no npm/pip/cargo additions), so no supply-chain (T-*-SC) checkpoint applies. No new external endpoints — the ESV and NLT passage fetches already exist.
