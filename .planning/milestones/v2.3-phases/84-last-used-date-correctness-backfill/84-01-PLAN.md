<objective>
R247 — make a song's `lastUsedAt` (last used / last scheduled date) reflect the date of the
most recent LOCKED service the song is in, not the wall-clock moment it was added to a plan.

Root cause: `src/stores/services.ts::assignSongToSlot` (~line 519) writes
`lastUsedAt: serverTimestamp()` at assignment time. A service planned weeks ahead therefore
stamps the add date, never the service date.

Purpose: Fix the live data-correctness bug and lay the shared, dependency-free derivation the
R248 backfill (plan 84-02) mirrors, so the live path and the backfill can never disagree.
Output: a canonical pure helper (`src/utils/lastUsed.ts`), lock/unlock recompute wired into the
service store, and unit + store tests proving the semantics.
</objective>
