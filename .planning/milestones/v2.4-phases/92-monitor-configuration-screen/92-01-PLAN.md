<objective>
Build the standalone Monitor Setup screen and wire its entry points. A projectionist opens
`/monitor-setup` (independent of any service), detects the connected monitors via the Window
Management API, assigns Audience/Confidence roles per monitor, and the assignment is remembered on
that device — with a first-class manual fallback when permission is denied or the API is
unavailable, and a save round-trip check so "Saved" is never shown when storage silently no-ops.

Purpose: Deliver R267 (standalone detect + assign screen), R268 (device-scoped persistence +
silent reuse / re-prompt-only-on-change), and R269 (first-class denied/unavailable fallback). This
provides the config and matchMapping seam that the Phase 95 Run flow will later call; it does not
itself launch a service.

Output: `MonitorSetupView.vue`, `MonitorCard.vue`, `MonitorFallbackPanel.vue`, a `/monitor-setup`
route, and a gated AppSidebar nav entry. Behavioral tests are authored in plan 92-02 (wave 2).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> Window Management API | User-gesture-gated permission prompt; getScreenDetails() may resolve, reject, or be absent |
| localStorage -> app | Persisted monitor mapping is untrusted input on read (already validated by monitorConfig.loadMapping) |
| router/nav -> view access | Any authenticated org member may reach /monitor-setup (intended per R275); no editor tier |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-92-01 | Tampering | localStorage monitor mapping read | low | mitigate | Rely on monitorConfig.loadMapping's shape validation (T-91-01): a tampered/corrupt value returns null and the view falls back to State B (fresh assign), never crashing or trusting malformed roles. |
| T-92-02 | Spoofing | Persisted "Saved" state vs actual storage | low | mitigate | Save round-trip check (saveMapping -> loadMapping set-equality) prevents falsely confirming a persist that silently no-op'd in private mode; shows a truthful non-blocking warning instead. |
| T-92-03 | Elevation of Privilege | /monitor-setup route + nav gate | low | mitigate | Route meta requiresAuth only and nav gated on authStore.orgId (not isEditor) — deliberately open to any member per R275; no new RBAC tier and no editor-only data exposed (device-local config only). |
| T-92-04 | Information Disclosure | OS screen labels persisted to localStorage | low | accept | Screen labels (manufacturer/model strings) are device-local, never transmitted to Firestore or any server; a minor same-device fingerprint surface accepted as out of scope. |
| T-92-SC | Tampering | package installs (npm) | n/a | accept | No package-manager installs in this phase — no new dependencies added; supply-chain checkpoint not applicable. |
</threat_model>
