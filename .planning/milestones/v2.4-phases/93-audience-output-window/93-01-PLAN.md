<objective>
Build the standalone Audience Output Window: a chromeless, fullscreen, receive-only route/view that
renders the live service's current slide (with its background image) on the monitor assigned as
Audience, stays awake for the whole service via the Screen Wake Lock, and recovers gracefully from
fullscreen loss without ever tearing down the running session.

R271 (stays awake + graceful fullscreen-loss recovery). This phase builds the output window that
Phase 95's Run/Control flow will later open and place on the assigned monitor; it does not itself
launch or position windows.

Output: `src/views/AudienceOutputView.vue` and a `/present/audience/:serviceId` route (org via
`?org=` query, `requiresAuth` only). Behavioral tests are authored in plan 93-02 (wave 2).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| BroadcastChannel -> audience view | Incoming `state` messages are untrusted input; a stale/out-of-order/malformed message must never drive the projector backward or crash it |
| ?org= query + :serviceId param -> Firestore subscription | The org and service are attacker-influenceable via the URL; reads are gated by Firestore org-membership rules |
| router/nav -> view access | Any authenticated org member may open /present/audience (intended per R275); presentation-only, no editor tier |
| congregation-facing surface -> rendered content | Whatever renders is projected publicly; only slide content may appear — never operator chrome, labels, or error text |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-93-01 | Tampering | Incoming run-channel `state` message | low | mitigate | Rely on runChannel's isRunChannelMessage shape guard + strictly-increasing stale-seq drop (Phase 91, runChannel.ts line 133); the view only reads onState, never trusts a raw index — currentSlide is `assembledSlideshow[index] ?? null`, so a malformed/out-of-range index renders pure black, never a crash. |
| T-93-02 | Information Disclosure | Congregation-facing render surface | low | mitigate | Chromeless by construction — no exit button, nav, progress, slide count, org label, or error text is rendered; loading/empty is pure black; channel/wake-lock/fullscreen failures are handled silently, never painted to the projector (R270). |
| T-93-03 | Elevation of Privilege | ?org=/:serviceId Firestore subscription + route access | low | mitigate | Route meta is requiresAuth only (any member, R275); useSlideshowAssembly is called with canWrite omitted (read-only) so no materialize/rebuild write is ever attempted; the services store read is gated by existing Firestore org-membership rules, so a URL naming an org the user cannot read yields empty data, not a leak. |
| T-93-04 | Denial of Service | Fullscreen-loss / wake-lock / visibilitychange lifecycle | low | mitigate | Fullscreen loss never tears down the session or channel (Pitfall 6); wake-lock and fullscreen requests are feature-detected and try/caught; a rejected font load is bounded by FONT_LOAD_TIMEOUT_MS and always resolves fontReady, so nothing can permanently strand the projector. |
| T-93-SC | Tampering | package installs (npm) | n/a | accept | No package-manager installs in this phase — no new dependencies added; supply-chain checkpoint not applicable. |
</threat_model>
