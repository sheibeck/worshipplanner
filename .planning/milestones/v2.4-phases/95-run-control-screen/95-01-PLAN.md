<objective>
Extract the pure service-load + read-only assembly slice out of useOutputWindow.ts into a new,
lifecycle-light composable `src/composables/useServiceAssembly.ts`, and refactor useOutputWindow to
consume it — WITHOUT changing any observable output-window behavior and WITHOUT touching the three
existing test files. This is the "reuse, don't fork" foundation the Phase 95 Run/control screen builds
on: RunControlView (95-03) needs the SAME serviceId/orgId scoping + initial-load watch + WR-02 subscribe
gate + read-only useSlideshowAssembly the output windows use, but it must NOT inherit useOutputWindow's
wake-lock / fullscreen / cursor / postHello / unsubscribeAll machinery (all wrong for a single-writer
in-app control surface). Sharing the small assembly slice is the clean seam; useOutputWindow keeps the
output-only lifecycle.

Purpose: R262/R263/R264 are delivered by RunControlView, whose rail and previews read the SAME assembled
slideshow the audience/confidence windows do. Extracting the ~20-line load core (rather than re-inlining
or reusing the whole output composable) means the control screen and the output windows can never drift
in how they resolve serviceId/org, do the initial-load watch, or run the WR-02 org-mismatch gate.

Output: `src/composables/useServiceAssembly.ts` (new) and a refactored `src/composables/useOutputWindow.ts`.
RunControlView consumes useServiceAssembly in 95-03. The regression gate for THIS plan is the three
existing, unmodified suites (18 + 23 + 12 = 53 tests).
</objective>
