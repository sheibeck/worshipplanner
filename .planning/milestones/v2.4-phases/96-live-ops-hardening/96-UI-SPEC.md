# Phase 96 — UI Design Contract

> Visual and interaction contract for the **recovery affordances** added to the existing Phase 95
> Run/Control screen. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This phase introduces NO new screen, route, or output surface.** It hardens
> `src/views/RunControlView.vue` by adding two calm recovery affordances inside the **existing top-bar
> output-status cluster** (and the sibling banner band beneath it) defined in `95-UI-SPEC.md §5`. Every
> design token — spacing, typography, color, the honest `idle | opening | placed | partial | fallback |
> blocked` state machine, the amber-never-red rule, and the colorblind-safe dot+word pairing — is
> **inherited verbatim from Phase 95** and is NOT restated or overridden here. This document specifies
> ONLY the delta: the closed-output reopen affordance (R274), the monitor-unplug reassign affordance
> (R274), and the confirmation that R273 sync needs no new visual element.

## Color

**Inherited verbatim from `95-UI-SPEC.md`.** The critical inherited rule governs this entire phase:

> **A recovery affordance is CALM — amber, never red.** A closed output window or an unplugged monitor
> mid-service is stressful; the UI's job is to reassure the operator it is fully recoverable and their
> place is safe. Red is reserved ONLY for (1) the on-air `LIVE` badge dot and (2) the destructive
> "Exit run mode" confirm button — see Phase 95. **No recovery state may use red.**

| Role | Value | Usage in this phase |
|------|-------|---------------------|
| Recovery / needs-attention | `amber-950` bg / `amber-800` border / `amber-200` text / `amber-300/400` dot+glyph | Closed-output status row, the Reassign banner — identical to the Phase 95 `fallback`/`blocked` amber idiom |
| Ready (unaffected outputs) | `green-400` dot + `text-gray-100` | An output that is still open stays green "Displays ready"; only the affected output turns amber |
| Accent (indigo) | `indigo-600` fill / `indigo-500` ring | The Reopen and Reassign buttons reuse the Phase 95 `Go live` primary-button idiom (`bg-indigo-600 hover:bg-indigo-500`, `focus:ring-indigo-500`) |

**Accent (indigo) reserved for:** the **Reopen Audience / Reopen Confidence** buttons and the **Reassign
displays** button (they are recovery CTAs, identical idiom to Phase 95's `Go live` retry). NOT for the
status dots, NOT for banner body text.

**Colorblind-safe (inherited):** every status dot is paired with a word. The amber "closed" dot is always
paired with the literal text "closed"; the reassign banner's amber triangle is always paired with a
heading. Never color-only.

## Copywriting Contract

The heart of this phase. Copy is prescriptive and tuned to **reassure**. Two hard rules govern it:

1. **Reopen copy MUST NOT imply the operator loses their place.** Reopening re-runs the Phase 95 open+place
   path; the reopened output `postHello`s and the control view (single source of truth for `index`)
   resends the current slide, so **position is restored automatically**. Copy must actively state this.
2. **Closed-window vs monitor-unplug must be distinguishable by copy alone.** A closed window = "your
   display window was closed, reopen it." A monitor unplug = "your monitors changed, reassign them." The
   two affordances use different headings, different verbs (Reopen vs Reassign), and different placements
   (inline cluster row vs banner band).

### Closed-output recovery (R274) — inline per-output, in the top-bar cluster

Rendered inside the existing `placed` cluster: the still-open output keeps its green
`Audience → {label}` / `Confidence → {label}` line; the **closed** output's line is replaced by an amber
recovery row.

| Element | Copy |
|---------|------|
| Closed-output status label (Audience) | **Audience display closed** (amber dot, `text-sm`) |
| Closed-output status label (Confidence) | **Confidence display closed** |
| Reassurance sub-label (both) | You won't lose your place — reopening returns to the current slide. (`text-xs text-amber-200/80`) |
| Reopen button (Audience) | **Reopen Audience** (`aria-label="Reopen the audience display on its screen"`) |
| Reopen button (Confidence) | **Reopen Confidence** (`aria-label="Reopen the confidence display on its screen"`) |

> Do **not** use the words "lost", "crashed", "error", "failed", or "disconnected" for a closed window —
> a closed window is expected and recoverable. Say **closed**.

### Monitor-unplug recovery (R274) — first-class banner, in the sibling banner band

Rendered as an amber banner in the same band that hosts the Phase 95 `fallback`/`blocked` banners
(`m-4 ... border border-amber-800 bg-amber-950 px-4 py-3 text-amber-200`), reusing `MonitorSetupView.vue`'s
reprompt language so the operator sees the same words in both places.

| Element | Copy |
|---------|------|
| Banner heading | **Your monitor setup changed** (verbatim from `MonitorSetupView.vue` reprompt; amber triangle glyph) |
| Banner body | A display was unplugged or rearranged, so we can't place the {role} output on its old screen. Your place in the service is safe — reassign your displays to keep going. |
| Primary action (link) | **Open monitor setup** → `router-link to="/monitor-setup"` (`text-amber-200 underline`) — reuses the Phase 95 fallback banner's link idiom |
| Secondary action (optional, if the role's window is still open on a valid screen) | **Reopen & replace {role}** — re-runs open+place for that output on the new mapping |

> The **distinguishing verb is "reassign"/"changed"** (monitors), never "reopen"/"closed" (windows). The
> banner names the *monitor* problem; the cluster row names the *window* problem. If both happen at once
> (a monitor is unplugged AND its window closed), the **banner takes precedence** — reassigning is the
> superset action and re-establishes placement before any reopen.

### Sync (R273) — NO new visual element

**R273 requires confirmation, not UI.** The audience and confidence outputs already stay in sync via the
Phase 91/93/94/95 BroadcastChannel `postState`/`onState` + `seq` stale-drop + `hello`→resend handshake.
This phase adds **no banner, badge, indicator, or "in sync" affordance** — a sync indicator would be
noise the operator must learn to trust, and the honest single-source-of-truth model already guarantees it.
The `placed` "Displays ready" summary already communicates the running state. **Record explicitly:** R273
introduces zero new visual elements; it is satisfied by end-to-end confirmation that a reopened/reloaded
output re-syncs to the exact current index via the existing handshake.

### Honesty rule (inherited from Phase 95, load-bearing)

**No recovery affordance may claim success unless the reopened window handle is non-null.** Clicking
Reopen re-enters the Phase 95 open+place path, which already resolves to the honest
`placed | partial | blocked` state based on real non-null handles (WR-01/WR-02 guards). A reopen that the
pop-up blocker refuses MUST fall back to the existing `blocked`/`partial` copy — it must NOT flip the row
back to green "Displays ready". The stale-resolution guard (`goLiveRequestId`/`isUnmounted`, WR-01) MUST
remain intact across a reopen.

## Layout & Component Contract

> Prescriptive placement of the two new affordances **within existing Phase 95 structure**. No new bands,
> routes, or surfaces.

### A. Closed-output reopen — lives in the top-bar cluster (`95-UI-SPEC.md §5`, §1 top bar)

- Detection is a per-output boolean (`audienceClosed` / `confidenceClosed`) driven by the shared
  `handle.closed` poll (Context decision). It does **not** add a value to the `OutputStatus` enum — the
  cluster stays in `placed` while one output is closed; only the affected **line** changes.
- Within the existing `placed` cluster (`flex flex-col items-end gap-0.5`), replace the affected output's
  green line with a compact amber recovery group:
  - Row 1: `inline-flex items-center gap-2` — amber dot (`h-2 w-2 rounded-full bg-amber-400`) + the label
    **"Audience display closed"** (`text-sm text-amber-200`) + the **Reopen Audience** button inline
    (`min-h-11 rounded-md bg-indigo-600 hover:bg-indigo-500 px-3 py-1.5 text-sm font-medium text-white
    focus:ring-2 focus:ring-indigo-500`).
  - Row 2: the reassurance sub-label (`text-xs text-amber-200/80`), from the Copywriting Contract.
- The unaffected output keeps its green `{role} → {label}` line unchanged. If **both** outputs are closed,
  render both amber rows (Audience above Confidence), each with its own reopen button.
- `data-testid`: `run-reopen-audience` / `run-reopen-confidence` on the buttons;
  `run-output-closed-audience` / `run-output-closed-confidence` on the rows (for the closed-detection test).
- On click: re-run the Phase 95 open+place path for **that role only** (single-output openPlaced/openUnplaced
  variant). On the reopened output's `hello`, the control resends the current `index` — position preserved.

### B. Monitor-unplug reassign — lives in the sibling banner band (`95-UI-SPEC.md §5`)

- Detection: the `screenschange` / `currentscreenchange` listener on the Go-live `ScreenDetails` re-runs
  `matchMapping(loadMapping(), liveScreens)`; a `needs-reprompt` result (assigned fingerprint gone) sets a
  `monitorChanged` flag. The listener is removed on exit/unmount (no leak — asserted in tests).
- Render an amber banner in the same band as the Phase 95 `fallback`/`blocked` banners, reusing that exact
  markup (`flex-none m-4 flex items-start gap-3 rounded-md border border-amber-800 bg-amber-950 px-4 py-3
  text-amber-200`, amber triangle glyph, `min-w-0 flex-1` body). Copy per the Copywriting Contract.
- `data-testid`: `run-reassign-banner`; the setup link reuses the existing `to="/monitor-setup"` router-link.
- **Precedence:** the reassign banner is mutually senior to the closed-output row. When `monitorChanged` is
  true, show the banner; a reopen chip for the same role is suppressed until reassignment resolves (avoids a
  reopen onto a screen that no longer exists).
- If `matchMapping` still returns `matched` after a `screenschange` (e.g. a benign refresh), **no banner
  appears** — no false alarm (asserted in tests).

### C. Sync — no component

No markup. See Copywriting Contract "Sync (R273)". Confirmation-only.

## Flags for the UI-Checker

- **FLAG (reassurance):** The closed-output reopen affordance MUST state that position is preserved. Verify
  the reassurance sub-label ("You won't lose your place — reopening returns to the current slide.") is
  present and that NO copy implies loss ("lost"/"crashed"/"error"/"failed"/"disconnected" are banned for a
  closed window). This is the highest-risk copy in the phase — a projectionist who fears losing their place
  under live pressure is the exact failure this phase exists to prevent.
- **FLAG (distinguishability):** Closed-window vs monitor-unplug MUST be distinguishable. Verify the two use
  different verbs (**Reopen** vs **Reassign**), different headings ("{role} display closed" vs "Your monitor
  setup changed"), and different placements (inline cluster row vs banner band). A single generic "something
  went wrong, click to fix" affordance would FAIL this contract.
- **FLAG (amber-never-red):** No recovery state may use red. Verify closed rows, the reassign banner, and
  their dots/glyphs are amber (`amber-200/300/400/800/950`), consistent with Phase 95's `fallback`/`blocked`.
- **FLAG (honesty):** A reopen must not flip to green "Displays ready" unless the reopened window handle is
  non-null. Verify the pop-up-blocked reopen falls back to Phase 95's `blocked`/`partial` copy (carries over
  the WR-01/WR-02 honesty guards).
