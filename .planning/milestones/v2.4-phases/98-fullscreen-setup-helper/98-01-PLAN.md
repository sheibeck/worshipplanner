<objective>
Build the pure, framework-free logic layer for the Automatic Fullscreen setup helper: OS/browser
detection, origin-baked policy-file generators (Windows `.reg` HKCU+HKLM, macOS `.mobileconfig`,
Linux managed JSON), a Blob download helper, and the read-only readiness composable. This is the
substrate the Wave-2 UI panel consumes.

Purpose: R285 (honest ready/not-ready/unsupported detection) and R286 (correct per-OS,
origin-correct artifact generation) are fundamentally pure-function problems — isolating them here
lets the UI plan (98-02) stay a thin rendering layer, and lets every string body + branch be pinned
by mock-light unit tests before any Vue is written.

Output: `src/utils/osDetect.ts`, `src/utils/fullscreenPolicyFiles.ts`, `src/utils/downloadTextFile.ts`,
`src/composables/useFullscreenReadiness.ts`, each with a co-located test file.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| app code -> generated policy file | The origin string is templated into a file the operator will run against their OS/browser policy store. |
| browser policy store -> permission query | The composable only READS grant state; it never writes policy or triggers fullscreen. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-98-01 | Tampering | fullscreenPolicyFiles generators | medium | mitigate | Origin flows in ONLY as the `origin: string` param; the caller supplies `window.location.origin` (a browser-computed, well-formed scheme://host[:port] string with no quote/newline/registry-special chars — RESEARCH V5). No URL query param or user text is ever threaded into a generator. Tests pin that the emitted artifact contains exactly the passed origin. |
| T-98-02 | Spoofing | generated .reg/.mobileconfig/JSON | low | accept | Files grant ONLY the single-origin AutomaticFullscreenAllowedForUrls content setting — no broader policy surface. This is the inherent, browser-mitigated risk profile of any policy file (the "may be dangerous" download prompt is the platform's own control), not new attack surface this plan introduces. |
| T-98-03 | Elevation of Privilege | useFullscreenReadiness | low | mitigate | Composable is read-only: it must not call requestFullscreen (behavioral test asserts the spy is never invoked), so it cannot self-grant or trigger no-gesture fullscreen — preserving the existing gesture-fallback contract. |

No package-install threat row (T-98-SC): this plan installs no npm/pip/cargo packages (RESEARCH Package Legitimacy Audit — N/A).
</threat_model>
