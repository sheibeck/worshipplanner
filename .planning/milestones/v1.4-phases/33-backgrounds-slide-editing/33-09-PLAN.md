<objective>
Break the click-selects-and-edits coupling, and make the menu the single dispatcher for every slide
action.

Purpose: R051's actual goal is that slides can be dragged without triggering edit. That is satisfied
by breaking the select-to-edit coupling, not by making the card inert. R052's two drawers then need a
caller that picks the mode.
Output: an `onSelectSlide` that only selects, an `onMenuAction` that dispatches all six keys, and a
drawer with no duplicated navigation affordance.
</objective>

## Flagged planner assumption (edge probe, unresolved row)

**R051** was classified `unclassified` by the specless edge probe and is therefore never
auto-backstopped. Its edge behaviour is defined by `33-UI-SPEC.md` §§2/3 and §11, not by the probe.
**The assumption being made:** "a slide enters edit mode only via the menu" is fully satisfied by
(a) the menu existing on every card whose stored entry resolves and (b) card click no longer opening
the drawer — with no additional keyboard route into edit mode required beyond the native tab order
into the trigger. Recorded so a reviewer can overturn it cheaply, and not treated as probe-verified.
