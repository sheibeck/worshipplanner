<objective>
Make `SlideCard.vue` able to host the 3-dot menu legally, and give it a background provenance chip.

Purpose: the menu trigger must be a real `<button>` with menu ARIA, and the HTML content model
forbids nesting one interactive element inside another — the card's current root blocks it. Separately,
R056's override is worthless if a user cannot see which slides have their own background and which
inherited one.
Output: a card whose root is a `role="button"` div with identical activation semantics, mounting
`SlideActionMenu`, and rendering one of three provenance chips.
</objective>

same workaround, because `aria-haspopup` and `aria-expanded` are only meaningful on a real button.
