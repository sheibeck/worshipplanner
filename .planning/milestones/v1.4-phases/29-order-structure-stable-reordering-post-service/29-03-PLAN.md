<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser DOM (SortableJS event) → view state | `evt.to` / `evt.from` / the index properties are attacker-influenceable in a compromised page and shape the persisted slots array. |
| view → Firestore (`updateService`) | The reorder write crosses into persisted, shared, production data. |
| viewer role → editor mutation | A non-editor must not be able to reorder. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-29-06 | Tampering | `onEnd` destination resolution | high | mitigate | The destination key is validated against `SERVICE_SECTIONS` before assignment (`groupBySection` routes an unknown value to the legacy bucket rather than minting a new section); the moved slot is spliced out of and into typed buckets, so a forged index can reorder but cannot fabricate or drop a slot. |
| T-29-07 | Tampering | Partial cross-section write | high | mitigate | Order and `section` are both fields of the single `slots` array; one `updateService` call carries both, so the move cannot half-apply. Asserted by the cross-section payload test in Task 2. |
| T-29-08 | Elevation of Privilege | Reorder by a non-editor | high | mitigate | Instances are created only when the `canReorder` guard holds (`authStore.isEditor`); the drag handle already renders editor-only (line 538). Server-side status/role enforcement in `firestore.rules` is Phase 31's scope and is explicitly not weakened here. |
| T-29-09 | Repudiation | Silent save failure | high | mitigate | Task 3's catch reverts local state, surfaces the §5 message, and logs with the bracketed module name — a rejected reorder can no longer look successful. |
| T-29-10 | Denial of Service | Sortable instances leaked across re-renders | medium | mitigate | Keyed create/destroy guard plus `onUnmounted` teardown; asserted by the unmount test in Task 2. |
| T-29-SC | Tampering | npm/pip/cargo installs | high | accept | No package install task in this plan; `sortablejs` is already a resolved dependency, so the legitimacy gate does not apply. |
</threat_model>
