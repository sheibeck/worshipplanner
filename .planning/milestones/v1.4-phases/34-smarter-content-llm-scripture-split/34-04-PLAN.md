## ★ Reachability: this component is mounted nowhere, and that is not this plan's to fix

Verified against live source. `CongregationalEditor.vue` has **no production mount path** — no route,
no parent component, no dynamic import references it anywhere outside its own test file. Phase 30's
R047 deliberately removed the editor panel from the Service Order tab and left both editor components
"on disk, unmounted, for Phase 34/R064 to reuse."

**This makes a third premise in this phase's own CONTEXT.md false.** CONTEXT states "Success criterion 1
is already true today, manually," citing the working 321-line manual editor. The editor works when
mounted, but no user can reach it — so ROADMAP success criterion 1 is **not** true for a user today,
and the AI split added here is equally unreachable until someone mounts this component.

**Do not fix that in this plan, and do not treat it as a reason to reduce scope.** Mounting it is
blocked on a data-model decision the owner has already ruled on once, in the opposite direction:

- `CongregationalEditor` reads and writes `congregationalSections` on a **separate `ScriptureReading`
  document** via `store.createReading` / `store.updateReading`.
- R047's delivered shape made the **SCRIPTURE slot** the source of truth (`scriptureRefFromSlot` →
  `slideGroupMaterializer`), and explicitly **rejected** linking a separately-created reading document
  to the slot — the owner superseded that model in favour of slot-as-source-of-truth.
- `ScriptureSlot` carries `readingMode` but has no `congregationalSections` field, so sections written
  by this editor currently reach no slide.

Making the sections reach a slide therefore requires either re-linking the reading document (the model
the owner rejected) or moving `congregationalSections` onto `ScriptureSlot` and carrying them through
the materializer. That is an owner decision with an existing precedent against one option, not a
default a planner may pick. Task 3 records it. Everything else in this phase is correct and complete
under either outcome.

Also read, before touching this component: its own `WR-04 CALL-SITE CONTRACT` comment at the bottom of
the file, addressed by name to Phase 34. `currentReadingId`, `surfaceId`, `sections`, `referenceText`
and `rawText` are captured once at mount and are **not** reactive to `props.readingId` changing.
Whoever mounts this must key it on `readingId`.
