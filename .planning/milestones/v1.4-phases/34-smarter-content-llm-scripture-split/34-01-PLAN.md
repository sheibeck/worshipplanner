<objective>
Build the pure-function boundary layer that makes altered scripture structurally impossible: compute
the ordered set of legal split positions from untouched ESV text, embed visible index markers for the
model to choose among, and slice byte-exactly back out of the source.

Purpose: This is the correctness guarantee of R064. Because the model may only emit integer indices
into a pre-computed array of legal positions, a mid-sentence split is not merely discouraged — it is
not a representable value. Everything downstream (schema, validation, the call) depends on this file.

Output: `src/utils/scriptureBoundaries.ts` with four pure exports and a full unit suite including a
Psalm-136-shaped fixture and a non-ASCII-punctuation encoding fixture.
</objective>

## Phase premise corrections — read before writing code

Three premises in this phase's own source documents are false. All three are verified against live
artifacts and all three change what you build.

1. **The `@anthropic-ai/sdk` upgrade is NOT a prerequisite.** R064 says `^0.78.0` "predates the
   structured-outputs support this depends on." It does not — structured outputs went GA in SDK
   `0.72.0`, and the installed `0.78.0` already ships `output_config.format`, `messages.parse()`, and
   `jsonSchemaOutputFormat`. **Do not schedule or perform an SDK upgrade in this phase.** No plan in
   this phase installs, upgrades, or removes any package.
2. **Validation cannot live at the Cloud Function proxy.** `functions/src/index.ts` is a byte-blind
   pass-through that never sees the ESV source text. Validation is client-side. **No plan in this
   phase touches `functions/`.**
3. **The manual congregational editor is not reachable by any user today.** See plan `34-04` — it
   affects reachability, not this plan's work. This plan is correct either way.
