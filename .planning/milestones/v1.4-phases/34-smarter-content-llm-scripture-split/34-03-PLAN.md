## Resolved spike — the Vitest mock shape for `messages.parse()`

RESEARCH flagged this as an open test-infrastructure question. It is now answered from the installed
SDK's own source; do not re-investigate.

- `messages.parse(params, options)` is a thin wrapper: it calls `create(params, options)` and then
  passes the resulting message through the SDK's `parseMessage` helper, which reads
  `output_config.format`, parses each text block, and exposes the first result as `parsed_output`.
- The existing test file replaces the entire `@anthropic-ai/sdk` module with a factory returning an
  object whose `messages` has only a `create` key. **The mock therefore has no `parse` method and a
  call to it would throw.** The factory must gain a second key alongside `create`, and the new tests
  assert against that second mock function.
- `jsonSchemaOutputFormat` is imported from the `@anthropic-ai/sdk/helpers/json-schema` subpath, which
  is a different module specifier and is therefore **not** covered by the existing module mock — the
  real helper runs in tests. It throws unless the schema's `type` is `object`; `SPLIT_SCHEMA` is an
  object, so this is satisfied. Do not add a second mock for the helper: letting the real one run means
  the tests exercise the real schema transform.
