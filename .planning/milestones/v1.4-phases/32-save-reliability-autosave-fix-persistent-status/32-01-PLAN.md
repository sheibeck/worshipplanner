<objective>
Reproduce, then fix, the autosave swallow that R039 names: a discrete one-shot mutation
(picking a song) that lands immediately after a prior save's own Firestore echo is silently
dropped — no debounce armed, no status change, no console signal.

Purpose: this is the phase's load-bearing plan. Every other plan in Phase 32 is status
plumbing; this one is the defect. R039's requirement text mandates repro-before-fix, so the
failing test is its own commit and must be observed RED before any source change.

Output: a red-then-green repro test, a store-layer echo classifier built on Firestore's own
`metadata.hasPendingWrites`, and a three-line guard in the view's remote-merge watcher.
</objective>

<recorded_deviation>
## ★ Deviation from 32-CONTEXT.md — fix location moved from the view to the store

`32-CONTEXT.md` was written assuming the fix would land in `ServiceEditorView.vue`
(its Integration Points section points at `onSave()` line 3467 and the payload destructure
at 3482). `32-RESEARCH.md` then verified the mechanism line-by-line at HIGH confidence and
concluded otherwise:

- Every write this view makes goes through `serviceStore.updateService`, which appends
  `updatedAt: serverTimestamp()` unconditionally (`src/stores/services.ts:171`).
- There are **two** write entry points, not one: the debounced `onSave()` *and* the D-15
  immediate reorder-save inside the Sortable `onEnd` handler
  (`ServiceEditorView.vue:1817-1863`). Both produce the identical echo and both reset the
  identical guard.
- Patching `onSave()`'s payload (re-including `updatedAt`, or re-syncing
  `localService.value.updatedAt` after a save) fixes one call site and leaves the other
  broken — RESEARCH Pitfall 1.

**Decision (recorded, not silent):** the primary fix is the store-layer echo classifier in
`src/stores/services.ts`. The view changes only to *consume* that signal. `onSave()`'s
payload shape is NOT touched. This deviation is deliberate and is the reason this plan
modifies `src/stores/services.ts` at all, which `32-CONTEXT.md` never anticipated.
</recorded_deviation>
