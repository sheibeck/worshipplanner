<objective>
Close the four Cloud-Functions-only security gaps the v2.8 review found (backlog 999.5): the
unauthenticated `/api/planningcenter` proxy (R339 / SEC-A-01, the milestone's highest-priority
finding), the ESV/NLT rate-limit gap (R340 / SEC-C-01), the missing `queueServiceMessage` enqueue
ceiling (R344 / SEC-C-05), and the missing `parsePptx` daily import quota (R345 / SEC-C-06). Every
change extends an existing in-repo pattern; no `firestore.rules` and no frontend files are touched.

Purpose: Every Cloud Functions entry point that today has no authentication or no rate/quota ceiling
gets one, without altering any within-limit behavior — closing an open-relay/DoS surface and three
unthrottled fan-out surfaces.

Output: A hardened `functions/src/index.ts` plus new tests in `functions/src/index.test.ts` proving
each gate/limit fires AND that ordinary within-limit usage and the sibling `anthropic` path are
unaffected.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| unauthenticated internet → /api/planningcenter | Reachable today with no app token; must now require a valid X-App-Auth Firebase ID token before any upstream relay |
| authenticated app user → /api/esv, /api/nlt | Trusted identity, untrusted request volume — no per-caller throttle exists today |
| authenticated editor → queueServiceMessage / parsePptx callables | Trusted identity, untrusted enqueue/import volume — no per-caller ceiling of their own today |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-117-01 | Spoofing/Elevation | api onRequest — planningcenter branch | high | mitigate | AUTH_REQUIRED gate → verifyAppCaller(X-App-Auth) → 401; closes the unauthenticated open relay and the shared-pool DoS on the paid AI/Bible proxies (R339) |
| T-117-02 | Denial of Service | api onRequest — esv/nlt branches | medium | mitigate | per-uid checkAndConsumeRateLimit on the shared aiRateLimits budget → 429, same shape as anthropic (R340) |
| T-117-03 | Denial of Service | queueServiceMessageHandler | medium | mitigate | per-uid enqueue-rate + per-org daily enqueue quota on dedicated counters → resource-exhausted (R344) |
| T-117-04 | Denial of Service | parsePptxHandler | low | mitigate | per-uid + per-org daily import quota on dedicated counters → resource-exhausted (R345) |
| T-117-05 | Denial of Service (fail-open window) | all four rate/quota limiters | low | accept | limiters fail OPEN on a Firestore error by locked decision (65-CONTEXT.md — cost guardrail, not a security control). The planningcenter AUTH gate does NOT fail open: an unverifiable token is a hard 401 |
| T-117-06 | Tampering | quota counter keys | low | mitigate | counter keys derive only from server-verified identity — resolveOrgId(token claim) for the proxy, and the independently re-verified membership + auth.uid for the callables — never a raw client-declared value, so no cross-org counter poisoning |
| T-117-SC | Tampering | npm/pip/cargo installs | low | accept | no new dependencies are added this phase; nothing to audit |
</threat_model>
