# Phase 58 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Scope & Precedent (read first)

Phase 58 ships plumbing, not send surfaces. There are exactly **two** UI elements in this phase:

1. **Primary — a new "Messaging" card on `SettingsView.vue`** (org owner surface). Mirrors the
   existing AI Features / Planning Center Integration / Bible Translation / Slide Typography cards
   **exactly** — same `rounded-lg bg-gray-900 border border-gray-800 p-4 mt-6` card shell, same
   explain-then-toggle ordering, same auto-save-on-change for toggles/selects, same explicit-Save-
   button for free-text fields, same inline `Saved!` / `Failed to save. Please try again.` feedback.
   Appended **after** the Slide Typography card (last), following the established precedent that each
   new settings feature appends its own card at the bottom rather than inserting mid-list.

2. **Secondary — a small per-service "Messaging defaults" panel on the Service Order tab**
   (`ServiceEditorView.vue`), required by ROADMAP.md's success criterion 3 (R132: per-service
   overrides that inherit from Settings, Draft-only editable, read-only once locked). This reuses the
   **exact** `<option value="">Default ({{ orgValue }})</option>` inherit-or-override select idiom
   already shipped for the per-scripture-slot Bible-version override (`ServiceEditorView.vue:1078-
   1092`), and the exact locked-read-only branch pattern already shipped at the same call site
   (`ServiceEditorView.vue:1093-1100`). No new visual language — the same idiom, one field-set over.

No composer, no modal, no delivery-history panel, no lock/re-lock UI ships in this phase — those
belong to Phases 59-62 per the phase boundary in `58-CONTEXT.md`.

**Focal point (visual hierarchy):** on the Messaging card, the eye lands first on the **global
Messaging on/off kill-switch** (the explain-then-toggle top row) — every other control on the card is
inert until it is on, so it is the primary anchor, consistent with the AI/PC cards' lead toggle. On the
per-service panel, the anchor is the **lock-notification override select**.

### Accepted deviations — app-wide consistency (concrete decisions, checker-reviewed 2026-08-13)

The `gsd-ui-checker` flagged three items against the generic design-system rubric. All three are cases
where the rubric's ideal conflicts with a convention **already shipped across the three sibling Settings
cards this phase is required to mirror**. Changing them here would make the new Messaging card the single
inconsistent card on the screen — a worse user-facing outcome than the rubric deviation. These are
**accepted as deliberate decisions** (not bare "precedent"), authorized under the v1.7 autonomous grant's
"pick the reasonable default, state it" clause, and recorded here so the planner treats them as locked:

1. **CTA label `Save` (Copywriting BLOCK → ACCEPTED).** Every existing settings-card free-text sub-form
   uses `Save`. A one-off `Save Email Settings` on only this card breaks the established button copy. If
   the app ever standardizes settings CTAs, that is a project-wide copy pass, not a Phase-58 divergence.
2. **Third font weight `font-medium` / 500 (Typography BLOCK → ACCEPTED).** `font-medium` on primary
   buttons is app-wide UI chrome (used by every existing card's Save button). This card inherits it; it
   introduces no new weight. Collapsing only this card to two weights would visibly mismatch its siblings.
3. **`12px` spacing (`gap-3`/`mb-3`/`px-3`/`space-y-3`) (Spacing BLOCK → ACCEPTED).** `12px` is a
   load-bearing app-wide token in every existing Settings card. It is a multiple of 4 and already the de
   facto scale here; re-spacing only this card to `8`/`16` would misalign it against its siblings.

Net: no new visual language, no new tokens, no new copy pattern — the card is byte-consistent with its
neighbors. A future design-system cleanup phase (project-wide) is the correct venue for the rubric ideals,
not a single new card. **Verification note:** these are UI-consistency judgments the owner can eyeball at
`/gsd-verify-work 58` against the existing AI/PC/Bible cards.

## Component Inventory

### 1. Messaging card (`SettingsView.vue`) — primary deliverable

Card shell (verbatim reuse of the existing card markup):
```html
<div class="rounded-lg bg-gray-900 border border-gray-800 p-4 mt-6">
  <h2 class="text-sm font-semibold text-gray-300 mb-3">Messaging</h2>
  ...
</div>
```
Position: appended **after** the Slide Typography card (currently the last card in the file).

Field order, top to bottom (explain-first pattern, mirroring the AI Features card):

1. **Explanatory copy** (`text-xs text-gray-400 mb-3`): one short paragraph stating what the switch
   controls before the switch itself is shown — mirrors the AI Features card's "This app uses AI to
   speed up planning... Turn it off and these disappear" framing.
2. **Global kill-switch** — checkbox, `Enable volunteer email messaging`, auto-saves on `@change`
   (mirrors `onToggleAiEnabled`/`onTogglePcEnabled` exactly: `updateDoc` a single quoted dot-path leaf
   `settings.messaging.enabled`, mirror-write into `authStore.settings.messaging.enabled`, 2s "Saved!"
   feedback, revert-on-error). **Defaults to unchecked** (fresh org = OFF), per R130 and
   `58-CONTEXT.md`'s deliberate deviation from the AI/PC toggles' default-true.
3. **Conditionally revealed sub-block** (`v-if="messagingEnabledInput"`, `mt-6 pt-6 border-t
   border-gray-800` — mirrors the PC Integration card's credential-reveal pattern exactly), titled
   "Automatic email defaults" (`text-xs text-gray-400 mb-3` intro line: "These are the starting values
   for every service — a planner can still override them per service while it's in Draft."):
   - **Lock-notify default** — checkbox, `Email everyone when a service is locked`, auto-saves on
     change, dot-path `settings.messaging.lockNotifyDefault`. Defaults **unchecked** (conservative,
     owner opts in — `58-CONTEXT.md`).
   - **Reminder-enabled default** — checkbox, `Send the service link before the service`, auto-saves
     on change, dot-path `settings.messaging.reminderEnabled`. Defaults **unchecked**.
   - **Reminder days-before** — `<select>` (NOT a raw number input — discretionary call, see below),
     conditionally revealed only when the reminder-enabled checkbox above is checked
     (`v-if="reminderEnabledInput"`), label `Send it this many days before the service`, options `1,
     2, 3, 5, 7, 10, 14` (default `7`), auto-saves on change, dot-path
     `settings.messaging.reminderDaysBefore`.
     - **Discretionary decision, stated explicitly:** a `<select>` of common day-counts rather than a
       free-`<input type="number">`, so this field can auto-save on `@change` like every other toggle
       in the card, avoiding a fifth "explicit Save button" exception in one card. Mirrors the design
       reference's `[7 days ▾]` dropdown-chip framing (`DESIGN-messaging.md` § 5b).
   - **From name / Reply-to** — two optional single-line text inputs (`From name`, `Reply-to email`),
     placeholder text `e.g. First Baptist Church` / `e.g. planning@yourchurch.org`, styled identically
     to the Organization Name input (`w-full sm:w-80 bg-gray-800 border border-gray-700 ...`). Grouped
     under one explicit **Save** button below both fields — mirrors the Organization Name /
     Organization Slug fields' explicit-Save pattern exactly (free text needs a debounce boundary;
     toggles/selects do not). Dot-paths `settings.messaging.fromName` /
     `settings.messaging.replyTo`, both optional (empty string clears the field, same as PC
     credentials' clear semantics).
4. **Organization timezone** — `<select>`, label `Organization timezone`, always visible (**not**
   gated by the kill-switch — it is conceptually org-wide, per `58-CONTEXT.md`), helper text (`text-xs
   text-gray-500 mt-2`): "Used by the scheduled service-link reminder, once messaging is turned on
   above." Options: a curated shortlist of common US timezones (discretionary, per `58-CONTEXT.md`'s
   "Claude's Discretion") — `America/New_York` (Eastern), `America/Chicago` (Central),
   `America/Denver` (Mountain), `America/Phoenix` (Arizona, no DST), `America/Los_Angeles` (Pacific),
   `America/Anchorage` (Alaska), `Pacific/Honolulu` (Hawaii) — labeled by common name, valued by IANA
   string. Auto-saves on change, dot-path `settings.timezone`. Default value `America/Chicago`
   (`DEFAULT_ORG_SETTINGS.timezone`, already decided in `58-CONTEXT.md`).

Every auto-saving control in this card follows the exact `Saved!`/error/revert triad already shipped
by `onToggleAiEnabled`/`onTogglePcEnabled`/`onChangeBibleVersion` — no new feedback pattern.

### 2. Per-service "Messaging defaults" panel (`ServiceEditorView.vue`) — satisfies ROADMAP criterion 3

A small card, same shell as the Settings cards (`rounded-lg bg-gray-900 border border-gray-800 p-4`),
placed on the Service Order tab near the top of the page (alongside other service-level metadata —
same tier as the sermon topic/passage fields), visible only to `authStore.isEditor`.

- **Draft-only editable, locked read-only** — gate exactly like the existing per-slot Bible-version
  override at `ServiceEditorView.vue:1061` / `:1093-1104`: `v-if="canEditService"` renders the editable
  controls, `v-else-if="authStore.isEditor && isLocked"` renders a static read-only summary line, `v-
  else` (viewer) renders the same summary line.
- **Editable state** — three rows, each an inherit-or-override `<select>` using the identical idiom
  already shipped for the scripture Bible-version override
  (`<option value="">Default ({{ resolvedOrgValue }})</option>` followed by explicit choices):
  - `Lock notification` — `Default (Settings: {{ on/off }})` | `On` | `Off` → writes
    `services/{id}.messaging.lockNotifyEnabled` (`null` for the Default option).
  - `Service-link reminder` — `Default (Settings: {{ on/off }})` | `On` | `Off` → writes
    `services/{id}.messaging.reminderEnabled`.
  - `Reminder days-before` — `Default (Settings: {{ N }} days)` | `1` | `2` | `3` | `5` | `7` | `10` |
    `14` → writes `services/{id}.messaging.reminderDaysBefore`. Shown only when the row above resolves
    to "on" (either explicitly or via inherited default) — mirrors the reminder-days field's
    conditional reveal in the Settings card above.
  - Each select's `@change` calls the new scoped action `setServiceMessagingDefaults(serviceId,
    patch)` (per `58-CONTEXT.md`, the same dot-path `updateDoc` shape as `setRoleOverride`), not
    `updateService` — no new Save button, no new feedback copy needed beyond the existing inline error
    pattern (`Failed to save. Please try again.`) on failure.
- **Locked / read-only state** — one static text line per field (`text-sm text-gray-200`, mirroring
  `slotScriptureText`'s read-only paragraph at `:1098-1100`), e.g.: `Lock notification: On (default) ·
  Service-link reminder: On, 7 days before (default)`. Overridden values read `On (overridden)` /
  `Off (overridden)` instead of `(default)`.
