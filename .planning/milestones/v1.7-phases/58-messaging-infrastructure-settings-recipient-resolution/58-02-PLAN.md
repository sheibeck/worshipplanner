<objective>
Build the single shared, PURE recipient resolver `src/utils/messagingRecipients.ts::resolveRecipients`
that every later messaging surface (Phase 59 composer, Phase 61 auto-sends, Phase 62 re-lock notice) will
reuse. It wraps the already-pure `resolveServiceRoleAssignments` and turns a `{ teams, individualPersonIds,
includeEveryone }` selection into `{ reachable: RecipientCandidate[], unreachableCount }`, deduped by
person id, with reachability split on empty email.

Purpose: R134 (recipients from assigned roles grouped into selectable teams + "Everyone") and R135 (dedup
by person, exclude + count no-email roles). This is the ONE resolution algorithm the milestone allows —
no later phase re-derives it. Zero Firestore/Pinia imports (types only), so it is unit-tested with no
mocking, matching the `src/utils/serviceRoles.ts` purity contract.
Output: new `messagingRecipients.ts` (resolver + `MESSAGING_TEAM_LABELS` + `RecipientCandidate`/
`RecipientSelection` types) and its comprehensive unit test.
</objective>

    - a matched personId absent from the people array (stale/deleted) is silently skipped and does NOT increment unreachableCount
