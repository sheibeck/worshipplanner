<objective>
Lay the data-model + settings foundation for all of v1.7 messaging: extend OrgSettings with the
`messaging` kill-switch block (default OFF) and a top-level `timezone`, add the optional per-service
`messaging` override shape to the Service type, deep-merge both new settings in loadOrgContext, and
create the single `isMessagingEnabled()` client choke point. No send path, no UI, no Cloud Function —
this is the typed/merged substrate every later plan and phase builds on.

Purpose: R130 (kill-switch default OFF + one choke point), R132 (per-service override shape + org
defaults), R133 (org timezone) all need the typed shape and the single merge point in place before any
consuming surface (the Settings card in 58-04, the per-service panel in 58-05, the send path in Phase 59)
can be written.
Output: extended `OrgSettings`/`DEFAULT_ORG_SETTINGS`, `Service.messaging?`, extended `loadOrgContext`
merge, new `src/utils/messaging.ts::isMessagingEnabled`, and the two new/extended unit test files.
</objective>
