<objective>
Add the thin enqueue half of the send path: `queueServiceMessage` (`onCall`, NO provider secret) that
re-authorizes the caller server-side, re-checks the messaging kill-switch, validates the request, and
writes ONE `messages/{id}` doc via a shared `createQueuedMessage()` doc-shaper. It resolves no recipients
and sends nothing — it returns the new message id and lets the 59-03 trigger do the work.

Purpose: R131 (the callable never trusts the client-declared orgId or kill-switch state — it independently
re-reads org-editor membership and `settings.messaging.enabled`; and it holds no secret, keeping the
provider key on a single Function), R137 (validates the three-type enum), R141 (persists send-now vs
schedule intent as `status: 'queued' | 'scheduled'`). Mirrors the shipped
`parsePptxHandler`/`parsePptx` shape (`functions/src/index.ts`) — handler body exported separately from the
wrapper for direct unit testing.
Output: `RESEND_API_KEY` secret declaration (bound later in 59-03), `createQueuedMessage()`, the exported
request/response types, `queueServiceMessageHandler` + `queueServiceMessage` wrapper, and new describe
blocks in `functions/src/index.test.ts`.

DEPLOY-GATED (v1.7 grant): ships built/tested/UNDEPLOYED. This Function holds no secret.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser (client SDK) → `queueServiceMessage` onCall | Untrusted caller crosses here with a client-declared orgId, recipientSelector, options, and scheduledFor — none is trusted at face value |
| queueServiceMessage → Firestore `organizations/{orgId}` (Admin SDK) | Writes the messages/{id} doc bypassing rules; the callable's own re-checks are the real control |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-59-02a | Elevation of Privilege | a viewer / non-member enqueuing a message | high | mitigate | Auth guard + independent members/{uid} read + role ∈ ['editor','admin'] check; the client's isEditor gate is convenience only. |
| T-59-02b | Tampering / Elevation | cross-org send via a client-declared orgId | high | mitigate | orgId is used only to scope the Firestore path; membership + role are re-read for THAT path, never trusting a client field (parsePptxHandler:292-302 precedent). |
| T-59-02c | Elevation | sending while the org kill-switch is off | high | mitigate | Server re-reads settings.messaging.enabled and rejects when off — defense in depth behind the disabled composer entry point. |
| T-59-02d | Input Validation | invalid type enum / absurd scheduledFor / missing fields | medium | mitigate | Explicit enum + required-arg + scheduledFor sanity validation → HttpsError('invalid-argument') before any write. |
| T-59-02e | Information Disclosure | provider key exposure via this Function | high | mitigate | queueServiceMessage carries NO `secrets:` array; RESEND_API_KEY is declared but bound only in 59-03 — smallest key-holding surface (R131 intent). |
| T-59-SC | Tampering | npm/pip/cargo installs | low | accept | Zero packages installed this plan (resend was installed in 59-01, gated there). No new supply-chain surface. |
