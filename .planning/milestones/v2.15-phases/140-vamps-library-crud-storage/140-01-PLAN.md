<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → Firestore `organizations/{orgId}/vamps/{id}` | Editor writes vamp name/key/tempo/attachment via the store |
| client → Cloud Storage `orgs/{orgId}/vamp-files/{vampId}/{uploadId}/…` | Editor uploads/replaces/deletes the vamp's MP3 |
| store singleton ↔ org identity | The vamps listener is bound to one orgId; a church switch must not leave a stale cross-org listener |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-140-11 | Tampering | in-place MP3 overwrite (replace flow) | high | mitigate | Every upload (incl. replace) uses a fresh `uploadId` path segment (`vampFileStoragePath`), so a replace is always a `create` on a new object, never an `update` — closing the immutable-rule bypass. The immutable `update: if false` gate itself lands in Plan 140-02. |
| T-140-12 | Information disclosure | stale cross-org vamps listener after a sidebar church switch | high | mitigate | `useVampStore().unsubscribeAll()` registered in `resetOrgScopedStores()` (Pitfall 1); test-proven in `orgScopedStores.test.ts`. Prevents Church-A vamps surfacing under Church B. |
| T-140-13 | Tampering | client-side MIME/size validation bypass | medium | mitigate | `validateVampFile` is UX-only; the real authority is the `storage.rules` `audio/mpeg` + `<50MB` gate (Plan 140-02). Client validation only improves the error message, never the security decision. |
| T-140-14 | Denial of service | oversize / many uploads growing the uncapped per-org Storage footprint | low | accept | Per-file ≤50MB cap is the only bound this phase adds; the per-org quota (SEED-003) is deferred. Documented residual, not a phase blocker. |
| T-140-SC | Tampering | npm/pip/cargo installs | low | accept | Zero new dependencies (RESEARCH Package Legitimacy Audit — "none"); every import is an existing direct dependency used identically to the Song twin. No package-legitimacy checkpoint required. |
</threat_model>
