# Phase 142 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Autonomous run.** No `components.json` — the app is a hand-built dark gray-950 Tailwind language
> (established since v1.2, most recently extended by Phase 140/141). This phase adds **one new
> component** (`SlideGroupSetupStrip.vue`) and **restyles two existing ones in place**
> (`SlotVideoOutputControl.vue`, `SlideGroupMusicControl.vue`); `BackgroundControl.vue` gains a new
> rendering mode behind a `variant` prop rather than being restyled, because it has a **second call
> site outside this phase's scope** (`SongLyricEditor.vue`, song-level background) that must render
> pixel-identically to today. Design source: `docs/design/slides-tab.dc.html` Turn 7 variant `7a`
> (chip row + popovers) and Turn 6 `6a` (fuller popover-content reference); sample hex tokens in both
> turns are mapped onto the app's existing gray-900/800/700 + indigo/amber tokens per CONTEXT.md — no
> mockup hex is ported verbatim.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Caret-to-value gap inside a chip, popover row internal gaps |
| sm | 8px | Chip-to-chip gap in the strip row (`gap-2`), popover padding (`p-3`≈12px, see exception) |
| md | 16px | — (not newly used by this phase) |

Exceptions (both mockup-derived, reused as fixed values — not new arbitrary tokens):
- **28px chip height** (`h-7`) — the mockup's `height:28px` pill (the 34px row height in the mockup includes the panel's own vertical padding, not the chip itself).
- **12px popover padding** (`p-3`) and **6px popover-to-chip gap** (`mt-1.5`) — mirrors the mockup's `padding:11px` / `top:34px` offset, rounded to the nearest Tailwind step.
- **232px / 258px popover width** (`w-[232px]` / `w-[258px]`) — verbatim from the mockup's `POP_LEFT`/`popStyle` sizing (`c.id === "audio" ? 258 : 232`); the Audio popover is wider because it hosts the segmented control + search input, which clip below 258px.
- **56px / 44px background swatch tiles** (`h-8 w-14`, i.e. 32×56px, scaled down from the mockup's `56×34`) — sized to fit four tiles (None · 2 recents · upload) across the 232px popover with `gap-2` and 12px padding: `4×56 + 3×8 + 2×12 = 272px` does not fit, so tiles are **44px wide** (`w-11`) in the app: `4×44 + 3×8 + 24 = 224px`, which fits. This is a deliberate deviation from the mockup's 56px swatch width, recorded here rather than silently shrunk during implementation.

## Component Specifications

### 1. Chip anatomy & state table (`SlideGroupSetupStrip.vue`, new)

Each chip is a `position:relative` wrapper holding one pill (button or inert span) and, when open, one
absolutely-positioned popover.

**Pill markup (editable, per state):**

```html
<span class="relative inline-flex">
  <button
    type="button"
    class="inline-flex h-7 items-center gap-1.5 rounded-full border px-2.5 text-[11.5px] transition-colors"
    :class="pillClass"
    :aria-haspopup="'dialog'"
    :aria-expanded="isOpen"
    :aria-controls="popoverId"
    :aria-label="chipAriaLabel"
    data-testid="slide-group-setup-chip-{{ id }}"
    @click="toggle('{{ id }}')"
  >
    <span class="text-[11px] text-gray-500">{{ label }}</span>
    <span class="truncate max-w-[10rem]" :class="valueClass">{{ value }}</span>
    <span class="text-[9px] text-gray-500" aria-hidden="true">▾</span>
  </button>
  <!-- popover, see §2–4 -->
</span>
```

**Pill markup (locked/non-editor — visible but inert, no interaction, no caret):**

```html
<span
  class="inline-flex h-7 items-center gap-1.5 rounded-full border px-2.5 text-[11.5px] cursor-default"
  :class="pillClass"
  data-testid="slide-group-setup-chip-{{ id }}"
>
  <span class="text-[11px] text-gray-500">{{ label }}</span>
  <span class="truncate max-w-[10rem]" :class="valueClass">{{ value }}</span>
</span>
```

| State | Applies to | `pillClass` | `valueClass` | Caret | Interaction |
|-------|-----------|-------------|--------------|-------|-------------|
| Set | Display (always), Background, Audio-Track/Vamp-with-MP3 | `border-gray-700 bg-gray-800 hover:border-indigo-700` | `text-gray-200` | shown | click opens popover |
| Unset ("Add") | Background, Audio only | `border-dashed border-gray-700 bg-transparent hover:border-indigo-700` | `text-gray-500` | shown | click opens popover, focus lands on the first tile/tab |
| Set — Audio, vamp no MP3 | Audio only | `border-gray-700 bg-gray-800 hover:border-indigo-700` | `text-amber-400` | shown | click opens popover on the Vamp tab, warning visible |
| Inherited (song background) | Background only, song group | `border-gray-700 bg-gray-800 hover:border-indigo-700` (solid, same as Set — never dashed) | `text-gray-300` | shown | click opens popover; explainer only, no override control |
| Open | any | `border-indigo-700 bg-indigo-950/40` | same value color as its underlying state | shown | click re-closes; Esc/outside-click closes |
| Locked / non-editor | all three, any underlying state | same colors as the state above, minus hover | same value color | **omitted** | no interaction — rendered as `<span>`, not `<button>`; no `aria-haspopup`/`aria-expanded` |

Only one popover open at a time — a single `openChip: ref<'display' \| 'background' \| 'audio' \| null>`
on `SlideGroupSetupStrip`. `toggle(id)` sets `openChip = openChip === id ? null : id` (verbatim mirror of
the mockup's `openChip` handler). Switching groups (`selectedSlot.id` changes) resets `openChip` to
`null` — same pattern as the existing `openMenuEntryId` watcher in `SlideGrid.vue`.

### 2. Popover shell (shared by all three)

```html
<div
  v-if="isOpen"
  :id="popoverId"
  role="dialog"
  aria-modal="false"
  :aria-label="label + ' options'"
  tabindex="-1"
  ref="popoverRef"
  class="absolute top-full z-20 mt-1.5 rounded-lg border border-gray-700 bg-gray-800 p-3 shadow-2xl"
  :class="[id === 'audio' ? 'w-[258px]' : 'w-[232px]', alignRight ? 'right-0' : 'left-0']"
  data-testid="slide-group-setup-popover-{{ id }}"
>
  <!-- per-chip content, §3–4 -->
</div>
```

No `Teleport` — the panel this strip lives in (`slide-grid-group-media-panel`) sits above
`slide-grid-drop-area`'s own `overflow-y-auto` region, so a plain `position:absolute` popover cannot be
clipped by a scroll ancestor. `alignRight` is computed on open (`popoverRef.value.getBoundingClientRect()`
vs `window.innerWidth`) and flips the popover to right-align under its chip when it would otherwise
overflow the viewport's right edge — this is JS, not a CSS-only `@media` rule, because the flip depends on
the chip's own horizontal position within the wrapped row, not the viewport width alone.

### 4. Background popover content

```html
<div class="flex flex-col gap-2">
  <div v-if="!inheritedFrom" class="flex gap-2"
    @dragover.prevent="isDragOver = true" @dragleave="isDragOver = false" @drop.prevent="onDrop">
    <button type="button" class="h-8 w-11 flex-none rounded-md border flex items-center justify-center text-[10px] text-gray-500"
      :class="!imageUrl ? 'border-indigo-600' : 'border-gray-700'"
      data-testid="background-control-swatch-none" @click="selectNone">None</button>
    <button v-for="r in recents" :key="r.url" type="button"
      class="h-8 w-11 flex-none rounded-md border bg-cover bg-center"
      :class="imageUrl === r.url ? 'border-2 border-indigo-600' : 'border border-gray-700'"
      :style="{ backgroundImage: `url(${r.url})` }"
      data-testid="background-control-swatch-recent" :data-url="r.url"
      @click="selectRecent(r)"></button>
    <label class="h-8 w-11 flex-none rounded-md border border-dashed flex items-center justify-center text-gray-500 cursor-pointer transition-colors"
      :class="isDragOver ? 'border-indigo-500 bg-indigo-950/20' : 'border-gray-700 hover:border-indigo-700'"
      data-testid="background-control-swatch-upload" aria-label="Upload a background image">
      ＋
      <input type="file" accept="image/*" class="hidden" data-testid="background-control-input" @change="onFileSelected" />
    </label>
  </div>
  <p v-if="!inheritedFrom" class="text-[10.5px] text-gray-500" data-testid="background-control-chip-caption">
    Recent in this service · drop a file on ＋
  </p>
  <p v-else class="text-[10.5px] leading-[1.45] text-gray-400" data-testid="background-control-inherited-explainer">
    Managed on the song — edit it from the song's Lyrics tab.
  </p>
</div>
```

This is `BackgroundControl.vue`'s **new `variant="chip-popover"` branch** — the existing default
(`variant="panel"`, or the prop simply omitted) keeps its current template/testids **byte-for-byte**, so
`SongLyricEditor.vue`'s song-level call site is unaffected. `imageUrl`, `isEditor`, `orgId`,
`inheritedFrom`, `useBackgroundUpload`, and the `attach`/`remove` emits are all reused unchanged; the new
`recents` prop (`{ url: string; label: string }[]`, capped to 4) is new and used only by this branch.

**Recents source (Claude's discretion, resolved):** computed in `SlidesTab.vue` from the already-loaded
`slideGroups` for the current service plus each song-group's own resolved background — dedupe by URL,
sort by the owning group/song's `updatedAt` descending, cap to 4, and pass down as a new
`recent-backgrounds` prop through `SlideGrid` → `SlideGroupSetupStrip` → `BackgroundControl`. No new
Firestore read; purely derived from state `SlidesTab` already subscribes to.

**`audioTab` derivation** (not stored — computed from the existing data, same as the mockup's
`audio = this.state.audio || "vamp"` default logic): `'none'` when neither `audioUrl` nor `bedVampId` is
set, `'vamp'` when `bedVampId` is set (with or without `audioUrl`), else `'track'`. Clicking a tab
**immediately clears the other slot** per CONTEXT.md (`setAudioTab('none')` → emits `remove`;
`setAudioTab('track')` with nothing attached shows the upload affordance without writing anything yet;
`setAudioTab('vamp')` shows the picker without writing anything until a row is clicked) — picking a
row/uploading a file is what actually writes, exactly as today.

**`VampPicker.vue` gets one new prop: `allowUnattached?: boolean` (default `false`).** Today, a vamp with
no `attachment?.downloadUrl` renders as the non-interactive `vamp-picker-row-disabled` variant
(`aria-disabled`, `cursor-not-allowed`, unclickable) — correct for the **per-slide** drawer (Phase 141's
scope), where an MP3-less vamp cannot be assigned. This phase's **group** slot explicitly allows it
(CONTEXT.md). When `allowUnattached` is `true`, a no-MP3 row renders with the **same enabled** markup as
an MP3-having row (`data-testid="vamp-picker-row"`, clickable, emits `select`) but keeps its amber "No
MP3" tag instead of the checkmark/selected styling difference. `EditSlideDrawer.vue`'s existing call site
passes nothing (stays disabled, unchanged); `SlideGroupSetupStrip.vue`'s Audio popover passes
`allow-unattached`.

**Data/write-path note (for the plan, not a template detail):** `slideGroups.ts`'s `setGroupBedMedia`
today only writes `bedVampId`/`bedVampLabel` inside the `patch.bedAudioUrl !== undefined` branch — a
no-MP3 vamp selection has `bedAudioUrl: undefined`, so today's function silently drops the vamp id/label
entirely. The patch handling needs a third path: **vamp selected, no URL** → write `bedVampId` +
`bedVampLabel`, and explicitly `deleteField()` any existing `bedAudioUrl` (a previous Track or
MP3-having-vamp may have left one). `SlideGrid.vue`'s `onAttachGroupVamp` early-returns on a missing
`downloadUrl` today (`if (!downloadUrl) return`) — CONTEXT.md already calls this out for removal; this
spec confirms the resulting write must land in the "clear audioUrl, keep vamp id/label" shape above, not
silently no-op.

### 7. `SlideGrid.vue` integration — the gate change

The panel wrapper's `v-if` **simplifies**:

```html
<!-- before -->
v-if="showGroupMusicControl || showGroupBackgroundControl || showCongregationalControl ||
      showRemoveImportedControl || canLoopSlot || showVideoOutputControl"

<!-- after -->
v-if="Boolean(selectedSlot)"
```

This is a deliberate, load-bearing change, not a simplification for its own sake: the Display chip
**always** renders a value once a group is selected (locked service or not, editor or not), so the panel
can never legitimately be empty anymore — the old six-condition OR existed only because every control
used to hide itself when it had nothing to show, which no longer holds for chips. `showGroupMusicControl`
and `showGroupBackgroundControl` are **retired** (they used to gate chip existence; chip existence is now
unconditional, and their old `Boolean(bedAudioUrl) || canWriteGroupMedia` shape is replaced by the
`canWriteGroupMedia` check alone, now controlling *editability* — button vs. inert span — not existence).
`canLoopSlot`, `showCongregationalControl`, `showRemoveImportedControl` are **unchanged** — Loop,
Congregational, and Remove-imported stay per-kind actions that still hide entirely when not applicable
(CONTEXT.md: "They are per-kind actions, not group settings; the chips always lead").

`SlideGrid.vue`'s six write handlers (`onAttachGroupMusic`, `onRemoveGroupMusic`, `onAttachGroupVamp`,
`onAttachGroupBackground`, `onRemoveGroupBackground`, and the inline video-output `@change`) are
**unchanged** — only their wiring moves from three separate child components to
`SlideGroupSetupStrip.vue`'s six passthrough emits (`attach-music`, `remove-music`, `attach-vamp`,
`attach-background`, `remove-background`, `video-output-change`), which the strip bubbles up from its
internally-mounted `SlotVideoOutputControl` / `SlideGroupMusicControl` / `BackgroundControl` instances.

## Accessibility Contract

- **Chip button** (editable): `aria-haspopup="dialog"`, `aria-expanded` bound to open state,
  `aria-controls` pointing at its popover's `id`, and an `aria-label` stating both the current value and
  the affordance (Copywriting Contract). Native `<button>` — Enter/Space toggle it for free.
- **Locked/non-editor chip**: rendered as a plain `<span>`, not a `<button>` — carries no
  `aria-haspopup`/`aria-expanded` (there is nothing to expand) and is not in the tab order. Its text
  content alone (`Display: Full-screen`, etc.) is sufficient for a screen reader.
- **Popover**: `role="dialog"`, `aria-modal="false"` (it is a lightweight non-modal popover, not a modal
  dialog — background content stays operable), `aria-label` restating the chip's label (e.g. "Audio
  options"), `tabindex="-1"` on the container so it is a valid focus target itself.
- **Focus on open**: focus moves to the first focusable control inside the popover (first tile for
  Display, the None swatch for Background, the active segmented tab for Audio) — this is new behavior for
  this phase, not a cited precedent.
- **Esc**: closes the open popover and returns focus to the triggering chip button (`popoverRef` tracks
  the last-focused chip; mirrors the `Escape`-listener pattern `VampPickerSlideOver.vue` already uses
  elsewhere in this codebase, adapted from a global `keydown` listener to one scoped to "a popover is
  open").
- **Click-outside**: a single document-level `pointerdown` listener, added only while a popover is open
  and removed on close/unmount (same lifecycle discipline as `VampPickerSlideOver.vue`'s existing
  `keydown` listener), closes the popover when the click target is outside both the popover and its own
  chip.
- **No focus trap / no blur-close**: Tab-ing through a popover's controls and past the last one moves
  focus to the next element in the page's natural order (the popover does **not** trap focus, since it is
  non-modal); losing focus by Tab does **not** close the popover — only Esc, outside-click, or re-clicking
  the chip do (CONTEXT.md: "click-outside / Esc closes" — no third mechanism).
- **Only one popover open at a time** is enforced at the state level (`openChip` is a single ref), which
  also means opening a second chip's popover while one is open never leaves two `aria-expanded="true"`
  chips simultaneously.
- **Display radiogroup**: unchanged from today — `role="radiogroup"` wraps the two tiles, each tile is
  `role="radio"` with `aria-checked`.
- **Audio segmented control**: `role="tablist"` / `role="tab"` / `aria-selected` (a real tri-state choice
  with associated content below, which is the ARIA `tablist` pattern's intended use — distinct from the
  Display radiogroup, which has no associated "panel" beyond the hint line).
- **Vamp popover list**: unchanged from `VampPicker.vue` today (no new ARIA — list rows are plain
  buttons with visible text, no `listbox`/`option` roles were used before and none are added now).
