<objective>
Fix R434: the auto-generated re-lock change-notice email never contained a link to the service plan, so update emails went out without a working plan link. Two-part fix, both client-side, in `src/components/ReLockNotifyPrompt.vue`:

1. Append a standalone plan-link line carrying the `{{service_link}}` token to the notice body (locked decision: "append `{{service_link}}` to the auto-generated re-lock notice body" — the diagnosed gap). The server's already-shipped `renderMessageTokens` substitutes this token for every other caller (`LOCK_BODY`, MessageComposer defaults); this extends the proven pattern to one more caller — no new server plumbing.
2. Guarantee the share link exists before send by calling the existing, idempotent `ensureShareLink(props.service, props.orgId)` (exported from the services store, `services.ts:1159/1320`) in `onSend()`, wrapped in the same log-only soft-fail try/catch already used at `createService` (services.ts:488) and `markAsPlanned` (services.ts:736) — a mint failure must never block sending the notice (locked decision + Pitfall 9).

### Open-question A1 decision (recorded per downstream request)
CONTEXT.md says "omit the link line gracefully — never substitute an empty/broken token." We resolve A1 with **client-side graceful omission using the `ensureShareLink` return value**, and we explicitly do **NOT** add a server-side empty-link omission guard in `sendQueuedMessageHandler`:
- `ensureShareLink` returns the resolved link string (`Promise<string>`). We include the `View the full plan: {{service_link}}` line in the sent body ONLY when that awaited return value is a non-empty string; a genuinely link-less service (mint failed / swallowed) omits the whole line rather than shipping a dangling "View the full plan:" label with nothing after it.
- The server-side guard is explicitly out of scope: it touches `sendQueuedMessageHandler`, the shared send path for every message type (raising the review bar for a single-caller fix), and it is redundant once the client conditionally includes the line. This is also distinct from — and does not touch — the deferred dead `attachServiceLink` field. The server's existing `{{service_link}}` -> `resolveServiceLink` substitution is unchanged.

Purpose: every service-update / re-lock notice reliably links to the plan, even for a service that had no share link at send time. Output: the two-part change in ReLockNotifyPrompt.vue and its unit coverage.
</objective>
