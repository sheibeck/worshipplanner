# Phase 141 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Autonomous run.** No `components.json` exists in this repo — the app uses a hand-built dark
> gray-950 Tailwind language, established since v1.2 and reused verbatim by every phase since
> (most recently Phase 140's Vamps tab). This phase adds **zero new design-system primitives**: every
> element below is either a direct reuse of an existing shipped pattern or a narrow, explicitly-noted
> derivation from one. Sources read: `EditSlideDrawer.vue`, `AudioPlayer.vue`, `VampTable.vue`,
> `VampSlideOver.vue`, `RunHeader.vue`, `RunDisplaysPanel.vue`, `RunPreviewPair.vue`, `RunControlView.vue`.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps (`gap-1`, `gap-1.5`) |
| sm | 8px | Compact row/chip spacing (`gap-2`, `p-2`) |
| md | 16px | Drawer section spacing (`space-y-4`), card padding (`p-4`) |
| lg | 24px | — (not newly used by this phase) |
| xl | 32px | — (not newly used by this phase) |

Exceptions (both pre-existing, reused verbatim — not introduced by this phase):
- **44px minimum touch target** (`min-h-11`) on every Run-surface button this phase adds (arm toggle, blocked-banner retry) — matches `.run-blackout` / `.run-exit` / `run-blocked-retry`.
- **480px max-width** on the picker's host surface (`EditSlideDrawer`'s existing `max-w-[480px]`) — the picker is inline content inside that fixed width, not a new panel width.
- **6px** (`gap-1.5` on the assigned-vamp row and the ♪ badge, `py-1.5` on picker rows) — the half-step Tailwind unit already used by `VampTable.vue` rows and the existing `audio-file-row`; reused verbatim, not a new value.

## Typography

Sizes/weights **newly touched by this phase's elements** (the app's full established type scale is wider — see the reused components for precedent; this phase adds no new heading-weight text):

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Mono chip (key/tempo, badge glyph) | 12px (`text-xs`) | 400 (regular, `font-mono`, no weight override) | 1.4 (default) |
| Body / assigned-row text | 13px (`text-[13px]`) | 400 (regular) | 1.5 (`leading-normal`) |
| Label / eyebrow / tag | 11px (`text-[11px]`) | 500 (medium, `font-medium`) | 1.4 (default) |
| Button / toggle / link | 14px (`text-sm`) | 500 (medium, `font-medium`) | 1.4 (default) |

Two weights only: **400 regular** (readonly/body copy) and **500 medium** (every interactive label, button, tag, and link this phase adds). No 600/semibold text is introduced — badges use 500, matching the "Playing"/live-tag precedent (`text-xs font-semibold` in `RunPreviewPair` is the ONE pre-existing exception this phase's ♪ badge deliberately does NOT copy — see Component Specifications, badge styling note).

## Component Specifications

Concrete implementation detail supplementing the tables above — every class string here is either
copied verbatim from an existing component or a minimal, explicitly-flagged derivation.

### 1. Vamp picker (`VampPicker.vue`, new — per CONTEXT.md's discretion, a separate component for testability)

Lives inline inside `EditSlideDrawer.vue`'s existing `data-testid="drawer-audio-section"` block, not a
modal/Teleport — it is short-lived contextual content, matching the drawer's own inline-expansion idiom
(e.g. the speaker toggle, the background three-state section).

**Trigger — "Choose a vamp" button**, shown beside the existing empty-state `audio-attach` file input
(when nothing is attached yet) OR as the **Change** action on the assigned row (see §2):

```html
<button type="button" class="text-xs font-medium text-indigo-400 hover:text-indigo-300"
  data-testid="vamp-picker-open">Choose a vamp</button>
```

**Open picker panel** — an inline expansion directly below the trigger, NOT a floating popover (avoids
z-index/overflow fights inside the already-scrolling drawer body):

```html
<div class="mt-2 rounded-md bg-gray-800 border border-gray-700 p-2" data-testid="vamp-picker-panel">
  <input type="text" placeholder="Search vamp name or key…" data-testid="vamp-picker-search"
    class="w-full rounded-md bg-gray-900 border border-gray-700 text-gray-100 placeholder-gray-500
           text-sm px-3 py-2 mb-2 focus:outline-none focus:ring-1 focus:ring-indigo-500 focus:border-indigo-500" />
  <ul class="max-h-56 overflow-y-auto space-y-1" data-testid="vamp-picker-list">
    <!-- one row per vamp, see below -->
  </ul>
</div>
```

**Row — enabled (has MP3):**

```html
<li>
  <button type="button" data-testid="vamp-picker-row"
    class="w-full flex items-center gap-2 rounded-md px-2 py-1.5 text-left transition-colors"
    :class="isSelected ? 'bg-indigo-950/40 border border-indigo-700' : 'hover:bg-gray-700/60 border border-transparent'">
    <svg v-if="isSelected" class="h-4 w-4 text-indigo-400 shrink-0" ...><!-- checkmark --></svg>
    <span class="min-w-0 flex-1 truncate text-[13px] text-gray-200">{{ vamp.name }}</span>
    <span class="font-mono text-xs px-2 py-0.5 rounded-full bg-gray-900 border border-gray-700 text-gray-300 shrink-0">{{ vamp.key }}</span>
    <span class="font-mono text-xs text-gray-500 shrink-0">{{ vamp.tempo || '—' }}</span>
  </button>
</li>
```

(Key/tempo chip styling is a verbatim reuse of `VampTable.vue`'s row cells.)

**Row — disabled (no MP3):**

```html
<li>
  <div aria-disabled="true" data-testid="vamp-picker-row-disabled"
    class="w-full flex items-center gap-2 rounded-md px-2 py-1.5 opacity-50 cursor-not-allowed">
    <span class="min-w-0 flex-1 truncate text-[13px] text-gray-400">{{ vamp.name }}</span>
    <span class="font-mono text-xs px-2 py-0.5 rounded-full bg-gray-900 border border-gray-700 text-gray-500 shrink-0">{{ vamp.key }}</span>
    <span class="inline-flex items-center gap-1 text-[11px] font-medium text-amber-400 shrink-0">
      <svg class="h-3.5 w-3.5" ...><!-- warning triangle, same path as VampTable's --></svg>
      No MP3
    </span>
  </div>
</li>
```

**Empty states** (inside `vamp-picker-list`'s parent, replacing the `<ul>`):
- Zero vamps in the org: `<p class="text-xs text-gray-500 px-2 py-3 text-center" data-testid="vamp-picker-empty">No vamps yet — add one from the Vamps tab.</p>`
- Search matched nothing: `<p class="text-xs text-gray-500 px-2 py-3 text-center" data-testid="vamp-picker-no-match">No vamps match your search.</p>`

Selecting an enabled row assigns immediately (no separate "Confirm" step — matches the drawer's existing
one-click attach/set-override affordances) and closes the panel.

### 3. Run control — "Audio: Off / Armed" toggle (in `RunHeader.vue`'s scoped-CSS button idiom, matching `.run-blackout`)

Placed in the header's right-hand cluster, immediately to the LEFT of the blackout toggle (both are
live-ops toggles; audio arms before blackout matters). Visible whenever `live` is true — i.e. both a
real go-live and a rehearsal (rehearsal audio testing is in-scope; blackout stays `trulyLive`-only since
rehearsal opens no output windows, but the Run control window itself can still play audio during a
rehearsal).

```html
<button type="button" class="run-audio-toggle" :class="{ 'run-audio-toggle--armed': armed, 'run-audio-toggle--needed': !armed && slideHasAudio }"
  data-testid="run-audio-toggle" :aria-pressed="armed ? 'true' : 'false'"
  :aria-label="armed ? 'Audio armed — click to turn off' : 'Arm audio playback for this Run session'">
  {{ armed ? 'Audio: Armed' : 'Audio: Off' }}
  <span v-if="playing" class="run-audio-toggle__dot" data-testid="run-audio-playing" aria-hidden="true"></span>
</button>
```

```css
/* Same shape/sizing as .run-blackout — a sibling live-ops pill button. */
.run-audio-toggle {
  min-height: 44px;
  padding: 0 14px;
  background: var(--color-surface);
  border: 1px solid var(--color-neutral-800);
  border-radius: 8px;
  color: var(--color-text);
  font-size: 13px;
  font-weight: 500;
  cursor: pointer;
  display: inline-flex;
  align-items: center;
  gap: 6px;
}
.run-audio-toggle:hover { border-color: var(--color-neutral-600); }
.run-audio-toggle--armed {
  border-color: #9184d9; /* run-accent */
  color: #9184d9;
}
/* Pulses amber ONLY while Off and the live/next slide carries audio (R439's
   prompt-before-going-live signal) — never combined with --armed. */
.run-audio-toggle--needed {
  animation: run-audio-pulse 1.6s ease-in-out infinite;
}
@keyframes run-audio-pulse {
  0%, 100% { box-shadow: 0 0 0 0 rgba(224, 178, 60, 0.5); }
  50% { box-shadow: 0 0 0 4px rgba(224, 178, 60, 0.25); }
}
/* Playing indicator — a small pulsing accent dot appended to the label text,
   visible only while armed AND audio is actually sounding. */
.run-audio-toggle__dot {
  height: 6px;
  width: 6px;
  border-radius: 9999px;
  background: #9184d9;
  animation: run-audio-playing-pulse 1.2s ease-in-out infinite;
}
@keyframes run-audio-playing-pulse {
  0%, 100% { opacity: 1; }
  50% { opacity: 0.35; }
}
```

An `sr-only` `aria-live="polite"` element (not shown above for brevity) announces "This slide has audio —
arm audio to hear it." exactly once per transition into the pulsing-needed state, so a screen-reader
user gets the same prompt a sighted operator sees as the amber pulse.

### 4. "Audio blocked" banner (in `RunControlView.vue`, sibling to the existing `run-blocked-banner`/`run-partial-banner`, same amber Tailwind idiom — NOT the RunHeader CSS-var idiom, since this lives in the Tailwind-styled banner band)

```html
<div v-if="audioBlocked" data-testid="run-audio-blocked-banner"
  class="flex-none m-4 flex items-start gap-3 rounded-md border border-amber-800 bg-amber-950 px-4 py-3 text-amber-200">
  <svg class="mt-0.5 h-5 w-5 flex-none text-amber-400" ...><!-- same warning-triangle path as the existing banners --></svg>

    <button type="button" data-testid="run-audio-blocked-retry"

  </div>
</div>
```

No dismiss (×) control — unlike `run-blocked-banner`/`run-partial-banner`, this one clears itself the
instant playback actually succeeds; it is never a stale, ignorable notice.
