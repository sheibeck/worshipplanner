<adr_convention_note>
Apply the owner-accepted convention EXACTLY (from 108-CONTEXT.md):
- Template: MADR-lite — headings `Title`, `Status`, `Context`, `Decision`, `Consequences`, plus an
  optional "Source comments" backlink list enumerating the `file:line` locations the ADR now carries.
- Filename: `docs/adr/NNNN-kebab-title.md`, 4-digit sequential starting at `0001`. Pointer id form: `ADR-0001`.
- Granularity: GROUP BY DECISION — one ADR per distinct rationale. Multiple comments across different files
  may point to the SAME ADR id (e.g. every `WR-01` comment maps to one ADR). This avoids ADR explosion.
- Pointer text: `// See ADR-0001 (docs/adr/0001-title.md)` — id plus relative path, greppable both ways.
  Rules files use `//` comments too, so the same pointer form applies to `firestore.rules` / `storage.rules`.

Test-suite / gate reality (from CLAUDE.md — required for Task 3):
- Type-check gate is `npm run type-check` (vue-tsc --build; checks test files), NOT `-p tsconfig.app.json`.
- App suite is a BARE `npx vitest run` (do NOT pass `--dir src`); documented baseline = exactly one failing
  file, `src/storage.rules.test.ts` (Storage-emulator cross-service `exists()` limitation, not a regression).
- render-service tests run via `cd render-service && npm test` (39 pass), never from the repo root.
</adr_convention_note>
