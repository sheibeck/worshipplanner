# Requirements: v1.2 — Worship Service Slide Management

**Defined:** 2026-07-23 (scoped in gsdpi as milestone M001)
**Migrated to gsd-core:** 2026-07-24
**Status:** IN PROGRESS

**Core Value:** A full slide management system for worship services — lyrics, scripture,
imported presentations, and media — that auto-assembles from the service order and is
approachable for non-technical church volunteers. Replaces ProPresenter for small churches.

> Ported faithfully from `.gsd/REQUIREMENTS.md` (gsdpi). Requirement IDs (R0xx), owning
> slice→phase mapping, and status are preserved. Slice→phase map:
> S01→P18, S02→P19, S03→P20, S04→P21, S05→P22, S06→P23.

## Active

- [x] **R001** (core-capability, P18): Song lyric slide creation from CCLI SongSelect paste — primary path for getting lyrics in; parser auto-splits by verse/chorus/bridge markers into slides.
- [x] **R002** (compliance/security, P18): CCLI copyright compliance on first and last lyric slides — license requires title, authors, CCLI number, license number on first/last slides of every song.
- [x] **R003** (core-capability, P18): Song performance order builder with section repeats — arrange the performance sequence (V1, C, V2, C, Bridge, C) with repeats to match how the song is actually sung.
- [x] **R004** (continuity, P18): Light version history on song lyrics for undo/revert — safety net for accidental edits/deletes; not branching versions.
- [ ] **R005** (primary-user-loop, P20): Service-driven slide auto-assembly from service order — slides auto-assemble from service elements; no manual slideshow build each week.
- [ ] **R006** (primary-user-loop, P20): Auto-reorder slides when service elements change order — reorder songs/scripture/elements and the slideshow follows automatically.
- [ ] **R007** (core-capability, P20): Formalized service sections: Pre-Service, Worship, Message, Sending — clear template structure; makes auto-assembly deterministic.
- [x] **R008** (core-capability, P19): Scripture slides via ESV API auto-pull with auto-split for long passages — auto-fetch scripture text on reference entry, auto-split into readable chunks.
- [x] **R009** (differentiator, P19): Congregational reading mode with Leader/Congregation labels — responsive/liturgical readings the congregation follows on screen.
- [ ] **R010** (core-capability, P21): PowerPoint (.pptx) import via Firebase Cloud Function — universal import format; server-side parsing extracts text/images/layout to native slides.
- [ ] **R011** (core-capability, P21): Announcement slides in Pre-Service section imported from PPTX or images — externally-created announcements imported into Pre-Service, auto-assembled.
- [ ] **R012** (core-capability, P21): Sermon slides in Message section imported from PPTX — pastor/secretary sermon PowerPoint imported into native format in the Message section.
- [ ] **R013** (core-capability, P22): Audio attachment per slide with auto-play on entry, no loop — vamps over prayers, background music; MP3 auto-plays on slide activate, stops at end.
- [ ] **R014** (core-capability, P22): Video playback per slide (MP4, WebM, MOV) with auto-play on entry, no loop — missionary/special media; auto-plays on slide activate, manual advance.
- [ ] **R015** (operability, P22): Firebase Storage with 2-week media retention auto-cleanup — media is ephemeral; auto-delete 2 weeks after service date to control storage cost.
- [ ] **R016** (primary-user-loop, P23): Presentation preview mode with full-screen view, manual advance, and media playback — volunteers preview the complete slideshow before Sunday.
- [x] **R017** (failure-visibility, P18; supporting P19, P21): Auto-save on all slide editing surfaces to prevent data loss — changes persist as the user works, not only on explicit save.
- [~] **R018** (quality-attribute, P18; supporting P19, P20, P21, P23): Polished, intuitive editor UX for non-technical volunteers — usable on first attempt with zero training (cross-cutting; advances each phase).
- [x] **R019** (constraint, P18): Unified slide data model across all content types — one slide type with content-kind variants (lyric, scripture, image, video, text).
- [x] **R020** (constraint, P18): Single canonical song lyric version, no per-service copies — one version in the catalog; every service references it live.

### v1.3 — Slides Tab Rework (Phases 24-28)

- [ ] **R028** (constraint, P24): Slide groups are owned by service plan items — group order and membership mirror the service plan, so reordering an element on Service Order reorders its slides with no second manual reorder. Slide content, media and audio are independent of the plan.
- [ ] **R029** (failure-visibility, P24): Slides whose owning plan item is removed surface as orphaned/unanchored and can be reassigned — never silently dropped or silently re-parented.
- [ ] **R030** (core-capability, P24): Audio attaches at two levels — a group-level bed that plays across the group, and per-slide audio with a scope toggle (this slide only / all slides in this group) and a loop-until-next-slide flag. Replaces Phase 22's slot-level media (D008); existing slot media migrates onto its group.
- [ ] **R031** (primary-user-loop, P25): A Slides tab where all slide editing lives — a plan rail mirroring service order (not draggable) plus a slide grid for the selected group.
- [ ] **R032** (core-capability, P25): A slide deck, image, video or audio file can be added at any point in the service, not only in Announcements/Sermon — imports and media append to the selected group.
- [ ] **R033** (core-capability, P26): An Edit Slide drawer that floats over the page without reflowing it, carrying slide preview, label, read-only text with an "Edit in song" link (D007), slide audio with scope and loop, operator-only notes, and delete.
- [ ] **R034** (quality-attribute, P27): The first tab is named "Service Order" and carries no slide editing — it matches its production behaviour at `origin/master` @ `9f3700f` (D009).
- [ ] **R035** (quality-attribute, P28): The song lyrics editor presents one scroll surface and one list that IS the slide order — no nested scrollbar, no duplicated Available-Sections / Performance-Order lists.

## Deferred (future milestone)

- [ ] **R021** (integration): ProPresenter import — proprietary XML/protobuf, varies across versions; deferred.
- [ ] **R022** (integration): Keynote native import — proprietary protobuf; users export to PowerPoint instead.
- [ ] **R023** (integration): ProPresenter song library migration — intentionally starting fresh to escape ProPresenter complexity.
- [ ] **R024** (core-capability): Multi-monitor output and confidence monitors — dedicated future presentation milestone (transitions, multi-monitor, streaming).
- [ ] **R025** (quality-attribute): Slide transitions and presentation polish — bundled with the future presentation-system milestone.

## Out of Scope

- **R026** (anti-feature): Google Slides API direct import — OAuth complexity; users export to PowerPoint. Descoped in favor of universal PPTX import.
- **R027** (constraint): CCLI API integration — CCLI does not provide API access to anyone (hard constraint); lyrics come via manual SongSelect paste.
