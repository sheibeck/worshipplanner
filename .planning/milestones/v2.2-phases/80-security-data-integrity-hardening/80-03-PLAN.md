<objective>
Close two client-only data-integrity gaps. R235: removing a song from a service currently leaves that song's slides orphaned — `rebuildSongGroup`'s `!songId` early return returns the stale slides unchanged (Phase 30 W-03 defect, its bug asserted by a locked-in test). Fix the one branch so a cleared slot empties its group, reprise-safe (groups are keyed 1:1 by slot.id, so the other occurrence is untouched). R236: `EditSlideDrawer.vue` receives each slide's `renderState` but never reads it — add a pending-render guard (amber notice + disabled customization) so an edit to a still-rendering deck slide is not silently discarded when the render flips pending -> ready.

Purpose: Orphaned slides from a removed song present stale content in the presentation (data integrity); an edit lost on render-completion is silent data loss (R235/R236, PENDING-VERIFICATION 999.2 / C4). Both client-only, no deploy.

Output: A one-branch fix + three tests in the materializer; a computed + amber notice + two gate compositions + component tests in the drawer.
</objective>
