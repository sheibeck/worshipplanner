# Spec: Default rehearsal day and time

**Code:** RHD
**Status:** Draft
**Last changed:** 2026-11-06

Section `## Purpose`:

Most churches rehearse on the same weekday every week. This feature lets an editor set that weekday once, in Settings,
so every new service starts with its rehearsal already on it, and planners only step in for the weeks that differ.
Existing services are left alone, and read-only views show nothing new.

Section `## Behavior`, these six paragraphs:

An editor picks one default rehearsal day, or None, in the Rehearsal & Report Defaults card. With a default day and at
least one default time set, a new service starts with one rehearsal on the most recent default day on or before the
service date, at the first default time. When the service falls on the default day, the rehearsal is that same day.
Without both, a new service starts with no rehearsal.

The defaults apply when a service is created, and only then. Changing them later does not touch existing services, and
there is no data migration.

A rehearsal added this way carries an internal auto-added marker. While it does, changing the service's date moves it
to the most recent day with its own weekday on or before the new date, at its own time, even if the Settings default
has changed since. Editing its date or time ends this for good, even if the value is set back by hand. Undo is different:
it means the edit never happened, so it restores the rehearsal as it was, auto-moving included. Removing it is final:
nothing adds it back.

A changed service date is saved with the service. The regular share link keeps working and shows the new date. The
public page for the old date is removed, so a link already sent with that date stops working. That removal never fails
the save. If a second service shares that date, it has no date page until its next save, and its regular share link is
unaffected.

The add-rehearsal form fills in the default date for the service's current date, using the current Settings day, unless
the service already has a rehearsal on that date. Nothing extra is stored on the service. A date the planner has typed
or cleared stands until they add the rehearsal.

The marker is internal. In the Times tab an auto-added rehearsal looks like any other, for every role, and the marker
never appears on a share link or another read-only view.

- The planner edited it, then set it back: it still stays put (AC-RHD-29).
- An edit was rejected: auto-moving continues (AC-RHD-30).
- The Settings day changed after creation: the rehearsal keeps its own weekday (AC-RHD-28).
- The service already has a rehearsal on the default date: the add form's date stays blank (AC-RHD-41, AC-RHD-46).
