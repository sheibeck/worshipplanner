# Milestone v2.7: Rehearsal, Stage Plans & Presentation Polish

**Status:** ✅ SHIPPED & DEPLOYED TO PRODUCTION 2026-09-01
**Phases:** 104–107
**Total Plans:** 10
**Tag:** `v2.7`

## Overview

Give teams richer live-presentation tooling and multi-church usability: an inline black slide in the
lyric editor, audience-only "Go to black", a system-wide dismissible-notification store, a per-item
loop, a user-menu church switcher, and a freeform visual per-service **stage layout**. The
rehearsal/file-storage cluster (song attachments + public Rehearse mode) was deferred out of v2.7 by
owner decision and carried to backlog 999.13 with a full cost model in
`seeds/SEED-003-rehearsal-attachments-and-storage-costs.md`.

**Requirements:** R302–R315 (14 mapped, 100% coverage) — see [v2.7-REQUIREMENTS.md](v2.7-REQUIREMENTS.md).

**Delivery model:** Built end-to-end via `/gsd-autonomous` on 2026-09-01 with per-phase verification
deferred to a batched end pass per explicit owner instruction, then extensively refined interactively
before ship (see Milestone Summary). Zero new npm dependencies (as designed). No new
`firestore.rules`/`storage.rules` and no new Cloud Functions — every feature rides existing patterns.

## Phases

### Phase 104: Notification & Multi-Church Foundations

**Goal**: A system-wide dismissible-notification store replaces stuck one-off banners, and a multi-org
member can switch active church from the user menu with a full org-scoped reset.
**Requirements**: R309, R310, R311, R312
**Delivered**: generalized `toasts.ts`/`ToastHost` mounted once at `App.vue`; the "monitors not
configured" warning made state-driven (auto-clears + dismissible); a user-menu church switcher
(`authStore.selectOrg` + `resetOrgScopedStores`, distinct from super-admin `enterOrgAsSuperAdmin`).
Code review caught a Critical R312 listener leak in `TeamView`/`GettingStarted` (org-scoped `onSnapshot`
opened from a non-reactive `orgId`) — fixed with a reactive re-subscription.

### Phase 105: Presentation Blackout & Inline Black Slide

**Goal**: Insert a black interlude slide within a song without a new section, and scope runtime
"Go to black" to the Audience output only.
**Requirements**: R302, R303, R304, R305
**Delivered**: additive `LyricSection.kind` blackout slide (excluded from section numbering); solid-black
render across Audience/Confidence/preview/SlideCard; "Go to black" scoped to Audience (Confidence overlay
removed). Code review caught a Critical background/"From group" chip leaking onto blackout cards — fixed.

### Phase 106: Per-Item Loop Playback

**Goal**: Mark a service item as looping so its slides auto-advance and wrap to the first slide during
Run, on a configurable interval, without fighting manual navigation.
**Requirements**: R306, R307, R308
**Delivered**: `MediaAttachableSlot.loop {enabled,intervalSeconds}` (default 10s, preset + custom);
`useLoopTimer` driven from `useRunControl.postIndex`'s single choke point; "Go to black" PAUSES the loop.

### Phase 107: Visual Stage Layout

**Goal**: A per-service Stage Layout tab where a user drags labeled markers onto a freeform canvas with
on/off-stage zones, saved per service and read-only on share/print.
**Requirements**: R313, R314, R315
**Delivered**: additive `Service.stageLayout` field (NO new collection/rules/store — resolved the
Phase-104 `STAGELAYOUTS-RESET-OBLIGATION` marker); native-Pointer-Events drag canvas + Stage Layout tab
(draft-locked); read-only render on the public share snapshot + print via `buildServiceSnapshot`
denormalization (explicit per-field projection, no PII/scope leak).

## Milestone Summary

### Decisions

- Stage layout stored as an **additive field on the service doc**, not a new collection/store/rules —
  the key architecture call that also satisfied R312 for free.
- Deferred the **rehearsal/file-storage cluster** (backlog 999.13 + SEED-003) — the milestone's biggest
  security/cost surface (unauthenticated Storage reads + egress).

### Post-audit interactive refinement (2026-09-01, this session)

After the automated audit PASSED (14/14 reqs, 6/6 seams), the owner drove a large interactive polish
round shipped in the same milestone/tag:

- **Stage Layout redesigned** to the owner's imported claude.ai/design "Nocturne" spec: one continuous
  room diagram (stage trapezoid + off-stage wings + audience), a left palette of typed chips, icon-tile
  markers (inline SVG, no icon-font dependency), and a right inspector slide-over (RoleSlideOver pattern).
- **Instruments palette mirrors the org's Band roles** (+ fixed Orchestra & Instrument extras); markers
  carry roleId/roleName, personId/personName (picked from the service's role assignments, shown
  "Name - Role"), a tech note, and a "player also sings" flag ("Electric Guitar + Vocal"). Added TV /
  Miscellaneous / Communion gear; renamed Vocal mic → Microphone.
- **Share + print separated**: stage layout dropped from the service-plan share/print; its own landscape
  "Share stage layout" link (`ShareView ?view=stage`) and a dedicated landscape B&W "Print for tech" sheet.
- **Loop authoring relocated** out of the Service Order plan into the Slide editor (SlideGrid group-media
  panel), MISC/ANNOUNCEMENTS only, never Song, via a self-contained `SlotLoopControl`.
- **Button-area polish**: Run → the one filled-indigo primary in the right cluster; Present → "Review
  Slides" (secondary); Mark as Planned leads the Stage Layout cluster; Save moved rightmost on Service
  Order and removed from Slides (slide edits never dirty localService); save-status relocated into the
  header so it no longer reflows the tab content.

### Issues fixed in review / testing

- **WYSIWYG stage bug (diagnosed live in the running app):** Tailwind v4's `-translate-x/y-1/2` emits the
  CSS `translate` property, which stacked with the editor's inline `transform` translate and drew every
  marker ~half a tile too far left ONLY while editing — a marker placed off-stage jumped onto the stage
  line once locked. Fixed by centering via a single inline transform on both surfaces, and hard-coding
  the room size (1200×750 screen / 960×600 print) so editing/locked/share/print render identically.
- Per-phase code review caught real defects each phase (104 Critical listener leak; 105 blackout-card
  background leak; 106 timer reconcile gaps; 107 multi-touch drag clobber) — all fixed.
