R107 — regeneration NEVER destroys manual work. Every user-added entry (imported PPTX slides,
hand-added text/blank slides, added media) survives any group rebuild in its stored position;
only auto-generated (derived) entries re-derive — including when a scripture slot toggles to/from
a congregational reading.

survivor and preserved by EVERY rebuild path AND by the scripture↔congregational transition; and,

invariants that Phase 38/49 CONTEXT and CLAUDE.md document as fragile.

silently drop a slide they added by hand.

Key facts from the planning read (verify against the code — do not weaken):
- `isSlotDerivableRef(slot, ref)` returns TRUE only for the slot's OWN derivation: SONG →
  lyric/copyright; SCRIPTURE → scripture; IMPORTED → imported with `ref.importId === slot.importId`;
  text-backed kinds → a payload-free `text` ref. An imported ref in a SCRIPTURE/PRAYER/etc group,
  a foreign-deck imported ref in an IMPORTED group, a `video` ref, and an authored `text` ref
  (title or body set) are all NON-derivable → rescued by `survivingEntries`.
- `＋ Add slide` writes `{ kind: 'text', title: 'New slide', body: '' }` (body is '' not undefined),
  so a hand-added blank slide is authored and survives; the payload-free auto-derived `text` entry
  is the one that re-derives.
- `rebuildGroup` only rebuilds SONG/SCRIPTURE/IMPORTED slots; PRAYER/MESSAGE/ANNOUNCEMENTS/MISC/HYMN
  return `{ changed: false }`, so manual entries in those groups are trivially untouched.
- `rebuildScriptureGroup`: (a) DETACHED — sections present AND stored signature equals the current
  signature → returns stored slides untouched; (b) NOT-YET-MATERIALIZED — sections present, signature
  differs → delegates to `rebuildUnstableIdGroup` (carry + `survivingEntries`); (c) CLEARED REFERENCE
  — no sections, no reference, has section entries → `renumbered(survivingEntries(...))` with
  `sourceSignature: null`; (d) otherwise → `rebuildUnstableIdGroup`. Every branch that mutates routes
  non-derivable entries through `survivingEntries`.
</context>
