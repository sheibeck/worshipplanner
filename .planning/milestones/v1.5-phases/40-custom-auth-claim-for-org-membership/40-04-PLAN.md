are the same thing. Idempotent skip-if-already-matching (D-11) means the script is safely re-runnable
from the top after any interruption, which is resumability in the only sense that matters here — and it
carries no cursor state that could itself go stale. State this reconciliation in the SUMMARY.

Create `functions/src/backfillOrgClaims.ts` exporting `backfillOrgMembershipClaims`, a plain async
function testable in isolation from any CLI wrapper — the same shape as `parsePptxHandler` and
`cleanupExpiredMediaHandler`. It is deliberately **not** exported from `functions/src/index.ts`: it is
an owner-run Node script with admin credentials, not a deployed or callable function (D-12).

Signature: take an options object with an `apply` boolean, and return
`{ processed: number; skipped: number; failed: Array<{ uid: string; orgId: string; error: string }> }`
(D-13 — counts plus every failure listed by uid).

Body:
1. Query `getFirestore().collectionGroup('members').get()`. One query, no pagination, no cursor, no
   batching, no rate limiting — D-10, at n=2. Do not add them.
2. For each document, derive `orgId` from `memberDoc.ref.parent.parent?.id` and `uid` from
   `memberDoc.id`. Apply a structural guard before anything else, in the spirit of
   `MEDIA_PATH_GUARD`: skip unless the parent document's own parent collection is named
   `organizations`, so a `members` subcollection appearing anywhere else in the schema can never be
   acted on.
3. Call `decideMembershipClaim({ uid, orgId, role })` from `./orgMembershipClaims` with the member
   document's `role`. **Do not reimplement primary-org resolution, role normalisation, or the
   already-matching comparison here** (DISC-02) — a second implementation of "what should this user's
   claim be" would drift from the trigger, and a drifted backfill writes a wrong claim to production.
4. Map the returned decision: `set` → in apply mode call `getAuth().setCustomUserClaims(uid, claims)`
   and increment `processed`, in dry-run mode increment `processed` without calling anything;
   `skip` → increment `skipped`; `clear` is not reachable from a live members document, so treat it
   defensively as skipped.
5. Wrap each account's handling in its own try/catch so one bad account cannot abort the run. Push
   `{ uid, orgId, error: String(err) }` into `failed` and continue.
6. Log one line per account naming the uid, the org, and the decision, then log the summary object.
   At n=2 the owner should be able to read the entire output and know the exact state of every account.

**Safety posture: dry run is the default.** The script writes only when `--apply` is passed. This
mutates authorization state for real users on a production project, and a default-write script is one
mistyped command away from an unintended run. Print the resolved target project id before doing any
work, and print a clearly-marked dry-run banner when `apply` is false so the owner can never mistake a
rehearsal for the real thing.

Add the CLI wrapper at the bottom, guarded by a `require.main === module` check so importing the module

exit non-zero if `failed` is non-empty so a wrapper script or the owner's shell can detect a partial run.
