# Phase 44 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope framing (read first):** This phase is reuse-heavy, not net-new design. Nothing here invents a
new visual language — every token, component shape, and interaction pattern below is copied from code
already shipping in `src/views/SettingsView.vue`, `src/views/ServiceEditorView.vue` (Phase 43's finalized
add-item palette and SortableJS reorder), and `src/components/slides/EditSlideDrawer.vue` (the app's one
existing slide-out-panel precedent). Where this document is prescriptive, it is prescribing "copy this
exact class string," not proposing an alternative.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — native HTML controls + hand-rolled Tailwind utility classes |
| Icon library | none — inline `<svg>` with hand-authored paths (no icon package dependency anywhere in the codebase) |
| Font | system default (no house font yet — Phase 46 sets one; do not anticipate it here) |

**shadcn gate result:** Not applicable, and not run as an init prompt. This is a Vue 3 project (shadcn's
CLI and registry target React/Next.js/Vite-**React**, not Vue). `components.json` is absent, no shadcn-vue
port is present, and 43 prior phases across four milestones have built a single, consistent hand-rolled
Tailwind v4 dark-theme system with zero component-library dependency. Introducing shadcn for one
settings drawer would fracture that established language rather than serve it — the opposite of what
this reuse-heavy phase needs. Recorded as an explicit researcher decision, not a skipped step.

## Spacing Scale

Declared values (must be multiples of 4), matching the scale already used throughout
`SettingsView.vue` and `ServiceEditorView.vue`:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps inside chips (`gap-1`, section-header icon spacing) |
| sm | 8px | Chip/button internal padding (`px-2 py-1`), compact row gaps (`gap-2`); **the new drawer's template list uses this token** — `space-y-2`/`gap-2` for its section-header row and slot-list vertical rhythm (normalized from the source component's 6px, see Exceptions below) |
| md | 16px | Card padding (`p-4`), drawer body padding (`px-4 py-4`), default row spacing |
| lg | 24px | Section-to-section gaps within the drawer (`mt-6`, `pt-6` dividers) |
| xl | 32px | Not used in this phase's surfaces |
| 2xl | 48px | Not used in this phase's surfaces |
| 3xl | 64px | Not used in this phase's surfaces |

**No non-4-multiple spacing values are accepted anywhere in this phase's new surfaces.** Note on the
reused source: `ServiceEditorView.vue`'s existing section-header row and slot-list use `space-y-1.5` /
`gap-1.5` (6px) elsewhere in that copied component — that pre-existing 6px is **not** carried into the
new Settings drawer this phase builds. The template list inside the new drawer normalizes to `sm` (8px):
`space-y-2` / `gap-2` for both the section-header row and slot-list vertical rhythm. This is the one
deliberate deviation from "copy the exact class string" called out in this document's scope framing —
the deviation exists specifically to keep this phase's accepted spacing tokens on the 4-point grid.

Exceptions (pre-existing in the reused components, kept verbatim — not new decisions this phase makes):

- `text-[11px]` sized chip labels are a 1px-off-scale font-size, not a spacing exception — noted here so
  it isn't mistaken for a typography contract violation (see Typography below, it is one of the four
  declared sizes).

## Typography

Exactly four distinct declared sizes (11px, 12px, 14px, 20px) and two weights, all already in use on
`SettingsView.vue` / `ServiceEditorView.vue`. This phase introduces no new size or weight. No row below
spans a range — each maps to one literal `text-*` class. 14px is shared by two roles (item/label content
vs. heading) at two different weights, which is why the weight column, not the size column, is what
distinguishes them; it does not add a fifth size.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Micro (chip/badge label) | 11px (`text-[11px]`) | regular (400) | 1.3 — used verbatim on every reused palette chip label and section slide-count label |
| Micro / help text | 12px (`text-xs`) | regular (400) | 1.5 — help text, empty-state body copy |
| Item / Label (item-row content) | 14px (`text-sm`) | regular (400) | 1.5 — template item-row text (kind label, section `<select>`), form labels |
| Heading (section title, drawer title) | 14px (`text-sm`) | semibold (600) | 1.2 — `SettingsView.vue`'s `<h2>` pattern, `EditSlideDrawer.vue`'s `<h2>` pattern |
| Display (page title) | 20px (`text-xl`) | semibold (600) | 1.2 — unchanged, `SettingsView.vue`'s `<h1>Settings</h1>` — this phase does not touch it |

**Inherited exception, not a new decision:** the reused palette-chip buttons and Save/action buttons use
`font-medium` (500) verbatim from `ServiceEditorView.vue`/`SettingsView.vue` — a third weight that exists
only because it ships unchanged inside components being reused wholesale. Any **new** copy this phase
introduces (the Services section body text, the drawer's empty-state copy, the Reset confirmation) uses
only the two declared weights (400/600) above.

## Color

Existing dark-theme palette, unchanged. Declared for completeness, not as a new choice.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `gray-950` / `gray-900` (`bg-gray-900`) | Page background, drawer panel background (`EditSlideDrawer.vue`'s `bg-gray-900`), Settings card backgrounds |
| Secondary (30%) | `gray-800` (`bg-gray-800`, `border-gray-800`/`border-gray-700`) | Card/drawer borders, item-row surfaces, input fields, section dividers |
| Accent (10%) | `indigo-600` / `indigo-500` / `indigo-400` | Reserved for: the "Edit Default Template" and "Save Template" primary buttons (`bg-indigo-600 hover:bg-indigo-500`), the "＋ Add item" text affordance if reused inline, focus rings (`ring-indigo-500`), the drag-over highlight (`bg-indigo-950/20`), and the section-header rule label tint (`text-indigo-300/80`) |
| Destructive | `red-400` / `red-900` | Reserved for: the per-item remove (×) icon's hover state (`hover:text-red-400`, matching `ServiceEditorView.vue`'s existing remove button exactly) and the "Replace Template" confirm button inside the Reset-to-1-2-3 confirmation (`bg-red-900/20 hover:bg-red-900/40 text-red-400`, matching `SettingsView.vue`'s existing "Clear Credentials" button) |

Accent reserved for: **only** the two named primary CTAs (open-editor button, Save Template), focus
rings, the drag-over drop-zone tint, and the section-label rule tint — never for the "Reset to 1-2-3
default" secondary action (that stays neutral gray, see Copywriting Contract) and never for passive
badges or static labels.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (Settings entry point) | "Edit Default Template" — button on the new Services card that opens the slide-out |
| Primary CTA (drawer footer) | "Save Template" — persists the current `{kind, section}[]` array to `OrgSettings.defaultServiceTemplate` |
| Secondary action (drawer footer) | "Reset to 1-2-3 default" — exact wording locked by R087's correction and ROADMAP.md; loads `buildSlots()`'s item types + sections into the draft list without saving |
| Empty state heading | "No items yet" — reused verbatim from `ServiceEditorView.vue`'s existing per-section empty-state copy (`group.entries.length === 0` branch), so the two surfaces read as the same product |
| Empty state body | "Add items below to build your church's default service, or click Reset to 1-2-3 default to start from the standard Vertical Worship flow." |
| Services card summary (template configured) | "{N} items across {M} sections" (e.g. "7 items across 3 sections") |
| Services card summary (no template / empty) | "No default template set — new services start empty until you add items here." |
| Error state | "Failed to save. Please try again." — reused verbatim, matching every other `SettingsView.vue` section's exact error copy (`onSave`, `onToggleVwMode`, `onToggleAiEnabled` all use this string) |
| Destructive confirmation — Reset overwrite | Only shown when the current draft list is non-empty (nothing to lose when the draft is already empty): "Replace your custom template with the standard 1-2-3 flow? This clears every item you've added." Confirm button: "Replace Template". Cancel: "Cancel" |
| Destructive confirmation — per-item remove | **No confirmation dialog.** Matches `ServiceEditorView.vue`'s existing `removeSlot(index)` behavior, which fires immediately on click with no modal — reasoned discretionary call: a template row holds only `{kind, section}`, no user content (Area 1 lock), so removing one loses nothing a single re-click of the palette can't restore. Reserve confirmation dialogs for genuinely content-destructive actions (Reset overwrite, above), not structural edits |

## Component & State Reuse Map

Concrete states requested by the orchestrator's scope grounding, each mapped to the exact existing
pattern being reused. This section exists so the executor never has to invent a shape.

| State | Behavior | Source pattern reused |
|-------|----------|------------------------|
| **Empty template** | Drawer body shows the "No items yet" empty-state block (dashed border, centered text) instead of any section list. **Valid state** — R087's override means an empty template is the correct default, not an error. | `ServiceEditorView.vue`'s per-section empty placeholder (`border border-dashed border-gray-800 p-4 text-center`) |
| **Populated / ordered template** | Items render grouped under the five `SERVICE_SECTIONS` headers (label + gradient rule + item count), in array order within each section. Each row: drag handle (grip-dots SVG) · kind label · section `<select>` · remove (×) button. | `ServiceEditorView.vue`'s `slot-item` row markup (`rounded-lg bg-gray-900 border border-gray-800 p-3 flex items-start gap-2`), section-header block (`section-header flex items-center gap-2 pt-3 pb-1`) |
| **"Reset to 1-2-3 default" affordance** | A neutral (non-accent) button in the drawer footer beside "Save Template." Clicking it replaces the in-drawer draft list with `buildSlots()`'s item types + sections (never touches saved state until "Save Template" is also clicked). Confirms first only if the draft is non-empty (see Copywriting Contract). | Styled like `SettingsView.vue`'s "Edit Credentials" secondary button (`bg-gray-800 hover:bg-gray-700 text-gray-200`) |
| **Add-item interaction** | The exact Phase 43 palette row, reused verbatim: Song · Scripture · Prayer · Message · Announcements · Miscellaneous chips (no Hymn — R084 palette-only removal already applies here since this editor shares the same palette component/markup). Clicking a chip appends a new `{kind, section: undefined}` entry to the end of the draft list (or the currently-open section band, if the per-section inline-add pattern is reused instead of the page-level palette — planner's call, either is Phase-43-verbatim). **The Song chip does not expose a VW-type picker here** — VW typing is computed at service-creation time (R087 `[ARCH]`), never stored in the template, so this editor's Song entries are VW-type-agnostic by design. | `ServiceEditorView.vue`'s palette chip row (`rounded-md border border-gray-700 px-2 py-1 text-[11px] font-medium text-gray-300 hover:bg-gray-800`), `data-testid="palette-add-*"` convention |
| **Drag-reorder** | SortableJS, one instance per section container (or one flat instance with `*DraggableIndex` — planner's call), `v-for` keyed on the entry's own stable `id` (mint one per template entry at creation the same way `createSlot()` mints `slot.id` — never keyed on array index or derived `position`, which is the exact Phase-29-era bug class this codebase already fixed once). Drag-over tint: `bg-indigo-950/20` on the target section container. **Accessibility requirement (new this phase):** the drag-handle grip-dots SVG is icon-only with no visible text — its handle element must carry `aria-label="Drag to reorder"` (or the row's kind label interpolated in, e.g. `"Drag to reorder {kindLabel}"`) so it has a text alternative. | `ServiceEditorView.vue`'s per-section `Sortable.create(...)` + `sectionSortables` map, `draggable: '.slot-item'` |
| **Per-item section-assignment** | Native `<select>` per row, options = `SERVICE_SECTIONS` via `SERVICE_SECTION_LABELS`, plus a "No section" empty option. Changing it moves the entry to the new section's group in the draft list — same interaction as `ServiceEditorView.vue`'s `onSectionChange`. | `ServiceEditorView.vue`'s `data-testid="section-select"` `<select>` block |
| **Per-item remove** | × icon button, `text-gray-600 hover:text-red-400`, fires immediately (no confirm — see Copywriting Contract). **Accessibility requirement (new this phase):** the button is icon-only with no visible text — it must carry `aria-label="Remove {kindLabel}"` (e.g. `aria-label="Remove Song"`) so it has a text alternative. | `ServiceEditorView.vue`'s remove-slot × button |
| **Save / error / loading** | Footer "Save Template" button: `Saving...` while in flight, `Saved!` for ~2s on success (identical `setTimeout(..., 2000)` pattern), red `text-red-400` error line below the footer on failure using the exact copy above. | `SettingsView.vue`'s `onSave`/`isSaving`/`savedFeedback`/`saveError` pattern, applied to `onSaveTemplate` |
| **Slide-out panel mechanics** | Fixed right-edge panel, `w-full max-w-[480px]`, slide-in/out transition (`translate-x-full` ↔ `translate-x-0`, 250ms ease-out in / 200ms ease-in out), header with title + close (×) button, scrollable body (`flex-1 overflow-y-auto px-4 py-4`), footer actions row. No scrim — matches the app's one existing slide-out precedent exactly, including its "no reflow underneath" property (R033-era decision, `26-CONTEXT.md`/`STATE.md`). | `EditSlideDrawer.vue` in full: `fixed inset-y-0 right-0 z-50 w-full max-w-[480px] bg-gray-900 border-l border-gray-800 shadow-2xl flex flex-col`, its `Transition` `enter-active-class`/`leave-active-class` set |
| **Settings entry point (new "Services" section)** | New card on `SettingsView.vue`, same shape as its four existing sections: `rounded-lg bg-gray-900 border border-gray-800 p-4 mt-6`, `<h2 class="text-sm font-semibold text-gray-300 mb-3">Services</h2>`, one line of explanatory copy, a live summary line (see Copywriting Contract), and the "Edit Default Template" button that opens the drawer. | `SettingsView.vue`'s existing four `<div class="rounded-lg bg-gray-900 border border-gray-800 p-4 mt-6">` section blocks |

## UI Considerations

Applicable state considerations resolved: 7 covered, 1 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | Template item list (list-collection) | ✅ covered | Empty template renders the "No items yet" + guidance body copy; this is a valid, expected state per R087's owner override, not an error condition — "Save Template" remains enabled on an empty draft |
| populated | Template item list (list-collection) | ✅ covered | Items render grouped by section header (label + rule + count), each row showing kind label, section select, drag handle, remove — identical shape to `ServiceEditorView.vue`'s live Service Order list |
| zero-one-many | Template item list (list-collection) | ✅ covered | 0 → empty-state block; 1 → single row under its section header, no singular/plural copy needed (kind labels are fixed short vocabulary, not counted); many → the section-header slide-count pattern (`{N} items`) and drawer-body scroll (see overflow) both already handle high counts |
| overflow | Template item list, drawer body (list-collection / static-content) | ✅ covered | The list scrolls inside the drawer's `flex-1 overflow-y-auto` body — the drawer itself never grows past the viewport, matching `EditSlideDrawer.vue`'s existing behavior at any item count |
| loading | Save action (form) | ✅ covered | "Saving..." button-label state, reused verbatim from every existing `SettingsView.vue` section's save action; opening the drawer itself needs no separate loading state because `authStore.settings` is already synchronously available from the existing `loadOrgContext` merge point by the time Settings renders |
| error | Save action (form) | ✅ covered | Exact existing copy "Failed to save. Please try again." rendered below the drawer footer on write failure, matching every other Settings section |
| long-text | Kind label, section label (static-content) | ✅ covered | Both vocabularies are fixed and short (6 `SlotKind` values, 5 `ServiceSection` labels) — no user-entered free text exists in a template entry (Area 1 lock: `{kind, section}` only, never content), so truncation/wrapping is structurally impossible here and does not need a resolution beyond that guarantee |
| partial | Template entry (form) | 🧪 backstop | A template entry is added as a complete `{kind, section: undefined}` pair in one action (clicking a palette chip) — there is no multi-step/partially-filled entry state by construction. Flagged as a backstop rather than dismissed outright because the planner should verify with a test that no code path can persist a `kind`-only entry mid-edit before the section select has been touched (i.e. `section: undefined` must be a legitimate, saveable value, not treated as "incomplete") |
