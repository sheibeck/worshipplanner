<objective>
Give the slide grid the two explicit states R080 requires — pending and failed — and build the one
sanctioned route from a machine failure slug to human prose.

Implements D-13 (grid pending: an explicit placeholder naming the state, never a blank tile, never
stale parsed text), D-14 (grid failed: an explicit failure state surfacing `failureReason`) and D-21
(exact visual treatment is the planner's discretion, subject to 42-UI-SPEC.md, whose approved
contract is followed here rather than re-designed).

Purpose: R080 exists because a blank, broken, or misleadingly-stale slide is worse than an honest
"still rendering." The grid is the operator's surface, so it uses the red family that already means
"this needs your attention" elsewhere in this codebase.

Output: a static failure-sentence lookup with a generic fallback arm, and two new tile states.
</objective>

**Probe edge 5 (R080, category `unclassified`) could not be classified by the deterministic edge
probe and is recorded here as an explicit flagged assumption, neither dismissed nor converted into a
backstop marker.** The probe returned no predicate for it. The planner's reading is that R080's
substance is separately and thoroughly covered by 42-UI-SPEC.md's `## UI Considerations` table (7
covered, 1 backstop, 0 unresolved), which this plan and 42-07 lift row by row, plus the two rules
cases in 42-01. The assumption being made is therefore: **R080 needs no predicate beyond the UI-SPEC
rows and the rules coverage already authored across 42-01, 42-03, 42-06 and 42-07.** If verification
finds an R080 behaviour none of those rows reaches, this assumption is what was wrong. It is recorded
here rather than silently dropped, and it is NOT a `backstop` marker — an unclassified row must never
be auto-backstopped.

## Additional recorded decision

The failure-sentence table implements 42-UI-SPEC.md's copywriting contract **exactly as approved** —
two mapped slugs plus a generic fallback arm. It deliberately does NOT add an entry for
`incomplete-render`, which is in fact the reason the render trigger's ready gate writes most often
(`functions/src/index.ts:411-415`). The UI-SPEC states the table is "not exhaustive of every string
the backend might ever write, by design; the fallback exists precisely so an unmapped value never
surfaces raw text," so routing `incomplete-render` to the generic sentence is contract-compliant.
Flagged for the owner as a candidate copy improvement rather than changed unilaterally, because the
UI-SPEC is an approved design contract.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| render-document string fields → operator-facing DOM | `failureReason` originates in a Firestore document an org editor can currently write (T-42-01) and lands on screen |
| assembled slide render state → what is drawn | a missed branch would draw parsed text or an empty-sourced image instead of the placeholder |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-42-04 | Tampering | `failureReason` reaching the DOM | medium | mitigate | A tampered render document can carry arbitrary text in `failureReason`. Vue escapes interpolation so this is content injection rather than script injection, but arbitrary attacker-chosen text on an operator's screen — and, via 42-07, a projection screen — is the real harm. Mitigated by `renderFailureSentence`'s closed output set: the displayed string is always one of three authored sentences. Proven by Task 1's hostile-input iteration and Task 2's markup assertion that the raw value is absent from the rendered HTML. |
| T-42-12 | Information Disclosure | parsed deck text drawn under a render placeholder | low | mitigate | Drawing the deck's parsed body under a pending state would present stale content as final — the "misleadingly-stale" outcome R080 names. Mitigated structurally: the reconciler never puts parsed text into a pending/failed content object (42-03), and the tile's branch ordering makes the body paragraph unreachable when a render state is set. Asserted as an absence in Task 2. |
| T-42-SC | Tampering | npm/pip/cargo installs | high | accept | No install task in this plan. `42-UI-SPEC.md § Registry Safety` declares no shadcn or third-party registry blocks; icons are inline SVG, matching every existing icon in these components. `42-RESEARCH.md § Package Legitimacy Audit` records zero new dependencies. |
</threat_model>
