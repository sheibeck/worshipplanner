<objective>
Hide every Planning Center entry point when the integration is off, without altering a single byte
of already-imported roster data, already-exported service status, or stored credentials.

Purpose: ROADMAP success criterion 3 — "In Settings, a church can turn Planning Center integration
off; its features hide without altering already-imported roster data or the status of services
already exported." 39-CONTEXT.md records the owner's longer-range intent: the toggle exists as the
first step toward a full migration off Planning Center, "once someone has fully ported planning
center item over and we have a full replacement system in place for it." Nothing here may assume
Planning Center data can be deleted.

Output: six entry points gated, with data-level coverage for the action bar and component coverage
for the two import triggers.

**The six entry points, enumerated exhaustively by `39-RESEARCH.md` § Focus Area 4** — this is the
work list, and it is complete. Planning Center has no single choke point, so a missed row is a real
hole:

| # | Surface | File | Existing gate | This plan |
|---|---|---|---|---|
| 1 | Export-to-PC action-bar item | `src/views/serviceEditorActionBar.ts` — `buildExportOrCopyItem` (line ~86) | returns `undefined` when there are no credentials | compose the new condition onto that same return |
| 2 | Export dialog invocation | `src/views/ServiceEditorView.vue` — `onExportToPC` (line ~3073) | early-returns without credentials | extend the same early return |
| 3 | "Set up Planning Center" hint row | `src/views/ServiceEditorView.vue` (line ~195) | shows when credentials are absent | compose so the nudge also hides when the integration is off |
| 4 | Roster import trigger | `src/views/RosterView.vue` lines ~13 and ~73 — TWO occurrences (toolbar button and empty-state CTA), both calling the same open handler | none | gate both |
| 5 | Song import trigger | `src/views/SongsView.vue` line ~42 — the button labelled `Import Songs` (NOT "Import from Planning Center"; verified during planning) | none | gate it |
| 6 | Credentials display/edit block | `src/views/SettingsView.vue` lines 71-160 | none | **delivered by 39-03, not this plan** |

**Confirmed out of scope by the same research pass, deliberately NOT gated:**
`src/utils/pcSongImport.ts` has no UI of its own and is reached only through the modal that surface
5 opens; `addSlotAsItem` in `planningCenterApi.ts` is called only from inside the already-gated
export flow. Hiding the trigger is sufficient for both — adding redundant internal gates would
create competing checks that drift.

**Locked decisions honored** (39-CONTEXT.md § Off-State Behavior; the file uses prose bullets, not
numbered `D-NN` identifiers, so decisions are cited by verbatim phrase):
| Decision (verbatim phrase) | Where honored |
|---|---|
| "Planning Center off hides: Export to PC, roster import, song import, and the credentials block" | Tasks 1 and 2 (+ 39-03 for the credentials block) |
| "Stored credentials are retained, not cleared" | preserved by omission — no task here touches credential state |
| "Already-imported roster data and the status of already-`exported` services are untouched" | preserved by omission — no task here writes to roster or service documents |

**Discretionary call, resolved:** `39-RESEARCH.md` Open Question 1 asks whether the set-up hint
(surface 3) should hide when the integration is disabled or only when credentials are absent. It is
resolved here as **hide when disabled**, per the research's own recommendation and consistent with
39-UI-SPEC.md's "hide entirely" contract: a nudge to configure a feature the church deliberately
turned off implies a currently-relevant action that is not relevant.

**Naming resolution:** `39-UI-SPEC.md` uses `authStore.aiEnabled`-style shorthand in places. The
real read everywhere is `authStore.settings.pcEnabled` — 39-CONTEXT.md locks "one typed `settings`
computed on the auth store, not one ref per setting."

| Boundary | Description |

| Stored Planning Center credentials at rest | Retained by design when the integration is disabled. |
