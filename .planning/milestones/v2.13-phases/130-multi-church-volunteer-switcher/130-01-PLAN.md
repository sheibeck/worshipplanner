<objective>
Thread a new optional `orgName` field through the `rehearseAccess` projection pipeline and add the
client-side distinct-church + filter backbone to the `mySchedule` store. This is the data layer the
volunteer switcher (Plan 02) renders on top of.

Purpose: A zero-membership volunteer cannot read `organizations/{orgId}` (membership-gated), so the only
way to label churches by name is to freeze `orgName` onto the projection doc the volunteer is already
authorized to read. The store then derives the distinct churches and a pure client-side filter over
already-loaded docs — never a data-scope switch.

Output: `orgName` on `RehearseAccessDoc` + `buildRehearseAccess`, forwarded through the single
`writeRehearseAccessDoc` choke point by both write paths; `mySchedule.churches` / `selectedChurch` /
`filteredDocs`; extended unit tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| volunteer client → Firestore (rehearseAccess collectionGroup) | The volunteer already legitimately reads every rehearseAccess doc they are assigned to (array-contains own email). No new query is added by this plan. |
| editor client → Firestore (organizations/{orgId} getDoc, rehearseAccess setDoc) | The resync path adds a member-gated org-document read; the write path adds one non-sensitive field to an existing editor-only projection write. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-130-01 | Information Disclosure | orgName added to the rehearseAccess projection (rehearseAccess.ts) | low | accept | orgName is a church's public display name, already exposed via the orgSlugs registry used by the Phase 128 self-service page; adding it to a doc an assigned volunteer can already fully read introduces no new exposure. Accepted risk: orgName is a point-in-time snapshot frozen at write time — it will not reflect a later org rename until the service is re-locked or re-synced, consistent with the projection's existing freeze semantics. |
| T-130-02 | Elevation of Privilege | mySchedule store filter (mySchedule.ts) | medium | mitigate | The filter is a pure in-memory slice of already-authorized docs; the store performs no additional Firestore query for the filter and does not import the auth store or call selectOrg — asserted by the Task 3 tests and the no-auth-import acceptance check. |
| T-130-03 | Denial of Service | resync org getDoc (services.ts) | low | mitigate | The org read is batched into the existing Promise.all (no extra serial round-trip) and stays inside the best-effort try/catch, so a denied/slow read degrades to no orgName and never blocks the attachment write or the status transition. |
</threat_model>
