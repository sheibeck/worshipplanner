<objective>
Render the volunteer-facing switcher and sidebar church label on top of Plan 01's store backbone: a native
`<select>` church filter on My Schedule (shown only when the volunteer serves at more than one church), and
the volunteer's current church name in the AppSidebar org-name slot.

Purpose: Complete R403 (a filter distinct from the admin membership switcher), R404 (churches labeled by
name; the selected-church context is reflected in the sidebar/service view), and R405 (single-church
volunteers see no switcher).

Output: the My Schedule church filter + filtered/empty rendering; the AppSidebar volunteer church label;
extended component tests including the never-selectOrg assertion.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| volunteer UI → mySchedule store | The switcher sets a selection value; that value can only ever come from clicking a rendered option (an entry already derived from the volunteer's own authorized docs), never from a URL/route/query param. |
| volunteer UI → auth org context | The switcher must NOT cross this boundary — it must never invoke the admin data-scope switch (selectOrg / resetOrgScopedStores). |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-130-04 | Elevation of Privilege | MyScheduleView church filter (MyScheduleView.vue) | medium | mitigate | The filter sets mySchedule.selectedChurch only; it does not import or call authStore.selectOrg / handleSwitch / any org-context reset. Asserted by the Task 1 selectOrg spy (zero calls on selection). |
| T-130-05 | Tampering | selectedChurch value source (MyScheduleView.vue) | low | mitigate | selectedChurch is only ever set from a rendered <select> option whose value is an orgId already present in the volunteer's own authorized docs; it is never read from route.query, a URL param, or any externally-suppliable input, and it never reaches a Firestore query (it slices an in-memory array the volunteer is already authorized to see in full). |
| T-130-06 | Information Disclosure | AppSidebar volunteer label (AppSidebar.vue) | low | accept | The label shows only a church name the volunteer is already assigned to (public via orgSlugs). The volunteer branch never renders when authStore.orgName is set, so no admin/super-admin context leaks into it. |
</threat_model>
