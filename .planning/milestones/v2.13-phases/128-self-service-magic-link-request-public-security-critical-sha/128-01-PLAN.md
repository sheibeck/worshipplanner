<objective>
Build the security-critical server core of self-service magic-link requests: a shared Admin-SDK mint/send
helper and a PUBLIC, unauthenticated `requestVolunteerLink` callable that is roster-gated, rate-limited,
and enumeration-safe (body AND timing).

Purpose: A volunteer must be able to request their own passwordless sign-in link without an account and
without any endpoint that reveals whether an email is on a church's roster or that can be abused to spam
inboxes / fan out email cost. This is the one new attack surface v2.13 adds; the gate that guards it lives
here (never in a separate helper that could be bypassed).

Output: `functions/src/volunteerLink.ts` (shared `mintAndSendVolunteerLink` core, reused by Phase 129),
`requestVolunteerLinkHandler` + `requestVolunteerLink` onCall export in `functions/src/index.ts`, a
dedicated `volunteerLinkRateLimits` counter collection, and a full ALLOW/DENY + TIMING test matrix.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| unauthenticated browser → requestVolunteerLink onCall | Fully untrusted, public input ({ orgId, email }) crosses into an Admin-SDK, secret-holding, email-sending function with no auth context |
| requestVolunteerLink → Firestore (Admin SDK) | Server reads organizations/{orgId}/people bypassing rules; must scope strictly to the request's own orgId |
| requestVolunteerLink → Resend | Server-side email send using RESEND_API_KEY on a public endpoint |

## STRIDE Threat Register (ASVS L1; block on high)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-128-01 | Information Disclosure | requestVolunteerLink response body/error code | high | mitigate | Uniform GENERIC response for roster-hit/miss/rate-limited; only structural invalid-argument differs (no membership info). No resource-exhausted, no permission-denied. Asserted by DENY-1/DENY-3 byte-identical test (R395). |
| T-128-02 | Information Disclosure | requestVolunteerLink response timing | high | mitigate | Timing pad on no-match + rate-limited branches to VOLUNTEER_LINK_TARGET_RESPONSE_MS, masking the mint+send latency of the hit branch (128-RESEARCH Pitfall 2 / A4). Asserted by TIMING-1 (R395/R397). |
| T-128-03 | Denial of Service (cost/abuse) | email fan-out / inbox spam | high | mitigate | checkAndConsumeRateLimit keyed `${orgId}::${emailLower}`, dedicated volunteerLinkRateLimits collection, conservative ceilings (1/min, 5/day). Throttled path sends nothing, returns GENERIC. Asserted by DENY-3 (R397). |
| T-128-04 | Elevation of Privilege / Info Disclosure | cross-org roster leakage | high | mitigate | Roster fetch scoped to organizations/{orgId}/people for THIS request's orgId only; never a global/cross-org query. Asserted by DENY-2 (R396). |
| T-128-05 | Tampering | forged/arbitrary orgId probing (direct call, bypassing UI) | medium | accept | A bogus orgId's people fetch returns empty → identical GENERIC response; naturally enumeration-safe. Proven by an explicit test (bogus orgId → GENERIC, no send). |
| T-128-06 | Elevation of Privilege | RESEND_API_KEY secret surface on a public endpoint | medium | mitigate | Secret bound ONLY to the requestVolunteerLink wrapper; no other new function declares it; the callable does no other secret-touching work (R131 smallest key-holding surface). |
| T-128-07 | Tampering (dev-only) | manual mint-volunteer-link script diverging from shipped core | low | mitigate | mintAndSendVolunteerLink is the ONLY application path calling generateSignInWithEmailLink + resend.emails.send together; a dev script may exist standalone but is never imported by production code. |

Package legitimacy: N/A — this plan introduces zero new npm packages (firebase-admin, firebase-functions, resend already installed). No supply-chain checkpoint required.
