<objective>
Extend the Phase 125 `rehearseAccess` projection so a single `getDoc` serves all three volunteer tabs. Add three new fields to `RehearseAccessDoc` — `orderOfService` (the running order, R392), `roleAssignments` (Who's Serving, R392), and `stageLayout` (the v2.7 stage diagram, R393) — plus a resolved `bpm` on each `RehearseSong` (R385/R386 meta line). Every new field is built from the EXACT PII-safe allowlist `buildServiceSnapshot`/`toPublicServiceSnapshot` already enforce, reused (not re-derived) so the free-text-strip rules (R346/SEC-S-04, WR-01) can never drift between the share-link path and the rehearse path.

Purpose: This is the data foundation for the whole phase. Plans 02–06 render these fields; none of them can be built or tested until this projection type exists. Reusing the existing allowlist is the phase's single most important security control (PII-leak prevention).

Output: An extended `buildRehearseAccess`, a shared store-free allowlist helper both projection builders call, a lock-time write that persists the new fields, extended unit tests proving no free-text leak, and a confirmation that no `firestore.rules` change is needed.
</objective>
