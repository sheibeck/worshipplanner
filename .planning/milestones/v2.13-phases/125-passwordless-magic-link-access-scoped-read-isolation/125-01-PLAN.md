<objective>
Establish the R377 scoped-read isolation guarantee at the data layer: a new `rehearseAccess` Firestore
collection readable by a magic-link volunteer ONLY when they are an assigned participant of a currently-Planned
service in their own org, proven by a Firestore-emulator ALLOW/DENY test suite. This is the phase's
non-negotiable security gate; every downstream volunteer read surface (Phases 126-127) depends on this
boundary.

Purpose: The enforced boundary for volunteer access lives in `firestore.rules`, not in client code or router
guards. Router/UI separation (Plan 04) is defense-in-depth layered on top of this.
Output: The `rehearseAccess` rule block, the catch-all exclusion decision, and a passing R377 emulator suite.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| volunteer session -> Firestore | An authenticated, zero-membership, email-claim-only token crosses into org-scoped data; the ONLY grant is the narrow rehearseAccess read arm |
| cross-org | A volunteer legitimately assigned in org A must never read org B's data with the same token |
| rehearseAccess doc -> live service status | The projection is a snapshot; the rule re-verifies the LIVE parent status on every read |

## STRIDE Threat Register (ASVS L1; blocks on High)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-125-01 | Elevation of Privilege | rehearseAccess read (cross-org) | high | mitigate | Read arm requires isOrgMember(orgId) OR email-claim match against THIS org's doc; orgId is bound from the path, never a client field. Proven by DENY case (2). |
| T-125-02 | Tampering (trust-state staleness) | rehearseAccess read of Draft/reopened service | high | mitigate | Live `parentIsPlanned()` get() on the sibling services doc re-checks current status every read. Proven by DENY cases (3) and (4). |
| T-125-03 | Information Disclosure | not-assigned volunteer read | high | mitigate | `request.auth.token.email.lower() in assignedEmailsLower` required. Proven by DENY case (5). |
| T-125-04 | Tampering | volunteer writes rehearseAccess or forges assignment | high | mitigate | `allow write: if isOrgEditor(orgId)` only. Proven by DENY case (7). |
| T-125-05 | Information Disclosure | enumeration via unfiltered list() | medium | mitigate | Per-doc array-membership rule is not expressible as a query-time equality filter, so Firestore denies an unconstrained list(). Proven by DENY case (8). |
| T-125-06 | Elevation of Privilege | direct read of services/{id} bypassing the projection | high | mitigate | Existing `services/{docId}` rule requires membership; volunteer denied. Proven by DENY case (6). |
| T-125-SC | Tampering | supply chain (npm installs) | n/a | accept | No new packages introduced in this plan or phase (RESEARCH §Package Legitimacy Audit) — no install task exists. |
