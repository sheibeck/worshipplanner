<objective>
Deliver the volunteer magic sign-in link through the EXISTING v1.7 messaging pipeline: mint a per-recipient
email-link server-side inside `sendQueuedMessageHandler` and merge it into the current reminder/share email via
a new `{{rehearse_link}}` token — one email, no new email system.

Purpose: R375 forbids a new email system. Client-side `sendSignInLinkToEmail` would fire a second,
Firebase-branded email; the Admin SDK's `generateSignInWithEmailLink` returns only a URL string, letting the
app embed the link in the ONE email it already sends.
Output: The `{{rehearse_link}}` token and the per-recipient link generation in the send loop.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Cloud Function -> Firebase Auth Admin | The handler mints a per-recipient sign-in link under the same secrets/trust boundary as the existing Resend send; no new public endpoint |
| generated link -> recipient inbox | The link is a bearer credential delivered to the roster email; interception/replay must be Firebase-managed |
| continue-URL -> app | The URL the link redirects to must be a fixed, app-controlled route on an authorized domain (no open redirect) |

## STRIDE Threat Register (ASVS L1; blocks on High)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-125-10 | Spoofing / Tampering | open redirect via continue-URL | high | mitigate | `actionCodeSettings.url` is server-constructed from the trusted `SERVICE_SHARE_BASE_URL` param + a fixed `/volunteer/verify` path — never client-supplied; Firebase enforces Authorized domains on the continue-URL (owner user_setup). |
| T-125-11 | Information Disclosure | link interception / replay | medium | mitigate | Firebase-managed one-time link with server-side expiry/replay protection; per-recipient and email-bound; the send loop never logs the full recipient email at info level (existing T-59-03c convention preserved). |
| T-125-12 | Spoofing | a second, Firebase-branded email creates a phishing/confusion surface | medium | mitigate | Server-side `generateSignInWithEmailLink` returns a URL only and sends nothing; the link rides the ONE existing Resend email — client `sendSignInLinkToEmail` is deliberately NOT used (COVERAGE.md OPT-OUT). |
| T-125-13 | Denial of Service | one recipient's link-gen failure aborts the whole batch | low | mitigate | The call sits inside the existing per-recipient try/catch; a failure marks that recipient 'failed' and the loop continues. |
| T-125-SC | Tampering | supply chain (npm installs) | n/a | accept | No new packages (RESEARCH §Package Legitimacy Audit); firebase-admin/resend already installed. |
</threat_model>
