<objective>
Populate and maintain the R377 read path from the editor side: a pure builder that assembles the frozen
`rehearseAccess` projection at lock time, wired into the service status lifecycle so the projection is created
on draft->planned and removed on reopen/delete. The doc shape MUST match the schema Plan 125-01 defined and
the rule enforces.

Purpose: The rule (Plan 125-01) is inert without a correctly-shaped projection; and a projection written once
at lock time would outlive a Reopen (Pitfall 3) without explicit cleanup. This plan supplies both.
Output: `buildRehearseAccess()` and its lifecycle wiring in the services store.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| editor (planner app) -> rehearseAccess doc | An org editor authors the projection; editors are already fully trusted within their own org |
| lock lifecycle -> projection lifecycle | The projection must track the service's Planned state; a reopen/delete must not leave a readable stale doc |

## STRIDE Threat Register (ASVS L1; blocks on High)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-125-07 | Tampering | editor writes a forged assignedEmailsLower entry (another person's email) | low | accept | Within an editor's existing in-org trust boundary; the R377 boundary is cross-org / non-assigned isolation, not editor-vs-editor. Documented acceptance (RESEARCH Pitfall 4 / Assumption A1); no cross-org escalation is possible because orgId is path-bound in the rule. |
| T-125-08 | Tampering (trust-state staleness) | a Reopen leaves a readable rehearseAccess doc for a now-Draft service | high | mitigate | Two independent defenses: reopenService/deleteService delete the doc (this plan) AND the rule's live parentIsPlanned() re-check (Plan 125-01). Both proven — the rule side by 125-01 DENY case (4). |
| T-125-09 | Information Disclosure | projection over-exposes private planner data (notes, PII) | medium | mitigate | buildRehearseAccess is a frozen PII-safe projection (mirrors buildServiceSnapshot); unit test asserts only rehearse-necessary keys are present. |
| T-125-SC | Tampering | supply chain (npm installs) | n/a | accept | No new packages (RESEARCH §Package Legitimacy Audit); no install task. |
