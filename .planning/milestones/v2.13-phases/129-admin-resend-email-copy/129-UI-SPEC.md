# Phase 129 — UI Design Contract

> Visual and interaction contract for the Volunteers-page admin affordance to email or copy a
> volunteer's sign-in link (R400–R402). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (manual Tailwind; no `components.json` in this repo) |
| Preset | not applicable |
| Component library | none (hand-rolled Tailwind, dark gray-950 theme) |
| Icon library | none — inline SVG; Heroicons **outline** paths (stroke, `stroke-width="2"`) for UI chrome, Heroicons **solid** single-path for `ToastHost.vue` severity icons |
| Font | system default stack (no custom `font-family` declared anywhere in the repo) |

This phase adds **no new chrome**. It reuses two existing RosterView.vue conventions verbatim:
1. The **drawer "Status actions" block** (`RosterView.vue:393–457`) — section header + small
   bordered action buttons — as the home for the new "Sign-in Link" section.
2. The **copy-to-clipboard transient-label idiom** from `ServiceEditorView.vue:4051–4073`
   (`onShare`/`onShareStage`) — a local ref flag flips the button's own label text, no toast.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | **"Email sign-in link"** (button label, verb + noun) |
| Secondary CTA | **"Copy sign-in link"** (button label) |
| Section label | "Sign-in Link" (uppercase header, matches "Status" sibling) |
| Help copy (has email) | "Send {name} their passwordless sign-in link, or copy it to share yourself." |
| No-email explanation (disable+explain) | "Add an email address above to email or copy a sign-in link for {name}." |
| Busy state — email | Button label → "Sending…" (disabled) |
| Busy state — copy | Button label → "Copying…" (disabled) |
| Success — email (toast) | `toasts.push('Sign-in link sent to {name}.', { variant: 'success', autoDismissMs: 3000 })` — renders clean (success variant carries no hardcoded prefix in `ToastHost.vue`) |
| Success — copy (inline label flip, NOT a toast) | Button label → "Link copied!" for ~2000ms, mirroring `ServiceEditorView.vue`'s `shareCopied` idiom exactly |
| Error — email (toast) | `toasts.push('Could not send the sign-in link to {name}. Try again, or use Copy sign-in link instead.')` — default `push(message)` call, variant defaults to `'error'`. **Known app-wide quirk, not introduced here:** `ToastHost.vue`'s compact (non-heading) shape always prepends the literal "Save failed." before any error-variant message (`ToastHost.vue:62`), even for non-save failures — this is the established codebase convention (`AppSidebar.vue`'s "Could not switch churches...", `TeamSlideOver.vue`'s "team already exists" both do the same). Follow it rather than diverging into the richer `setSticky` heading shape, per "do not invent new chrome." Rendered result: "Save failed. Could not send the sign-in link to {name}. Try again, or use Copy sign-in link instead." |
| Error — copy (inline label flip, NOT a toast) | Button label → "Couldn't copy — try again" for ~3000ms, mirroring `ServiceEditorView.vue`'s `shareError` ref idiom (reset via `setTimeout`) |
| Destructive confirmation | None — neither action is destructive. Per CONTEXT's accepted trust tradeoff (an editor minting a volunteer's sign-in link can sign in as that read-only volunteer), no confirmation step is required; this is documented in the phase's threat model, not re-litigated in the UI. |

Both new callable errors (network failure, non-roster/no-email target, permission-denied) render
through the SAME error path described above — this is an authenticated editor view, so honest,
specific server error text is fine (no enumeration-safe generic copy, unlike the public self-service
page).

## Interaction & Placement Detail

(Non-template section — implementation guidance the checker/executor need beyond the standard
contract shape, carried over from `129-PATTERNS.md`'s already-settled placement decision.)

**Where it lives:** the per-volunteer row itself gets **no new markup** (no kebab menu, no inline
row buttons — RosterView.vue has no existing per-row action-menu chrome to reuse, and inventing one
would violate "do not invent new chrome"). Instead, the affordance lives inside the **existing
Add/Edit Volunteer drawer** that a row click already opens (`onEditPerson`), as a new sibling
section immediately after the existing "Status" block:

```html
<!-- after the existing Status actions block, RosterView.vue:394-457 -->
<div v-if="editingPerson" class="mt-6 pt-5 border-t border-gray-800">
  <h3 class="text-xs font-medium text-gray-400 uppercase tracking-wider mb-2">Sign-in Link</h3>

  <template v-if="editingPerson.email">
    <p class="text-xs text-gray-500 mb-2">
      Send {{ editingPerson.name }} their passwordless sign-in link, or copy it to share yourself.
    </p>
    <div class="flex flex-wrap items-center gap-2">
      <button
        type="button"
        :disabled="emailingLink"
        @click="onEmailSignInLink"
        class="text-xs px-3 py-1.5 rounded-md border border-indigo-700 text-indigo-300 hover:bg-indigo-900/30 disabled:opacity-40 disabled:cursor-not-allowed transition-colors"
      >{{ emailingLink ? 'Sending…' : 'Email sign-in link' }}</button>

      <button
        type="button"
        :disabled="copyingLink"
        @click="onCopySignInLink"
        class="text-xs px-3 py-1.5 rounded-md border border-indigo-700 text-indigo-300 hover:bg-indigo-900/30 disabled:opacity-40 disabled:cursor-not-allowed transition-colors"
      >{{ copyingLink ? 'Copying…' : linkCopyLabel }}</button>
    </div>
  </template>

  <p v-else class="text-xs text-gray-500">
    Add an email address above to email or copy a sign-in link for {{ editingPerson.name }}.
  </p>
</div>
```

- `linkCopyLabel` is a computed mirroring `ServiceEditorView.vue`'s `stageShareLabel`: `'Link copied!'`
  when the copied flag is set, the transient error string when set, else `'Copy sign-in link'`.
- Both buttons share the SAME visual style (equal weight — neither is more "primary" than the
  other), matching the existing "Reactivate" button class string exactly, char for char.
- `emailingLink` / `copyingLink` are separate busy refs (one action's in-flight state must not
  disable the other button).
- The section is gated on `v-if="editingPerson"` exactly like "Status," so it never renders in
  "Add Volunteer" mode (no person to target yet).
- Clicking either button does NOT touch `unsavedGuard` state (mirrors the existing status-action
  handlers, which are deliberately independent of the form's dirty-tracking).
