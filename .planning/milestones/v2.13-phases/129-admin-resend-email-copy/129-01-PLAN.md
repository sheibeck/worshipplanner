<objective>
Add the server side of the admin resend feature: a NEW authenticated, editor/admin-gated,
roster-gated callable `adminVolunteerLink` that reuses Phase 128's mint/send core to either
email a rostered volunteer their sign-in link (`mode: 'email'`) or return the raw link for
clipboard copy (`mode: 'copy'`). A small, mechanical refactor of `volunteerLink.ts` extracts
the mint step so the copy path can obtain a link without sending — preserving R402's single
mint code path.

Purpose: Give editors/admins a way to (re)deliver a volunteer's passwordless sign-in link from
the Volunteers page, reusing exactly one server-side mint/send core (R402), under an
authorization model proportionate to a trusted, authenticated caller (no enumeration/rate-limit
machinery — the public path's ceremony is deliberately NOT copied).

Output: `mintVolunteerLink` helper in `volunteerLink.ts`; `adminVolunteerLink` onCall +
`adminVolunteerLinkHandler` + typed request/response in `index.ts`; a full ALLOW/DENY +
single-mint-path test suite in `index.test.ts`. NOT deployed this phase (owner-gated batched UAT).
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| authenticated client → adminVolunteerLink callable | Client-supplied `orgId`, `email`, `mode` are untrusted input; authorization is decided server-side, never from client-declared values. |
| callable → Firebase Auth Admin SDK | `generateSignInWithEmailLink` mints an account-level credential; Admin-SDK-only capability. |
| callable → Resend (email mode) | Secret-holding (`RESEND_API_KEY`) delivery of the minted link. |
