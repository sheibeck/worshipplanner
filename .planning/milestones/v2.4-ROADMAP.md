## Key accomplishments

1. **A complete, standalone "Run the Service" experience** — a Run button on locked services (and the
   service list) opens a dedicated control screen that drives a fullscreen audience projector and a
   black-background confidence monitor from one browser, with a calm pre-flight → live flow and a
   single-selection (no push-to-live) model.
2. **Robust multi-monitor delivery** — Window Management API placement with a first-class pop-out fallback,
   per-device saved Audience/Confidence mapping, wake lock, and live-ops recovery (reopen a closed output,
   reassign after a monitor unplug) without losing the operator's place.
3. **Owner-approved live-operator redesign (Phase 97)** — blackout, clock/elapsed timers, in-item filmstrip
   click-to-jump, rehearse-without-screens, confidence left/right, and an honest live-status model.
4. **A long, decisive hardware-UAT round** — reliable **per-display "Go fullscreen" buttons** on the control
   (gesture-delegated; real fullscreen-state indicators that flip back on Escape; all buttons in one place
   so nobody chases the mouse across monitors), the "go to black" state mirrored on the On-screen preview,
   a whole-chapter sermon-passage `:undefined` fix, and locked-service song-edit propagation.

## The fullscreen note (the milestone's hardest-won lesson)

R278 asked for outputs to auto-fullscreen on go-live with no per-window clicking. **Zero-click
multi-monitor fullscreen is not achievable in a plain browser here.** The one browser mechanism that could
do it — the Chromium Automatic Fullscreen content setting (`AutomaticFullscreenAllowedForUrls` policy) —
was proven inert on the owner's hardware: with a provably-correct machine-wide policy (`chrome://policy`
OK) on **both Chrome 151 and Edge**, `requestFullscreen()` still rejected `not granted`, and the
`{name:'fullscreen', allowWithoutGesture:true}` permission query returned a **false-positive** `granted`.
Phase 98 (the in-app policy-setup helper built on that query) was therefore **built then removed**.

The delivered solution is **per-display "Go fullscreen" buttons** driven by Fullscreen Capability
Delegation — a real operator gesture, one click per display, all at the control, no registry, no
per-computer setup, and confirmed working with the policy fully uninstalled. This satisfies R278's intent
(get the displays fullscreen without chasing monitors) within the browser's one-gesture-one-window limit,
and scales to any number of outputs (a future Live Stream output is anticipated). **Do not resurrect the
registry-policy approach.**
