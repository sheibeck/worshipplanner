# Phase 72 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** This is a low-risk layout refactor that reuses existing app patterns end-to-end. No new
design language, tokens, or components are introduced. The Configuration pane is a byte-for-byte relocation
of the current `OwnerConsoleView` body (visual contract: unchanged from today — see
`src/views/OwnerConsoleView.vue`). The Organizations pane is a placeholder empty-state only. The design
surface here is: the tab strip, the two panes, active/inactive tab states, and focus/keyboard behavior.

## Component Spec: Tab Strip

Mirrors `ServiceEditorView.vue:695-746` exactly (structure and classes), reduced to 2 static tabs (no
`v-if`-gated tabs — both Configuration and Organizations render unconditionally, since both live behind the
same super-admin gate).

**Container:**
```html
<div class="flex items-center gap-1 mb-3 border-b border-gray-800 pb-0">
```

**Tab button (per tab), active/inactive branch — identical class recipe to ServiceEditorView:**
```html
<button
  type="button"
  class="px-4 py-2 text-sm font-medium rounded-t-md transition-colors -mb-px border-b-2"
  :class="activeTab === 'configuration'
    ? 'text-indigo-300 border-indigo-500 bg-gray-900'
    : 'text-gray-400 border-transparent hover:text-gray-200 hover:border-gray-600'"
  @click="setTab('configuration')"
>
  Configuration
</button>
```

Same recipe for the Organizations button, swapping the label and the `activeTab === 'organizations'` check.

**States:**
- **Active:** `text-indigo-300`, `border-indigo-500` (2px bottom border), `bg-gray-900` subtle panel tint — this is the ONLY place indigo accent appears in the tab strip itself.
- **Inactive:** `text-gray-400`, `border-transparent`.
- **Hover (inactive only):** `hover:text-gray-200 hover:border-gray-600` — no hover treatment change on the active tab (already indicating state).
- **Focus:** rely on the button's native focus ring behavior already present project-wide (no custom `focus:ring` override on tab buttons in the `ServiceEditorView` source — browser default focus outline applies; do not suppress it). This is a plain `<button>`, so keyboard Tab reaches it in document order and Enter/Space activates it — standard behavior, no custom keydown handling needed.
- **Keyboard/interaction contract:** clicking a tab calls `setTab('configuration' | 'organizations')`, which updates `activeTab` locally AND calls `router.replace({ query: { ...route.query, tab } })` (per CONTEXT decision — replace, not push, no history spam). No ARIA `role="tablist"`/`role="tab"` pattern is introduced — `ServiceEditorView.vue`'s existing tab strip uses plain buttons with no ARIA tab roles, and this phase mirrors that precedent exactly rather than inventing a new (more accessible but inconsistent) pattern.

**Panes:** Use `v-show` or `v-if` per two `activeTab === 'x'` conditions (planner/executor discretion per
CONTEXT — "either is acceptable"), each pane a direct sibling below the tab strip container, matching the
`<div v-show="activeTab === 'service-order'" ...>` sibling structure in `ServiceEditorView.vue:748`.
