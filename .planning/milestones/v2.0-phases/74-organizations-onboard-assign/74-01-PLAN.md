Build the three super-admin-gated org-provisioning callables in a new `functions/src/orgProvisioning.ts`
— `onboardOrganization`, `assignOrgAdmin`, `listOrganizations` — plus a data-only ported seed module
(`orgTemplateSeed.ts`) and comprehensive mocked-Admin-SDK unit tests. This is the entire server surface
for Phase 74; the Wave 2 UI (Plan 02) consumes the callable contracts this plan fixes.

Purpose: Give super-admins a rules-bypassing, server-verified path to list every org, onboard a church
end-to-end (org + settings + seeded template + first admin) in ONE atomic Firestore transaction, and
assign additional editor admins by email — with the R206 additive `arrayUnion` guarantee and the
R201/R202 uniqueness-and-no-half-created-org invariant enforced BY CONSTRUCTION (the first-admin write is
part of the same atomic commit as org creation, so a failed onboarding strands nothing), where the client
can never bypass them.

Output: `functions/src/orgTemplateSeed.ts` (+ test), `functions/src/orgProvisioning.ts` (+ test), and the
three-line export wiring in `functions/src/index.ts`. Callables ship built + tested + UNDEPLOYED (deploy is
handed over — see success criteria).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser (super-admin session) → onCall callable | Client-supplied `{name, adminEmail}` / `{orgId, email}` selectors and the caller's ID token cross here; nothing the client sends about its own authority is trusted. |
| callable → Firestore / Auth (Admin SDK) | Privileged, rules-bypassing reads/writes to organizations/orgNames/members/invites/inviteLookup/users and Auth `getUserByEmail`. |

Accepted-risk note: a compromised super-admin token is a full-platform admin-assignment primitive by
design (a super-admin may assign to ANY org) — the same blast radius as the existing `setSuperAdminClaim`
callable. This is the pre-existing accepted shape of the `superAdmin` claim, not new risk from this phase.
