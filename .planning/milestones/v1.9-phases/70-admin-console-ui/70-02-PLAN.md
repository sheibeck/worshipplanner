<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| super-admin browser -> Firestore `appConfig/global` | Every card's Save crosses here via `store.saveField`; the client is not the security boundary |
| Sender form input -> stored config | The one surface where a provider secret could be solicited/leaked (R192) |
| client value -> Cloud Functions read (Phase 69) | Written values are coerced server-side before use |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-70-01 | Information Disclosure | SenderConfigCard | high | mitigate | The card renders exactly two inputs (fromName, fromAddress); `AppConfig.sender` has no secret field by construction, so `RESEND_API_KEY` is never solicited, displayed, or fetched. A negative-assertion test proves the rendered card exposes no secret/API-key field (R192). |
| T-70-02 | Elevation of Privilege | card Save -> `appConfig/global` write | high | mitigate | Write authority is enforced by Phase 68 `firestore.rules` (`appConfig/*` gated to `isSuperAdmin()`, claim-only) and the route by Phase 68's requiresSuperAdmin guard; the cards are a convenience surface, not the boundary. No rules change this phase (client-only, per v1.9 grant). |
| T-70-03 | Tampering | numeric/model/toggle values written from cards | high | mitigate | Client min/max/required + cross-field validation is UX-only; the Phase 69 `coerce*` layer is the authoritative backstop — enable-flags and the model allow-list fail CLOSED, rate limits/caps are capped-open — so a bypassed client cannot zero the delete cap, widen the model allow-list, or lift a cap at read time. |
| T-70-04 | Repudiation / mis-send | SenderConfigCard fromAddress | low | mitigate | An unverifiable Firebase-managed host (`*.web.app` / `*.firebaseapp.com`) surfaces a non-blocking amber warning that emails will fail until a custom domain is configured; the global provenance stamp records who set it and when. Domain verification itself is an out-of-band owner action (R192). |
| T-70-SC | Tampering (supply chain) | npm installs | low | accept | No package installs this phase — zero new dependencies. |
</threat_model>
