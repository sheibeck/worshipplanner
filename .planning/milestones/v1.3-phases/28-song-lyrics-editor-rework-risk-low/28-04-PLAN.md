Editing writes back to the pooled section's `lines` in the editable state — never to a per-row copy.

Wire autosave with the existing `useAutoSave` composable: the watched source is the editable state,

one call. Because seeding runs the loaded document through `normalizeLyricOrder`, a document needing
repair reads as dirty and is healed by the ordinary save path, while a well-formed document reads as
clean and produces no write.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user keystrokes → editable state → Firestore lyrics document | Typed lyric text is persisted to an org-scoped document by autosave with no intermediate confirmation. |
| stored lyrics document → rendered rows | A document written by another session, or an older client, is rendered here without validation beyond the invariant normaliser. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-28-12 | Tampering | autosave write scope | high | mitigate | Sections and order are written in one update call to the current lyrics document, so a reorder can never land without its text; asserted by a single-call test. |
| T-28-13 | Tampering | seeding from store state | medium | mitigate | The editable state is a deep copy of the normalised load, so rendering never mutates the store's snapshot and a failed save cannot corrupt what other components read. |
| T-28-14 | Information Disclosure | rendered lyric text | low | accept | Lyric text is org-scoped content the user already has read access to; `firestore.rules` is unchanged and no new read path is introduced. |
| T-28-15 | Denial of Service | expansion state growth | low | mitigate | Expanded rows are tracked by row key in a set bounded by the row count; no unbounded accumulation is possible. |
| T-28-SC | Tampering | package installs | high | accept | This plan installs nothing; no package-manager command runs. |
</threat_model>
