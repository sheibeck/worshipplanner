<objective>
Give a group its music from the Slides tab: attach, preview, and remove a group-level audio bed on the
selected group, in the slot the mockup reserved for it above the card grid.

Purpose: R032 names audio explicitly, and D-14 makes audio the one dropped file type that does NOT
become a slide — it becomes the group's bed. This plan builds the deliberate, non-drop half of that,
so 25-07's drop routing has a persistence path already proven by tests.
Output: one new component, one mount, two test suites.
</objective>

## STRIDE Threat Register (OWASP ASVS L1 — block on `high`)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-25-06-01 | Denial of Service | oversized or wrong-type file uploaded as group music | high | mitigate | The existing media-upload composable validates the MIME prefix and the size cap before any bytes leave the browser, and `storage.rules` enforces the same ceiling server-side. | T-25-06-02 | Elevation of Privilege | a viewer attaching or removing group music | high | mitigate | Both controls are gated on the editor flag, and Firestore's org-editor rule on `slideGroups` plus the Storage rule on the org media path are the authoritative boundaries. | T-25-06-05 | Tampering | a bed write racing first materialization and resetting a group's slides to empty | high | mitigate | Unchanged Phase 24 mitigation — the store's skeleton create is a merging write for exactly this race. This plan adds no second create path on the bed route. |
| T-25-06-06 | Information Disclosure | a Storage object path exposed in the displayed file name | low | accept | The name is decoded from a URL the user's own browser already holds and only the final segment is shown. The URL itself is already in the DOM as the player's source. |
