<objective>
Build the pure materializer: derive a slide group's structure from a plan slot's canonical source, and
reconcile a stored group when that source later changes shape.

Purpose: this module is where D-02's "never silently drop a user's added slide, audio, label or note"
is actually enforced. RESEARCH.md proved the three source kinds have fundamentally different id
stability, so this ships three small kind-specific functions rather than one generic diff that would
hide that difference.
Output: one pure utility file plus its test file — no Firestore, no store, no reactivity.
</objective>

  <action>
Export `reconcileSongGroup(group: SlideGroup, slot: SongSlot, inputs: AssemblyInputs): { slides: GroupSlideEntry[]; changed: boolean }`.

Diff by `sourceRef.sectionId`, the only content-stable key available (song section ids are slugified
labels, so re-pasting CCLI text with unchanged labels regenerates the same ids). Build the fresh
resolved section order using the same precedence chain Task 1 uses.

Rules, in this order:
1. A `sectionId` present in the fresh resolution and absent from the stored entries → INSERT a new
   entry at the position the fresh order puts it, minting a new `crypto.randomUUID()`.
2. A `sectionId` present in both → KEEP THE STORED ENTRY OBJECT AS-IS. Do not rebuild it, do not
   re-derive it, do not touch its `id`, `label`, `notes`, `audioUrl`, `audioScope` or `audioLoop`.
   Only `order` may be renumbered.
3. A `sectionId` present in the stored entries and absent from the fresh resolution → RETAIN the
   stored entry. It will simply fail to resolve live text at assembly time, which the assembler
   renders as a removed-section placeholder in 24-04. Removing it is a user action in Phase 26, never
   an automatic one. This rule is the concrete mechanism satisfying D-02's never-silently-drop rule.
4. The two `copyright` entries are matched by `sourceRef.kind === 'copyright'` and position (leading /
   trailing), never by `sectionId`; keep exactly the stored ones when present, insert them when the
   stored group somehow lacks them.

Do NOT re-run derivation and overwrite `group.slides` — RESEARCH.md § Pitfall 4 names exactly that
shortcut as the failure mode this function exists to prevent. Set `changed` true only when the merged
list differs from the stored list in membership or order.

Add the tests for every behavior above, including the Pitfall-4 regression: attach a `label` to a
stored entry, reconcile against a song that gained an unrelated verse, and assert the label survives.
  </action>

  <action>
Export two sibling functions with the same result shape:
`reconcileScriptureGroup(group: SlideGroup, slot: ScriptureSlot, inputs: AssemblyInputs)` and
`reconcileImportedGroup(group: SlideGroup, slot: ImportedSlot, inputs: AssemblyInputs)`, each returning
`{ needsConfirm: boolean; changed: boolean; slides: GroupSlideEntry[]; proposed?: GroupSlideEntry[]; loss?: { customizedEntries: number; withAudio: number; withNotes: number } }`.

Both follow the same three-branch shape:
1. Compute the fresh signature with Task 1's `sourceSignature`. If it equals `group.sourceSignature`,
   return the stored slides with `needsConfirm` and `changed` both false.
2. Signature diverged and `hasCustomization(group)` is false → return
   `deriveGroupEntries(slot, inputs)` with `changed: true`, `needsConfirm: false`.
3. Signature diverged and the group IS customized → return the STORED slides as `slides` (nothing is
   applied), `needsConfirm: true`, `changed: false`, the freshly derived list as `proposed`, and a
   `loss` count summary the Phase 26 confirm dialog can render (mirroring D-03's
   name-what-will-be-lost discipline).

Do NOT attempt id-based diffing in either function. Scripture inner ids are positional and are
reassigned wholesale by any re-split; imported deck ids are fresh random UUIDs on every import. Matching
on them would map a user's audio and notes onto the wrong text — a silent corruption that looks like
success. Add a comment on each function saying so, citing the id-generation site.

Also export a small discriminating helper `reconcileGroup(group, slot, inputs)` that dispatches on
`slot.kind` to the right one of the three reconcilers and returns the union result shape, so the
composable in 24-05 has one entry point. A `text`-kind slot returns the stored slides with both flags
false.

Add tests for every behavior above, including the equal-count-but-changed-text case that
RESEARCH.md § Assumptions Log A2 flags as the reason the signature must hash the text and not only
count the slides.
