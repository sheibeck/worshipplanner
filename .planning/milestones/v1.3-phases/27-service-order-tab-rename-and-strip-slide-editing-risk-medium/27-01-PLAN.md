<objective>
Settle one thing the phase context did not anticipate: stripping the slideshow-preview panel from the
first tab also removes the only way a user can start a presentation.

Purpose: Phase 27 is a removal phase, and removal phases fail by taking too much. The phase context's
fate table marks the preview panel for removal, but the panel carries a "Present Slideshow" button that
is the sole trigger for Phase 23's presentation viewer. Nothing on the Slides tab replaces it. This is
exactly the case the phase brief says to flag rather than quietly paper over.
Output: A recorded decision (option-a, option-b or option-c) that 27-05 implements verbatim.
</objective>

<task type="checkpoint:decision" gate="blocking">
  <name>Task 1: Where does "Present Slideshow" live after the strip?</name>
  <decision>
  The first tab's slideshow-preview panel is marked for removal by the phase context's fate table. That
  panel contains the "Present Slideshow" button, and that button is the only thing anywhere in the app
  that sets the flag mounting Phase 23's presentation viewer. Removing the panel removes the ability to
  present. Decide whether that capability is preserved, and how.
  </decision>
  <context>
  Verified in the codebase before asking:

  - The presentation viewer component is imported by exactly one file, the service editor view, and is
    mounted only behind a local flag that the preview panel's present event sets. There is no route, no
    menu item and no other caller.
  - `src/components/slides/` (the whole Slides tab built in Phases 25-26) contains no present/play
    affordance — only prose comments naming the viewer. So the capability has NOT been rehomed, even
    though the ROADMAP's rationale for sequencing Phase 27 after 25-26 was "so the functionality has a
    new home before it leaves the old one."
  - Phase 23 shipped this capability and its batch human-verify checkpoint (real fullscreen + Esc sync,
    autoplay policy, expired-media degradation, projector legibility, iPad Safari) is still OUTSTANDING
    per STATE.md's Deferred Verification table. Losing the entry point makes those checks unperformable.
  - The phase brief for this planning run says: do not build anything new; if the strip leaves users
    unable to do something that has no home on the Slides tab, flag it rather than quietly building a
    replacement. Hence this checkpoint.

  Whichever option is chosen, the presentation viewer component file and its test file are NOT deleted
  by this phase.
  </context>
  <options>
    <option id="option-a">
      <name>Keep a bare "Present Slideshow" button on the Service Order tab (RECOMMENDED)</name>
      <pros>
      Preserves a shipped, human-verify-pending capability with no capability regression. Retains the
      existing presenting flag and the existing viewer mount — no new component, no new store, no new
      data path. The preview RENDER (the slide thumbnails, which really are slide content) still leaves
      the tab, so the phase's intent holds. The button already exists today inside the preview panel; it
      is retained one level up, not invented.
      </pros>
      <cons>
      Leaves one non-order-of-service control on the Service Order tab. Requires authoring a small
      button and its disabled/empty-slideshow guard rather than deleting outright.
      </cons>
    </option>
    <option id="option-b">
      <name>Keep the whole slideshow-preview panel mounted, unchanged</name>
      <pros>
      Zero code risk and zero capability loss. Arguably correct on the merits: previewing and presenting
      are not slide EDITING, which is the same reasoning D-01 already used to keep scripture editing on
      this tab.
      </pros>
      <cons>
      Directly contradicts the phase context's fate table, which marks the panel for removal, and
      contradicts the v1.3 organizing idea that all slide content lives on the Slides tab. Leaves a full
      slide render on the order-of-service tab, which is the visual clutter the milestone set out to fix.
      </cons>
    </option>
    <option id="option-c">
      <name>Remove the preview panel and the viewer mount; accept that presenting has no entry point</name>
      <pros>
      The cleanest possible strip. Fully honours the fate table and D-02 (the preview component becomes
      orphaned and is deleted along with its test file).
      </pros>
      <cons>
      A real capability regression: nobody can present a slideshow until a later phase gives the Slides
      tab a present affordance. Phase 23's outstanding batch human-verify becomes unperformable and must
      be recorded as blocked debt against v1.3, not merely deferred.
      </cons>
    </option>
  </options>
