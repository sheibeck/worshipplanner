<objective>
Finish the panel with its two remaining actions — copy a slide, and delete one behind a warning that
names what goes with it — and make a copied song slide survive the next reconciliation.

Purpose: D-04 ships copy and defers the mockup's undefined affordances. The reconciliation interaction
is the reason this is its own plan rather than a footnote in another: song reconciliation keeps one
stored entry per song section, so a copy of a song-section slide would be silently swallowed the next
time that song changed. Shipping the copy action without fixing that would introduce a quiet data loss
into the exact feature Phase 24 built its confirm gate to prevent.
Output: a duplicate-tolerant song merge, the delete warning's four wordings as pure functions, and both
actions in the panel.
</objective>

  <behavior>
    - A song group holding two stored entries for the same song section keeps BOTH after a reconciliation, in their stored relative order.
    - Each kept entry keeps its own id and its own label, notes, audio and loop values.
    - A song group holding exactly one entry per section behaves exactly as it does today.
    - A section newly present in the source is still inserted, and a section that no longer resolves is still retained rather than deleted.

  <action>
Make the song merge tolerant of more than one stored entry per song section.

Today the merge indexes stored song-section entries into a map keyed by section id, which keeps only the
last entry for any repeated section, and then emits one entry per fresh section. Two entries for the same
section therefore lose one — silently, with no confirmation, because this path is the additive
within-song merge that never gates on confirmation. That is precisely what a copied song-section slide
would be.

Change the index so it holds ALL stored entries for a section, in stored order, and have the rebuild emit
all of them for that section in that order rather than just one. Keep everything else about the merge as
it is: the same insertion of newly-present sections, the same retention of sections that no longer
resolve, the same by-kind-and-position handling of the leading and trailing copyright entries, the same
carry-through of other kinds, and the same changed-or-not decision.

Preserve each kept entry by value — its own id, label, notes, audio and loop — renumbering only its
order, exactly as the current merge already does for the single-entry case.

Add a comment stating why this tolerance exists: the panel can create a copy of a song-section slide, and
without it that copy would disappear on the next source change with no warning.

Do not touch the confirmation-gated paths, the identity-swap branch, or the scripture and imported
reconcilers.
  </action>

    - A test asserts a newly-present section is still inserted and an unresolvable section is still retained.
