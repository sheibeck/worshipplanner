<objective>
Lay the cross-component plumbing the drawer's "Edit in scripture" affordance needs (D-15): a request
that travels from the Slides tab up to the page view, which switches to the tab owning the scripture
editor and expands the right plan item's editor.

Purpose: 26-RESEARCH.md Pitfall 5 establishes that this cannot be a link. The scripture editor is
collapsed by default behind per-plan-item state that lives inside the page view, and the whole Slides
tab subtree is deliberately prop-down/emit-up with no upward reach. Research also flagged, as an
assumption to verify, that the existing expansion function might be a strict toggle — it is, so a link
reusing it would close the editor on a second click. Building this plumbing on its own, ahead of the
drawer, keeps a four-component change out of a UI plan and gets the expand-only semantics right once.
Output: one new expand-only entry point and one request handler on the page view, one relay on the
Slides tab, both covered by their existing test suites.
</objective>
