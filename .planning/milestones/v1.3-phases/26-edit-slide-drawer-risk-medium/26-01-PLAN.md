<objective>
Close the three data-model gaps the Edit Slide drawer's reconciliation confirm dialog needs before it
can exist: the reconciler must name the old and new song on an identity swap (D-08), the group document
must be able to record a declined update durably (D-07), and the store must expose a scoped write for
that record.

Purpose: 26-RESEARCH.md and 26-UI-SPEC.md both flag the same thing — the confirm dialog's D-08 copy
names two songs the data layer does not carry, and D-07's durable decline has nowhere to live. Both are
real model changes, not UI concerns, and every later plan in this phase reads through them. This plan
also proves the compare-and-swap contract for the drawer's read-modify-write shape (research Pitfall 2)
before any drawer code exists to get it wrong.
Output: one widened result type, one new group field, one new store action, three extended test suites.

**Planner decision recorded here (resolves 26-UI-SPEC.md § UI Considerations' one ⚠ unresolved row):**
the old/new song identity travels as `songSwap: { oldSongId, newSongId }` on the reconciler's result —
ids only, from the pure layer. Titles are resolved one layer up, in 26-04, where the song catalog is
already in scope. The durable decline is a `dismissedSignature` field on the group document, chosen over
a separate collection because the group document is already subscribed live and a second document would
cost a second read for no benefit (26-RESEARCH.md Assumptions Log A1).
</objective>

tab is self-correcting, because the next reconciliation recomputes the current divergence from the
