## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Not applicable — this phase adds no button/submit action. The "CTA" is the checkbox itself: label text **"Loop"** (checkbox), matching the terse existing per-item control vocabulary (badge pills read "SONG"/"MISC" etc., not full sentences) |
| Interval control label | **"Every"** + preset `<select>` (5s / 10s / 15s / 20s / 30s / 60s / Custom) — inline, sentence-style reads "Loop · Every [10s ▾]", mirroring the existing inline Bible-version selector's terse "Default (ESV)" idiom rather than a verbose form-field label |
| Custom-seconds input placeholder | **"Seconds"** (shown only when "Custom" is selected in the preset dropdown) — matches the existing placeholder-driven idiom (`notesPlaceholder()`, `"Details"`, `"Hymn Name"`) rather than a `<label>` element |
| Empty state | Not applicable — the loop control has no data-dependent empty state; unchecked (default) is not an "empty" condition to communicate, it is simply off |
| Error state | Custom-seconds entry below 1 or non-numeric: clamp silently to the nearest valid value (1–3600s) on blur, mirroring this codebase's existing silent-normalize pattern for other free-form numeric-adjacent inputs (e.g. `slot.notes = value || undefined`) rather than surfacing a validation banner — no new error-copy string is needed. If the checker requires an explicit error string for the "invalid custom value" UI consideration below, use: **"Enter 1–3600 seconds"** as a `title`/`aria-describedby` hint on the custom input, not a blocking toast. |
| Destructive confirmation | Not applicable — unchecking "Loop" is a reversible, non-destructive toggle with no confirmation, consistent with every other checkbox/select in the item editor (PC-Teams checkboxes, Bible-version selector) never requiring confirmation |
| Optional Run-rail indicator copy | **"Loop"** (10px uppercase badge/label), or an icon-only ⟳ glyph with `aria-label="Looping"` if the checker prefers icon-first parity with the rail's existing dot-based status idiom — researcher recommendation: **text label "Loop"**, since the rail has no existing icon-badge precedent to reuse cleanly (only colored dots for active/current state), and a text label is more legible at the rail's compact row height without introducing a new icon system for one badge |

## UI Considerations

Applicable state considerations resolved: 4 covered, 1 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| error | Custom-seconds numeric entry (form / interactive-control) | ✅ covered | Out-of-range or non-numeric custom entry (e.g. `0`, `-5`, empty, non-numeric) is clamped to the nearest valid value (1–3600s) on blur rather than left invalid or silently dropped — mirrors the codebase's existing silent-normalize idiom on free-form fields (`slot.notes = value \|\| undefined`); the field never persists an invalid `intervalSeconds`. |
| zero-one-many | Looping item with only 1 slide (interactive-control state, not list-collection, but the same "zero/one/many" shape applies to the loop's target) | ✅ covered | Per 106-CONTEXT.md decisions: "a single-slide looping item is a harmless no-op (stays put)" — the checkbox/interval UI itself renders identically regardless of slide count; no special-cased warning copy is needed because the runtime behavior is already a safe no-op, not an error. |
| long-text | Custom-seconds `<input>` (form) | ✅ covered | Numeric-only field (`type="number"`, no free text) — no long-text/overflow risk exists; dismissed as not applicable to a bounded numeric control. |
| overflow | Optional Run-rail "Loop" badge next to a long/truncated item title (static-content, inside `RunRail.vue`'s existing row) | ✅ covered | The badge is `flex-none` (fixed width, never grows/shrinks), placed after the `min-w-0 flex-1` title span exactly like the existing `countLabel` "N slides" badge at `RunRail.vue:117` — the title truncates (`truncate` class already present) before the badge is ever squeezed, so a long item title cannot push the badge off-row or collide with it. |
| loading | Loop checkbox / interval control (form) | 🧪 backstop | No async load exists for this control (it's a local field on the already-loaded service document, same as every other item-editor field) — dismissed as not applicable, but held as a backstop in case a future data-shape change adds a fetch here; no explicit loading UI is specified. |

Dismissed as not applicable (no reason needed beyond kind mismatch, per probe rules — noted for completeness): `empty` (a checkbox has no "no data" state), `populated`/`partial` (not a list or multi-field form with optional fields at risk of partial fill — `loop.enabled`/`loop.intervalSeconds` are always both-or-neither, written together).

## Component Inventory (new controls only)

Everything below is placed inside `src/views/ServiceEditorView.vue`'s existing per-slot row (`.slot-item`, field column, `class="flex-1 min-w-0 flex flex-col gap-2"`), stacked immediately AFTER the per-kind content block (SONG/SCRIPTURE/HYMN/etc.) and BEFORE the existing consolidated notes field (`slot-notes-input`) — a new row in the same vertical `gap-2` stack, matching the "near the item's existing controls" placement from 106-CONTEXT.md, editor-only (`v-if="canEditService"`), draft-locked like every other Service Order field (no new rules surface — it's a field on the existing `slots` array).

### 1. Loop checkbox row

```html
<div class="flex items-center gap-2" data-testid="slot-loop-row">
  <label class="flex items-center gap-2 text-sm text-gray-200 cursor-pointer">
    <input
      type="checkbox"
      :checked="slot.loop?.enabled ?? false"
      class="h-4 w-4 rounded border-gray-600 bg-gray-800 text-indigo-600 focus:ring-indigo-500 focus:ring-offset-gray-900"
      data-testid="slot-loop-checkbox"
      @change="onToggleLoop(index, ($event.target as HTMLInputElement).checked)"
    />
    Loop
  </label>

  <!-- interval control: only rendered when loop.enabled -->
  <template v-if="slot.loop?.enabled">
    <span class="text-xs text-gray-400">Every</span>
    <select
      :value="loopPresetFor(slot)"
      class="rounded-md bg-gray-800 border border-gray-700 text-gray-300 text-xs px-1.5 py-2 focus:outline-none focus:ring-1 focus:ring-indigo-500"
      data-testid="slot-loop-preset"
      aria-label="Loop interval"
      @change="onLoopPresetChange(index, ($event.target as HTMLSelectElement).value)"
    >
      <option value="5">5s</option>
      <option value="10">10s (default)</option>
      <option value="15">15s</option>
      <option value="20">20s</option>
      <option value="30">30s</option>
      <option value="60">60s</option>
      <option value="custom">Custom…</option>
    </select>

    <input
      v-if="loopPresetFor(slot) === 'custom'"
      type="number"
      min="1"
      max="3600"
      step="1"
      :value="slot.loop?.intervalSeconds"
      placeholder="Seconds"
      class="w-20 rounded-md bg-gray-800 border border-gray-700 text-gray-200 text-xs px-2 py-1 focus:outline-none focus:ring-1 focus:ring-indigo-500 placeholder-gray-500"
      data-testid="slot-loop-custom-seconds"
      aria-label="Custom loop interval in seconds"
      title="Enter 1–3600 seconds"
      @blur="onLoopCustomBlur(index, ($event.target as HTMLInputElement).value)"
    />
  </template>
</div>
```

**Reused classes** (verbatim from existing patterns, not invented): checkbox class is byte-for-byte identical to the PC-Teams checkbox (`ServiceEditorView.vue:536`); `<select>` class is byte-for-byte identical to the Bible-version selector (`ServiceEditorView.vue:1188`); custom-seconds `<input>` class matches the HYMN-slot text inputs' size/fill token (`ServiceEditorView.vue:1248`) with `type="number"` and a narrower `w-20` (fixed-width numeric field vs. `flex-1`/`w-24`/`w-36` text fields, since seconds never need more than 4 digits).

**Behavior notes (for the plan, not re-litigated here):**
- Default preset on first check = 10s, per R307/CONTEXT decision.
- `loopPresetFor(slot)` returns the matching preset string if `intervalSeconds` matches one of 5/10/15/20/30/60, else `'custom'` — so a service saved with e.g. 45s (custom) correctly re-selects "Custom…" and shows the numeric field pre-filled with 45 on reload, never silently snapping to a nearest preset.
- Unchecking "Loop" hides the interval control immediately (`v-if`) but MAY retain the last `intervalSeconds` value in the model so re-checking restores it — plan-phase decision, not a UI-contract concern.

### 2. Optional Run-rail "Loop" indicator (nice-to-have, build only if it stays this small)

Inside `src/components/run/RunRail.vue`'s existing active-item row (`RunRail.vue:117`, next to the existing `countLabel` "N slides" badge), add a second `flex-none` span, shown only when `row.loop?.enabled` is passed through from the parent's `RailRow`:

```html
<span
  v-if="row.loop?.enabled"
  class="flex-none rounded px-1.5 py-0.5 text-[10px] font-semibold uppercase tracking-wide text-indigo-300 bg-indigo-950/40"
  data-testid="rail-loop-badge"
  aria-label="Looping"
>Loop</span>
<span class="flex-none text-xs text-gray-500">{{ countLabel(row.count) }}</span>
```

This is the ONLY Run-screen UI this phase specifies. It requires `RailRow` (defined in `useRunControl.ts`) to carry the slot's `loop?.enabled` flag through — a data-plumbing change, not a new visual pattern. The badge tint (`text-indigo-300 bg-indigo-950/40`) is a direct reuse of this codebase's existing pill idiom (compare `ServiceEditorView.vue:935`'s group-label pill: `text-indigo-300/80` on a dark ground) adapted to RunRail's own indigo-accent vocabulary (`bg-indigo-600/15`, `text-indigo-400`) already present in that same file — no new color is introduced. **If this indicator cannot be built as a clean two-line addition to the existing row (e.g. it requires new RailRow plumbing beyond a boolean pass-through), drop it — it is explicitly a nice-to-have per the phase brief, not a requirement.**
