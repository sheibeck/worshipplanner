<objective>
Add the inline black (blackout) slide as an additive content kind at the pure data/resolution layer:
the `LyricSection.kind` field, a `BlackoutSlide` variant on the `Slide` union, the `addSection('BLACKOUT')`
minting rule, the numbering-exclusion in `buildSectionRows`, the assembler branches that emit a blackout
`AssembledSlide`, and the display-label helpers. This is the foundation the editor/rendering UI (105-02)
builds on. No Vue components change here — every file in this plan is pure TypeScript with existing unit
test suites to extend.

Purpose: Get the data-model decision (CONTEXT.md: additive `kind` on the lyric slide model, NOT an empty
LyricSection, NOT a SourceRef change) settled and proven before any UI is built on top of it — the exact
sequencing PITFALLS Pitfall 5 demands ("get the contentKind question settled before any editor UI").
Output: a blackout section resolves end-to-end into a `contentKind:'blackout'` assembled slide, and song
section numbering is provably unaffected (R304).
</objective>
