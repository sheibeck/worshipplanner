<objective>
Generalize the deliberately-narrow failure-toast store (`src/stores/toasts.ts`) and its host (`src/components/ToastHost.vue`) into the app's ONE system-wide dismissible-message system, and prove it by migrating the two known "stuck banner" cases onto it. Delivers: four severities (info/success/warning/error), a mandatory manual-dismiss control on every message (R309), and a keyed persistent/sticky lifetime that a view clears programmatically when its condition resolves (R310). Relocates the single global host from `AppShell.vue` to the `App.vue` root so it renders on `RunControlView.vue` (which does NOT use AppShell) — without that relocation R310's proof case cannot render.

Purpose: The owner's verbatim requirement is "no warning messages or errors that get 'stuck' on the screen … Allow us to dismiss errors, warnings, etc." Today the monitor warning is ad-hoc `v-if` markup in `RunControlView.vue` with no dismiss path — the actual stuck bug. This plan makes the store the single seam every future message surface uses.

Output: A generalized `toasts.ts` store + `ToastHost.vue` host mounted at `App.vue`, with the RunControlView monitor-reassign warning and the MonitorSetupView save-outcome warning both routed through it.
</objective>
