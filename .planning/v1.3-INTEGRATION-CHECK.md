## API/Data Flow Chains Traced

- Present flow: SlidesTab Present button emits present, ServiceEditorView owns a single presenting flag and mounts a single PresentationViewer (verified only one exists, no dead second mount survives from the old Service Order tab); assembledSlideshow prop drives playback including per-slide audioUrl/audioLoop.
- Bed audio flow: file drop on SlideGrid routes through dropRouting.resolveDrop, classifies the first audio file as bed, then slideGroupsStore.setGroupBedMedia writes bedAudioUrl, SlideGroupMusicControl.vue displays it, slideshowAssembler.ts folds group.bedAudioUrl into each entry assembled audioUrl (only when the entry has no own entry.audioUrl), PresentationViewer.vue AudioPlayer plays currentSlide.slide.audioUrl with audioLoop. Full chain intact.
- Drag-reorder: SlideGrid.vue Task 3 SortableJS instance recomputes order on drop and writes the full reordered array back to the store; a base-array staleness guard is present.
- Plan-item reorder to slide order (R028): slideshowAssembler.ts derives output order solely from service.slots sorted by position plus GroupSlideEntry.order within a slot, no second manual reorder step exists or is needed.
- Four-kind drop routing: dropRouting.ts resolveDrop covers PPTX (extension-sniffed first, since MIME is unreliable for pptx files), image, video, audio, with a documented precedence order and a skipped bucket surfaced via inline notice rather than silently dropped.
