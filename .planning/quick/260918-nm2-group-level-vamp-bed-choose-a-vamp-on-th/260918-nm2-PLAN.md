## Design (locked by the owner/orchestrator — implement exactly)

1. Data model: `SlideGroup.bedVampId?: string`, `bedVampLabel?: string` (display-only, mirrors
   `GroupSlideEntry.vampId`/`vampLabel`). Assign writes all three bed fields; `clearAudio` deletes all three;
   an uploaded-URL write deletes the two vamp fields. Assign-over-upload replaces with no confirm.
2. UI: empty state = file label + `Choose a vamp` link (indigo text-link styling of the drawer's
   `vamp-picker-open`); vamp state = `Vamp: {label}` + scope line + preview + Change + Clear + stale hint;
   inline `VampPicker` below the control gated by `isEditor`; component stays emit-only (`attach-vamp`).
3. Assembler: vamp-sourced beds loop (entry fallback AND scripture-reference path); uploaded beds never loop.
4. Run badge: group-level fallback; entry-level `vampId` wins.
5. R440 scan matches `bedVampId` too. No copy change in `VampSlideOver`.
6. TDD per task: RED commit `test(260918-nm2): …` then GREEN `feat(260918-nm2): …`.
7. Gates: per-task `npx vitest run <touched test files>`; final `npm run type-check` (vue-tsc --build).
   Do NOT run the bare full `npx vitest run` (~9 min; the orchestrator runs it). Do NOT deploy.
8. Comments short (CLAUDE.md convention). No new dependencies. No rules changes (the slideGroups update rule
   has no key allowlist — verified in firestore.rules lines 462-465).

Label format is the SAME inline literal `EditSlideDrawer.attachVampToSlide` uses (line 928):
`` `${vamp.name} · ${vamp.key}` `` (U+00B7 middle dot, single spaces). Do not introduce a different format.
