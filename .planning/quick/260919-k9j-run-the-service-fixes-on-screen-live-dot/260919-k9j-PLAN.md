## Design (locked by the owner/orchestrator — implement exactly)

- **Fix 1 scope is the On-screen pane only.** The filmstrip thumbs' current-slide `ring-green-500` frame (RunFilmstrip.vue line 23, asserted by RunFilmstrip.test.ts lines 70-72) is a "current slide" marker, not an on-air indicator — leave it green. Use Tailwind `bg-red-500` / `ring-red-500` (the header uses a CSS custom property `--color-live: #e5484d`; the pane is Tailwind-utility styled, and `red-500` is already the Run screen's red family — RunControlView.vue line 337).
- **Fix 2 default-On mechanism (decided):** keep `const audioArmed = ref(false)` and both teardown resets to `false` (useRunControl.ts lines 1115 and 1151). Add ONE `watch(live, …)` rising-edge handler in the audio block that sets `audioArmed.value = true`, clears `audioBlocked`, awaits `nextTick()`, then calls `tryPlayAudio()`. Rationale: `postIndex(0)` already fires on mount (line 1416) or when assembly arrives (line 1422), so `rehearse()` (line 224) and `finishOpen()` (line 907) never re-post index 0 and the slide-change watcher (line 302) cannot start the first play; the rising edge is the single wiring point covering BOTH go-live paths, the AudioPlayer mounts on `live` so the `nextTick` is required before `audioElRef` is bound, `audioNeeded` (`live && !audioArmed && …`) stays correct (pulses only after a manual Off), and the resets keep meaning "Off while not live". A `play()` on an already-playing element (the rare index-null go-live where both watchers fire) is a browser no-op — do not add extra guards.
- **Fix 2 copy:** label `Audio: On` / `Audio: Off`; aria-label `Audio on — click to turn off` / `Turn audio on for this Run session`; sr-only prompt `This slide has audio — turn audio on to hear it.`; CSS class `run-audio-toggle--armed` and prop/emit names unchanged. `RunControlView.vue` wiring for the toggle is unchanged (no edit).
- **Fix 3:** the cap becomes `<button type="button">` keeping `data-testid="run-filmstrip-endcap"` and its inner copy; `:disabled="!props.nextItemLabel"`; `:aria-label` = `Go to next item: {label}` when enabled, `End of service` otherwise; new emit `'next-item': []` fired from a handler that early-returns when `nextItemLabel` is falsy; classes add `focus:outline-none focus-visible:ring-2 focus-visible:ring-indigo-400 enabled:cursor-pointer enabled:hover:border-indigo-500 enabled:hover:text-gray-200 disabled:cursor-default` to the existing dashed-box classes. RunControlView destructures `goByItem` and wires `@next-item="goByItem(1)"` — the ArrowDown path (`handleKeydown` line 469). Note the R331 label names the row after the active one even if that row has no slides (default control fixture: slot 1 is empty) — the click then lands on slot 2, identical to ArrowDown; that quirk is pre-existing and out of scope.
- **Comments stay short** (CLAUDE.md): one line naming `260919-k9j` where a behaviour changed; colour history in words ("was green"), never by utility-class name, so the negative grep gates below cannot be tripped by a comment.
- **Test commands:** targeted `npx vitest run <files>` per task (the full suite is ~9 min); `npm run type-check` once, in Task 3. Never `--dir`.
