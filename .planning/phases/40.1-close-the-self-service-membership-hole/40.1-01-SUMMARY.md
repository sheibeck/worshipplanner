# Phase 40.1 Plan 01: Close the Self-Service Membership Hole Summary

**Replaced Firestore's unconditional `allow create` on `members/{uid}` with an OR of two explicit, emulator-proven flow branches (`getAfter()` for org founding, `get()`/`exists()` with role-pinning for invite acceptance), closing a pre-existing privilege-escalation hole where any signed-in user could self-join any org at a role of their choosing.**

## Accomplishments

## get() vs getAfter() — Empirical Resolution of Research Assumption A1

Research flagged MEDIUM confidence on the exact batch-internal ordering semantics of `get()`/`exists()`
versus `getAfter()` (assumption A1) and pre-authorized a swap as an expected, non-defect outcome if the
recommended arrangement failed on first run.

**No swap was needed.** The recommended arrangement worked exactly as researched on the first emulator
run:
- **Org-creation branch → `getAfter()`** on the sibling `organizations/{orgId}` doc created in the
  same batch (`auth.ts:327` then `:334`) — confirmed by Test C passing.
- **Invite-acceptance branch → plain `get()`/`exists()`** on the invite doc, which predates the batch
  and is deleted later within it (`auth.ts:301`) — confirmed by Test B passing (its batch includes the
  invite delete, per the plan's explicit requirement that a test omitting it would prove nothing about
  this exact distinction).

After the Task 2 rule edit, `npx vitest run --config vitest.rules.config.ts` reported **107 passed, 0
failed** on the first run — both DENY tests flipped from failing to passing, both ALLOW tests continued
to pass.

## Decisions Made
- Applied the research document's recommended rule design verbatim, including its explanatory comments — the file already carries load-bearing rationale comments elsewhere (e.g. the `/services` and org-level wildcard blocks), and the `get()` vs `getAfter()` asymmetry is exactly the kind of detail a future editor could "simplify" into a regression without them.
- Test file placement: extended `src/rules.test.ts` in place per plan/research/context guidance — no new test file, no duplicated emulator lifecycle boilerplate.
- Did not fix either of the two other over-permissive findings research located (`organizations/{orgId}`'s unrestricted editor write of `createdBy`; `inviteLookup`'s signed-in-only create) — both recorded in `PENDING-VERIFICATION.md` as explicitly out of this phase's one-predicate scope, with the reason neither defeats this fix.
