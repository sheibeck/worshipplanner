<objective>
Restructure the Phase 61 R144 lock side-effect block inside `onMarkAsPlanned` (`ServiceEditorView.vue:2907-2988`)
into the Phase 62 re-lock flow: compute a REAL `slideGroupsFingerprint` on every lock; on a re-lock (a prior
`lockSnapshots/current` exists) read the prior snapshot + fingerprint, run `diffServiceSnapshots`, and — for a
non-empty diff with messaging on — open `ReLockNotifyPrompt` while DEFERRING the `lockSnapshots/current` overwrite
to the modal's confirm; overwrite silently on an empty diff or with messaging off; and update the Phase 61
first-lock tests that asserted the null-fingerprint stub.

overwrites `lockSnapshots/current`, so the next re-lock diffs against the new state — never before confirm). This
is the integration plan: it wires the pure diff (62-02) and the modal (62-03) into the shipped lock hook, and it
is the ONLY place the overwrite timing is enforced.

DECISIONS (locked, from 62-CONTEXT.md / 62-RESEARCH.md § Critical Finding 4 / 62-PATTERNS.md § lock hook):
- The first-lock path is unchanged EXCEPT it now writes a real fingerprint instead of `null`; the Phase 61
  auto-send stays. The Phase 61 tests asserting `slideGroupsFingerprint: null` are UPDATED (a stub realized).
- Overwrite `lockSnapshots/current` ONLY on confirm for a re-lock-with-prompt — the Phase 61 code writes on every
  lock; for this path the write moves into a `writeSnapshot` closure the modal's `sent`/`cancel` resolution runs.
  A failed send (no event) leaves the snapshot as the safe pre-edit basis (SC4). Empty-diff and first-lock paths
  still write immediately.
- Messaging OFF → NO prompt even on a non-empty diff — overwrite silently (nowhere to send). Read-before-write is
  preserved. The whole block stays in its own try/catch, never re-raised into `lifecycleError`.

  `buildServiceSnapshot` (the share-link path is untouched).
