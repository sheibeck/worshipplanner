<objective>
Give the song-files Storage prefix a permission-correct, server-authoritative home in storage.rules and
prove it with rules-emulator allow/deny tests. This is the security half of the phase (R364 type/size
enforcement, R372 editor-only mutation). Resolve the OR-combination problem the research identified: a
dedicated restrictive song-files/ block ALONE cannot narrow what the existing permissive org-wide
catch-all already grants — the catch-all itself must be amended to exclude song-files/.

Purpose: Without this, an oversized or disallowed file (or a viewer) could write to song-files/ by
bypassing the future UI — R364/R372 require the gate to live at the rules layer, not the client.
Output: An amended storage.rules and an extended src/storage.rules.test.ts proving every allow/deny case.

Cross-plan note (no hard dependency): Plan 122-02's hardDeleteSong cascade (R371) relies in production on
this plan's `allow delete: if isOrgEditor(orgId)` grant. That cascade's own unit test mocks Storage, so
the two plans execute independently in the same wave; together they satisfy R371's delete path.
</objective>

  <name>Task 1: Amend storage.rules — isOrgEditor claim helper, dedicated song-files/ block, catch-all exclusion (R364, R372)</name>
  <files>storage.rules</files>
  <action>
Implement the research's RESOLVED rule structure (122-RESEARCH.md "Recommended storage.rules structure").
Three coordinated edits inside `service firebase.storage > match /b/{bucket}/o`:

(1) Add an isOrgEditorByClaim(orgId) helper mirroring the EXACT structure of the existing
isOrgMemberByClaim (storage.rules:13-40) — same superAdmin outer arm, same multi-org-arm/legacy-arm OR,
same isOrgDeactivatedForCaller wrap — but requiring the resolved role to be in ['editor','admin'] rather
than merely non-null. The multi-org arm checks request.auth.token.orgs[orgId] in ['editor','admin'] (with
the orgs != null null-guard BEFORE indexing, matching isOrgMemberByClaim's guard); the legacy arm checks
request.auth.token.orgId == orgId && request.auth.token.role in ['editor','admin']. 'admin' is
intentionally synonymous with 'editor' (mirrors firestore.rules isOrgEditor). Add a thin
isOrgEditor(orgId) that returns isOrgEditorByClaim(orgId), mirroring the existing isOrgMember wrapper.

(2) Add a dedicated block `match /orgs/{orgId}/song-files/{allPaths=**}` positioned like the existing
media block (before the catch-all), with SEPARATE verbs (not bundled `write`): `allow read: if
isOrgMember(orgId)`; `allow create: if isOrgEditor(orgId) && request.resource.size < 52428800 &&
request.resource.contentType in ['application/pdf', 'audio/mpeg']`; `allow update: if false` (attachments
are immutable — every re-upload uses a new attachmentId/path, so denying update closes an in-place
overwrite bypass of the create-time type check); `allow delete: if isOrgEditor(orgId)` (delete needs its
own unconditioned grant because request.resource is null on delete, so any request.resource.size/.name
reference would error-deny — this is the app's first client-initiated Storage delete, for R371's cascade).

(3) Amend the EXISTING catch-all `match /orgs/{orgId}/{allPaths=**}` (storage.rules:69-77) so it cannot
OR-override the restrictive song-files block: add `&& !resource.name.matches('^orgs/[^/]+/song-files/.*')`
to its `allow read`, and `&& !request.resource.name.matches('^orgs/[^/]+/song-files/.*')` to its `allow
write`. Use the string-regex on resource.name/request.resource.name (a documented String supporting
.matches) — NOT indexing into the {allPaths=**} path capture. This exclusion is MANDATORY, not optional:
Firebase Storage OR-combines every matching block, so without it the catch-all's `isOrgMember && size<25MB`
grant alone would allow a small non-PDF file the dedicated block denies (122-RESEARCH.md Pitfall 1).

CONSTRAINTS: Do NOT introduce any firestore.exists()/get() or `/databases/(default)/documents/` reference
— role/membership checks are claim-only (CLAUDE.md; the inert-in-emulator cross-service read is exactly
how a deny-everyone rule once shipped). Leave the media block and every existing pptx/backgrounds path
grant unchanged. Keep the existing "claim-only membership" static guard test green (it strips // comments
then asserts firestore.exists( / isOrgMemberByFirestore / the databases path are absent and that
isOrgMember returns isOrgMemberByClaim — your isOrgEditor wrapper does not affect that isOrgMember regex).
  </action>
