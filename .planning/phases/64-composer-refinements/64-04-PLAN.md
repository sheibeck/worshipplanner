<objective>
Kill the perpetual "Sending…" in the delivery history. `ServiceMessageHistory.vue` renders a `queued`/
`sending` message as a grey "Sending…" spinner with no age check — so a message whose send trigger never
flipped its status spins forever. Add a read-only aged-out affordance: a `queued`/`sending` row whose
`createdAt` is older than 5 minutes (or a `failed` status) surfaces the existing red **"Failed to send"**
pill instead of a spinner. Recent (< 5 min) in-flight rows keep the spinner; a null `createdAt` (fresh
serverTimestamp sentinel) is treated as not-yet-aged.

Purpose:
- R155 (history half, SC5) — a message that cannot progress shows a failed/timeout state in the history
  rather than a perpetual "Sending…". Read-only presentation only.

This is a Wave-1 plan, independent of the composer work: it touches only `ServiceMessageHistory.vue` and
its test — zero overlap with `MessageComposer.*` — so it runs in parallel with 64-01 and 64-02. (R155's
composer half — the Send-button spinner + success-toast removal — lives in 64-03; this plan is the history
half only.)

DECISIONS (locked, from 64-CONTEXT.md / 64-RESEARCH.md §R155 / 64-UI-SPEC.md §R155 / 64-PATTERNS.md §R155b):
- Threshold `STUCK_THRESHOLD_MS = 5 * 60 * 1000` (300000 ms / 5 min). Age = `Date.now() -
  createdAt.toMillis()`. Field is `createdAt` (server-set on queue), NOT `sentAt` (null while queued).
- A `queued`/`sending` row with a non-null `createdAt` AND age > threshold → the `failed` red pill recipe
  verbatim (`bg-red-900/50 text-red-300 border-red-800`, `spinner: false`) with label **"Failed to send"**.
  Otherwise keep the current grey `Sending…` spinner pill.
- Null `createdAt` ⇒ NOT stuck (keep the spinner) — a just-written doc briefly carries the unresolved
  serverTimestamp sentinel; treating null as epoch-0 age would flash "Failed" on every fresh message
  (Pitfall 3).
- Mirror the SAME age check in `sendTimeLabel` so an aged row's time line reads "Failed to send" (not
  "Sending…"); a recent in-flight row still reads "Sending…".
- Copy is **"Failed to send"** (not "Stuck — retry") — there is NO retry affordance; the actual
  resend-from-history action is explicitly DEFERRED. This plan adds no write path.

Output: the extended `statusPill` + `sendTimeLabel` (with a shared age helper + the threshold constant) in
`ServiceMessageHistory.vue`, plus the aged-queued test case. jsdom test; no deploy, no `.env.local`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Presentation over stored status (client) → user | The stuck affordance is a READ-ONLY render over existing `createdAt`/`status`; it mutates no doc and triggers no callable. The authoritative status is still the server send trigger's write — this only changes how a not-yet-flipped `queued` doc is DISPLAYED |
| Clock skew (client Date.now vs server createdAt) | The age compares the client clock to a server timestamp; a badly skewed client could mislabel a genuinely-recent row as failed (or vice versa). Bounded, cosmetic, self-correcting once the status flips; no data effect |
| npm registry → app build | No package installed — an in-component helper + a constant + a test case. Zero supply-chain surface |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|

| T-64-04b | Tampering (correctness) | Only one of the two status→label sites is updated, so the pill says 'Failed' while the time line still says 'Sending…' | medium | mitigate | Both `statusPill` and `sendTimeLabel` call the shared `isStuck` helper; the test asserts both the pill text and the time line for the aged row (Pitfall 4) |
| T-64-04c | Repudiation (misleading UX) | Threshold too low mislabels a slow-but-live send as failed, or too high leaves a perpetual spinner | low | accept | 5-min default is the CONTEXT/UI-SPEC-approved value; it is a single named constant, trivially tunable. No retry action is offered, so a mislabel is cosmetic and self-corrects when the status flips |
