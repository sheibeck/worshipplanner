<objective>
Surface the already-shipped, already-hardened multi-org switch primitive (`authStore.selectOrg()` + `resetOrgScopedStores()`, built for v2.1) in the sidebar user block, so a member of more than one church can change active church without signing out (R311) with zero stale prior-church data (R312). Reuses the app's one existing ARIA-menu interaction model (`SlideActionMenu.vue`) and `TeamView`'s role-badge markup. Strictly distinct from the super-admin `enterOrgAsSuperAdmin()` "enter any church" path.

Purpose: This is the owner's explicit choice — the switcher lives in the user menu (this app's user menu is the sidebar footer avatar/name/email row, not a top bar), not in Settings. The reset path already exists and was bug-fixed once ("quick 260823-switch-church-cache"); this plan exposes it, it does NOT reimplement switching.

Output: `authStore.memberships` entries carry the user's per-org role; `AppSidebar.vue` gains a multi-org "Switch church" dropdown; a forward-obligation marker in `orgScopedStores.ts` guards R312 for the Phase 107 stage-layout store.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-104-04 | Elevation of Privilege | church switcher target-org selection | high | mitigate | Switch ONLY via `authStore.selectOrg()`, which rejects any `targetOrgId` not in the caller's own `memberships`; the switcher never assigns `orgId` directly and never calls `enterOrgAsSuperAdmin()`. Server claim remains the true gate. |
| T-104-05 | Information Disclosure | stale prior-org data after switch (R312) | high | mitigate | `selectOrg()` routes through `resetOrgScopedStores()` before loading the new org (prevents cross-tenant data flash); Task 1's `STAGELAYOUTS-RESET-OBLIGATION` marker ensures the Phase 107 store is registered too. |
| T-104-06 | Spoofing | conflating regular switch with super-admin enter-any-church | medium | mitigate | Switcher gated `memberships.length > 1 && !viewingAsSuperAdmin`; the two switch mechanisms never render together. |
| T-104-07 | Tampering | role badge display accuracy | low | accept | The role badge is display-only, sourced from the claim; server-side rules enforce actual permissions regardless of what the badge shows. |
