<objective>
Ship R144: when a planner locks a DRAFT service for the FIRST time, the client automatically emails everyone
assigned (their roles, song list, service-order link) — governed by the Phase 58 lock-notify default — and shows
a subordinate confirmation line inside the existing amber lock banner. The hook lives in `onMarkAsPlanned`
(`ServiceEditorView.vue:2757`), fires only on the draft→locked transition, and its failure never undoes or
misreports the successful lock.

Purpose: R144 (auto lock email on first lock, roles/songs/link, governed by the per-service/Settings default) +
its SC2 guarantee (never on a draft, never while messaging is off). Every lock also writes
`lockSnapshots/current` so Phase 62 has a prior snapshot to diff against (Phase 61 computes no diff). The net-new
UI is exactly one confirmation line, hosted in the banner that already appears on the draft→locked transition —
no new component, no toast (the app's `ToastHost` is failure-only and would misrender a success; UI-SPEC § Scope).

DECISIONS (locked, from 61-CONTEXT.md / 61-UI-SPEC.md / 61-RESEARCH.md):
- First lock is AUTOMATIC (governed by the default), not a confirm-before-lock prompt — the re-lock diff-prompt
  is Phase 62. A re-lock (a prior `lockSnapshots/current` exists) writes the snapshot but does NOT auto-send here.
- Effective lock-notify path is `localService.messaging?.lockNotifyEnabled ?? authStore.settings.messaging
  .lockNotifyDefault` — the org value is under `settings.messaging.*`, NOT `messaging.*`.
- `slideGroupsFingerprint: null` — deferred to Phase 62 (buildServiceSnapshot has no slide text; research A1).
- The confirmation is an inline transient amber line in the lock banner (NOT the failure-only ToastHost, NOT a
  shared-component refactor); a failed enqueue is amber-informational, NEVER the red `lifecycleError` line.

Output: the lock hook + `lockNotify` state in `onMarkAsPlanned`, the confirmation line markup in the
`service-lock-banner`, and the extended `ServiceEditorView.test.ts`. No functions/ change; no deploy.
</objective>
