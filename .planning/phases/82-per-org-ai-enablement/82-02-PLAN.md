## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Vue client render -> user | UI-visible AI affordances; hiding a panel is UX, not enforcement |
| authStore -> claudeApi choke point | The client-side gate deciding whether to originate an AI request |
| Owner Console -> setOrgAiEnabled callable | Super-admin mutation issued from the browser (authorization is enforced server-side in Plan 01) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-82-06 | Information Disclosure / policy bypass | SettingsView AI card v-if (UI-only hide) | medium | mitigate | The v-if is UX; real enforcement is the server proxy gate (Plan 01, T-82-03) plus the `isAiEnabled()` client AND-gate (Task 1). A stale/hidden card cannot be relied on alone. |
| T-82-07 | Tampering | field-name collision top-level vs settings.aiEnabled | medium | mitigate | Use the distinct top-level name `aiMasterEnabled` in the type + store + snapshot read; never a bare top-level `aiEnabled` (Pitfall 1). |
| T-82-08 | Elevation of Privilege | Owner Console toggle invoked by a non-super-admin | high | transfer | The button is a pure httpsCallable consumer; authorization is enforced by `assertSuperAdminCaller` inside the callable (Plan 01, T-82-04) — the client never trusts itself for this. |
| T-82-SC | Tampering | package installs | low | accept | No new npm package is introduced (RESEARCH Package Legitimacy Audit: N/A). |
