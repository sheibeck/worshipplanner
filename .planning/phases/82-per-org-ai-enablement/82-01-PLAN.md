<objective>
Deliver the super-admin-only master AI gate on the backend: a new `aiMasterEnabled` boolean on `organizations/{orgId}` that is Admin-SDK-write-only (denied to every client), a `setOrgAiEnabled` super-admin callable that flips it (and force-writes the church's own `settings.aiEnabled: false` on disable), and live fail-closed enforcement in the AI proxy so a disabled org genuinely cannot call Anthropic.

Purpose: R242 requires a super-admin to control per-org AI with AI OFF by default; R243 requires that disabling AI forces the church's own setting off. This plan is the security boundary — the client gating in Plan 02 is UX on top of it. Every piece mirrors an existing, tested twin (`active` / `setOrgActiveHandler`), so this is composition, not new design.

Output: extended `firestore.rules`, the new callable + `OrgSummary` field in `orgProvisioning.ts`, the proxy gate in `index.ts`, matching tests, and the UNDEPLOYED deploy hand-over recorded in PENDING-VERIFICATION.md.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| org editor client -> organizations/{orgId} write | An org editor (or a super-admin's own client SDK) attempting to set the master gate directly, bypassing the callable |
| Owner Console -> setOrgAiEnabled callable | Super-admin-authenticated mutation of another org's AI state |
| authenticated client -> AI proxy (`api` onRequest, anthropic) | A valid ID token from any org hitting the billed Anthropic upstream directly, bypassing the Vue UI |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-82-01 | Elevation of Privilege | organizations/{orgId} client write (org editor) | high | mitigate | Add the master-gate field to `lifecycleFields()`; `preservesLifecycleFields()` denies the write at the rules layer — proven by an editor-DENY emulator test (Task 1). |
| T-82-02 | Tampering | organizations/{orgId} client write (super-admin's own SDK) | high | mitigate | Same `lifecycleFields()` guard denies a super-admin client write too, forcing use of the callable so the forced-off side effect on `settings.aiEnabled` can never be skipped — proven by mirroring the CRITICAL test at src/rules.test.ts:682 (Task 1). |
| T-82-03 | Elevation of Privilege / cost abuse | `api` onRequest anthropic branch | high | mitigate | Live org-doc read (not claim-trust) fails closed (403 disabled, 503 on read error) before any billed call — the real security boundary (Task 3). |
