<objective>
Build the `slideGroups` Pinia store: an org-scoped live subscription plus the deterministic-id CRUD
actions every later plan calls — materialize-if-missing (which also performs the D-05 media
migration), delete (the R029 cascade target), bed-media write, and slide-array replace.

Purpose: this is the only module in the phase that talks to Firestore about groups. Keeping every
group write behind it is what stops a second, competing save path from appearing next to
`ServiceEditorView`'s existing whole-document autosave (R018).
Output: a store that mirrors `importedSlides.ts` structurally, with its own test file.
</objective>

  <action>
Add three more actions to the store.

`deleteGroup(orgId: string, slotId: string): Promise<void>` — a plain `deleteDoc` against
`doc(db,'organizations',orgId,'slideGroups',slotId)`. This is the R029 cascade target that 24-06
calls. Firestore's `deleteDoc` on a missing document is a no-op, so no existence guard is needed;
state that in a comment so nobody adds a defensive `getDoc`.

`setGroupBedMedia(orgId, slotId, patch: { serviceId: string; bedAudioUrl?: string; bedVideoUrl?: string; clearAudio?: boolean; clearVideo?: boolean }): Promise<void>` —
`getDoc` first. If the document exists, `updateDoc` with only the requested bed field(s) plus
`updatedAt: serverTimestamp()`, using `deleteField()` as the value for any field whose corresponding
`clear*` flag is set. If it does not exist, `setDoc` a skeleton (`id`/`slotId` = slotId, `serviceId`
from the patch, `slides: []`, the supplied bed field, both server timestamps) so that attaching media
to a slot whose group has not materialized yet cannot throw. Explicit clear flags are used rather than
"undefined means clear" because `stripUndefined()` would otherwise erase the intent before it reached
Firestore.

`replaceGroupSlides(orgId, slotId, slides: GroupSlideEntry[], sourceSignature?: string): Promise<void>` —
an `updateDoc` writing `slides`, `sourceSignature` (omitted when undefined) and `updatedAt`. This is
the apply half of reconciliation; the decision of WHETHER to apply lives in 24-03's pure functions and
24-05's composable, never here.

Resolve RESEARCH.md Open Question 1 explicitly in a store-level doc comment: a `GroupSlideEntry` whose
`audioScope` is `'group'` is persisted by the Phase 26 UI as a write to the PARENT group's
`bedAudioUrl` (via `setGroupBedMedia`) with the entry's own `audioUrl` cleared. The stored
`audioScope` value exists only so the drawer can round-trip the toggle's visual state; the assembler
never interprets it. This is the "single source of truth, zero ambiguity" option research recommended,
and it is being stated here rather than left implicit in code.

Add tests for the five behaviors above.
