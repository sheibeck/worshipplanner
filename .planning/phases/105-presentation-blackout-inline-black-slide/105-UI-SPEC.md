# Phase 105 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Scope note

This phase touches ONE new authoring surface (an "Insert black slide" affordance inside
`SongLyricEditor.vue`'s existing Sections list) plus the read-only rendering fallout of that new
content kind across the app's existing generic slide pipeline (`SlideCanvas.vue`,
`PresentationViewer.vue`/in-app preview, `SlideCard.vue` in the read-only Slides tab grid). The
runtime "Go to black" fix (R305) is a pure suppression change in `ConfidenceOutputView.vue` — it
removes chrome, adds none, and requires no design contract of its own; it is confirmed here as a
non-surface (see "Go to Black — Confirmed No New UI" below) so the checker has an explicit record
rather than a silent gap.

No shadcn / component registry in this project (`components.json` absent, Tailwind v4 CSS-first,
no `tailwind.config.*` — verified by direct scan). Every token below is reverse-engineered from the
existing hand-rolled dark theme in `SongLyricEditor.vue`, `SlideCanvas.vue`, `AudienceOutputView.vue`,
`ConfidenceOutputView.vue`, and `slideDisplay.ts`. Nothing here introduces a new color, size, or
spacing primitive — every value is reused verbatim from those files.

## Typography

**Scope note:** the blackout slide renders NO text at all (that is the whole point of R303), so this
phase introduces almost no new type. The only NEW text this phase adds is a small set of muted
"black slide" captions in the editor/preview (so a blackout row never reads as broken/empty). That NEW
subset is the design contract audited here — and it fits within 4 sizes / 2 weights:

| NEW text (in scope) | Size | Weight | Line Height |
|------|------|--------|-------------|
| Row preview caption ("Solid black — no text or image") | 11.5px (`text-[11.5px]`) | 400 | default |
| Row line-count replacement ("no text") | 10.5px (`text-[10.5px]`) | 400 | default |
| Slide-card body caption | 12px (`text-[12px]`) | 400 | default |

→ **3 sizes {10.5, 11.5, 12}px, 1 weight {400}** — within the 4-size / 2-weight caps.

**Pre-existing chrome (inherited verbatim, NOT re-audited here):** the blackout row reuses the existing
`LABEL_CHIP_CLASSES` label chip, the `add-section-chip-*` button, and `SlideCard.vue`'s content/footer
labels exactly as they already render for every other slide — their sizes/weights are app-wide values
outside this phase's control, listed for reference only, not part of this phase's typography contract.

No new heading/display sizes are introduced — the blackout slide renders NO text at all on
Audience/Confidence/in-app-preview/print (that is the entire point of R303); typography only
applies to the editor's chrome-level row labeling, not slide content.

## Color

Reused verbatim from the existing dark palette (gray-900/gray-800 base, indigo-500/600 accent,
red-600/900 destructive). No new hex values.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `gray-900`/`gray-950` (Tailwind default) | App shell, row card backgrounds, slide-canvas root |
| Secondary (30%) | `gray-800`/`gray-700` | Row borders, chip backgrounds, action buttons |
| Accent (10%) | `indigo-500`/`indigo-600`/`indigo-300` | Expanded-row border/chip highlight (existing `LABEL_CHIP_CLASSES.expanded`), focus rings |
| Destructive | `red-600`/`red-900` (existing `Remove`/`Delete` styling) | Unused by this phase — a black slide's Remove/Delete/Duplicate controls are the SAME shared row buttons already styled destructive/neutral; nothing new to declare |
| Blackout content | `#000000` (pure black, `bg-black`) | The rendered slide itself on Audience/Confidence/preview/print — no gray tint, no scrim, no gradient |

Accent reserved for: the SAME elements it is already reserved for app-wide (expanded-row chip/border,
focus rings, primary actions) — the new "Black Slide" add-chip explicitly does NOT use indigo/accent
styling; it uses the same neutral chip style every other `ADD_SECTION_KINDS` chip uses
(`border-gray-700 bg-gray-800 text-gray-300`, hover `hover:border-indigo-600 hover:text-indigo-300`
— unchanged, shared hover treatment). No new accent usage is introduced.

**Blackout row chrome (new, but drawn only from existing row-chrome primitives):** the row itself
uses the SAME `ROW_CARD_CLASSES` shape as every other row (`ordinaryCollapsed`/`ordinaryExpanded`),
so a blackout row is visually a normal row card. The distinguishing element is a small solid-black
swatch preview (`bg-black`, `border border-gray-700`) in place of the lyric preview text — see Visual
Contract below.

## Visual Contract — SongLyricEditor.vue row (new "Black Slide" row)

Match the EXISTING row markup exactly (`section-row` div, `rowCardClass(row)`, header row with
drag handle + label chip + actions + chevron) — the only new branch is what renders in place of the
lyric preview span and the expanded textarea/split-divider block:

**Collapsed header row** (identical structure/spacing to a lyric row):
- Position number, drag handle — unchanged.
- Label chip — same `LABEL_CHIP_CLASSES` component, text reads `BLACK SLIDE` (or numbered).
- In place of `row-preview` (lyric text truncated span): a small solid-black swatch,
  `inline-block h-3 w-3 shrink-0 rounded-sm bg-black border border-gray-700`, immediately followed
  by the muted caption `Solid black — no text or image` (`text-[11.5px] text-gray-400`, same class
  as the lyric preview span it replaces — same slot, same truncation behavior).
- In place of `row-line-count` ("N lines"): the caption `no text` (`text-[10.5px] text-gray-500`,
  identical classes to the lyric row's line-count span).
- Duplicate / Remove buttons (when expanded) — UNCHANGED, same classes, same confirm-dialog flow.
- Expand/collapse chevron — UNCHANGED.

**Expanded body** (in place of the textarea + slide-split block): a single, calm placeholder panel
reusing the same container treatment as the collapsed swatch, scaled up — `rounded-md border
border-gray-800 bg-black px-3 py-6 flex items-center justify-center` containing the caption `This
slide renders solid black — no text, background, or label.` (`text-[12px] text-gray-500`). No
textarea, no slide-split UI (a black slide has no lines to split). This is the ONLY new visual
element this phase introduces; it borrows its border/radius/padding from the existing
`row-split`/`row-shared-text` panels (`rounded-md border border-gray-800 bg-gray-950/40 px-2
py-1.5` family) with the background swapped to pure black to signal content, not just chrome.

**Add-section row:** append one chip, `Black Slide`, styled identically to the six existing
`ADD_SECTION_KINDS` chips — no color/size deviation. Clicking it calls `onAddSection('BLACKOUT')`
(new kind literal, mapped in `songSectionOrder.ts::addSection` to mint `kind: 'blackout'`,
`lines: []`, label `Black Slide`) and auto-expands the new row exactly like every other add-chip
already does (existing `onAddSection` auto-expand behavior, unchanged).

**Drag/reorder, Duplicate, Remove:** no new UI — all three already operate purely on
`performanceOrder`/`orderSlotIds`, agnostic to row content (confirmed in `ARCHITECTURE.md`). A
blackout row drags, duplicates, and deletes with the identical handle/buttons/confirm-dialog as
every other row. Duplicating a split section that contains a blackout row copies the whole unit,
per R304 — no special-cased duplicate UI.

## Visual Contract — Rendering surfaces (Audience / Confidence / in-app preview / print)

**Content contract (R303, locked by CONTEXT.md — keep dead simple):**
- Full solid black (`#000000`), no lyric text, no background image, no scrim, no organizational
  label, no position number, no "BLACK SLIDE" chrome of any kind.
- Instant — no fade/transition. No owner-visible chrome distinguishes it from the existing full-bleed
  black root each of these surfaces already paints (`bg-black` on `AudienceOutputView.vue`'s root,
  `ConfidenceOutputView.vue`'s root, `PresentationViewer.vue`'s root) — a blackout slide is
  achieved by rendering NOTHING inside `SlideCanvas.vue`'s per-kind chain for `contentKind ===
  'blackout'` (no new template branch content, matching the "pure black fill, no text" instruction
  in ARCHITECTURE.md), letting the parent's existing black background show through unchanged.
- Participates in normal next/prev navigation — no new nav control, no new keyboard shortcut. This
  is a slide like any other in the deck.
- Still honors `audioUrl`/`audioLoop` exactly like every other slide kind (SlideCanvas's audio/video
  wiring is unconditional on `contentKind`) — a bed track can still play under a black interlude
  slide; no new UI for that, it is the existing per-slide audio attachment mechanism unchanged.
- Confidence monitor's own suppression rules (`suppressBackground`, dual-pane current/next layout)
  apply unchanged — a blackout slide in the CURRENT pane shows the pane as solid black with no
  "Next" label change; the NEXT pane preview (scaled 0.8, per existing `confidence-next-region`)
  shows the SAME solid black if the upcoming slide is also a blackout slide, so the operator can see
  a black slide is coming next exactly as they'd see any other slide type preview.

**Slides tab read-only grid card (`SlideCard.vue`), read-only mirror of the song's slide order:**
- Preview pane background: `bg-black` (in place of the default `bg-grey-950/40`) for a blackout
  slide only — makes the card itself preview literally what will project.
- Content label (top-left, existing `slide-card-content-label` slot): `BLACKOUT`.
- Body area: the muted caption `Solid black` in place of the lyric/scripture body text (no
  `line-clamp-6` text block needed — one short caption, same font/color as the existing `slide-card-body`
  paragraph: `text-[13px] text-gray-200`, but centered rather than left-aligned top-padded, since
  there's no multi-line content to clamp).
- Footer kind badge / label: unchanged position, reads `Black Slide` via `slideFooterLabel`.
- No Edit affordance beyond the existing shared 3-dot menu (Edit details / Edit in song / Duplicate
  / Delete) — a blackout slide's "Edit details" still routes to the Song Lyrics editor, same as any
  other lyric-sourced slide (P-03: lyric/copyright-sourced entries never get Duplicate/Delete in
  THIS menu — those actions live in the editor's own row, unchanged).

**Print/export path:** confirmed no change — the print/text-only order-of-service surface never
renders slide *content* today (ARCHITECTURE.md, verified: it lists sections/songs/scripture
references, not projected text), so a blackout slide requires no new print treatment. If a future
print path DOES render slide content, it must show solid black with no label — noted here so a
later implementer doesn't silently render `[Black Slide]` as printed text.

## Go to Black — Confirmed No New UI (R305)

Per CONTEXT.md and ARCHITECTURE.md's recommended Option B, this fix removes chrome only:

- `ConfidenceOutputView.vue`'s existing `v-if="blackout"` overlay block
  (`confidence-blackout`, `absolute inset-0 bg-black`) is deleted or gated permanently false — no
  replacement element, no new visual state.
- `AudienceOutputView.vue`'s equivalent overlay (`audience-blackout`) is UNCHANGED — audience-only
  blackout keeps working exactly as today.
- `RunHeader.vue`'s blackout toggle button (`run-blackout-toggle`, labels `Go to black` / `Clear
  black`) is UNCHANGED — same wiring (`postBlackout(!blackout)`), same active-state styling
  (`.run-blackout--active`). No relabel is required by R305 itself; an optional discretionary
  relabel to "Blackout audience" is NOT required and is left to the executor's judgment, not
  mandated by this contract.
- No new control, no new indicator, no new copy anywhere in the Run screen. The confidence monitor
  simply keeps showing whatever `currentSlide`/`nextSlide` already resolve to during a runtime
  "Go to black" — including rendering pure black if the actual authored current slide IS a blackout
  slide (R303's content black, not R305's runtime black) — CONTEXT.md's explicit distinction, worth
  restating here as the design contract's own confirmation: these are two different reasons for the
  same pixel color, and only one of them (content) should ever paint the confidence monitor black.
