<objective>
Scaffold `render-service/` — the standalone Cloud Run project this phase adds — and author its
Dockerfile so that R062 criterion 3 (metric-compatible open fonts only, never Microsoft fonts) becomes
a **testable gate rather than an intention**.

Purpose: R062 exists because Firebase Functions buildpacks cannot install LibreOffice and Poppler. That
forces a custom-Dockerfile Cloud Run service. This plan creates that project and locks its font policy
behind a test that runs with no Docker daemon and no cloud access.

Output: `render-service/` with its manifest, TypeScript and Vitest configs, ignore files, the Dockerfile,
a fontconfig alias file, and `src/dockerfile.test.ts`.

**This plan builds nothing and deploys nothing.** The Dockerfile is authored and asserted as text.
</objective>

    Write `render-service/Dockerfile` as a **two-stage** build. Research's single-stage sketch is not
    usable as written: it runs `npm ci --omit=dev` and then `npm run build`, but `typescript` is a
    devDependency, so `tsc` would be absent. Fix that with stages.

    Builder stage — `FROM node:22-bookworm-slim AS builder`, `WORKDIR /app`, `COPY package*.json ./`,
    `RUN npm ci` (full deps, so `tsc` exists), `COPY tsconfig.json ./`, `COPY src ./src`,
    `RUN npm run build`.

    Runtime stage — `FROM node:22-bookworm-slim AS runtime`. One `RUN apt-get update && apt-get install
    -y --no-install-recommends` installing exactly: `libreoffice-impress`, `poppler-utils`,
    `fonts-crosextra-carlito`, `fonts-crosextra-caladea`, `fonts-liberation`, `fontconfig` — then
    `rm -rf /var/lib/apt/lists/*` in the same layer. `--no-install-recommends` is load-bearing, not
    style: without it a recommends chain can pull a font package in behind your back.

    Then `COPY fontconfig/60-metric-compat-aliases.conf /etc/fonts/conf.d/60-metric-compat-aliases.conf`
    followed by `RUN fc-cache -f`. Order matters — the cache must be rebuilt after the alias file lands.

    Then the font-provenance assertion, as its own `RUN`: a shell `if` that runs `dpkg -l`, pipes to
    `grep -qiE` for the Microsoft core-font package names (`mscorefonts|msttcorefonts`), echoes a FATAL
    message to stderr and `exit 1` when matched. This is the "assertion, not an intention" R062
    criterion 3 needs: it fails the build if a future base-image or transitive change ever bundles
    Microsoft fonts. It runs at build time; this run does not build.

    Then `WORKDIR /app`, `COPY package*.json ./`, `RUN npm ci --omit=dev`,
    `COPY --from=builder /app/lib ./lib`, `ENV HOME=/tmp` (Pitfall 3 — LibreOffice bootstraps a profile
    and the default `$HOME` is not guaranteed writable; `/tmp` is Cloud Run's guaranteed writable path),
    `ENV NODE_ENV=production`, `EXPOSE 8080`, `CMD ["node", "lib/main.js"]`.

    `lib/main.js` is compiled from `render-service/src/main.ts`, which plan 37-02 creates. That forward
    reference is deliberate and both plans must agree on the name.

    Write `render-service/fontconfig/60-metric-compat-aliases.conf` as a fontconfig XML document
    (`<fontconfig>` with `<alias binding="same">` entries) mapping family `Calibri` to prefer `Carlito`
    and family `Cambria` to prefer `Caladea`. 37-RESEARCH.md's Pitfall 2 and assumption A4 record that
    installing the packages makes the glyphs *available* but does not necessarily make LibreOffice
    *substitute* them — without this file, a Calibri deck can silently fall back to Liberation Sans,
    which is still not a Microsoft font but is visually wrong. Shipping the alias file closes A4.

    Write `render-service/src/dockerfile.test.ts` using `node:fs` `readFileSync` against
    `render-service/Dockerfile` resolved relative to the test file. Structure it around a helper that
    (a) strips comment-only lines matching `/^\s*#/`, and (b) extracts the runtime stage's
    `apt-get install` argument list by joining backslash-continued lines and taking the tokens after
