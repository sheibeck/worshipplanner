<objective>
Give the volunteer a passwordless sign-in completion flow, a persistent session with explicit sign-out, and a
route surface that does NOT participate in the org-member church-picker gate. Session/identity plumbing reuses
the existing `auth.ts` listener; this plan adds only the email-link request/completion helpers, two thin
volunteer views, and the router exemption.

Purpose: R374 (passwordless sign-in) and R376 (persistent session + sign-out + uid attribution). The single
most important non-obvious wiring fix is the router org-selection exemption (Pitfall 1) — without it a
successfully signed-in volunteer bounces to an empty /select-church picker.
Output: `volunteerAuth` store, the completion + landing views, and the `isVolunteerRoute` router changes.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| emailed link -> browser | The link is a bearer credential; completion must bind to the correct email and not accept it from a URL param |
| volunteer session -> router | The router must route a non-member session to volunteer routes only and never strand it at the org picker |
| router guard vs data layer | Router separation is UI defense-in-depth ONLY; the enforced boundary is firestore.rules (Plan 125-01) |

## STRIDE Threat Register (ASVS L1; blocks on High)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-125-14 | Spoofing | session fixation via email passed in a URL param | medium | mitigate | Email lives only in `localStorage.emailForSignIn` or an explicit re-entry input; never read from a URL query param (Firebase documented pattern); unit-tested. |
| T-125-15 | Elevation of Privilege | router-level gating mistaken for the security boundary | high | mitigate | The router exemption is explicitly UI-only; the enforced boundary is firestore.rules (Plan 125-01), proven independently by the emulator suite regardless of any router code. Documented in-plan. |
| T-125-16 | Spoofing (cross-device) | a wrong/attacker email completes sign-in on re-entry | low | mitigate | `signInWithEmailLink` verifies the re-entered email against the link server-side; a mismatch fails auth (Firebase-enforced) — the app never trusts the entered email on its own. |
| T-125-17 | Elevation of Privilege | a volunteer session reaches a planner/editor route | medium | mitigate | Planner routes require membership/editor (existing requiresEditor / org-selection gate); a zero-membership volunteer is denied/redirected there — AND the data layer denies planner reads regardless (Plan 125-01). |
| T-125-SC | Tampering | supply chain (npm installs) | n/a | accept | No new packages (RESEARCH §Package Legitimacy Audit); firebase already installed. |
</threat_model>
