<objective>
Relocate the behavioral/architectural "how it works" narration out of the BACKEND source comments
(`functions/src/**`, `firestore.rules`, `storage.rules`) and into the `.planning/codebase/` map docs, then
shrink each source comment to a short pointer — the R318 sweep for the backend tree.

This plan owns every Bucket B handoff entry whose source path is `functions/src/**`, `firestore.rules`, or
`storage.rules` (~76 entries: the largest single file is `functions/src/index.ts`). It works the "Phase 109
Handoff" worklist in `108-COMMENT-INVENTORY.md` (lines ~6951-7272), which already names a target map doc
per entry (ARCHITECTURE / INTEGRATIONS / CONCERNS / STACK).

Purpose: per 109-CONTEXT.md, comments carry only what code cannot convey; multi-paragraph narration moves to
the map docs. Backend rules/functions comments are the highest-value relocations because their gates and
triggers are security- and cost-critical.
Output: updated map docs + shrunk backend source comments.

Dependency note: 109-03..109-05 also append to these four map docs. To avoid concurrent writes to the same
doc files, the R318 plans are serialized by wave (this plan is Wave 1); the dependency is doc-write
serialization, not content. This plan runs in parallel with 109-01 (which touches only CONVENTIONS.md +
CLAUDE.md).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| comment edit -> compiled backend | A malformed comment edit could delete a delimiter and change executable code (functions) or a rule clause. |
| relocated comment -> planning docs | Backend comments describe security gates and secret handling; relocating text could surface a secret. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-109-03 | Tampering | Block/JSDoc shrink dropping a delimiter -> invalid TS or a changed rule | high | mitigate | Comment-only diffs; preserve opener/closer per the 108 lessons; Task 3 type-check + app + rules suites must show no new failures. |
| T-109-04 | Tampering | firestore.rules / storage.rules comment edit altering a gate | high | mitigate | Rules-file edits are comment-only; Task 3 runs the Firestore-rules suite and requires zero new failures. |
| T-109-05 | Information disclosure | Relocating a comment that quotes a key/secret into a committed doc | medium | mitigate | Do not copy secret literals; relocate behavior narration only; spot-check relocated text for credentials before commit. |

No package-manager installs occur in this phase, so the supply-chain threat (T-{phase}-SC) does not apply.
</threat_model>
