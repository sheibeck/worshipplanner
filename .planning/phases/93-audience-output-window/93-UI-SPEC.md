# Phase 93 — UI Design Contract

> Visual and interaction contract for the **Audience Output Window** (`AudienceOutputView.vue`,
> `/present/audience/:serviceId?org=`). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This is a congregation-facing projection surface, not an app screen.** The default 60/30/10 /
> multi-size-typography heuristics are deliberately collapsed: the surface is edge-to-edge pure black
> with the current slide (rendered by `SlideCanvas`) and **exactly one** conditional operator
> affordance. Almost every "chrome" the checker normally looks for is *forbidden here by requirement*
> (R270). Read the Design Intent section before scoring against the six pillars.

---

## Design Intent (read first)

**What this window is:** a receive-only, chromeless render of the live service's current slide,
fullscreen, background image ON, zero operator chrome, cursor hidden, awake for the whole service,
recovering gracefully from fullscreen loss. Requirements **R270, R271**.

**Composition (locked by CONTEXT.md):**
- `<SlideCanvas :slide="currentSlide" :interactive="false" />` — background **ON** (do NOT pass
  `suppressBackground`; that is Phase 94's confidence monitor). `SlideCanvas` owns all per-slide
  rendering, the background layer + scrim, media playback, and its own render-pending / render-failed
  states. This spec does **not** re-specify anything `SlideCanvas` already renders.
- The view root is a full-bleed `fixed inset-0 bg-black` surface (project convention, e.g.
  `AppShell.vue`, `PresentationViewer.vue`), carrying the same `--slide-font-*` typography CSS-var
  wrapper `PresentationViewer.vue` sets (so `SlideCanvas`'s scoped per-element font rules inherit
  correctly), and running the same bounded `slideTypography.ts` font-load gate before first paint.

**Deliberate divergences from `PresentationViewer.vue`** (flag these to the checker as *intentional*,
not omissions — see Checker Notes):
1. **No exit button, no nav chevrons, no progress pill, no `registerActivity` mousemove-reveal chrome.**
   The output is receive-only; navigation lives only in the control window (Phase 95). (R270, Pitfall 19)
2. **No spinner / "Loading slideshow…" text.** The loading and empty states are **pure black, zero
   elements** — a projector must never flash a spinner or copy at a congregation. (Divergence rationale
   below.)
3. **`cursor: none`** over the whole surface while fullscreen (R270) — restored only in the
   fullscreen-loss recovery state so the operator can click the re-enter affordance.
4. **Fullscreen loss NEVER tears down the session.** No `handleFullscreenChange → exitPresentation()`.
   On loss, keep the slide live underneath and surface the single re-enter affordance only. (Pitfall 6)

## Spacing Scale

Tailwind's default scale (all multiples of 4). This surface uses almost no spacing — the only
spaced element is the re-enter affordance.

| Token | Value | Usage |
|-------|-------|-------|
| sm | 8px | Icon → label gap inside the re-enter affordance (`gap-2`) |
| md | 16px | Re-enter affordance horizontal padding (`px-4`) |
| lg | 24px | Re-enter affordance vertical rhythm / min touch height backstop |

Exceptions: the re-enter affordance must meet a **44px minimum touch target** (`min-h-11 min-w-11`,
matching `PresentationViewer.vue`'s exit/nav buttons) even though 44 is not on the 4-scale midpoints —
this is an accessibility floor, not a spacing-scale value.

## Typography

The **slide body typography is owned entirely by `SlideCanvas.vue`** (its scoped `--slide-font-*`
rules: `text-5xl`/`text-6xl` lyric/scripture/text/copyright, etc.) and is NOT re-declared here. The
only typographic element this view introduces is the re-enter affordance label.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Re-enter affordance label | 16px (`text-base`) | 500 (`font-medium`) | 1.5 (normal) |
| Slide content | (owned by `SlideCanvas` — not re-specified) | — | — |

Rationale: 16px/medium is calm and legible from the booth without shouting; it is the app's standard
control-affordance label weight and deliberately *not* the large `text-4xl` presenter loading heading
(this affordance may be congregation-visible during a degraded windowed state, so it stays quiet).

## Color

This is a **pure-black projection surface**; the 60/30/10 split does not apply. There is exactly one
non-black element (the re-enter affordance). No dark-mode toggle concern — the surface is black by
construction, independent of app theme.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (100%) | `#000000` (`bg-black`) | The entire surface: view root, loading state, empty state, and the underlay behind the live slide |
| Accent | `bg-gray-900/80` + `text-gray-100` (calm neutral) | The re-enter affordance surface + label ONLY |
| Destructive | not used | No destructive actions in this phase |

Accent reserved for: **the fullscreen re-enter affordance surface only.** Deliberately a calm neutral
(`gray-900/80` translucent panel with `backdrop-blur-sm`), **NOT** the app's indigo action accent —
this affordance appears in a degraded, possibly congregation-visible state and must read as calm
recovery, not an alert. No red, no amber at the view level. (Note: `SlideCanvas`'s inherited
render-failed state uses amber per `42-UI-SPEC.md`; that is its contract, not this view's.)

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (re-enter affordance) | **`Re-enter fullscreen`** |
| Empty state heading | *(none — pure black, no text)* |
| Empty state body | *(none — pure black, no text)* |
| Error state | *(none at the view level — see below)* |
| Destructive confirmation | not applicable (no destructive actions) |

**Re-enter affordance copy details:**
- Visible label: `Re-enter fullscreen`
- `aria-label`: `Re-enter fullscreen`
- Icon: inline SVG "expand/maximize" arrows (heroicons `arrows-pointing-out` style), `aria-hidden="true"`,
  placed before the label with an 8px gap.

**Empty / loading copy — deliberately blank.** Before slides assemble AND before the first `RunState`
arrives (and while the font gate holds), the surface is **pure black with zero elements**. Rationale:
this is congregation-facing; a spinner, "Loading…" text, or org label on the projector reads as broken.
Pure black is indistinguishable from an intentional pre-service blackout and is the calmest safe state.
This is an explicit divergence from `PresentationViewer.vue`'s spinner + "Loading slideshow…" heading.

**Error state — none surfaced by this view.** Channel-subscription failure, wake-lock absence/rejection,
and fullscreen-request rejection are all handled **silently** (feature-detected / try-caught) per
CONTEXT.md and the pitfalls — never a toast, never on-screen error text on the projector. The only
"error-shaped" states a congregation could see are `SlideCanvas`'s own inherited **render-pending**
("This slide is still rendering.") and **render-failed** ("This slide couldn't be rendered.") slides —
those belong to `SlideCanvas` (`42-UI-SPEC.md` / Phase 90) and are intentionally reused as-is.

## Interaction Contract — the re-enter affordance (the ONLY interactive element)

| Property | Specification |
|----------|---------------|
| **Trigger to show** | `document.fullscreenElement === null` (i.e. NOT in fullscreen). Hidden whenever fullscreen is active. |
| **Placement** | Centered on both axes over the live slide (`absolute inset-0 flex items-center justify-center`). Center maximizes operator findability from the booth under pressure. |
| **Underlay** | The current slide stays **live and visible** underneath (no full scrim) — slides keep advancing while windowed (Pitfall 6). The operator retains context that content is still running. |
| **Appearance** | A single rounded-full pill: `bg-gray-900/80 backdrop-blur-sm text-gray-100`, `px-4`, `min-h-11 min-w-11`, expand icon + `Re-enter fullscreen` label with `gap-2`. High enough contrast to find, calm enough not to alarm. |
| **Behavior** | On click, call `requestFullscreen()` **synchronously in that click handler** (Pitfall 5 — only a gesture *in this window* can re-enter). No `await` before the call. |
| **Cursor** | While fullscreen: `cursor: none` over the whole surface (R270). While NOT fullscreen (recovery state): restore the cursor (`cursor: auto`/pointer) so the affordance is actually clickable — hiding the cursor here would strand the operator. |
| **Never** | Never tears down the session, never touches the confidence output, never navigates/unmounts the window, never closes the run channel. Losing fullscreen is a windowed-but-live state, not an exit. |

## UI Considerations

Applicable state considerations resolved: **6 covered, 1 backstop, 0 unresolved.**

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | slides assembled but empty, or `index` out of range | ✅ covered | Renders pure black, zero elements (see Copywriting — deliberately blank). `currentSlide = slides[index] ?? null`; `SlideCanvas` renders nothing when `slide` is null. |
| loading | pre-assembly / pre-first-`RunState` / font-gate holding | ✅ covered | Pure black, zero elements until slides + first `onState` index + font gate all resolve. No spinner, no copy. |
| populated | a valid current slide | ✅ covered | `<SlideCanvas :slide="currentSlide" :interactive="false" />`, background ON. |
| error (recovery) | fullscreen lost | ✅ covered | Single centered calm `Re-enter fullscreen` affordance over the live slide; cursor restored; session untouched (Interaction Contract). |
| error (slide render) | render-pending / render-failed slide | ✅ covered | Delegated to `SlideCanvas`'s existing inherited states (`42-UI-SPEC.md`); not re-specified. |
| error (silent) | channel/wake-lock/fullscreen-request failure | ✅ covered | Feature-detected / try-caught silently; no on-screen error ever painted to the congregation. |
| long-text / overflow | very long lyric/scripture slide text | 🧪 backstop | Slide text sizing/overflow is `SlideCanvas`'s contract; true full-bleed projection legibility is only provable on real hardware → human UAT (deferred per CONTEXT.md `<specifics>`). Lifts as `{ statement, verification: backstop }`. |

## Checker Notes (intentional divergences — do NOT flag as defects)

The following are **requirement-driven** and correct for this surface; scoring them against the
generic six-pillar defaults would be a false positive:

1. **No CTA-rich chrome / near-empty Copywriting table.** R270 forbids operator chrome. The single CTA
   (`Re-enter fullscreen`) is the *only* permitted interactive element, shown *only* on fullscreen loss.
2. **Blank empty/loading copy.** Pure black with no text is the specified, safest congregation-facing
   state — an intentional divergence from `PresentationViewer.vue`'s spinner + heading.
3. **Single-color "palette."** Pure black + one calm neutral affordance is by design; there is no
   60/30/10 to satisfy on a projection surface.
4. **Slide typography absent from the table.** It is owned by `SlideCanvas.vue` and must not be
   duplicated here.

## Risks to scrutinize (FLAG for review / human UAT)

- **FLAG — cursor toggle correctness:** `cursor: none` while fullscreen but restored when windowed. If
  the implementation hides the cursor unconditionally, the operator cannot click `Re-enter fullscreen`
  and the recovery path is dead. Verify the cursor is available whenever the affordance is shown.
- **FLAG — affordance findability vs. calm:** the re-enter pill is deliberately quiet (`gray-900/80`,
  not accent). Confirm on real hardware it is still findable from the booth under live pressure without
  reading as an alert. (Human UAT — deferred.)
- **FLAG — congregation-visible degraded state:** when fullscreen is lost the window is windowed WITH
  browser chrome already showing; the affordance overlays a live slide the congregation may see.
  Confirm the calm treatment is acceptable and the live-underneath behavior (not a black scrim) is the
  intended look. (Human UAT — deferred.)
- **FLAG — no auto-teardown:** verify `fullscreenchange → null` does NOT call any exit/unmount/close
  path (Pitfall 6). This is the single most dangerous copy-paste risk from `PresentationViewer.vue`.
