<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| URL `?tab=` → client tab state | The `tab` query value is attacker-controllable (any string via a crafted/shared URL) and drives client-side pane selection. |
| client → Firestore / callable (unchanged) | Existing super-admin-gated roster onSnapshot, appConfig subscription, and setSuperAdminClaim callable — relocated, not modified this phase. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-72-01 | Tampering | `?tab=` query param → `activeTab` | low | mitigate | `normalizeTab()` whitelists the value to exactly `'configuration' \| 'organizations'`; any other value (including injected/malformed strings or arrays) falls back to `'configuration'`. The value is never rendered as HTML or used in a lookup/eval — only in `===` comparisons — so there is no reflected-XSS surface. |
| T-72-02 | Elevation of Privilege | Direct navigation to `/owner-console?tab=organizations` | low | accept | Not a new bypass vector — the query is read only AFTER the existing `requiresSuperAdmin` router guard (R177/R178) has resolved for the underlying route; a non-super-admin never reaches OwnerConsoleView's `<script setup>` regardless of query string. No new gate/claim/rule/callable is introduced this phase. |
| T-72-SC | Tampering | npm/pip/cargo installs | n/a | accept | No package installs this phase — `vue-router` is an existing, already-vetted project dependency (RESEARCH Package Legitimacy Audit); no new supply-chain surface, so no legitimacy checkpoint applies. |
</threat_model>
