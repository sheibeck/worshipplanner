<objective>
Extend the existing super-admin-gated `listOrganizations` callable and the Organizations tab's list table so
every church row distinguishes ACTIVE members (have logged in -- `organizations/{orgId}/members` docs) from
PENDING invitees (onboarded/assigned by email but never logged in -- live `organizations/{orgId}/invites`
docs, deleted on first-login claim). Purely additive visibility; no change to onboarding, invite writes, or
the invite-to-first-login claim flow. Implements R222, R223.

Purpose: today an onboarded-but-unclaimed admin reads as "0 members," indistinguishable from a genuinely
empty church. The super-admin needs to see at a glance whether an invited admin has actually claimed their
login yet.

Output: `OrgSummary.pendingCount` computed server-side alongside the existing `memberCount`, rendered as an
accessible "N pending" badge in the Organizations tab's Members cell. Ships built + tested + UNDEPLOYED --
the exact `firebase deploy --only functions:listOrganizations` command is handed to the owner (see
`<success_criteria>`); the client half needs no deploy.
</objective>
