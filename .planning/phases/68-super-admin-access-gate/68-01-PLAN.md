<objective>
Establish the shared read-merge-write claim helper (`functions/src/claimsHelpers.ts`) and refactor BOTH blind-write call sites in `orgMembershipClaims.ts` onto it, closing the claim-replace / claim-wipe hazard (R175).

This is the correctness foundation of Phase 68 and it lands in Wave 1 — before the new `superAdmin` claim is introduced (Plan 02) — so the merge-safety fix can never lag the new claim it protects. Today's `setCustomUserClaims(uid, decision.claims)` REPLACES the whole claims object, and `setCustomUserClaims(uid, null)` WIPES it entirely; either would silently strip a granted `superAdmin` the next time any org-membership document is touched (which happens constantly in production).

Identity-model note (settled, add-alongside): `superAdmin` is a SEPARATE app-wide authority axis, orthogonal to per-org `{ orgId, role }` — a user may be a super-admin, an org editor, both, or neither. This plan's regression tests encode that orthogonality: they go red if a future change ever reconflates the two axes.

Purpose: Every custom-claim writer this app ever adds inherits claim-survival safety by routing through one helper (R175).
Output: `claimsHelpers.ts` (+ unit test) and a behavior-preserving `orgMembershipClaims.ts` refactor with a both-directions regression test.
</objective>
