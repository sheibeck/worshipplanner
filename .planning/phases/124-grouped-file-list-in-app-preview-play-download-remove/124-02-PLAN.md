<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| denormalized downloadUrl | The modal iframe `src` and the inline `<audio>` `src` both read `attachment.downloadUrl`, a Storage download-token (bearer) URL embedded in the DOM. |
| embedded PDF render surface | The iframe renders remote PDF bytes inside the app origin's overlay. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-124-04 | Information Disclosure | downloadUrl bearer token in iframe/audio/Download | low | accept | Identical exposure to every existing media downloadUrl in the app — a capability URL readable by anyone holding it. Signed/short-lived read URLs for anonymous playback are explicitly a Rehearse-milestone concern per REQUIREMENTS.md; this milestone's readers are authenticated org members. |
| T-124-05 | Tampering | remote PDF bytes rendered in the preview iframe | low | accept | The iframe renders the browser's native PDF viewer on an org-scoped, editor-uploaded, size/type-capped (R364, enforced in storage.rules) object; no app script trusts the PDF content. No new server surface is introduced. |
| T-124-06 | Denial of Service | Escape/backdrop handler leaking to the editing slideout | low | mitigate | The modal's Escape/backdrop/Close dismiss is scoped to the modal (dialog-root or open-gated window listener, removed on close/unmount) and must not reach SongSlideOver — a regression here could re-introduce the outside-click/Escape dismiss the recent quick-task deliberately removed from the slideout. Covered by the modal-dismiss tests. |
| T-124-SC | Tampering (supply chain) | npm/pip/cargo installs | n/a | accept | No new dependencies — preview uses a native `<iframe>` and play uses a native `<audio>` element (SEED-003 no-new-deps). No install tasks → no package-legitimacy gate required. |
</threat_model>
