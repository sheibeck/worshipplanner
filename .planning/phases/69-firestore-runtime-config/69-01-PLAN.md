## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| config writer → appConfig/global | The writer (Phase 70 form, or a hand-edited/compromised super-admin doc) is Phase-68-rules-gated for WHO may write, but the SHAPE they write is untrusted. `coerce*` is the validation boundary. |
| appConfig/global → getAppConfig (Admin SDK) | Server-trusted read; Admin SDK bypasses rules by design. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-69-01 | Elevation of Privilege | coerceAllowedModels | high | mitigate | A non-array/empty/malformed allow-list falls CLOSED to the restrictive default list; a bad doc can only narrow/break the allow-list, never widen it to "allow all models" |
| T-69-02 | Tampering | coercePositiveInt (deleteCapPerRun) | high | mitigate | 0 / negative / non-integer deleteCapPerRun is rejected and falls back to 500; the blast-radius cap cannot be turned into "unbounded deletes" via a config typo |
| T-69-05 | Tampering | coerceEnableFlag (cleanup + cron flags) | high | mitigate | Only a literal `true` enables; missing / "true"-string / 1 / null resolve to false (fail-closed dry-run/off) — a malformed flag can never silently enable deletion or the cross-org cron |
| T-69-03 | Information Disclosure | AppConfig schema | medium | mitigate | The schema defines only non-secret fields (sender.fromName/fromAddress); RESEND_API_KEY and all secrets are structurally excluded — the doc is client-readable by super-admins, so no secret may enter it |
| T-69-SC | Tampering | npm/pip/cargo installs | low | accept | Zero new packages this phase (RESEARCH Package Legitimacy Audit: N/A) — no supply-chain surface is added |
