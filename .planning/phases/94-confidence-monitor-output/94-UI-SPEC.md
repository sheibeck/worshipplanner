# Phase 94 — UI Design Contract

> Visual and interaction contract for the **Confidence Monitor Output Window**
> (`ConfidenceOutputView.vue`, `/present/confidence/:serviceId?org=`). Generated by gsd-ui-researcher,
> verified by gsd-ui-checker.
>
> **This is the worship band's glanceable stage-reference surface, not an app screen, and not the
> congregation projector.** It is the SIBLING of Phase 93's Audience Output Window and inherits that
> window's entire lifecycle + chrome contract *verbatim* — the ONLY visual divergence is the render
> body: a **current + next two-pane** layout with **both backgrounds suppressed to plain black**
> (R272). Every "chrome" the checker normally looks for is *forbidden here by requirement*. Read the
> Design Intent and the "Inherited from Phase 93" section before scoring against the six pillars.

---

## Design Intent (read first)

**What this window is:** a receive-only, chromeless render for the band/team on the stage confidence
monitor. It shows the **current slide** (dominant) AND the **next upcoming slide** (clearly
subordinate, labeled), fullscreen, with the actual **background image NEVER shown — both panes are
plain black** (`suppressBackground=true`). Zero operator chrome. Cursor hidden while fullscreen.
Awake for the whole service. Recovers gracefully from fullscreen loss. Requirement **R272**.

**Composition (locked by CONTEXT.md):**
- Two `<SlideCanvas>` instances, both with `:suppressBackground="true"` `:interactive="false"`:
  - **Current pane** — `:slide="currentSlide"`, the dominant element; drives media `play()/pause()`.
  - **Next pane** — `:slide="nextSlide"`, clearly subordinate + labeled; a **static preview** (does
    NOT autoplay the upcoming slide's media).
- `current = index == null ? null : (assembledSlideshow[index] ?? null)`;
  `next = index == null ? null : (assembledSlideshow[index + 1] ?? null)` — "next" is the next flat
  assembled slide, NOT a service-item lookup. A null/out-of-range index resolves to null (pure black),
  never a crash or a wrap-around.
- The view root is a full-bleed `fixed inset-0 bg-black` surface carrying the same `--slide-font-*`
  CSS-var typography wrapper `PresentationViewer.vue`/`AudienceOutputView.vue` set (so `SlideCanvas`'s
  scoped per-element font rules inherit), and running the same bounded `slideTypography.ts` font-load
  gate before first paint.

**`SlideCanvas` owns all per-slide rendering** (text, media, its own render-pending / render-failed
states). This spec does **not** re-specify anything `SlideCanvas` already renders. It specifies only
the two-pane *arrangement*, the "Next" label, the black-suppression invariant, and the shared chrome
inherited from Phase 93.

**Deliberate divergences from `PresentationViewer.vue`** (flag as *intentional*, not omissions):
1. **No exit button, nav chevrons, progress pill, slide counts, org labels, or `registerActivity`
   mousemove-reveal chrome.** Receive-only; navigation lives only in the control window (Phase 95).
   (R272, Pitfall 19)
2. **No spinner / "Loading…" text.** Loading and empty states are **pure black, zero elements**.
3. **`cursor: none`** over the whole surface while fullscreen; restored only in the fullscreen-loss
   recovery state so the operator can click the re-enter affordance.
4. **Fullscreen loss NEVER tears down the session** (no `fullscreenchange → exit`). (Pitfall 6)

## Render Body — the current + next two-pane layout (this phase's ONLY new visual)

This is the single element that distinguishes the confidence monitor from its Phase 93 sibling. Every
other section below is inherited.

### Structure & proportions

The band monitor is a landscape display; the band needs the **live** slide as large as possible with
the **upcoming** slide readable at a glance beneath it. Use a **vertical split, full-width panes**:

| Region | Placement | Size | Content |
|--------|-----------|------|---------|
| **Current pane** (dominant) | Top, full width | `flex: 7 1 0%` (~70% of height) | `<SlideCanvas :slide="currentSlide" :suppressBackground :interactive="false" />` |
| **Next pane** (subordinate) | Bottom, full width | `flex: 3 1 0%` (~30% of height) | `<SlideCanvas :slide="nextSlide" :suppressBackground :interactive="false" />` + "Next" tag |

- Root: `fixed inset-0 bg-black flex flex-col`. Current region grows 7, next region grows 3 — the
  current pane is ~2.3× the next pane's area, which reads unambiguously as dominant/subordinate while
  keeping the next slide's first line legible from the stage.
- **Full-width panes (not side-by-side).** Full width maximizes horizontal room for lyric/scripture
  text in BOTH panes; a left/right split would halve the live text width, the opposite of the
  glanceability goal.
- **Seam:** a single hairline divider between the two regions — `border-t border-white/10` (a
  near-black 10%-white seam) on the next region. It reinforces the "clearly distinguished" separation
  without introducing an accent color. This is the only non-black, non-label pixel in the render body.
- Each region is `relative flex items-center justify-center overflow-hidden` so its `SlideCanvas`
  centers and clips within its own band (a long slide in one pane never bleeds into the other).

### "Next" label treatment

R272 forbids operator chrome but the current/next distinction is *required*. The label serves the
band, not an operator, so it is minimal and calm:

- Copy: **`Next`** (rendered uppercase via CSS: `NEXT`).
- Placement: `absolute top-2 left-3` within the **next** region (corner-anchored so it never displaces
  the centered slide text).
- Treatment: `text-sm` (14px) `font-medium` `uppercase` `tracking-wide` `text-gray-500` — a quiet
  neutral, deliberately **NOT** the app's indigo accent and **NOT** a bright color; it whispers the
  distinction rather than competing with the slide.
- **The current pane carries NO label** — its size and top placement ARE its distinction. Only the
  subordinate pane needs naming. This keeps the surface as chrome-free as R272 demands.

### Last-slide case (no next slide) — must not crash, must not reflow

When `currentSlide` is the last assembled slide, `nextSlide` is `null`:
- The next region renders **pure black, zero elements** (`SlideCanvas` renders nothing for a null
  slide — the same null-safety Phase 93 relies on).
- The **"Next" tag is HIDDEN** when `nextSlide == null` (`v-if="nextSlide"`) — do not label an empty
  void "Next"; a labeled black strip reads as broken, an unlabeled one reads as "nothing coming,"
  which is the honest state.
- **The 70/30 layout regions stay fixed** regardless of whether a next slide exists. Do NOT collapse
  the next region on the last slide — collapsing would make the current pane suddenly grow on the
  final advance, a jarring resize in front of the band. Stable layout > reclaimed space for one slide.

### Media invariant on the two panes

- **Current pane drives media** exactly as Phase 93: a `watch(index)` sequence calls
  `currentCanvasRef.pause()` → `await nextTick()` → `currentCanvasRef.play()` on the CURRENT canvas
  only.
- **Next pane is a static preview** — never call `play()` on the next canvas. `:interactive="false"`
  already suppresses its autoplay-blocked affordances (Phase 90); do not autoplay the upcoming slide's
  video/audio. The band should not hear the next slide's audio nor see its video motion.

## Hard Invariant — backgrounds suppressed to black on BOTH panes (R272)

**Both** `SlideCanvas` instances MUST receive `suppressBackground="true"`. The actual background
image is NEVER shown on the confidence monitor, on either pane, under any condition. This is Phase
90's `suppressBackground` prop's **first real consumer** (it was wired but dormant): it is checked
FIRST in `SlideCanvas`'s `currentBackgroundUrl`, forcing `null` regardless of what the slide carries,
so no `presentation-background` element is emitted.

- **Testable invariant:** for both the current and next panes, the `presentation-background` element
  (and its `presentation-background-scrim`) MUST NOT render — assert their absence in unit tests.
- No exception for video slides: a video slide's background is suppressed like any other. (`SlideCanvas`
  still plays a *video slide's own source* on the CURRENT pane if present, per its Phase 90 contract;
  the suppression is of the *background* layer, not the slide's own video element. The NEXT pane plays
  nothing regardless.)

## Inherited from Phase 93 (identical — do NOT re-derive; keep visually identical across both windows)

The confidence window shares Phase 93's lifecycle core and MUST render these shared surface elements
**pixel-identically** to `AudienceOutputView.vue`. (CONTEXT.md floats extracting a shared
`useOutputWindow` composable — that is an implementation-structure call for the planner/pattern-mapper.
Whether extracted or duplicated, the shared elements below must stay visually identical across both
output windows.)

| Inherited element | Contract (verbatim from 93-UI-SPEC) |
|-------------------|-------------------------------------|
| **Pure-black loading/empty state** | Before slides assemble AND before the first `RunState` arrives AND while the font gate holds: pure black, zero elements. No spinner, no copy, no org label. |
| **Re-enter fullscreen affordance** | The ONLY interactive element. Shown ONLY when `document.fullscreenElement === null`. Centered pill: `bg-gray-900/80 backdrop-blur-sm text-gray-100`, `px-4 min-h-11 min-w-11`, expand icon + `Re-enter fullscreen` label, `gap-2`, `text-base font-medium`. Calm neutral, NOT the app accent. On click, `requestFullscreen()` synchronously (Pitfall 5). Overlays the live panes (no black scrim). |
| **Cursor toggle** | `cursor: none` while fullscreen; restored (`cursor: auto`) when windowed so the re-enter affordance is clickable. |
| **No auto-teardown on fullscreen loss** | `fullscreenchange → null` updates an `isFullscreen` ref ONLY. Never exit/unmount/close the channel. Losing fullscreen is a windowed-but-live state. (Pitfall 6) |
| **Silent failure handling** | Channel-subscription, wake-lock absence/rejection, fullscreen-request rejection: all feature-detected / try-caught silently. Never a toast, never on-screen error text. |
| **Font-load gate** | Bounded `Promise.race`-guarded `slideTypography.ts` gate before first paint; degrades to "render anyway" on timeout/rejection. |
| **SlideCanvas inherited states** | Render-pending ("This slide is still rendering.") and render-failed ("This slide couldn't be rendered.", amber) belong to `SlideCanvas` (`42-UI-SPEC.md`) and are reused as-is on the current pane. |

## Spacing Scale

Tailwind's default scale (all multiples of 4). This surface uses almost no spacing — only the "Next"
tag and the re-enter affordance are spaced elements.

| Token | Value | Usage |
|-------|-------|-------|
| sm | 8px | "Next" tag top inset (`top-2`); icon → label gap in the re-enter affordance (`gap-2`) |
| md | 12–16px | "Next" tag left inset (`left-3` = 12px); re-enter affordance horizontal padding (`px-4`) |
| lg | 24px | Re-enter affordance vertical rhythm / min touch height backstop |

Exceptions: the re-enter affordance must meet a **44px minimum touch target** (`min-h-11 min-w-11`,
matching Phase 93 / `PresentationViewer.vue`) even though 44 is not a 4-scale midpoint — an
accessibility floor, not a spacing-scale value. The 70/30 pane split is a flex-grow *ratio*, not a
spacing token.

## Typography

The **slide body typography is owned entirely by `SlideCanvas.vue`** (its scoped `--slide-font-*`
rules) and is NOT re-declared here. This view introduces exactly two typographic elements: the "Next"
pane tag and the inherited re-enter affordance label.

| Role | Size | Weight | Line Height | Notes |
|------|------|--------|-------------|-------|
| "Next" pane tag | 14px (`text-sm`) | 500 (`font-medium`) | 1.5 (normal) | `uppercase tracking-wide text-gray-500`; the ONLY new label this phase adds |
| Re-enter affordance label | 16px (`text-base`) | 500 (`font-medium`) | 1.5 (normal) | Inherited verbatim from Phase 93 |
| Slide content (both panes) | (owned by `SlideCanvas` — not re-specified) | — | — | Scales via `--slide-font-*` within each pane's flex box |

Rationale: the "Next" tag is one step *smaller* (14px) than the re-enter label (16px) and neutral-gray
— it must be the quietest text on the surface, present only to name the subordinate pane, never to
draw the eye off the live slide.

## Color

A **pure-black stage-reference surface**; the 60/30/10 split does not apply. There are exactly two
non-black elements (the "Next" tag and the re-enter affordance) plus one hairline seam.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (100%) | `#000000` (`bg-black`) | The entire surface: both panes' underlay, loading state, empty state, last-slide next region |
| Neutral label | `text-gray-500` | The "Next" tag ONLY |
| Neutral seam | `border-white/10` | The 1px divider between the current and next regions ONLY |
| Accent (recovery) | `bg-gray-900/80` + `text-gray-100` | The re-enter affordance surface + label ONLY |
| Destructive | not used | No destructive actions in this phase |

Accent/neutral reserved for: **the "Next" tag, the region seam, and the fullscreen re-enter affordance
— nothing else.** All three are calm neutrals; the app's indigo action accent and any red/amber are
deliberately absent at the view level (they'd read as an alert on a black stage surface). (Note:
`SlideCanvas`'s inherited render-failed state uses amber per `42-UI-SPEC.md` — that is its contract,
not this view's.)

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (re-enter affordance) | **`Re-enter fullscreen`** (inherited from Phase 93) |
| "Next" pane tag | **`Next`** (rendered uppercase → `NEXT`); hidden entirely when there is no next slide |
| Empty state heading | *(none — pure black, no text)* |
| Empty state body | *(none — pure black, no text)* |
| Error state | *(none at the view level — silent handling, see Inherited table)* |
| Destructive confirmation | not applicable (no destructive actions) |

**"Next" tag copy details:** visible label `Next` (uppercased by CSS). No `aria-label` requirement (an
output-only stage surface has no assistive-tech audience during a live show); if one is added for
consistency it should read `Upcoming slide`. Absent whenever `nextSlide == null`.

**Re-enter affordance copy:** visible label `Re-enter fullscreen`; `aria-label` `Re-enter fullscreen`;
inline expand SVG (heroicons `arrows-pointing-out` style), `aria-hidden`, 8px gap — identical to
Phase 93.

**Empty / loading copy — deliberately blank.** Pure black with zero elements until slides + first
`onState` index + font gate all resolve. A spinner or "Loading…" on a stage monitor reads as broken;
pure black is the calmest safe state (identical rationale to Phase 93).

**Error state — none surfaced by this view.** All failure modes handled silently (see Inherited
table). The only "error-shaped" states are `SlideCanvas`'s own render-pending/render-failed on the
current pane, reused as-is.

## Checker Notes (intentional divergences — do NOT flag as defects)

Requirement-driven and correct for this surface; scoring against the generic six-pillar defaults would
be a false positive:

1. **No CTA-rich chrome / near-empty Copywriting table.** R272 forbids operator chrome. The single CTA
   (`Re-enter fullscreen`) is the only interactive element, shown only on fullscreen loss. The "Next"
   tag is a required distinction label, not chrome.
2. **Blank empty/loading copy.** Pure black with no text is the specified, safest stage-facing state.
3. **Single-color "palette."** Pure black + two calm neutrals (the "Next" tag, the re-enter affordance)
   + a hairline seam is by design; there is no 60/30/10 to satisfy on a black projection surface.
4. **Slide typography absent from the table.** Owned by `SlideCanvas.vue`; must not be duplicated here.
5. **Two `SlideCanvas` instances with suppressed backgrounds.** The doubled canvas and the always-black
   background are the literal R272 requirement, not a rendering mistake.

## Risks to scrutinize (FLAG for review / human UAT)

- **FLAG — two-pane legibility on a real band monitor (Human UAT — deferred).** The core R272 UX risk:
  the next pane is only ~30% of a landscape monitor's height, and lyric/scripture text scales down to
  fit. On a physically small or distant stage monitor the upcoming slide's text may be too small to be
  glanceably useful. The 70/30 split is the design's best legibility/dominance tradeoff, but only real
  hardware with a real band proves it. Confirm both panes are readable from the stage; if the next pane
  is unreadable, revisit the split ratio (e.g. 65/35) or the next pane's own font scale — not the
  current pane's dominance.
- **FLAG — black-suppression invariant on BOTH panes.** The single most important R272 assertion. Verify
  `suppressBackground=true` is passed to BOTH canvases and that NO `presentation-background` /
  `presentation-background-scrim` element renders on either pane, for background-carrying AND video
  slides. A regression here leaks the congregation background onto the band monitor — the exact thing
  R272 forbids.
- **FLAG — last-slide next pane (no crash, no reflow).** Verify `nextSlide == null` renders the next
  region black with the "Next" tag hidden and NO layout reflow of the current pane, and that
  `assembledSlideshow[index + 1]` out-of-range never throws or wraps to slide 0.
- **FLAG — next pane must not autoplay media.** Verify the next `SlideCanvas` is never driven by
  `play()` and that `:interactive="false"` suppresses its autoplay affordances — the band must not hear
  the upcoming slide's audio or see its video motion.
- **FLAG — shared surface stays visually identical to Phase 93.** The loading state, re-enter
  affordance, and cursor behavior must match `AudienceOutputView.vue` pixel-for-pixel. If a
  `useOutputWindow` composable is extracted, confirm the extraction did not visually drift either
  window and that Phase 93's 18 tests stay green.
- **FLAG — cursor toggle correctness (inherited).** `cursor: none` while fullscreen, restored when
  windowed; if hidden unconditionally the operator cannot click `Re-enter fullscreen` and recovery is
  dead.
- **FLAG — no auto-teardown (inherited, Pitfall 6).** Verify `fullscreenchange → null` does NOT call any
  exit/unmount/close path — the most dangerous copy-paste risk from `PresentationViewer.vue`.
