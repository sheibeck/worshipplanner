<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| unauthenticated browser → orgSlugs/{slug} (client getDoc) | Public-read registry (ADR-0007); slug existence is not a secret |
| unauthenticated browser → requestVolunteerLink callable | The client invokes the public callable; all real gating lives server-side (plan 128-01) |
| minted link continue-URL query (slug) → request-new-link route target | Attacker-influenceable query value flows into route navigation |

## STRIDE Threat Register (ASVS L1; block on high)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-128-C1 | Information Disclosure | orgSlugs lookup / church-not-found + "find your church" | low | accept | orgSlugs is intentionally public-read (ADR-0007); slug validity carries no roster/membership info, so a direct "not found" is acceptable and reveals nothing about any volunteer. |
| T-128-C2 | Information Disclosure | VolunteerRequestView confirmation render | high | mitigate | The confirmation is one render path invoked on callable resolve regardless of the returned message; the UI never branches on roster status. Only a genuine transport rejection shows different (non-membership) copy. Asserted by the component test (R395). |
| T-128-C3 | Spoofing / open-redirect | slug from route.query.slug → request-new-link target | low | mitigate | The re-request target is built as a NAMED route with slug as a params value only — never used as a raw redirect URL or window.location assignment, so a crafted query cannot redirect off-app (R399, 128-RESEARCH Pitfall 5). |
| T-128-C4 | Tampering | client-supplied orgId/email to the public callable | high | mitigate (server) | No client-side trust is placed in orgId/email; all authorization (roster gate, rate limit, enumeration-safety, timing) is enforced server-side in plan 128-01. The client only forwards { orgId, email, slug }. |

Package legitimacy: N/A — this plan introduces zero new npm packages (vue-router, firebase/functions, firebase/firestore already installed). No supply-chain checkpoint required.
</threat_model>
