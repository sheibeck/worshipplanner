<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| editor browser -> Firebase Storage | Upload bytes cross to `orgs/{orgId}/song-files/{attachmentId}/…` (untrusted file content/type/size). |
| editor browser -> Firestore song doc | Attachment metadata (incl. external link href) written via `updateSong` onto the org-scoped Song document. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-123-01 | Tampering / Elevation | useSongFileUpload upload + updateSong write | low | mitigate | Client type/size checks are UX only; Phase 122 `storage.rules` enforce editor + `application/pdf`/`audio/mpeg` + ≤50MB server-side, and the metadata write goes through the editor-gated Song-doc `updateDoc` (Firestore rules). Bypassing the UI cannot write a disallowed/oversized object or a record as a viewer. |
| T-123-02 | Tampering (XSS / tabnabbing) | external link href (songLinks) | medium | mitigate | Accept only `https://` URLs (`new URL` + `protocol === 'https:'`); reject `javascript:` / `data:` / non-https. The consuming UI (123-03) opens links with `target="_blank" rel="noopener noreferrer"`. |

No package-manager installs occur in this phase; the package-legitimacy gate is not applicable.
</threat_model>
