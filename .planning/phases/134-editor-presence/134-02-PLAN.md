<objective>
Build the live presence experience for R422: a `useServicePresence` composable that
heartbeats the current user's presence doc (coarse ~30s, paused when the tab is
hidden), subscribes to the service's presence subcollection, filters stale viewers
client-side (~60s soft-TTL), and tears down correctly across BOTH an in-app
service→service route change (which reuses the mounted editor instance) and unmount
— plus the header indicator in ServiceEditorView and a fake-clock forced-disconnect
test proving stale presence clears without a graceful teardown.

Purpose: Firestore has no onDisconnect() (that is RTDB-only, and this app is
deliberately Firestore-only). The client soft-TTL is the real-time correctness
mechanism; the coarse, paused-when-hidden heartbeat is the v1.8 cost discipline
(this is a Blaze app with active cost hardening).
Output: `src/composables/useServicePresence.ts` + its test, and the ServiceEditorView
header indicator.
</objective>

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

Residual in-org display-name impersonation is accepted (same trust level as any org member). |
| T-134-06 | Denial of Service (cost) | heartbeat write volume | medium | mitigate | Coarse PRESENCE_HEARTBEAT_MS (~30s), one doc per viewer, PAUSED while `document.hidden` (Page Visibility) — the v1.8 cost-hardening discipline; proven by the paused-when-hidden test |
| T-134-07 | Integrity (stale state) | crashed/closed tab leaves a stale "present" doc | low | mitigate | Client soft-TTL (~60s) hides it immediately (forced-disconnect test), and the Plan 03 cron removes it eventually; Firestore has no onDisconnect |
