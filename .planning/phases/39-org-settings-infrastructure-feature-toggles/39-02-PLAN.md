<objective>
Establish the typed `OrgSettings` shape and its single defaults-merge point, and migrate
`vwModeEnabled`'s storage location behind a dual-read that cannot flip a deliberately-off church
back on.

Purpose: this is the infrastructure half of Phase 39, and it is a hard prerequisite for Phases 44
(default service template, R086), 45 (Bible version, R090) and 46 (slide typography, R093). Those
phases each add one field to `OrgSettings`/`DEFAULT_ORG_SETTINGS` and are done — they should never
have to re-solve loading, defaulting or type-safety.

Output: `src/types/organization.ts` (new), a `settings` ref on the auth store merged once in
`loadOrgContext`, and R073 regression coverage in `auth.test.ts`.

**Locked decisions honored** (39-CONTEXT.md § Implementation Decisions → OrgSettings Shape; the
file records decisions as prose bullets, not `D-NN` identifiers, so they are cited by phrase):
| Decision (verbatim phrase) | Where honored |
|---|---|
| "Nested `settings: {…}` sub-object on the organization document, not flat top-level fields" | Task 1 |
| "`vwModeEnabled` MIGRATES into `settings`" with read shape `settings?.vwModeEnabled ?? orgData.vwModeEnabled ?? true` | Task 2 |
| "Dual-read with lazy backfill — write the value into `settings` on the next org write, never a bulk migration script" | Task 2 (read side); 39-03 Task 3 (write side) |
| "One defaults-merge point: `auth.ts::loadOrgContext`" | Task 2 |
| "Components read one typed `settings` computed on the auth store, not one ref per setting" | Task 2 (the exported `settings` ref) |
| "Exact `OrgSettings` field names and the `DEFAULT_ORG_SETTINGS` constant's location" (§ Claude's Discretion) | Task 1 — resolved to `aiEnabled`/`pcEnabled`/`vwModeEnabled` in `src/types/organization.ts` |

**Deferred, and therefore NOT built here** (39-CONTEXT.md § Deferred Ideas): removing the flat
`vwModeEnabled` field. The dual-read must stay. Do not delete, deprecate, or stop reading the flat
field.

**Naming resolution the whole phase depends on:** `39-UI-SPEC.md`'s Hide-Don't-Disable table uses
the shorthand `authStore.aiEnabled`. That shorthand resolves to `authStore.settings.aiEnabled`.
No top-level `aiEnabled` or `pcEnabled` ref is created on the store — 39-CONTEXT.md locks
"one typed `settings` computed on the auth store, not one ref per setting."
</objective>
