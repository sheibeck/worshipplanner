<objective>
Enforce the AI toggle at the module entry point and hide the three AI affordances that depend on it.

Purpose: ROADMAP success criterion 2 is explicit that a `v-if` test does not satisfy it — "a direct
call into `claudeApi.ts` with the toggle off issues no network request — proven by a test at the
module entry point, not a `v-if`." This plan builds the guard that makes that true and the hiding
that makes it coherent. 39-CONTEXT.md also records the owner's forward-looking reason for wanting
one clean choke point: "If we need to gate this behind a paywall later to offset AI costs this is a
good starting point."

Output: a private guard in `claudeApi.ts` called by exactly three exports, module-entry-point proof
in `claudeApi.test.ts`, and three composed `v-if`s with component coverage.

**The 3-of-7 gating boundary is a hard constraint, not a simplification.** `39-RESEARCH.md` § Focus

|---|---|---|---|

| `validateSongSuggestions` | 122 | No — pure filter | **NO** |

Gating all seven would be a functional regression: the four pure helpers are exported and unit-
tested independently of the toggle, and a caller unrelated to AI would silently start receiving

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → Anthropic proxy endpoint | Every AI request crosses here. The toggle's whole purpose is that with AI off, nothing crosses. |
| A stale or manipulated client → `claudeApi.ts` exports | The exports are module-level functions callable from any component, from the console, or from a stale bundle whose UI still shows the removed affordance. |

## STRIDE Threat Register

Stable IDs shared across all Phase 39 plans. Rows below are in scope for this plan.

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-39-02 | Elevation of Privilege | `claudeApi.ts`'s three network-calling exports | high | mitigate | This is the anti-pattern the phase exists to avoid: a toggle that hides UI while leaving the code path callable. A stale client, a cached bundle, or any future component that imports the module directly would still reach the Anthropic proxy — spending the church's AI budget on a feature it turned off, and defeating the paywall gate 39-CONTEXT.md names as the toggle's eventual purpose. Mitigated by a single private guard called as the first statement of each of the three exports, so no entry point can forget it, and proven by a module-entry-point test asserting the SDK mock was never invoked. The three `v-if`s are the consequence, never the enforcement. **Blocking severity** — this row must be closed before the phase is considered done. |
| T-39-10 | Spoofing | the proving test itself (mocking the wrong transport) | high | mitigate | A test that stubs `fetch` would pass no matter what the guard does, because `claudeApi.ts` never calls raw `fetch` — it goes through the Anthropic SDK. A vacuously-passing security test is worse than none, because it converts an untested assertion into apparent evidence. Mitigated by reusing the existing `vi.hoisted` SDK mocks and asserting on those specific spies, and by resetting them between cases so "never called" cannot pass on a stale counter. This is CLAUDE.md's own recorded lesson applied forward. |
| T-39-11 | Tampering | AI-generated content already stored on a service | medium | mitigate | Turning AI off must never mutate, clear or freeze an existing congregational split. The mitigation is architectural — nothing in this plan writes to slide or reading data; the guard only affects generation — and is proven positively in Task 3 by asserting stored content is byte-identical and still hand-editable with AI off, rather than merely asserting the button is gone. |
| T-39-SC | Tampering | npm/pip/cargo installs | low | accept | Zero packages installed by this phase — `39-RESEARCH.md` § Package Legitimacy Audit records "Not applicable." No install task exists in any Phase 39 plan. |
</threat_model>
