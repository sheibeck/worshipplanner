<objective>
Add the per-item loop configuration model and its authoring UI so an operator can mark any
Service Order item as looping and choose the auto-advance interval (R306 authoring half, R307).

This is the "author it" half of Phase 106. It ships the additive `loop` field on the service
slot and the checkbox + interval control in the Service Order item editor, following the approved
106-UI-SPEC.md contract verbatim. It deliberately does NOT touch Run-time behavior — the timer
that consumes this config is Plan 02.

Purpose: Persist a per-item `{ enabled, intervalSeconds }` loop config the Run screen reads later,
using the codebase's established additive-optional-field + autosave patterns (no migration, no new
save path, no new rules surface).

Output: `MediaAttachableSlot.loop` type field, the loop checkbox/interval row in
ServiceEditorView.vue, and scoped authoring tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator → client model | Free-form custom interval seconds typed into the editor cross into the persisted slot model. |
| client editor → Firestore | The slot (with `loop`) is written via the existing draft-locked `services/{docId}` autosave path — no new rules surface. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-106-01 | Tampering | onLoopCustomBlur custom-seconds input | low | mitigate | Clamp the custom value to the inclusive 1–3600s range on blur (non-numeric/empty/out-of-range → nearest valid) so no invalid `intervalSeconds` is ever persisted; the value is a plain integer, never rendered as HTML. |
| T-106-02 | Tampering | persisted slot.loop.intervalSeconds | low | accept | A hand-edited Firestore doc could carry an out-of-range interval; the Run-side timer (Plan 02) defensively clamps intervalSeconds before arming, so the authoring layer accepts this residual. |
| T-106-SC | Tampering | npm/pip/cargo installs | low | accept | No dependency installs in this phase — the loop field and control are pure in-repo Vue/TS; no Package Legitimacy Gate applies. |
</threat_model>
