<objective>
Deliver R260: weight a person's multiRole assignments onto the same date. Add a non-recursive
`propagateMultiRole(personId)` pass inside `proposeQuarterSchedule` — parallel in shape to the existing
`propagatePairing` — that, after any multiRole assignment, sweeps the person's OTHER multiRole roles for
that date and pulls in each one that passes its own `withinCadence` + slot-capacity + group-compat gate.

their rarest role) instead of scattered across the month, as a strong-but-coverage-bounded preference. The
rarity-anchoring, determinism, and "never exceeds cadence / fills solo not empty" guarantees all emerge
from the existing `withinCadence` even-spread gate — NO rarity sort and NO deficit-score change (RESEARCH
B.2/B.3/B.4).
Output: `propagateMultiRole` closure + two trigger points + a `describe('multi-role bundling')` suite whose
competition fixture genuinely fails before the implementation exists (RED→GREEN).
</objective>
