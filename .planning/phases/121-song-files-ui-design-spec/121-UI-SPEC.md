# Phase 121 — UI Design Contract: Song Files

> Visual and interaction contract for the Song Files feature (R361–R373). Generated by
> gsd-ui-researcher, verified by gsd-ui-checker. Governs implementation phases 122 (data/rules),
> 123 (Files tab + upload UI), and 124 (preview/play/manage). **This phase writes no app source
> code** — this document plus (per owner request, produced during this phase's plan/execute step,
> not by this research step) a throwaway standalone HTML mock are the only deliverables.

Design reference: the owner's **"Song Files"** mock (Turn 10, *Worship Planner Slideshow Design*
Claude Design project, id `e8e6c287-3e88-402f-88e1-7ad6d5101fa2`). Its **layout and interaction
model are authoritative**; its Nocturne palette is **not** — every color below is remapped to the
app's existing Tailwind v4 stock dark theme, verified against the live source of
`SongSlideOver.vue`, `SongTable.vue`, `CleanupEnableConfirmDialog.vue`, and `useMediaUpload.ts`.

## Spacing Scale

Base scale (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| 2xs | 2px | badge vertical padding (`py-0.5`) |
| xs | 4px | icon-gap / micro padding (`gap-1`, `p-1`) |
| sm | 8px | badge horizontal padding, row-action gaps (`gap-2`, `px-2`) |
| sm+ | 12px | form-row / group-header spacing (`gap-3`, `px-3`, `py-3`) |
| md | 16px | drop-zone padding, default block spacing (`px-4`, `py-4`, `gap-4`) |
| lg | 20px | tab-panel outer padding + inter-block rhythm (`px-5`, `py-5`, `space-y-5`) |
| xl | 32px | not used at this surface size — reserved for page-level layout only |

Exceptions (must be reused verbatim for continuity with the existing Details/Lyrics tabs, not
invented fresh):
- `py-1.5` (6px) — secondary buttons and icon-only action buttons, matching `SongSlideOver.vue:68,86`.
- `py-2.5` (10px) — the tab-bar buttons themselves; the **Files** tab button reuses this exact
  value so all three tabs (Details/Lyrics/Files) sit flush at identical height (`SongSlideOver.vue:102,113`).
- The Files tab body container is `px-5 py-5 space-y-5` — **identical** to the Details tab
  container at `SongSlideOver.vue:124` — so switching tabs produces zero layout jump.

## Access Control (R372, cross-cutting)

- **Editors:** full read/write. Drop zone, "link instead" field, and every per-row action
  (Preview/Play, Download, Remove) render and are enabled.
- **Viewers:** read-only. The drop zone and the "link instead" field are **not rendered at all**
  (omitted, not merely disabled/grayed — a dead-end affordance a viewer can't use is worse than no
  affordance). Per-row **Preview, Play, and Download remain** (these are read actions, not
  mutations, per R372's explicit scope). Per-row **Remove is not rendered**. The Files tab count
  badge and the Songs-list Files column render identically for both roles — visibility of *that
  there are files* is never restricted, only the ability to mutate them.
- Enforcement of the underlying `storage.rules`/Firestore rule is out of this design contract's
  scope (that's R372's Phase 122 half) — this contract only specifies what the UI shows/hides per
  role.

## Surfaces & Components

### 1. Files tab (`SongSlideOver.vue` tab bar + panel)

A third tab button beside Details/Lyrics, reusing the exact active/inactive classes at
`SongSlideOver.vue:97–121`:

```
active:   text-indigo-400 border-indigo-500
inactive: text-gray-400 border-transparent hover:text-gray-300
shared:   px-4 py-2.5 text-sm font-medium transition-colors border-b-2 -mb-px
```

Label: `Files`, followed immediately by the count badge (only rendered when count > 0 — see
Copywriting Contract for the zero-count "no badge" rule). Badge classes:
`inline-flex items-center px-2 py-0.5 rounded-full text-xs font-medium border bg-indigo-900/50 text-indigo-300 border-indigo-800`.

Panel container: `flex-1 overflow-y-auto px-5 py-5 space-y-5` — identical to the Details tab
container (`SongSlideOver.vue:124`) so tab-switching produces no layout jump. Panel body, in
order: Drop Zone → Link field → Documents group → Audio group.

`SongEditTab` (`src/utils/songEditLink.ts:4,6`) gains `'files'` alongside `'details' | 'lyrics'`
in the implementation phase — not this one.

**States:** empty (both groups show their per-group empty line, drop zone + link field still
fully present — see §6/§7), populated (reference density: 3 PDFs + 2 MP3s), upload-in-progress
(one or more rows in §5's transient state within their target group).

**A11y:** tab button keeps the existing plain-button convention (no `role="tab"`/`aria-selected` —
matches Details/Lyrics, which have neither; do not introduce ARIA tab roles unilaterally for only
this tab). Badge text is real DOM text (not `::before`/CSS-generated), so it's screen-reader
readable as part of the button's accessible name.

### 2. Songs-list Files column (`SongTable.vue`)

A new toggleable column, positioned **last, immediately before the trailing chevron `th`**
(`SongTable.vue:158`), matching the existing column pattern exactly:

- `th`: `<th v-if="songStore.columnVisibility.files" scope="col" class="px-4 py-3 text-left text-xs font-medium text-gray-400 uppercase tracking-wider">Files</th>`
- `td`: `<td v-if="songStore.columnVisibility.files" class="px-4 py-3 text-gray-300">` containing the paperclip icon (`h-4 w-4 text-gray-500`) + copy text (`text-sm`) — **plain text, not a pill badge** (the pill/badge treatment is reserved for the Files-tab count badge only — this column matches the plain-text style of the `key`/`ccli`/`lastUsed` columns beside it).
- Store additions (`src/stores/songs.ts:50–58`): `DEFAULT_COLUMN_VISIBILITY.files = true`; `toggleableColumns` gains `{ key: 'files', label: 'Files' }` in the cog menu (`SongTable.vue:171–192`), same checkbox pattern as every other toggle.

**Copy:** `none` (0 files) / `1 file` / `N files` (2+) — see Copywriting Contract.

**States:** the cell has no independent loading/error state — it renders synchronously off the
already-subscribed `Song` document, same as every other column in the row.

**A11y:** no additional markup — inherits the row's existing accessible structure.

### 3. Drop zone

**Always visible** at the top of the Files tab panel (editors only — omitted for viewers per
Access Control) — not swapped out once files exist; it remains the permanent "add more" affordance,
directly above Documents/Audio.

```
idle:       border-2 border-dashed border-gray-700 rounded-lg bg-gray-800/40 (px-6 py-8, text-center)
drag-over:  border-indigo-500 bg-indigo-950/20 (icon + primary line shift to text-indigo-400)
```

Contents: `arrow-up-tray` icon (`h-8 w-8`, centered) → primary line **"Drop files here, or click to
browse"** (`text-sm font-medium text-gray-200`) → helper line **"PDF, MP3 · up to 50 MB each ·
several at once"** (`text-xs text-gray-500`, exact wording per owner scope — no MP4/JPG/PNG). The
entire zone is `click`-able (opens the native file picker) as well as drag-and-drop-able; both
paths accept multiple files in one action.

**States:**
- **error (client-side rejection):** each file is validated independently the instant it's
  dropped/picked — a batch of 5 with 1 bad file uploads the 4 good ones and shows one inline
  rejection line per bad file (see Copywriting Contract), never blocking the valid files.
- **long-text:** N/A — helper copy is fixed and short.

**A11y:** the zone is a real `<button>` or has `role="button" tabindex="0"` plus a hidden
`<input type="file" multiple accept=".pdf,audio/mpeg">` triggered on click/Enter — drag-and-drop is
a progressive enhancement, click-to-browse is the accessible baseline.

### 4. "Link instead of upload" field

Sits directly beneath the drop zone (editors only), a single input, no separate submit button —
submits on Enter, matching the User Tags input idiom (`SongSlideOver.vue:226–232`).

```html
<label>Or link instead of uploading</label>
<input placeholder="Paste a YouTube, Google Drive, or Dropbox link" />
<p class="helper">Opens in a new tab when clicked — not previewed in-app.</p>
```

Classes: label `text-xs font-medium text-gray-400 mb-1`; input the standard app input treatment
(`w-full rounded-md bg-gray-800 border border-gray-700 text-gray-100 placeholder-gray-500 text-sm px-3 py-2 focus:outline-none focus:ring-1 focus:ring-indigo-500 focus:border-indigo-500`); helper `text-xs text-gray-500 mt-1`.

**States:**
- **empty:** blank input, placeholder shown (covered above).
- **error:** an unparseable/non-URL value shows `text-xs text-red-400 mt-1` **"Enter a valid link
  (starting with https://)."** below the input; nothing persists until valid.
- Once linked, the link appears as its own row in the appropriate group (Documents or Audio —
  Claude's discretion at implementation which group a generic link defaults to when type can't be
  inferred; recommend a third small "Links" sub-group only if this proves common, otherwise fold
  into Documents by default) with the `arrow-top-right-on-square` glyph replacing Preview/Play (a
  link always opens in a new tab per R365, never previewed in-app) and no Play/Preview action.

**A11y:** standard labeled `<input>`, error text linked via `aria-describedby`.

### 5. Per-file upload progress row

Rendered **inline, within its eventual target group** (Documents or Audio, determined by file
type) — the row IS the file's future home; it morphs into the normal row (§6/§7) on completion
rather than disappearing and being replaced.

```
filename (truncate)                                    [x cancel]
[███████████░░░░░░░░░] 42%
```

- Progress track: `h-1.5 rounded-full bg-gray-800`; fill: `h-1.5 rounded-full bg-indigo-500`,
  width bound to `snapshot.bytesTransferred / snapshot.totalBytes * 100` (mirrors
  `useMediaUpload.ts`'s existing `state_changed` pattern — a future `useSongFileUpload.ts` composable
  reuses it directly).
- Percentage text: `text-xs text-gray-400` right-aligned or trailing the bar.
- Cancel affordance (`x-mark`, `h-4 w-4`, `aria-label="Cancel upload"`) — recommended for UX
  completeness; not required by R363, which only mandates progress display.

**States:**
- **loading:** this row *is* the loading state.
- **error:** on failure, the row flips to a compact red-tinted inline error: `exclamation-triangle`
  + **"Upload failed. Check your connection and try again."** + a **Retry** text action
  (`text-xs text-red-300 hover:text-red-200`), still inside its group, not silently dropped.
- **long-text:** filename truncates identically to a completed row (`truncate` + `title` attr).

**A11y:** progress announces via a visually-hidden `aria-live="polite"` region updated at
completion (not on every percent tick, to avoid screen-reader spam) — e.g. "3 of 3 files
uploaded."

### 6/7. Documents / Audio grouped rows

Two always-rendered sections, each: an eyebrow group header (Display role: 11px/500/uppercase/
tracking-wide/`text-gray-500`, with the group's icon at `h-5 w-5 text-gray-400` beside it) followed
by its rows or its empty line.

**Row anatomy** (`flex items-center gap-3 px-3 py-3 rounded-md bg-gray-800/60 border border-gray-800` — matches the row-card treatment used elsewhere, e.g. the delete-confirm panel's card shape):

```
[icon] Filename.pdf                              [eye] [↓] [🗑]
       PDF · 12 pages · 2.4 MB · Sep 5, 2026
```

- Icon: `document-text` (PDF) or `musical-note` (MP3), `h-5 w-5 text-gray-400`, left-aligned,
  vertically centered against the two-line name/metadata block.
- Filename: `text-sm text-gray-100 truncate`, native `title` attribute carries the full name.
- Metadata line: `text-xs text-gray-500`, format **`{TYPE} · {pages-or-duration} · {size} · {date}`**:
  - PDF: `PDF · 12 pages · 2.4 MB · Sep 5, 2026` (singular `1 page` when exactly 1).
  - MP3: `MP3 · 3:42 · 5.1 MB · Sep 5, 2026` (duration as `M:SS`, no leading zero on minutes).
  - Date format: `toLocaleDateString('en-US', { month: 'short', day: 'numeric', year: 'numeric' })`
    — the exact convention already used in `TeamView.vue:268` for "joined" dates; reuse it, don't
    invent a new date format.
  - Linked (non-uploaded) rows: `{SOURCE} link` in place of type/size, e.g. `YouTube link · Sep 5, 2026`
    — no size/page/duration fields since nothing was transferred (R365).
- Row actions (editors only for Remove; Preview/Play/Download for everyone per Access Control),
  right-aligned, `gap-2`, each an icon-only button `p-1 rounded hover:bg-gray-700`:
  - PDF row: `eye` (Preview) → `arrow-down-tray` (Download) → `trash` (Remove, editors only).
  - MP3 row: `play`/`pause` (Play, toggles) → `arrow-down-tray` (Download) → `trash` (Remove, editors only).
  - Linked row: `arrow-top-right-on-square` (Open, replaces Preview/Play) → `trash` (Remove, editors only) — no Download for a link (nothing was uploaded).
  - Every icon-only button has an explicit `aria-label` (`"Preview {filename}"`, `"Play {filename}"`, `"Download {filename}"`, `"Remove {filename}"`, `"Open {filename} in a new tab"`) — matches the existing `aria-label="Close"` / `aria-label="Remove tag"` convention.

**Per-group empty state (R366):**
- Documents, 0 items: header still shows, body line **"No documents attached yet."** (`text-xs text-gray-500 py-2`).
- Audio, 0 items: header still shows, body line **"No audio files attached yet."**

**States:**
- **empty:** per-group lines above.
- **loading:** N/A — synchronous off the Song doc (no fetch), so no group-level spinner (dismissed by design, not an oversight).
- **error:** an individual row whose download URL fails to resolve shows **"Couldn't load this file."** in place of the metadata line, with the Download action swapped for a **Retry** text link; the rest of the group is unaffected.
- **populated:** reference density above (3 + 2).
- **partial:** a pre-Files legacy song with no `attachments` field at all renders **identically** to an empty array in both groups — never throws, never shows a broken row (see UI Considerations table, flagged `backstop`).
- **overflow:** the group's rows scroll within the shared tab-panel `overflow-y-auto` container — no per-group max-height, no separate scrollbar.
- **zero-one-many:** group header carries no count suffix (the rows themselves communicate volume); the Songs-list badge and Files-tab badge separately own the "1 file"/"N files"/"none" singular/plural copy.
- **long-text:** filenames truncate per the `truncate` idiom above.

### 8. In-app PDF preview

Opens on clicking `eye`/Preview. A **modal overlay**, reusing the established dialog shell from
`CleanupEnableConfirmDialog.vue` (backdrop `fixed inset-0 z-40 bg-black/60`, dialog
`role="dialog" aria-modal="true"`), sized larger than the 480px slideout since it's an independent
full-viewport overlay: `w-full max-w-3xl h-[85vh] bg-gray-900 rounded-xl border border-gray-800 shadow-2xl flex flex-col`.

- Header: filename (`text-sm font-medium text-gray-100 truncate`) + Download (`arrow-down-tray`) +
  Close (`x-mark`, `h-5 w-5`, `aria-label="Close preview"`), `px-4 py-3 border-b border-gray-800`.
- Body: `<iframe>`/`<embed>` rendering the file's download URL, `flex-1`.
- Dismiss: Close button, `Escape` key, or backdrop click (matches `CleanupEnableConfirmDialog.vue`'s `@click.self="onCancel"` convention) — dismissing never leaves the Files tab; it's an overlay, not a navigation.

**States:**
- **loading:** centered spinner (reuse the existing spinner SVG pattern from `SongTable.vue:12–13`) while the iframe/embed loads.
- **error:** load failure → **"Couldn't preview this file."** + a Download button as fallback, replacing the iframe.
- **populated:** the rendered PDF, scrollable within the iframe itself.

---

### 9. In-app MP3 player

Opens on clicking `play`. **Inline expansion**, not a modal — a native `<audio controls>` element
reveals directly beneath the clicked row (`mt-2 w-full`, browser-default chrome, no custom skin),
keeping the user visually anchored to the Files list. Clicking `pause`/collapsing removes the
element. Only one track expanded at a time (starting a second Play collapses the first).

**States:**
- **loading:** native `<audio>` buffering UI (no custom loading treatment needed).
- **error:** native `<audio>` error surfaces as **"Couldn't play this file."** (`text-xs text-red-400 mt-1`) beneath the controls, with a Download fallback link.
- **populated:** native controls, playing.

---

### 10. Remove confirmation

Reuses the **exact inline-expand pattern** already established for "Delete Song"
(`SongSlideOver.vue:283–316`) rather than a new modal — clicking `trash` replaces that row's action
group with an inline confirm card directly beneath the row:

```html
<div class="mt-2 rounded-lg bg-red-900/20 border border-red-800 p-3">
  <p class="text-sm text-gray-200 mb-2">
    Remove <strong class="text-white">"{filename}"</strong>? This file appears on every service
    that uses this song. Removing it here removes it everywhere — including past services. This
    can't be undone.
  </p>
  <div class="flex gap-2">
    <button>Cancel</button>  <!-- text-gray-300 bg-gray-800 hover:bg-gray-700 border-gray-700 -->
    <button>Remove</button>  <!-- text-white bg-red-700 hover:bg-red-600 -->
  </div>
</div>
```

Only one row's confirm card is open at a time (opening a second collapses the first). Editors only
— never rendered for viewers (no `trash` icon to click in the first place).
