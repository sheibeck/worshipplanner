  <action>
Add `setSongBackground(orgId: string, songId: string, lyricsId: string, url: string | null):
Promise<void>` to `src/stores/songLyrics.ts` and export it from the store's return object.

It performs a single `updateDoc` against the same document path `updateCurrentLyrics` already
targets, setting the background field to the supplied URL when one is given and to an explicit field
deletion when `null` is passed, plus the server timestamp. Import the field-deletion helper from the
Firestore SDK alongside the existing imports.

★ Use an explicit deletion rather than "an undefined value means clear" — the same reason
`setGroupBedMedia` already records for itself in `slideGroups.ts`: an undefined value would be
stripped before the intent ever reached Firestore, so a clear would silently become a no-op.

Do NOT extend `updateCurrentLyrics` to carry this instead. That action is the autosave path and is
typed as a partial of the document; threading a deletion sentinel through it would widen its type for
one caller. A dedicated single-purpose action keeps the autosave payload shape honest.

Add cases for both branches to the song lyrics store's test file, or create one following the mocking
idiom of a sibling store test if none exists.
