<objective>
Deliver the client-side import experience: a resumable Storage upload utility and a step-based PptxImportModal that drives the two import modes — .pptx via the parsePptx Cloud Function, and direct image upload entirely client-side (R011's image path, no parsing). The modal reuses the established step-machine UX of RosterImportModal (idle → uploading → parsing → preview → error/confirmed) and the friendly error contract from CONTEXT.

On confirm it persists an imported deck through the importedSlides store (from 21-01) and hands the new importId plus target section back to the host view (wired in 21-06). It never touches service.slots directly, keeping the modal reusable and the slot mutation with the editor view.
Output: pptxUpload.ts, PptxImportModal.vue, and a component test covering the pptx path, the image-only path, and the error path.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user file input → Firebase Storage | Untrusted .pptx / image files enter org-scoped Storage from the browser. |
| client → parsePptx callable | The modal invokes the authenticated Cloud Function with a Storage path. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-21-05-01 | Denial of Service | oversized upload from the browser | medium | mitigate | Uploads target org-scoped paths governed by the 25 MB storage.rules cap (21-02); the function's magic-byte + memory/timeout caps (21-04) backstop parsing. |
| T-21-05-02 | Information Disclosure | image display URLs bypassing org access | medium | mitigate | Image paths are resolved via getDownloadURL (rules-respecting), never via long-lived admin signed URLs. |
| T-21-05-03 | Spoofing | client sending file bytes or a foreign orgId to the callable | low | mitigate | Modal passes only the Storage path + the caller's own orgId; the function independently re-validates path prefix and membership (21-04). |
</threat_model>
