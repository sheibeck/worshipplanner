<objective>
Make the Run control window the one and only audio owner. `useRunControl.ts` gains a small audio state
machine (armed / blocked / unavailable / playing / needed) driven by its existing `current`, `blackout`,
and `live` state and bound to a single chromeless `AudioPlayer` mounted in `RunControlView.vue`;
`RunHeader.vue` gains the `Audio: Off / Armed` arm toggle (the R439 gesture), the playing dot, and the
`Audio unavailable` indicator; `RunControlView.vue` gains the amber `Audio blocked — click to play` banner
with a `Play audio` retry; `RunPreviewPair.vue` gains the `♪ Vamp: {vampLabel}` badges (resolved via a
`groupsBySlotId` lookup, bypassing the assembler) and, for defense-in-depth, `suppress-audio` on its own
inert preview canvases.

Purpose: R438 (plays + loops while live, audible from the control machine only) and R439 (explicit arm
gesture in the window that plays; blocked/unavailable failures are always visible) under the 2026-09-13
owner override, with no cross-window delegation.
Output: composable audio API + view mount + header toggle/indicators + blocked banner + preview badges;
`RunControlView.audio.test.ts` (new sibling per the `.loop.`/`.output.` convention) and badge cases in
`RunPreviewPair.test.ts`.
</objective>
