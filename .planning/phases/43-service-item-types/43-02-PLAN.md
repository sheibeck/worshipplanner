<objective>
Close R085 — the silent-fallthrough trap this phase exists for.

`addSlotAsItem` is an unguarded if-chain whose final block is an implicit `else` returning a
Planning Center item titled `Message`. Any `SlotKind` without an explicit branch is silently exported
under that title, and the compiler cannot catch it because an if-chain is not a switch. Verified by
direct read: the last block is preceded only by a bare kind-name comment.

Fix in two parts. Part 1 makes every kind explicit — including converting the trailing implicit else
into an explicit MESSAGE test and adding the IMPORTED branch that has never existed. Part 2 adds an
exhaustiveness backstop after the chain so the NEXT phase to widen `SlotKind` gets a compile error
instead of a silent mislabel. Part 1 fixes today; part 2 is what makes the fix durable.

Purpose: a planner's Announcements item must reach the volunteers reading the Planning Center plan
labelled as an Announcements item. Mislabeling it is a misrepresentation of the planner's intent to
other people, not merely a display bug.
Output: an exhaustive, compiler-guarded export dispatch with a per-branch test suite.
</objective>
