**★ A divergence you must resolve explicitly, not silently.** `NewServiceDialog`'s
`nextSunday()` is strictly forward — on a Sunday it returns the FOLLOWING Sunday.
`quarterDates`' internal Sunday advance (`d.setDate(d.getDate() + ((7 - d.getDay()) % 7))`)
returns TODAY when today is a Sunday. That is a 7-day difference and it changes D-13's
fallback behaviour. Pick one convention, state it in a comment, and cover it with a test
that runs on a Sunday. Do not let the two coexist unreconciled.

## Task 1 — `nextFreeSunday` in `src/utils/quarterDates.ts`

Add it INSIDE that module. Do not create a new file: `fmtDate` is module-private and
unexported, so a new file would produce a fourth copy of the same date formatter in this
codebase — the exact duplication that produced Phase 30's four-way scripture-formatter
drift and two review findings.

Signature roughly:

```ts
export function nextFreeSunday(from: Date, takenDates: ReadonlySet<string>, maxWeeks = 52): string
```

Behaviour:
- Walk FORWARD from the first Sunday on/after `from` (per whichever convention you settled
  above), returning the first date string not in `takenDates`.
- After `maxWeeks` with no free Sunday, return the plain next Sunday — the field is never
  blank and the user can type a date.
- Pure. No `Date.now()` inside; the caller passes `from`, which also makes it testable.

## Task 2 — Wire the dialog

  a store import — `31-PATTERNS.md` §6 confirms prop-drilling is this codebase's convention
  for dialogs, and the dialog currently has zero store imports).
- Its default date comes from `nextFreeSunday`. Keep the private `nextSunday()` only if it
  is still the bounded fallback; otherwise delete it rather than leave two date sources.

## Task 3 — ★ The team side effect

`sundayOrdinal()` (`NewServiceDialog.vue:148-154`) derives which Sunday-of-the-month a date
falls on, and the default TEAM selection depends on it. Changing the default date therefore
changes the default teams. This is a real behaviour change, not a bug — but it must be
deliberate and tested, not discovered later.

Add a test: two candidate Sundays with different ordinals, the first taken, and assert the
resulting default team selection matches the SECOND Sunday's ordinal.
