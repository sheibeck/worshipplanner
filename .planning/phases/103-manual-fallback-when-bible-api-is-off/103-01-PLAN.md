Output: `bibleGatewayLink()` exported + unit-tested; the "Bible Translation" card gated by `authStore.isBibleApiEnabled` + visibility tests.
</objective>

  <files>src/utils/scripture.ts, src/utils/__tests__/scripture.test.ts</files>
  <behavior>
    - A range reference (book Romans, chapter 8, verseStart 1, verseEnd 11) with version 'NLT' → `https://www.biblegateway.com/passage/?search=Romans%208%3A1-11&version=NLT`
    - A single-verse reference (Romans 8:28) with no version arg → `https://www.biblegateway.com/passage/?search=Romans%208%3A28` and the string contains no `&version=`
    - A chapter-only reference (Romans 8) with version 'ESV' → search param `Romans%208` plus `&version=ESV`
    - A multi-word book name (1 Corinthians 13:4-7) URL-encodes the space in the book name inside the search param
    - An empty-string version is treated as absent → no `&version=` appended
  </behavior>
  <action>Add an exported `bibleGatewayLink(ref: ScriptureRef, version?: string): string` to `src/utils/scripture.ts`, placed next to the existing `nltLink`/`scriptureWebLink` builders (~line 87-104) and following their pattern. It builds `https://www.biblegateway.com/passage/?search=<encoded>` where `<encoded>` is `encodeURIComponent(formatScriptureReference(ref))` — reuse the canonical `formatScriptureReference` (already in this file, ~line 190) so the search string is exactly the human-readable form ("Book Chapter:Start-End", "Book Chapter:Verse", or "Book Chapter"). Append `&version=` + `encodeURIComponent(version)` ONLY when `version` is a non-empty string; otherwise omit the version param entirely (per R298 — the link works with ANY version, and an org with no stored version falls back to BibleGateway's default). Do NOT modify or re-route `esvLink`, `nltLink`, or `scriptureWebLink`.
