<objective>
Build the two client-only Pinia stores the rest of the phase reads from: `useSaveStatus`, the
per-surface save-status aggregator R040 names, and `useToasts`, the one-purpose array store
behind R041's failure toast.

Purpose: these are the first stores in this codebase with no Firestore involvement at all, and
`useSaveStatus` is the reason a `saved` on one surface can no longer visually erase a `saving`
on another. Building them standalone, with real Pinia and no component mounted, means the
component and migration plans that follow are wiring, not design.

Output: two stores and two test files, with the error-edge toast trigger living inside
`set()` so no caller has to know toasts exist.
</objective>

    interface `SaveStatusEntry` with `status: AutoSaveStatus`, `savedAt?: Date` and

    Export the store as `useSaveStatus`.

    State: `entries` — a `ref<Record<string, SaveStatusEntry>>({})`.

    Members: `set(surfaceId, entry)` assigns; `clear(surfaceId)` deletes the key; `entryFor(surfaceId)`
    returns the stored entry or a literal idle entry for an unknown key (return a fresh idle
    object rather than a shared singleton, so a consumer cannot mutate it into the store);
    `mostUrgent` is a `computed` returning the highest-urgency entry or null when there are no
    entries.

    keyed by `AutoSaveStatus` — one place, so no consumer re-derives the ordering in a template
    `v-if` chain. Iterate `Object.keys(entries.value)` sorted lexicographically before reducing,

    surface id and therefore identical on every re-evaluation. Ties resolving by insertion order

    testable rather than incidental.

    This store holds no Firestore state at all — no `orgId`, no `subscribe`, no `unsubscribeAll`,
    and no import from `firebase/firestore` or `@/firebase`. It is deliberately the first store
    of that kind in this codebase. It also must not re-implement anything `useAutoSave` owns:
    no debounce, no inflight flag, no flush, no cleanup. It records what a surface reports; it
    does not decide when to save.

    read the current entry for that surface. If the incoming entry's status is `'error'` and the
