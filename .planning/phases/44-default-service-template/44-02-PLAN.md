<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| org editor (browser UI) → Firestore `organizations/{orgId}.settings.defaultServiceTemplate` | The editor's Save writes org-editor-writable settings data; the UI itself gates the controls behind `authStore.isEditor` |
| draft array in the drawer → the shared DEFAULT_ORG_SETTINGS array reference | Editing the draft must not mutate the store's shared default array (aliasing hazard) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-44-01 | Tampering | non-editor writing `settings.defaultServiceTemplate` (bypassing the UI) | low | mitigate | UI gates Save/Edit behind `authStore.isEditor` (same pattern as every Settings section); backstopped by the existing `allow write: if isOrgEditor(orgId)` rule on `organizations/{orgId}` (RESEARCH Pitfall #5 — verified, no new rule needed) |
| T-44-05 | Tampering | malformed `kind`/`section` entered through the editor | low | mitigate | Input is structurally constrained: the palette is a closed six-button set of literal `SlotKind` values (not free text), and section is a closed `<select>` over `SERVICE_SECTIONS` + "No section" — a malformed value cannot be entered through the UI |
| T-44-06 | Information Disclosure | undefined/content fields leaking into the persisted Firestore payload | low | mitigate | Save writes `stripUndefined(draft)` so no `section: undefined` reaches Firestore; entries are built as `{ id, kind, section? }` only (never a raw `createSlot()` result), so no content fields (songId/body/hymnName) are persisted (Pitfall #4) |
| T-44-SC | Tampering | npm/pip/cargo installs | low | accept | Not applicable this phase — RESEARCH Package Legitimacy Audit confirms zero new packages; nothing to slopcheck |
</threat_model>
