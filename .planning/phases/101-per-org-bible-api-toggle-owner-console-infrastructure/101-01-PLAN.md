<objective>
Establish the server-side and rules-layer half of the per-org Bible API master gate: a `bibleApiEnabled?: boolean` field on the `Organization` document, a super-admin-gated `setOrgBibleEnabled` Cloud Function that is the ONLY write path to it, its re-export from `index.ts`, the `listOrganizations` echo that lets the Owner Console read it, and the `firestore.rules` deny that blocks every direct client write. This is a 1:1 mirror of the shipped v2.2 AI master gate (`aiMasterEnabled` / `setOrgAiEnabled`), changing only names and the default-OFF single-field shape (no `settings` leaf — that church-editable leaf is deferred).

Purpose: Phase 102 (fetch dispatcher) and Phase 103 (manual fallback) both gate against this field via the `authStore` mirror that Plan 02 wires. This plan creates the authoritative persistence + write-authority boundary.
Output: `Organization.bibleApiEnabled` type, `setOrgBibleEnabled` callable + handler tests, `listOrganizations` echo, `index.ts` re-export, `firestore.rules` deny + rules tests. No deploy (batched for milestone end).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → setOrgBibleEnabled callable | An untrusted caller invokes the super-admin-only function |
| client → organizations/{orgId} doc | An untrusted client attempts a direct write to bibleApiEnabled |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-101-01 | Elevation of Privilege | setOrgBibleEnabledHandler | high | mitigate | `assertSuperAdminCaller` runs before any Firestore read; unit tests cover unauthenticated + non-super-admin rejection (mirrors setOrgAiEnabled) |
| T-101-02 | Tampering | firestore.rules organizations/{orgId} update | high | mitigate | bibleApiEnabled (+ audit siblings) added to `lifecycleFields()` deny; rules tests deny an ordinary editor AND a super-admin client SDK direct write (mirror of T-82-02) |
| T-101-03 | Repudiation | audit fields bibleApiEnabledBy/At, bibleApiDisabledBy/At | medium | mitigate | audit siblings written server-side by the Admin SDK and included in `lifecycleFields()`, so a client cannot forge them (mirror of WR-01) |
| T-101-04 | Information Disclosure | listOrganizations bibleApiEnabled echo | low | accept | non-sensitive on/off flag, returned only to super-admin callers (handler already gated by assertSuperAdminCaller) |

No package-manager installs in this plan — no package-legitimacy checkpoint required.
</threat_model>
