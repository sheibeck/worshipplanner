Add the client half of the admin resend feature: a "Sign-in Link" section inside RosterView's
existing Add/Edit Volunteer drawer, offering "Email sign-in link" and "Copy sign-in link" for a
rostered volunteer who has an email, wired to Plan 01's `adminVolunteerLink` callable.

clipboard/label-flip + toast conventions — no new UI primitives.

covering both modes and the no-email hidden state. NOT deployed this phase.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| RosterView (browser) → adminVolunteerLink callable | The client sends `orgId`, `email`, `mode`; the server (Plan 01) is the authorization control. The UI affordance and no-email hiding are UX conveniences, NOT security gates. |
| callable response → navigator.clipboard | The minted link is written to the local clipboard by the browser; the server never writes the clipboard. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-129C-01 | Elevation of Privilege | Client-side affordance mistaken for the authz control (e.g. a tampered client showing buttons for a non-editor) | high | mitigate | Authorization is enforced server-side in adminVolunteerLinkHandler (Plan 01, T-129-01/02); the client hiding/disabling is convenience only — a bypassed client still hits the server gate. No client-side authz decision is trusted. |
| T-129C-02 | Elevation of Privilege | Editor copies/emails a volunteer's account-level link → impersonation of the read-only volunteer | medium | accept | ACCEPTED, documented tradeoff (CONTEXT.md locked): read-only volunteer view, editor already has full org access. No confirmation dialog by design; recorded in the phase threat model, not re-litigated in the UI. |
| T-129C-03 | Information Disclosure | Minted link leaked via console/telemetry on the client | low | mitigate | Do not console.log the returned link; write it only to navigator.clipboard. |
| T-129C-04 | Denial of Service (UX) | Missing clipboard API / rejected callable leaving the button stuck | low | mitigate | Guard `if (navigator.clipboard)`, reset busy refs in `finally`, and surface a transient error label/toast; separate busy refs so one action never wedges the other. |
| T-129C-SC | Tampering | npm/pip/cargo installs (supply chain) | low | accept | No new packages this phase — navigator.clipboard is a browser built-in; httpsCallable/functions/useToasts already in the app. No install task exists. |
</threat_model>
