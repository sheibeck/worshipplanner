<objective>
Build the receiving side of the old-address settings hand-off on the new origin (R452). A dependency-free `src/originHandoff/` module decodes the `#wph1=` URL fragment at boot, imports only allowlisted keys through per-key validate-and-rebuild validators, fills only absent keys, strips the payload with `history.replaceState` while restoring the original hash, and raises a one-time "new address" notice through the existing toast store. `src/main.ts` imports the bootstrap first, so the fragment is consumed before vue-router's `createWebHistory` snapshots `location`.

Purpose: the hand-off is an injection surface, since anyone can craft a `https://worshipbuilder.web.app/#wph1=...` link. Validation on this side is the security boundary. Plan 145-03 builds the sending side (the old-site bridge) on top of `allowlist.ts` and `codec.ts` from this plan.

CONTEXT decisions implemented (CONTEXT.md bullets are unnumbered; named here for traceability):
- "Receiving side (R452)": decode on boot before stores read localStorage; allowlist plus per-key shape validator; fill-if-absent; `history.replaceState` strip and original-hash restore; malformed, oversized and unknown entries dropped silently. Tasks 1-2.
- "Moved keys" + Amendment "explicit allowlist, not a prefix scan": the seven keys and patterns listed in must_haves, tag filters included. Task 1.
- "Never moved" + Amendment: emailForSignIn, Firebase Auth state, the session `wp.selectedOrg`, `rehearse-audio-position:*` and the bridge's own flag form an explicit documented denylist (Claude's discretion: yes, in code). Rehearse playback positions are not moved (discretion: unbounded key count, re-derivable, written continuously). Task 1.
- "After a hand-off, show a one-time dismissible notice via the existing system-wide notification store". Task 3.
- Amendment "Boot order: the import runs from a side-effect module imported first in src/main.ts". Task 3.
- Claude's discretion "payload encoding (base64url JSON), size cap, fragment key name": `#wph1=` + base64url(UTF-8 JSON `{v:1,h?,k}`); caps 49152 / 40 / 8192 / 512. Task 1.
- Claude's discretion "test strategy": jsdom unit tests of encode, decode, validate and apply, plus a bootstrap import test and a main.ts source-order test. Tasks 1-3.

Output: five `src/originHandoff/*.ts` modules, five test files, a two-line `export` change in monitorConfig.ts, and the main.ts wiring.

src/originHandoff/codec.ts (no imports):
- `export const FRAGMENT_PREFIX = '#wph1='`
- `export const MAX_FRAGMENT_CHARS = 49152` (whole fragment string including the prefix)
- `export const MAX_ENTRIES = 40`
- `export const MAX_VALUE_CHARS = 8192`
- `export const MAX_HASH_CHARS = 512`
- `export interface HandoffPayload { v: 1; h?: string; k: Record<string, string> }`. The decoded `k` values are UNTRUSTED until validated.
- `export function encodeFragment(payload: HandoffPayload): string` returns FRAGMENT_PREFIX plus the base64url (no padding, `-`/`_` alphabet) of the UTF-8 bytes of JSON.stringify(payload). Build the binary string with a loop, not a spread, so large payloads cannot overflow the call stack.
- `export function decodeFragment(hash: string): HandoffPayload | null` never throws. It returns null unless all of these hold:
  - `hash` starts with FRAGMENT_PREFIX and its length is at most MAX_FRAGMENT_CHARS;
  - the body after the prefix is non-empty and matches `^[A-Za-z0-9_-]+$`;
  - the body decodes through atob and a fatal UTF-8 TextDecoder;
  - JSON.parse yields a non-null, non-array object with `v === 1`;
  - its `k` is a non-null, non-array object.
  A present `h` is kept only when `isRestorableHash(h)` holds and is otherwise dropped from the returned object.
- `export function isRestorableHash(h: unknown): h is string`: a string of length 2..MAX_HASH_CHARS that starts with '#' and does NOT start with FRAGMENT_PREFIX.
