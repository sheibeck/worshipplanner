<objective>
Make `worshipbuilder` the app's hosting target and turn the default site into a separately targeted `legacy` site. Point the server-side share-link default at the new origin and add the new origins to the Storage CORS file. Guard all of it with config-shape, CORS, link-format and old-origin source-scan tests (R448, R449, R450, R451 config side).

Purpose: this is the config half of the cutover. Plan 145-02 builds the receiving side of the settings hand-off, and plan 145-03 builds the old-site bridge page, the runbook and ADR-0247. Nothing here touches production: the Storage CORS re-apply, the Auth authorized-domain change and every deploy are owner-confirmed runbook steps at milestone end.

CONTEXT decisions implemented (CONTEXT.md bullets are unnumbered; named here for traceability):
- "Hosting + links (R448, R449)": two-target `hosting` array with `.firebaserc` targets `app` -> `worshipbuilder` and `legacy` -> `worship-planner-bc515`. Deploys are always `hosting:app` / `hosting:legacy`. Task 1.
- "Old-domain bridge": the legacy site keeps the `/api/**` -> `api` rewrite, and every other path goes to the bridge page `/index.html` (built into `dist-legacy` by 145-03). Task 1.
- "Hosting + links": the `SERVICE_SHARE_BASE_URL` default becomes `https://worshipbuilder.web.app`; grep app and function code for hard-coded old-domain URLs. Tasks 2 and 3.
- Amendment "functions/.env pins the old share base URL": change the `params.ts` default anyway (code + tests). The local `functions/.env` fix is a runbook pre-flight step (145-03), never done here. Task 2.
- Amendment "Reserved paths": no explicit `/__/**` exclusion; a shape test proves no hosting block targets `/__`. Task 1.
- Amendment "Docs: update the old-domain URL in functions/DEPLOY-EMAIL-DOMAIN.md". Task 3.
- "Allowlists (R450)": `storage-cors.json` gains both new origins and keeps the old ones. The Auth authorized-domain change is a console step owned by the 145-03 runbook. Task 3.
- "authDomain stays worship-planner-bc515.firebaseapp.com this milestone": not touched (it lives in the gitignored `.env.local`).
- Claude's discretion (recorded in ADR-0247 by 145-03): the legacy block marks only `/bridge-assets/**` immutable, so a stale `/assets/*` chunk request from an old tab gets the no-cache bridge HTML rather than a year-long cached copy that would break a rollback.

Output: two-target `firebase.json`, `.firebaserc` targets, the new-origin share default, the five-origin CORS file, four new or adapted root tests, one new and four extended functions tests, and two doc updates.
