<objective>
Collapse the duplicated order model. Phase 18 shipped TWO places a song's section order could live —
`Song.performanceOrder` on the catalog record and `SongLyrics.performanceOrder` on the lyrics
document — read through a three-tier precedence chain, written by two different code paths, and
edited through a second list sitting beside the lyric editor. R035 names that duplication directly.

This plan deletes the second order field, the precedence chain, and the second list, in that order,
leaving `SongLyrics.performanceOrder` as the single source of truth for the slide order.

Purpose: option 2a's premise is that the list you see IS the order. That is only true if there is one
order. Every later plan in this phase builds the editor against a single field.
Output: one order source, one list surface, and a green test suite proving the Slides tab still
renders song slides in the user's order.
</objective>

  into the lyrics document at line 194 and onto the Song record at lines 196-198.

it in Phase 20 is greenfield and goes.
