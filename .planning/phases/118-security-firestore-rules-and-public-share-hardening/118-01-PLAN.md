  <name>Task 1: R341 — provenance-field-diff guard on the services draft-update branch</name>
  <files>firestore.rules, src/rules.test.ts</files>
  <action>
Implement R341 (SEC-R-03, real rules fix). In `firestore.rules`, harden the `services/{docId}`
`allow update` branch 1 — the `storedStatus() == 'draft'` ordinary-editing disjunct at line 204.
Today it permits ANY field change while draft, so an org editor can forge `createdBy`. Add a
provenance-diff guard that mirrors `preservesCreatedBy()` (:104-106) using the already-defined
`keys()` helper (:196): branch 1 must additionally require that the changed keys do NOT include
`createdBy` or `createdAt`. Protect exactly `createdBy` and `createdAt` per the locked CONTEXT R341
decision — do NOT restrict `pcExportedAt`/`pcPlanId` (they have their own legitimate export branch 2)
and do NOT touch branches 2 (export) or 3 (reopen), which already use `hasOnly()` and cannot reach
provenance fields.

This is safe against every live write path: `updateService` (services.ts:410-428), `markAsPlanned`,
`reopenService`, and the Roles-tab writes all use `updateDoc` with only their passed fields +
`updatedAt`, and NONE writes `createdBy`/`createdAt` — so `affectedKeys()` never contains them on a
legitimate draft save. Before finalizing, re-read services.ts:410-480 and the Roles-tab writes
(services.ts:632-712) to reconfirm no draft write path emits `createdBy`/`createdAt`; if one does,
STOP and surface it rather than shipping a guard that breaks a live save.

Keep the comment short per the project comment convention (rationale belongs in the SUMMARY/finding,
not a paragraph in-rule): a one-line note citing R341/SEC-R-03 and the mirrored preservesCreatedBy
idiom is enough.

Then add tests to the existing `Service draft lock (R036/R037)` describe in `src/rules.test.ts`
(:1891), reusing its `seedService`/`editorDb`/`svcRef` helpers:
- DENY: seed a draft service with `createdBy: 'userA'`; an editor `updateDoc(svcRef, { createdBy: 'someoneElse', updatedAt: new Date() })` must `assertFails`.
- DENY (forge-by-add): seed a draft service with NO createdBy; an editor `updateDoc(svcRef, { createdBy: 'forged', updatedAt: new Date() })` must `assertFails`.
- ALLOW: seed a draft service with `createdBy: 'userA'`; an editor `updateDoc(svcRef, { notes: 'edited', updatedAt: new Date() })` (createdBy untouched) must `assertSucceeds`.
  </action>
