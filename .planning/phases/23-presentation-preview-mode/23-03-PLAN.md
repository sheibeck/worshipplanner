<objective>
Layer media playback into the presentation canvas built by plan 23-02: mount the chromeless
players, drive them imperatively across slide transitions, and render the three degraded states the
UI-SPEC specifies — missing media, blocked audio/video, and silently-playing muted video.

Purpose: this is the phase's second genuinely-new-logic area. Nothing currently consumes the
players' `error` or `autoplay-blocked` emissions; both are new wiring, and getting the
pause-before-advance ordering wrong is the documented way to end up with two audio tracks playing
at once mid-rehearsal.

Output: a viewer that plays a service's attached media hands-free and degrades quietly when it
cannot.
</objective>

<planner_assumptions>
1. **"Media unavailable" placement.** UI-SPEC puts the notice at "bottom-left, near but visually
   distinct from the progress bar", which is the same corner the bottom chrome bar occupies.
   Decision: render it at `absolute bottom-20 left-6` — directly above the chrome bar, visually
   separated, and deliberately NOT bound to the chrome auto-hide, since a volunteer who steps away
   and comes back must still see that a slide's media is gone.

2. **A single `mediaFailed` flag per slide, not per element.** A slide can theoretically carry both
   `audioUrl` and `videoUrl`. Decision: one flag, one notice — the first `error` from either player
   removes both and shows one notice. Splitting into two flags would double the notice copy for a
   case the assembler does not currently produce, and UI-SPEC specifies a single notice string.
</planner_assumptions>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Firebase Storage media URL → `<audio>` / `<video>` `src` | A Storage download URL resolved by Phase 22 crosses into a browser media element. The URL may be stale (retention cleanup) or 404. |
| Media element error events → viewer UI | An untrusted network/decoder outcome drives a UI state transition. |

## STRIDE Threat Register (ASVS L1, block on `high`)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-23-07 | Information Disclosure | Media failure surface in `PresentationViewer.vue` | medium | mitigate | The degraded path renders exactly one fixed literal, `Media unavailable`. The `error` handler never interpolates the failing URL, the `Event` object, or any exception text into the DOM — a Storage download URL carries an access token and must never be projected onto a screen. Grep-asserted indirectly by the exact-copy acceptance criteria. |
| T-23-08 | Denial of Service | Media playback across slide transitions | medium | mitigate | `pauseCurrentMedia()` runs before every index change, on exit, and on unmount; `mediaFailed` removes an errored element instead of retrying; no retry loop and no timer exists. A failing or expired media URL therefore cannot stall navigation or accumulate playing elements. |
| T-23-09 | Tampering | Reaching into child-component internals to read muted state | low | mitigate | The driving layer reads the exposed `isMuted` accessor added in plan 23-01 rather than reaching through `$refs` into `VideoPlayer`'s private element; grep-asserted to zero `$refs` occurrences. This keeps the player's contract the only coupling surface. |
