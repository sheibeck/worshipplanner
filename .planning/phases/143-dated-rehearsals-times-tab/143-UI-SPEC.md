# Phase 143 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Brownfield: every token below is derived from existing code (`ServiceEditorView.vue` tab strip ~L818-916, header
> Times block ~L240-330, `SettingsView.vue` ~L555-600). No new design system, no new dependencies, no new colors.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Tailwind v4 utility classes, hand-written Vue 3 SFCs; no `components.json`) |
| Preset | not applicable |
| Component library | none (native `<input type="date|time">`, `<button>`) |
| Icon library | none for this phase (inline SVG only if needed; none required) |

Surface: dark UI, `gray-950` page, `gray-900` panels/cards, `gray-800` inputs and secondary buttons.

Component split (Claude's discretion, recommended): extract `src/components/ServiceTimesPanel.vue` from
`ServiceEditorView.vue`. It receives `rehearsals`, `reportTime`, `serviceDate`, `canEdit`, `defaultTimes` as props and
emits `add`, `remove`, `date-change`, `time-change`, `report-time-change`. The parent keeps the handlers (each re-checks
`canEditService`, R036) and the `updateService(id, { rehearsals, reportTime })` autosave path. The panel root
carries the `v-show`, `id`, `role`, `aria-labelledby` attributes (as on sibling panels).

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `gray-950` (#030712) page / `gray-900` (#111827) active tab + panel surface | Page background, active tab fill, section cards |
| Secondary (30%) | `gray-800` (#1f2937) with `gray-700` border; text `gray-100` / `gray-300` / `gray-400` | Inputs, chips, secondary controls, helper text |
| Accent (10%) | `indigo-300/400/500/600` | Active tab text/underline, "+ Add rehearsal" primary button, input focus ring |
| Destructive | `red-400` / `red-300` hover | "Remove" row action text only (existing treatment) |
| Warning (semantic, existing) | `amber-300` text, `amber-900/40` fill, `amber-800` border, `amber-400` dot | Legacy "Needs a date / Needs a time" marker, tab dot, highlighted empty input border |

Accent reserved for: (1) active tab text + underline (`text-indigo-300 border-indigo-500 bg-gray-900`, copied verbatim
from siblings), (2) the "Add rehearsal" button fill (`bg-indigo-600 hover:bg-indigo-500 text-white`), (3) the focus ring on
inputs (`focus:ring-1 focus:ring-indigo-500`), (4) the selected state of a default-time chip whose value equals the
form's current time (`border-indigo-500 text-indigo-300`). Nothing else uses indigo.

Warning color (amber) is used only for the legacy-row signal, reusing the existing amber badge recipe from
`ServiceEditorView.vue` L1563 (`bg-amber-900/40 text-amber-300 border border-amber-800`):
- "Needs a date" / "Needs a time" marker: `inline-flex items-center px-1.5 py-0.5 rounded text-[10px] font-medium bg-amber-900/40 text-amber-300 border border-amber-800` (reuses the existing 10px badge exactly; it is an inherited exception to the 12px floor).
- Highlighted empty date/time input on a legacy row: swap the border to `border-amber-700` and the focus ring to `focus:ring-amber-500`; keep `bg-gray-800 text-gray-100`.
- Tab dot: `inline-block h-2 w-2 rounded-full bg-amber-400 ml-1.5 align-middle`, `aria-hidden="true"`, with the tab button carrying an accessible description (see Interaction).

Disabled controls: `disabled:opacity-50 disabled:cursor-not-allowed` (existing `disabled:opacity-50` convention).

## Layout & Components

**Focal point:** in the editable state, the Rehearsals add form (the only primary/indigo action on the tab); in the read-only state, the rehearsal list.

### Tab button (R444)

- New 6th (editor) / 3rd (viewer) tab, appended after Messages, **no `v-if`** (visible to everyone, like Slides).
- Copy a sibling button verbatim: `id="svc-tab-times"`, `ref="timesTabButtonRef"`, `role="tab"`, `type="button"`,
  `:aria-selected="activeTab === 'times'"`, `aria-controls="svc-panel-times"`, `:tabindex="activeTab === 'times' ? 0 : -1"`,
  class `px-4 py-2 text-sm font-medium rounded-t-md transition-colors -mb-px border-b-2` with the standard active/inactive
  `:class`, `@click="activeTab = 'times'"`. Label text: `Times`.
- Order: editor = Service Order, Slides, Roles, Stage Layout, Messages, Times. Viewer = Service Order, Slides, Times.
  Add `'times'` to `visibleTabOrder` after `'messages'`, `tabButtonRef`, and the `activeTab` / `ServiceEditorTabId` unions.
- Amber dot (editors only, `authStore.isEditor && hasNonDisplayableRehearsal`): `<span data-testid="times-tab-attention-dot" class="inline-block h-2 w-2 rounded-full bg-amber-400 ml-1.5 align-middle" aria-hidden="true" />` after the label, plus
  `<span class="sr-only">(needs attention)</span>` inside the button. Dot disappears reactively once every row is displayable.
  Shown regardless of Draft/locked status for editors (it is an information signal, not an edit control).

### Panel (R444)

```
<div v-show="activeTab === 'times'" id="svc-panel-times" role="tabpanel" aria-labelledby="svc-tab-times" data-testid="times-panel">
```

Content wrapper: `space-y-4`. Two sections, each a card `rounded-lg bg-gray-900 border border-gray-800 p-4` (same card
recipe as SettingsView L550), each headed by `<h2 class="text-sm font-semibold text-gray-300 mb-3">`.

### Editable state (`canEditService`)

**Section 1 — Report time** (`data-testid="report-time-section"`)
- Heading: `Report time`.
- Single `<input type="time" id="report-time-input" data-testid="report-time-input">`; classes exactly
  `bg-gray-800 border border-gray-700 text-gray-100 rounded-md px-2 py-1.5 text-sm focus:outline-none focus:ring-1 focus:ring-indigo-500`
  (same classes and test id as the current input; `@change` -> `onReportTimeChange`). Associated `<label class="block text-xs text-gray-400 mb-1" for="report-time-input">`.
- Helper under the input: `text-xs text-gray-400 mt-1` — "Day-of call time on {service date}" where service date is
  rendered with the existing short date formatter (`formatRehearsalDateShort`). If the service has no date yet, drop the
  "on ..." clause: "Day-of call time".
- Clearing the report time is allowed (it is optional; unchanged behavior).

**Section 2 — Rehearsals** (`data-testid="rehearsals-section"`)
- Heading: `Rehearsals`.
- List `space-y-2`, rows sorted chronologically by `sortRehearsals` (date, then time; non-displayable legacy rows sort
  first so they are seen). Each row: `flex flex-col gap-2 sm:flex-row sm:items-center` (stacks on mobile <640px, inline
  at >=640px):
  - date input (`type="date"`, `data-testid="rehearsal-date-input"`, existing input classes),
  - time input (`type="time"`, `data-testid="rehearsal-time-input"`, existing input classes),
  - `Remove` text button (`text-xs text-red-400 hover:text-red-300 transition-colors`, `data-testid="remove-rehearsal-btn"`),
    `sm:ml-auto` is NOT used; Remove sits right after the time input (`gap-2`) to match today.
  - On a legacy non-displayable row: the marker badge (before the inputs on mobile, after Remove on desktop is not required;
    place it first in the row so it is read first: `order-first` is unnecessary, simply render it first in DOM), plus the amber
    border on whichever input is empty. Marker text: "Needs a date" if date is empty; else "Needs a time" if only time is empty.
    The row's `data-testid="rehearsal-row-needs-fix"`.
- Inline add form directly below the list, separated by `border-t border-gray-800 pt-3 mt-3` when the list is non-empty
  (omit the divider when the list is empty). `data-testid="add-rehearsal-form"`:
  - Wrapper `flex flex-col gap-2 sm:flex-row sm:items-end`.
  - Date input with `<label class="block text-xs text-gray-400 mb-1" for="new-rehearsal-date">Date</label>`, `data-testid="new-rehearsal-date"`.
  - Time input with label `Time`, `data-testid="new-rehearsal-time"`, **pre-filled from `rehearsalTimeDefaults[0]`** when the form is empty (and again after each reset).
  - Button `data-testid="add-rehearsal-btn"`, label `Add rehearsal`, classes
    `rounded-md bg-indigo-600 px-4 py-2 text-sm font-medium text-white transition-colors hover:bg-indigo-500 disabled:opacity-50 disabled:cursor-not-allowed`
    (the existing Run-button recipe). `:disabled="!canEditService || !newDate || !newTime"`.
  - Below the inputs, only when `rehearsalTimeDefaults.length > 1`: a chip row `flex flex-wrap items-center gap-2 mt-2` with a lead-in
    `<span class="text-xs text-gray-400">Default times:</span>` and one chip button per default time:
    `rounded-full border border-gray-700 bg-gray-800 px-3 py-1 text-xs text-gray-200 hover:bg-gray-700 transition-colors`,
    selected (value equals the form time): `border-indigo-500 text-indigo-300`. Chip label = `formatWallClockTime(time)`; `type="button"`; `data-testid="rehearsal-default-chip"`; `aria-pressed` reflects selected. Click sets the form's time only (does not add a row). With exactly one default no chips render (it is simply the pre-fill).
  - After a successful add: form date clears, time re-pre-fills from the first default (or clears if none), focus returns to the date input.
- Helper line below the Rehearsals heading (`text-xs text-gray-400 mb-3`): "Every rehearsal needs a date and a time."

### Read-only state (viewer, or editor on a non-Draft service)

- Section cards as above but no inputs, no add form, no Remove, no chips, no attention markers (legacy rows hidden).
- Report time row: `text-sm text-gray-300` — `Report time: 8:00 AM` (label `text-gray-400`, value `text-gray-100`), rendered via `formatWallClockTime`. Omitted if not set.
- Rehearsals: `<ul class="space-y-1">`, each `<li class="text-sm text-gray-100">` — `{formatRehearsalDateShort(date)}, {formatWallClockTime(time)}` e.g. "Thu, Nov 6 · 7:00 PM" (exact separator follows `formatRehearsalDateShort` + ", " as in the current read-only string). Only `isDisplayableRehearsal` rows, chronological. `data-testid="times-readonly"`.
- When both report time and rehearsals are empty: the empty state below.

### Removed (R444)

The header `data-testid="service-times-section"` block (L240-L332 incl. its comment) is deleted entirely. Nothing time-related
remains above the tab strip. Its inline comment is replaced by at most a 1-2 line comment on the new panel (comment convention).

### Settings copy (R442)

`SettingsView.vue` ~L553-556 helper text becomes (same `text-xs text-gray-400 mb-3` classes):
"Default rehearsal time(s) pre-fill the time when a planner adds a rehearsal to a service, and the report time is copied onto every new service. Dates are always chosen per service." No structural or class change; the "+ Add rehearsal time" button label in Settings is unchanged.

## Interaction Contract

- **Add:** creates a row only on submit with both date and time set; button is disabled until both are non-empty. Pressing Enter in either form input triggers Add when enabled (wrap in `<form @submit.prevent>` with `type="submit"` on the button, or equivalent key handler). No row is ever created undated.
- **Edit existing rehearsal:** date `@change` / time `@change` write through the existing debounced autosave. Setting date to `''` on a row that already had a date reverts to the previous value; same for time. On revert, force the DOM input back to the previous value (`$event.target.value = previous`) and show an inline message `text-xs text-amber-300 mt-1` ("A rehearsal needs a date. Use Remove to delete it." / "A rehearsal needs a time. Use Remove to delete it.") that clears on the next change or after 4 seconds. The message is `role="status"`.
- **Legacy row (no date or no time):** the marker and amber border are shown; setting the missing field clears the marker immediately. The reject-clear rule applies only once the field has a value.
- **Remove:** immediate, no confirm dialog (consistent with existing Remove behavior in Times and Settings; recoverable by re-adding). Focus moves to the Add form's date input after removal.
- **Save status:** the existing persistent save status line in the editor header region continues to reflect autosave (no new indicator in the panel).
- **Keyboard / a11y:** tab uses the existing roving-tabindex (ADR-0217) with arrow keys; `'times'` must be in `visibleTabOrder` so ArrowRight from Messages (editor) / Slides (viewer) wraps correctly. All inputs have visible `<label>`s (new form, report time) or an `aria-label` on row inputs ("Rehearsal date", "Rehearsal time"). Touch targets: inputs render about 34px tall on desktop (text-sm + inherited `py-1.5` + border, identical to today's controls) and the Add button about 36px; on mobile (<640px) form inputs and Add button are full width (`w-full`) so they are comfortable tap targets. Amber is never the only signal: the text marker "Needs a date" accompanies it, and the tab dot has `sr-only` text.
- **Tab persistence:** switching tabs uses `v-show` so form state (a half-filled add form) survives tab changes within a session.

## UI Considerations

Applicable state considerations resolved: 9 covered, 1 backstop, 0 unresolved

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | Rehearsals list (editable) | ✅ covered | Zero rehearsals renders the "No rehearsals yet" empty state with the add form visible below it (see Copywriting Contract). |
| empty | Times panel (read-only) | ✅ covered | With no report time and no displayable rehearsal, the read-only panel renders the "No times set" empty state. |
| one/many | Rehearsal rows + default chips | ✅ covered | One default time shows no chips (pre-fill only); two or more render one chip per default; rows are sorted chronologically by `sortRehearsals`. |
| partial | Legacy rows missing date and/or time | ✅ covered | Any non-displayable row in the editable view renders "Needs a date" / "Needs a time" with an amber-highlighted empty input; read-only views and both projections still filter it via `isDisplayableRehearsal`. |
| partial | Add form | ✅ covered | The Add button is disabled until both date and time are non-empty; no undated row can be created. |
| error | Cleared date/time on an existing row | ✅ covered | The edit reverts to the previous value, the input is forced back, and the inline revert message is shown. |
| permission | Editor non-Draft / viewer | ✅ covered | Times tab is visible to everyone; edit controls render only when `canEditService`, otherwise the read-only list is shown; amber dot is editors-only. |
| responsive | Rehearsal rows / add form | ✅ covered | Rows and the add form stack vertically below 640px with full-width inputs, inline from 640px up. |
| overflow | Tab strip with 6 tabs on narrow screens | 🧪 backstop | The strip already has `overflow-x-auto scrollbar-hide`; verify via visual check at 360px that the Times tab is reachable by scroll and the active tab scrolls into view. |
| long-text | Many rehearsals (10+) | covered | No cap, no inner scroll: the list grows with the page (the tab panel scrolls with the editor). Real services carry 0-3 rehearsals, so a cap adds no value. |
