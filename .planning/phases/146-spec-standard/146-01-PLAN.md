<objective>
Build the automated spec check test-first: a pure module that reads test titles with the `typescript` parser, parses
specs line by line, and reports every uncited criterion by ID, wired into a bare `npx vitest run`.

Purpose: The repo has no CI, so this check inside the root run is the only thing that can hold a spec to its tests. A
citation must mean a test that can really run, so the extractor has to understand skip chains and nesting, which a
regex cannot.
Output: `src/__tests__/specCoverage.ts` and `src/__tests__/specCoverage.test.ts`, with RED and GREEN commits.
</objective>

## Flagged assumptions

- **The edge probe left R457 unclassified.** Its shapes came from manual review, not the probe, so that list may be
  incomplete. The table above names the test that answers each one.
- **The `(Rnnn)` source suffix on a criterion is a convention the check does not enforce.** Phase 147's trace of
  R459-R465 is proved by that phase's verification.
- **Prohibitions stay open for a human.** They are `judgment`-tier with no check descriptor, so `/gsd-verify-work`
  disposes them flagged-unverified and routes them to human review. A test named in a statement is backing, not a wired
  check.
- **Not counted beyond the locked `.skip` and `.todo`:** `fails`, `skipIf`, `runIf`. These are Claude's discretion
  (research A1), under the intent of the owner's skipped-test decision: a citation must mean a test that can really run.
  None is used in the repo today. ADR-0248 records this (Plan 02 Task 2).
- **A describe-level citation needs an active child** (research A4). Claude's discretion for the same reason: a suite
  with no counted test runs nothing. ADR-0248 records this too.
- **`README.md` is excluded from the spec scan** (A3), so a later index cannot register as a criterion-less spec.
- **Planner additions to research's extractor, proven by a probe during planning.** These are also Claude's discretion
  for the same reason, and ADR-0248 records them. Research's walker counts a test
  nested in `describe.skip(NAME, ...)` when the title is a variable, a test with a `{ skip: true }`, `{ todo: true }` or
  `{ fails: true }` options object, and a test with no body, which the runner turns into a todo
  (`node_modules/@vitest/runner/dist/index.js` line 779). All three break the locked skipped-test decision, so Task 1
  corrects them. A test with an empty body is also not counted, because the roadmap says nothing may quiet the check
  with an empty test. The amended walker passed 45 edge cases and found zero wrongly excluded tests across all 256 real
  test files (6,393 test calls).
- **`lib` and `dist` are not filtered inside the three roots**, unlike research's safety net. `functions/lib` and the
  root `dist` sit outside the roots, and the filter would silently drop a future `src/lib/x.test.ts`.
- **Static proof only.** `ctx.skip()` in a body, a title held in a variable and aliased imports cannot be seen. A
  variable title fails safe, since it cites nothing. Plan 02 documents the limit.
