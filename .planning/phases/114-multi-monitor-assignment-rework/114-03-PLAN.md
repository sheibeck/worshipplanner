<objective>
Generalize the Run-mode output orchestration from exactly two hard-coded windows (`wp-audience` / `wp-confidence`) to N windows driven by the saved assignments — so multiple Audience monitors are supported (R325), any number of displays are handled (R324), each window carries its target fingerprint for macOS placement (R327), and every display shows its nickname (R338).

Purpose: The v2.4 launch path assumes one Audience and one Confidence window. A real 3-monitor setup with two Audience outputs cannot be expressed in that model. This plan replaces the singleton refs, fixed window names, fixed URLs, and two-card panels with an assignment-iterating model keyed by stable fingerprint identity, and adds the "at least one Audience to go live" gate.

Output: An assignments-driven `useRunControl.ts`, dynamic `RunDisplaysPanel.vue` / `RunPreflightPanel.vue`, updated `RunControlView.vue` wiring, and regenerated Run-mode tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| opener -> popup (same-origin URL) | The target fingerprint travels to each output window as a same-origin URL query param the opener constructs. |
| saved mapping -> window orchestration | The saved mapping (localStorage) drives which windows open and where. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-114-03 | Spoofing | screen query param passed opener->popup | low | accept | The fingerprint is delivered via a same-origin URL query the opener itself builds (not a forgeable cross-window postMessage); a spoofed value at worst selects the wrong local display, no cross-origin exposure. Rationale accepted per RESEARCH Security Domain. |
| T-114-04 | Denial of Service | N-window open loop | low | mitigate | window.open returns null when blocked; openAll* treat a null handle as "not opened" and never throw, and go-live only claims live when at least one Audience window actually opened (preserves the existing never-throw contract). |

No package installs occur in this plan — no supply-chain checkpoint required.
</threat_model>
