<objective>
Add the macOS placement fix (R327): from inside each output popup, once it independently confirms Window Management permission, re-resolve its screens and call `document.documentElement.requestFullscreen({ screen })` targeting the assigned display — the documented, spec-backed mechanism that lands fullscreen on a specific screen without relying on the JS `moveTo` positioning the field report found broken on macOS.

Purpose: The opener's `window.open` feature-string + `moveTo` is exactly what fails on macOS/Chrome. This adds a corrective SECOND step owned by the popup (the only context that can fullscreen its own document element on a chosen screen), leaving the existing plain-fullscreen path and the manual Go-fullscreen button intact as fallbacks.

Output: `attemptScreenTargetedFullscreen` in `useOutputWindow.ts`, wired into mount, reading the target fingerprint from the route query — with the two output views unchanged.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| popup -> Window Management API | The popup calls getScreenDetails()/requestFullscreen({screen}) in its own context under an already-granted permission. |
| route query -> popup | The target fingerprint arrives as a same-origin URL query the opener constructed. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-114-05 | Spoofing | screen query param read by the popup | low | accept | The fingerprint comes from a same-origin URL the opener built, not a forgeable cross-window message; a bad value only mis-selects a local screen and the attempt fails closed to the manual fallback. |
| T-114-06 | Denial of Service | popup-side getScreenDetails/requestFullscreen | low | mitigate | The whole attempt is wrapped so any rejection/absence returns false and never throws; the projector still renders content immediately (placement is never allowed to block first paint). |
