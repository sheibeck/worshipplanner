## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| volunteer browser -> confirmations subcollection | the scoped write; enforcement is the Plan 01 rule, this UI must not attempt to write outside the caller's own key |
| route/props -> identity | the confirming email is derived from auth.currentUser, never from a route/query/prop |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-133-08 | Spoofing | confirming identity | high | mitigate | emailLower derived only from auth.currentUser?.email (never a prop/route value); the Plan 01 rule independently re-checks own-email, so a tampered client cannot escalate |
| T-133-09 | Tampering | write payload | medium | mitigate | UI writes only the 6 rule-allowlisted fields with status:'confirmed'; any extra field or foreign key is denied by the Plan 01 rule regardless of client behavior |
| T-133-10 | Information Disclosure | confirmations subscription | low | accept | the volunteer's list() is already permitted (isAssignedVolunteer) and returns only this service's confirmations for a service they are assigned to; no cross-service/tenant exposure |
</threat_model>
