## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | none — this phase adds a filter, not an action. The `<select>`'s default/reset option is the CTA-equivalent: **"All churches"** |
| Church filter — default option | `All churches` (value: empty string / null — shows every church's services, unfiltered) |
| Church filter — per-church option | The church's own `orgName` verbatim (e.g. "Grace Fellowship") |
| Church filter — missing-name fallback (per-option) | `Unnamed church` — shown ONLY for a distinct church whose `rehearseAccess` docs predate the `orgName` field (pre-backfill). Never blank, never a raw orgId. |
| Sidebar volunteer label — single church | The church's `orgName` verbatim, in the exact same slot/classes as the admin's `authStore.orgName` |
| Sidebar volunteer label — single church, name missing | `Your church` (singular fallback — distinct from the plural-list "Unnamed church" fallback above, since there's exactly one candidate and no ambiguity to resolve) |
| Sidebar volunteer label — multi-church, "All churches" selected | `Multiple churches` (130-REVIEW IN-01: the shipped `volunteerChurchLabel` computed and its `AppSidebar.test.ts`/`130-VALIDATION.md` coverage use this literal, not the filter's own `All churches` default-option label — reconciled here so spec, validation, and code agree) |
| Sidebar volunteer label — multi-church, one church selected | That church's `orgName` (or `Unnamed church` if absent), same as the filter option |
| Error state | Unchanged — reuses `MyScheduleView.vue`'s existing "Couldn't load your schedule. Check your connection and try again." + Retry. No new error path (the switcher is a pure client-side filter over already-loaded docs — it cannot itself fail) |
| Empty state (after filtering) | `No upcoming services for {church name}.` when a specific church is selected and the filtered set is empty but `mySchedule.docs` as a whole is non-empty (distinguishes "nothing at this church" from the existing global empty state, which stays for the true zero-docs case) |
| Destructive confirmation | not applicable — no destructive action in this phase |

## Component Specifications

### 1. My Schedule church filter

**Location:** `src/views/MyScheduleView.vue`, in the page header area, directly below/beside the greeting `<h1>`/summary line (the `<div class="mb-8">` block, L35-38), before the schedule sections render.

**Visibility gate:** renders ONLY when the distinct-church count derived from `mySchedule.docs` (by `orgId`) is `> 1`. Exactly 0 or 1 distinct church → this element does not render at all (R405 — zero DOM footprint, not just visually hidden).

**Markup pattern (reuse `SongFilters.vue` verbatim):**

```html
<select
  :value="selectedChurchId ?? ''"
  @change="onChurchChange(($event.target as HTMLSelectElement).value)"
  data-testid="church-filter"
  class="rounded-md bg-gray-800 border border-gray-700 px-3 py-2 text-sm text-gray-100 focus:outline-none focus:ring-1 focus:ring-indigo-500 focus:border-indigo-500"
>
  <option value="">All churches</option>
  <option v-for="c in distinctChurches" :key="c.orgId" :value="c.orgId">
    {{ c.orgName || 'Unnamed church' }}
  </option>
</select>
```

**Behavior:** a pure client-side filter over the already-loaded `mySchedule.docs` array (filters by `orgId` before `groupMySchedule()` runs). It NEVER calls `authStore.selectOrg()` or touches org context — distinct from `AppSidebar.vue`'s admin church-switcher panel, which does. Selection defaults to "All churches" (empty value) on load; persistence across sessions is optional (Claude's discretion — a plain `ref`, session-only, is sufficient; localStorage persistence is a nice-to-have, not required for R403/R404/R405).

**Sort order:** distinct churches listed alphabetically by `orgName` (fallback-labeled entries sort using the literal string "Unnamed church").

### 2. Volunteer sidebar church-name label

**Location:** `src/components/AppSidebar.vue`, the SAME slot as the admin org-name block (L16-30), same box (`px-5 py-2 border-b border-gray-800`), same text treatment (`text-xs text-gray-500 truncate`).

**Visibility gate:** renders for a zero-membership volunteer session (`authStore.orgName` is falsy AND the user is signed in with My Schedule data available) — must NOT disturb the existing admin path, which keeps rendering purely off `authStore.orgName`/`authStore.superAdminOutsideOwnChurch` unchanged.

**Label resolution (in priority order):**
1. Multi-church volunteer with a specific church selected in the My Schedule filter → that church's `orgName` (or "Unnamed church" fallback).
2. Multi-church volunteer with "All churches" selected (the default) → literal `Multiple churches` (130-REVIEW IN-01).
3. Single-church volunteer (exactly one distinct church across their `rehearseAccess` docs) → that church's `orgName` (or `Your church` fallback if missing).
4. No `rehearseAccess` docs at all yet (loading, or a genuinely-zero-assignment volunteer) → render nothing in this slot (matches the admin path's own `v-if` — an empty slot is the existing pattern for "nothing to show here," not a new blank state).

**Markup pattern (extend the existing `v-if`/`v-else` chain at AppSidebar.vue L16-30 with one more branch — do not restructure the admin branches):**

```html
<div
  v-if="authStore.orgName || authStore.superAdminOutsideOwnChurch"
  class="px-5 py-2 border-b border-gray-800"
>
  <!-- existing admin branches, unchanged -->
</div>
<div v-else-if="volunteerChurchLabel" class="px-5 py-2 border-b border-gray-800">
  <p class="text-xs text-gray-500 truncate">{{ volunteerChurchLabel }}</p>
</div>
```

No "viewing as super-admin" sub-line applies to the volunteer branch (that concept doesn't exist for a zero-membership session).
