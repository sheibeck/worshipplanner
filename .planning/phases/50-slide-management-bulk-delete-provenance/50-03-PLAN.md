<objective>
R108 (part 1 of 2 — RECORD the page). Give every parsed imported deck slide a render-stable
page reference and carry it onto a hand-added imported entry's `sourceRef` at add-time. Part 2
(plan 50-05) CONSUMES it to resolve the slide. This plan produces the data; on its own it is
type-clean and test-green but does not yet change resolution (the multi-image deck still hangs
until 50-05 ships — that is expected and acceptable as an intermediate state).

Why a source PAGE, not a position: `mapAstToSlides` iterates one AST node per source PPTX slide,
SKIPS slides with neither text nor images, and emits ONE ENTRY PER IMAGE on a multi-image slide —
so the parsed array index is structurally decoupled from the rendered-page count in both directions
(see importedRenderReconciler.ts's header, "Fact 1"). The render service renders one page per
source slide in order, so the source slide's 1-based index IS its rendered page number. Recording
that index at parse time is the only render-stable reference available.

Purpose: R108 supersedes the interim ec217aa 1:1 positional resolver, which resolves hand-added
imported slides only when parsed-slide count equals rendered-page count. A multi-image deck fails
that equality and hangs on "Rendering".

## Artifacts this plan produces
- `MappedSlide.sourcePage: number` (1-based source slide index), set in `mapAstToSlides`.
- `ImageSlide.sourcePage?` / `TextSlide.sourcePage?` (optional, mirrors the Mapped* shapes).
- `SourceRef` imported variant widened to `{ kind: 'imported'; importId; innerSlideId; renderedPage? }`.
- `PptxImportModal` threading `sourcePage` from the `parsePptx` callable into stored deck slides
  (and setting it for image-only imports).
- `SlideGrid.onImportConfirmed` recording `renderedPage` on each new imported entry's `sourceRef`.
</objective>
