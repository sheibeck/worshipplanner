## Flagged assumptions

- **The new settings getter must be ref-backed.** `SettingsView.test.ts` mocks settings through getters over plain
  `let` variables, which Vue cannot watch, so AC-RHD-67 would never fire. Back only the new getter with a `ref`.
- **`setValue` is unreliable for the None option.** With `:value="null"` the option has no value attribute. Select
  options with `findAll('option')[n].setSelected()`.
- **Two existing tests change on purpose:** the `R442` help-text test at `SettingsView.test.ts:364` and `WR-02` at `:370`.
- **The panel needs no marker code.** It renders date and time only, so AC-RHD-53 is a parity test.
- **`SettingsView.test.ts` has ten resets to mirror.** Each of its ten top-level describes resets
  `mockRehearsalTimeDefaults` in its own `beforeEach`.
- **AC-RHD-48 is scoped to the Date field.** `Default times:` beside the chips (`ServiceTimesPanel.vue:327`) is existing,
  correct text, so the test must not scan the whole form.
- **Six criteria pass at RED by design:** AC-RHD-41, 42, 44, 48, 53 and 54. Today's Date is always blank, a typed date
  already stays, and nothing renders the marker. They are regression guards. Every other RED test must fail.
