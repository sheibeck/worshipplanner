## Component Contract

### 1. Settings: "Default rehearsal day" select (new)

Placement: inside the existing "Rehearsal & Report Defaults" card, directly under the help paragraph and above "Default rehearsal time(s)". Day before time follows the order the help text describes (day, then first default time). It sits in its own block; the following "Default rehearsal time(s)" block keeps its existing markup and gains a `mt-4` wrapper gap so the card's block rhythm (`mt-4`) holds.

Markup contract:

| Part | Value |
|------|-------|
| Wrapper | `<div>` (no extra classes) |
| Label | `<label for="rehearsal-default-day" class="block text-xs text-gray-400 mb-1">Default rehearsal day</label>` (same class string as the card's other labels; `for`/`id` added so the label names the control, which the neighbouring labels lack) |
| Select | `id="rehearsal-default-day"`, `data-testid="rehearsal-default-day-select"`, `:disabled="!authStore.isEditor"` |
| Select classes | `bg-gray-800 border border-gray-700 text-gray-100 rounded-md px-3 py-2 text-sm focus:outline-none focus:ring-1 focus:ring-indigo-500` (identical to the card's time inputs; no width utility, so it sizes to its longest option, "Wednesday", like the time inputs size to their content) |
| Options, in order | `None`, `Sunday`, `Monday`, `Tuesday`, `Wednesday`, `Thursday`, `Friday`, `Saturday` |
| Initial selection | `None` when the org has no value (old orgs read as none). Otherwise the saved weekday. |
| Value encoding | planner's choice (number or name), per CONTEXT. "None" must be distinct from Sunday. |
| Persistence | held in local state like `rehearsalTimeDefaultsInput` and saved only by the existing "Save defaults" button through `onSaveRehearsalDefaults`. Choosing an option writes nothing by itself. |

Interaction states (all inherited from existing card behaviour):

| State | Behaviour |
|-------|-----------|
| Default | gray-800 fill, gray-700 border, gray-100 text |
| Focus | outline removed, 1px indigo-500 ring |
| Disabled (non-editor) | native `disabled`. It shows the saved value, cannot be changed, and no Save button renders. Same as the card's time inputs. |
| Saving | existing "Save defaults" button goes `disabled:opacity-50` while `isSavingRehearsalDefaults` |
| Saved | existing `<p class="text-green-400 text-sm mt-2">Saved!</p>` |
| Save failed | existing `<p class="text-red-400 text-sm mt-2">{{ rehearsalDefaultsSaveError }}</p>`, and the existing rollback restores the previous weekday too |

Keyboard and a11y: native select (arrow keys, type-ahead, Space/Enter to open). Label is associated by `for`. No `aria-describedby` is added; the card help text above applies to the whole card, as it does today.

No second inline control, no "clear" link: choosing `None` is the clear.

### 2. Settings: help text (replaced)

Replace the contents of `<p data-testid="rehearsal-defaults-helper">`. Keep the element, its classes (`text-xs text-gray-400 mb-3`) and its test id. New text, verbatim from CONTEXT, one paragraph:

> New services start with one rehearsal on the default day at the first default time. The report time is copied onto every new service. Changing these defaults doesn't affect existing services.

`src/views/__tests__/SettingsView.test.ts:367` changes on purpose to assert this text. The apostrophe in "doesn't" is a plain `'` in the template, as written above.

### 3. Times tab: add-rehearsal form Date input (value only)

No markup, class, label, test id or layout change. The input stays `id="new-rehearsal-date"`, `data-testid="new-rehearsal-date"`, `type="date"`, `max="9999-12-31"`, class `${inputBase} ${inputOk}`, with its `Date` label.

Behaviour contract:

| Situation | Date input shows |
|-----------|------------------|
| Settings weekday set, service has a date, service has no rehearsal on the computed default date | the default date: the most recent default weekday on or before the service date (same day when the service falls on that weekday) |
| Weekday set, but the service already has a rehearsal on that date | blank |
| Weekday is None or the org has no value | blank (as today) |
| Service has no date or an invalid date | blank |
| Weekday set, no default time | date still fills, Time stays blank (Time already follows `defaultTimes[0] ?? ''`); Add stays disabled until Time is filled |
| Planner has edited the date | their value stands until they add the rehearsal. It does not follow later service-date changes. |
| Planner has not touched the date | the shown value follows the service date and the Settings weekday as they change |
| After "Add rehearsal" is pressed | the planner's edit is cleared, so the field returns to the computed default. If that date now holds the just-added rehearsal, it shows blank (R464). |

Implementation shape, as a constraint on the planner: mirror the existing `newTime` / `newTimeOverride` pair (`newDateOverride: string | null`, `newDate` as a writable computed that returns `newDateOverride ?? defaultDate`). The submit handler resets the override to `null`, where it currently sets `newDate.value = ''`. The weekday maths use plain `YYYY-MM-DD` arithmetic, not a local-time `new Date('YYYY-MM-DD')` (R460, ADR-0009). The component gets the Settings weekday as a prop alongside `defaultTimes` (name is the planner's).

`canAdd` is unchanged. Add stays disabled until Date and Time both match their patterns. A pre-filled date therefore makes Add enabled as soon as a time exists, which is the intended speed-up.

Focus: unchanged. After Add or Remove the Date input still takes focus via `focusAddDate()`.

No note, hint, badge or helper text says the date came from a default (CONTEXT: "No note").

### 4. Times tab: rehearsal rows (no change)

An auto-added rehearsal renders exactly like any other row (same `rehearsal-row` test id, same inputs, same Remove button), for every role. No marker, tooltip or badge. The read-only list and the "No times set" empty state are unchanged. The marker field is never rendered and never reaches share or snapshot payloads (R465).

## UI Considerations

Applicable state considerations resolved: 5 covered, 1 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | Default rehearsal day select | ✅ covered | An org with no saved weekday shows "None" selected, and a new service gets no rehearsal unless a default time is also set (R461). |
