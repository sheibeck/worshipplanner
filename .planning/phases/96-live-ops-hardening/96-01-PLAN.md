<objective>
Harden the EXISTING Phase 95 RunControlView so a live Run session survives the two real-world failures R274
names — an output window CLOSED mid-service and a monitor UNPLUGGED mid-service — plus a realistic service
duration, WITHOUT losing the projectionist's place and WITHOUT a restart. No new view, route, or output
surface: every behavior grafts into src/views/RunControlView.vue, reusing the Phase 95 output-window
orchestration + honest state machine and the MonitorSetupView screenschange idiom.

Purpose: R274 (one-click reopen of a closed output + one-click reassign on a monitor change, each without
losing position) and R273 (the control stays the single source of truth; a reopened/reloaded output re-syncs
to the exact current index through the existing handshake — this plan PRESERVES that handshake and adds NO
heartbeat/re-broadcast). Recovery is CALM — amber, never red — and HONEST — a reopen never claims success over
a window that did not actually open. The interval poll and the screenschange listener are cleaned up exactly
once in the two existing teardown sites, so nothing accumulates over a long service and no reopen chip
re-surfaces for a deliberately-closed window after exit.

Output: an extended src/views/RunControlView.vue. All behavioral coverage (fake-timer poll tests, the
screenschange-listener fake, the position-preserved handshake assertion, the no-leak assertions, and the
client-only re-confirmation) lands in 96-02. Real close→reopen-onto-the-right-monitor and physical
monitor-unplug recovery are human-UAT, deferred to milestone end.
</objective>
