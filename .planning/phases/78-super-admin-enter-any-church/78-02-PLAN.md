<objective>
Give a super-admin a one-click way to step into any church for support (R224) and make that visit both
visible to them and invisible to the church (R226, R227): a new `enterOrgAsSuperAdmin`/`exitSuperAdminView`
pair in `src/stores/auth.ts` that switches active org context WITHOUT a membership document and without
tripping the router's org-selection guard, a per-row "Enter church" action on the Organizations tab, and a
persistent "Viewing X as super-admin" banner with a one-click exit in `AppShell.vue`. The rules-layer
authorization this depends on (`isOrgMember`/`isOrgEditor`/`isOrgMemberByClaim`'s new super-admin arm) ships
in the sibling `78-01-PLAN.md` — this plan's code assumes it functionally, but touches none of the same
files, so the two plans run independently.

Purpose: R224/R226/R227 — the visible, usable half of "step into any church," paired with the
invisible-to-the-church guarantee the owner explicitly asked for ("a hidden user they don't see in their
list").
Output: `src/stores/auth.ts` (enter/exit actions, `viewingAsSuperAdmin` state, the `hasNoOrg` router-guard
fix), `src/components/admin/OrganizationsTab.vue` (row action), `src/components/AppShell.vue` (banner +
exit), and unit/component test coverage for all three.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser session state (`viewingAsSuperAdmin`/forced `userRole`) → UI rendering only | Convenience/UX state; NEVER the authorization boundary — every Firestore/Storage op made while in this state is independently re-checked by `78-01-PLAN.md`'s rules arm |
| Organizations tab row action → `enterOrgAsSuperAdmin(orgId)` | `orgId` is server-sourced (from the `listOrganizations` callable's response), not free client text — no new injectable input surface |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-78-03 | Tampering / Elevation of Privilege | `enterOrgAsSuperAdmin` (client) | low | accept | Cross-referenced from `78-01-PLAN.md`'s threat model: `members/{uid}`'s `allow write` legally permits `create`, so R226's "no member doc" guarantee is a client-code contract, not a rules invariant. Mitigated here by Task 1's unit test asserting `enterOrgAsSuperAdmin`/`exitSuperAdminView` never call `setDoc`/`writeBatch`. |
| T-78-05 | Denial of Service (self-inflicted, availability) | `hasNoOrg` computed / router org-selection guard | medium | mitigate | Before this plan, `hasNoOrg` (`memberships.value.length === 0`) has no awareness of a super-admin's temporary viewed org, so the very next navigation after "Enter church" bounces back to `/select-church`, undoing the feature for every super-admin with zero real memberships (the expected account shape). Mitigated by adding `&& viewingAsSuperAdmin.value === null`; proven by a unit test asserting `requiresOrgSelection === false` immediately after `enterOrgAsSuperAdmin`. |
| T-78-06 | Information Disclosure / Tampering (client-state-mistaken-for-boundary) | `viewingAsSuperAdmin`, forced `userRole = 'editor'` | low | accept | Both are pure client/UI-gating state, mirroring the codebase's own documented `isSuperAdmin` ref posture ("must never be treated as access control on its own", `auth.ts:97-100`). Every read/write made while viewing is independently re-authorized by `78-01-PLAN.md`'s `firestore.rules`/`storage.rules` super-admin arm — a compromised or tampered client gains nothing beyond what the rules layer already grants a genuine super-admin claim holder. |
| T-78-07 | Repudiation | `enterOrgAsSuperAdmin` sessions | low | accept | No audit log of who entered which church, when — explicitly Deferred per 78-CONTEXT.md ("An audit log of super-admin enter-church sessions ... future scope"). Accepted for this milestone; the owner already scoped it out. |

No high/critical-severity threat is accepted in this plan; T-78-03/T-78-06/T-78-07 are the documented
low-severity residuals, each with a stated mitigation or explicit owner-scoped deferral.
