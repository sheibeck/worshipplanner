<objective>
Make a service's share link exist automatically at the Planned/lock transition, and ONLY at that
transition — a Draft service must never get a share link (R421). This is implemented by adding one
fail-closed `ensureShareLink` side-write to `markAsPlanned` and by REMOVING the existing
creation-time mint in `createService`.

Purpose: Deliver the auto-share-link half of the "trivial wins" phase while closing the Draft-exposure
risk the milestone explicitly calls out (PITFALL 3 / the v2.8 SEC-S-01 cross-tenant share-token
history). Reuse the already-idempotent `ensureShareLink` so relock cycles never mint duplicate tokens.
Output: a modified `markAsPlanned` + `createService` in `src/stores/services.ts`, with updated/added
tests in `src/stores/__tests__/services.test.ts`.

CRITICAL CONTEXT — a conflict the source artifacts did not account for:
`createService()` ALREADY calls `ensureShareLink()` at Draft creation today (src/stores/services.ts
lines ~421-443), added by explicit owner request on 2026-08-17 so a volunteer message's
`{{service_link}}` is never empty. That means the phase's premise ("a Draft never gets a link; this
preserves the one manual 'I'm ready' signal") is currently FALSE — every service gets a link at birth,
and `src/views/ShareView.vue` renders any token's snapshot regardless of Draft/Planned status. Fully
satisfying R421's "Draft never exposed" therefore REQUIRES removing the createService draft-mint, which
has a real side effect: `{{service_link}}` resolves empty (functions `resolveServiceLink` returns '')
for any message composed/sent before the service is Planned. Task 1 is a blocking decision to get owner
consent on exactly that side effect before the code change lands.
</objective>
