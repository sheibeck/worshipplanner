    - a missing svix-id, svix-timestamp, OR svix-signature header returns false (never throws)
    - a candidate signature of a different byte-length than the expected digest returns false and does NOT throw (timingSafeEqual length-guard)
    - a svix-timestamp outside ±REPLAY_TOLERANCE_SEC (300s) of now returns false (replay defense); one just inside returns true
    - a multi-entry `v1,<sigA> v1,<sigB>` header returns true when ANY entry is the correct signature (key rotation)
    - the whsec_ prefix is stripped and the remainder base64-decoded before HMAC — a secret without the prefix still verifies against a signature computed the same way
  </behavior>
  <action>
    Create NEW pure file `functions/src/webhookSignature.ts` exporting
    `verifySvixSignature(rawBody: Buffer, headers: Record<string, string | string[] | undefined>, secret: string,
    toleranceSec?: number): boolean` implemented EXACTLY per 60-RESEARCH.md § Architecture Patterns → Pattern 4
    (node:crypto `createHmac('sha256', keyBytes)` + `timingSafeEqual`). Also export a named
    `REPLAY_TOLERANCE_SEC = 300` constant used as the default tolerance, with a doc-comment tagging it
    [ASSUMED — confirm against a real Resend event at owner verification] (research A1 / Open Question 1). Steps:
      1. Read `svix-id`, `svix-timestamp`, `svix-signature` via a small `hdr()` that normalizes a possibly-array
         header value to a single string; if ANY of the three is absent → return false.
      2. Replay window: `tsNum = Number(ts)`; if not finite → false; if `Math.abs(Date.now()/1000 - tsNum) >
         toleranceSec` → false.
      3. Key bytes: `Buffer.from(secret.replace(/^whsec_/, ''), 'base64')` (strip prefix, base64-decode remainder).
      4. Signed content: `` `${id}.${ts}.${rawBody.toString('utf8')}` `` (the exact UTF-8 payload bytes — never a
         re-serialized object).
      5. Expected: `createHmac('sha256', keyBytes).update(signedContent).digest('base64')` → `expectedBuf`.
      6. Split the header on spaces; for each part strip a leading `v1,` (`part.slice(part.indexOf(',')+1)` when a
         comma exists); LENGTH-GUARD (`sigBuf.length === expectedBuf.length`) BEFORE `timingSafeEqual` — a length
         mismatch is simply "not a match", never a throw (research Pitfall 2). Return true on the first match,
         else false.
    Keep the function PURE — secret + headers + rawBody in, boolean out; NO Firestore, NO firebase-admin import,
    NO `svix` package. Do NOT hand-roll the compare with `===` (timing side-channel — research V6). This is the
    fresh no-analog primitive; model only the fail-closed DISCIPLINE on `parsePptxHandler`'s independent re-check
