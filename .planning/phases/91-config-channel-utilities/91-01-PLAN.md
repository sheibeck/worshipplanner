      only, never 2.

      NOT; a state message does NOT fire onHello.

    Create a pure module `src/utils/runChannel.ts`, mirroring `shareTokens.ts`/`lastUsed.ts` (a
    module-level rationale comment, exported interfaces, framework-free). It MUST NOT import from the
    Vue framework, the Firebase SDK, `@/firebase`, Pinia, or any `@/stores/*` module — its only runtime
    dependency is the BroadcastChannel primitive, supplied through an injectable factory.

    Export a discriminated message model: `RunState` is `{ index: number; blackout: boolean; seq: number }`;
    `RunStateMessage` is `{ type: 'state' } & RunState`; `HelloMessage` is `{ type: 'hello' }`;
    `RunChannelMessage` is the union. Export `runChannelName(serviceId: string): string` returning
    the template `wp-run-{serviceId}` (per ARCHITECTURE Pattern 4 and 91-CONTEXT) — this is the ONLY
    place the channel name is constructed.

    Export `openRunChannel(serviceId, factory?)` returning a handle exposing `postState(state: RunState)`,
    `onState(cb)`, `postHello()`, `onHello(cb)`, and `close()`. `factory` is an optional
    `(name: string) => BroadcastChannelLike` where `BroadcastChannelLike` is a minimal structural
    interface (`postMessage`, `addEventListener`/`onmessage`, `close`) so tests inject a deterministic
    fake and production defaults to the global BroadcastChannel constructor. Control is the SINGLE
    writer of `state`; the module does NOT enforce writer identity, it just provides the primitives.

    postState posts `{ type: 'state', ...state }` verbatim — the CALLER owns the monotonic `seq`
    counter and passes `seq` in (matches ARCHITECTURE's `postState({ index, blackout, seq: seq++ })`).
    Do NOT generate seq inside postState.

    onState is where the stale-drop lives: keep a per-handle highest-delivered seq, and invoke the
    callback for an incoming state message ONLY when its seq is strictly greater than that high-water
    mark (then advance the mark). This is the load-bearing reload/re-open-race guard (PITFALLS 10-11).
    onState ignores non-state messages; onHello ignores non-hello messages (branch on `type` FIRST).

    Do NOT add any echo-suppression / self-message filtering — the platform never delivers a context's
    own broadcast back to itself (91-CONTEXT + ARCHITECTURE Pattern 4); adding one would be dead,
    misleading code. Treat an incoming message defensively: guard the shape before use so a malformed
    message can never throw inside a listener.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| localStorage → monitorConfig | Persisted device config is attacker/corruption-reachable (any script on-origin, a partial write, a data-clear) and must be treated as untrusted input on read. |
| BroadcastChannel → runChannel listener | Same-origin messages from another window cross into a listener; a malformed or replayed/out-of-order message must not throw or regress state. |
| service data → serviceSlots | In-memory `Service`/`AssembledSlide[]` already resident in the window; pure derivation, no external trust crossing. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-91-01 | Tampering | monitorConfig.loadMapping (localStorage read) | medium | mitigate | JSON.parse + shape-validate inside try/catch; return null on malformed/corrupt data — never throw, never apply an unvalidated mapping (Task 2). |
| T-91-02 | Tampering/DoS | runChannel.onState (incoming state message) | medium | mitigate | Guard message shape before use; strict-increasing-seq stale-drop discards out-of-order/replayed state so a reopened output cannot be driven backward (Task 1). |
| T-91-03 | Information disclosure | runChannel channel naming | low | mitigate | Channel name scoped per service (`wp-run-{serviceId}`) so two concurrent Run sessions in one browser profile cannot cross-talk (Task 1). |
| T-91-04 | Denial of service | monitorConfig save/load under disabled storage | low | mitigate | All localStorage access wrapped in try/catch; private-mode throw degrades to silent no-op / null instead of crashing the caller (Task 2). |
| T-91-SC | Tampering | npm/pip/cargo installs | n/a | accept | No package installs this phase — all three modules are zero-dependency native TypeScript (STACK.md: "Zero new npm dependencies"). Package Legitimacy Gate is N/A. |
</threat_model>
