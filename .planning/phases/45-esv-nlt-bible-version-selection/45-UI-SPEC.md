# Phase 45 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This is a MINIMAL, reuse-heavy contract by design** (per orchestrator scope grounding). The UI
> surface is: (1) one new Settings section mirroring the existing AI/Planning Center/Vertical Worship
> toggle cards, and (2) an inline attribution suffix on scripture text that already renders. Nothing
> here introduces a new visual language, component, or typography scale.

## Spacing Scale

Reused verbatim from the four existing Settings cards (`SettingsView.vue`) — no new spacing values introduced:

| Token | Value | Usage (as already applied in sibling cards) |
|-------|-------|-------|
| xs | 4px | `gap-1` inline glyph spacing (not used by this phase's new elements) |
| sm | 8px | `mt-2` between a control and its helper caption; `space-y-2` in stacked micro-copy |
| — | 12px | `mb-3` card header→body gap; `gap-3` within a `flex items-center` label row (a card-pattern constant, kept as-is though not on the canonical 8pt ladder) |
| md | 16px | `p-4` card interior padding |
| lg | 24px | `mt-6` gap between stacked Settings cards |

Exceptions: 12px (`mb-3`/`gap-3`) is not a strict multiple of 8, but it is the load-bearing constant every existing Settings card already uses for header-to-body and label-row spacing — deviating from it here would make the new card visually inconsistent with its siblings, which is worse than the scale purity. Reused, not reinvented.

## Attribution Contract (R091) — the second UI surface this phase touches

This is not a new visual element. It is an **inline text suffix** appended to scripture text that
already renders, using the text's own existing classes untouched.

| Property | Contract |
|----------|----------|
| Exact string | `(ESV)` or `(NLT)` — parenthesized initials only, no full copyright notice (per R091/Area 2) |
| Which version's initials render | Driven by the **slide's own `translationSource` field** (R092, Area 3) — never by the org's current `bibleVersion` setting. This is the mechanism that makes "changing the setting never retroactively alters an existing slide" true at the attribution layer too, not just the text layer. |
| Separator | Exactly one space before the opening parenthesis: `{passage text} (ESV)` |
| Placement | Appended to the END of the existing scripture text, inside the SAME paragraph/text node — not a new element, not a new line, not a badge, not a different size/weight/color. It shares every class already on that paragraph. |
| Built once, shared | One pure helper (e.g. `scriptureAttribution(version: 'ESV' \| 'NLT'): string`) consumed by both render sites below — no second implementation |

**Concrete render sites this phase's attribution suffix must reach** (both already exist; neither gets new styling):

1. **`PresentationViewer.vue` scripture branch (projected view)** — append the suffix inside:
   - the normal-mode passage paragraph (`data-testid="presentation-body"`, class `text-gray-100 whitespace-pre-line text-5xl font-normal leading-[1.4]`), AND
   - the congregational-mode section paragraph (`data-testid="presentation-congregational-section"`, identical class set) — **each individual congregational section slide carries its own suffix**, not just the reading's first or last slide. (Assumption, recorded below.)
2. **`slideBodyText()` in `src/components/slides/slideDisplay.ts`** — the shared preview-text function `SlideCard.vue`'s grid thumbnail already consumes (`case 'scripture': return slide.text ? `${slide.reference}\n${slide.text}` : slide.reference`). Append the suffix to the returned string when `slide.text` is non-empty, using the same helper — this is the "one implementation, two consumers" CONTEXT.md calls for.

**Does NOT apply to:** a reference-only slide with empty passage text (D1's "the reference always renders unconditionally, frequently the slide's entire visible content" case) — there is no quoted scripture text on that slide to attribute, so no suffix appears. Only slides carrying actual passage/section words get the suffix.

**Two assumptions recorded here** (Claude's discretion per CONTEXT.md, made explicit so planner/executor/checker can challenge them):

- **Per-slide, not per-reading.** R091's literal wording is "every scripture display and projected slide carries its required attribution" — read literally rather than by analogy to the CCLI copyright convention (which the v1.4-era CLAUDE.md notes deliberately runs first+last, not every slide). A multi-slide congregational reading therefore shows `(ESV)`/`(NLT)` on every section slide, which may read as repetitive across a long reading. This is the legally-conservative reading of an explicit requirement, not an invented embellishment — if the owner later wants a first/last convention instead, that is a scope change to R091, not a UI-SPEC gap.
- **Grid-preview inclusion.** R091 says "displayed or projected" — `slideBodyText()` feeds the editor's grid thumbnail, which is a *display* surface even though it is not *projected*. Included for consistency with the literal requirement text; if this is judged unnecessary noise in the small grid card, dropping it from `slideBodyText()` alone (keeping the projected `PresentationViewer.vue` suffix) is a low-cost adjustment that does not touch the shared helper's contract.

## UI Considerations

Applicable state considerations resolved: 5 covered, 1 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | Bible Translation radio control (`form`/`interactive-control`) | ✅ covered | A two-option exclusive choice always resolves to a value (defaults to `NLT` per the locked override) — there is no unset state to render, matching every sibling toggle's always-has-a-value shape. |
| loading | Bible Translation radio control (`form`) | ✅ covered | No dedicated loading/disabled-while-saving state — mirrors every sibling toggle (`onToggleAiEnabled`/`onTogglePcEnabled`/`onToggleVwMode`), which fire-and-forget the write and only react on success/error, never show an in-flight spinner. Consistency with existing pattern IS the resolution. |
| error | Bible Translation radio control (`form`) | ✅ covered | On save failure: revert the selection to its prior value + show `Failed to save. Please try again.` in `text-red-400 text-sm mt-2` — copy and revert-on-catch behavior both reused verbatim from sibling toggle handlers. |
| partial | Bible Translation radio control (`form`) | ✅ covered | Not applicable to a two-radio exclusive group — there is no partially-filled state a binary choice can occupy. Dismissed, not silently skipped. |
| overflow | Attribution suffix on scripture text (`static-content`) | 🧪 backstop | The suffix is appended inline into a `whitespace-pre-line` paragraph that already wraps naturally at 48px display size; no new truncation/ellipsis handling is added. Verify at implementation time that a scripture passage running to the container's edge does not visually clip the trailing `(ESV)`/`(NLT)` — held out as a backstop rather than asserted, since the exact passage lengths that reach this edge are query-dependent and not exercised by this contract. |
| long-text | Attribution suffix on scripture text (`static-content`) | ✅ covered | The suffix itself is a fixed-format, fixed-length string (`(ESV)` / `(NLT)`, 5 characters) — not user-authored content, so long-text variance does not apply to the suffix itself. Dismissed. |
