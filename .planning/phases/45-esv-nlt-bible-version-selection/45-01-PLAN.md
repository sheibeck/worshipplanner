<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> Cloud Function proxy | Client request (ref, version, and possibly a forged `key`) crosses into the secret-injecting proxy |
| Cloud Function -> api.nlt.to | Server-held NLT_API_KEY injected server-side; external HTML returned |
| external HTML -> slide text (via nltApi.ts) | Untrusted upstream HTML is parsed and reduced to plain text that becomes slide content |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-45-11 | Spoofing/Elevation | functions/src/index.ts nlt branch | high | mitigate | Proxy always OVERWRITES the `key` query param with the server-held secret after building upstreamUrl — a client-supplied `key` is never trusted (mirrors esv/anthropic header overwrite). Unit-tested in Task 1. |
| T-45-12 | Denial of Service (quota theft) | new `nlt` proxy target | medium | mitigate | `nlt` added to SECRET_INJECTED, reusing the existing x-app-auth Firebase ID token gate — unauthenticated callers get 401. No new auth surface. |
| T-45-13 | Information Disclosure | NLT_API_KEY | high | mitigate | Key declared via defineSecret (Google Secret Manager), injected only server-side, never returned to the client and never logged; no client-bundle exposure. Code comment forbids logging it. |
| T-45-14 | Tampering (HTML/script injection into slide text) | nltApi.ts stripNltHtml | medium | mitigate | Output is reduced to `.textContent` (plain strings), never HTML; the app renders scripture as text and forbids v-html, so parsed markup cannot execute. DOMParser 'text/html' does not execute scripts. |
| T-45-15 | Denial of Service (silent empty passage) | nltApi.ts | low | mitigate | Explicit empty-body guard throws the standard fetch error instead of yielding silent empty text (Pitfall 5). |
| T-45-SC | Tampering | npm/pip/cargo installs | low | accept | No new dependencies introduced this phase (45-RESEARCH.md § Package Legitimacy Audit: N/A) — DOMParser and fetch are platform built-ins already used in this exact file. Nothing to install, nothing to slopcheck. |
</threat_model>
