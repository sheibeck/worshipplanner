<objective>
Restructure the per-service messaging surfaces in `src/views/ServiceEditorView.vue`: add a dedicated
**Messages** tab (4th button, appended after Roles), MOVE the already-shipped **Messaging defaults** panel
and the **ServiceMessageHistory** ("Sent on this service") mount out of the Service Order tab into a new
`v-show="activeTab === 'messages'"` panel, and fix the history's mount gate so it stays visible on a LOCKED
service. This is a pure relocation + one gate fix — the two moved blocks keep their internal behavior
byte-for-byte; only their PARENT (which tab, which gate) changes.

Purpose:
- R149 — the messaging surfaces live in one dedicated Messages tab, out of the Service Order tab.
- R150 — the delivery history is visible at all times (draft / locked / exported); its render no longer
  depends on `canEditService`, only on `isMessagingEnabled() && authStore.isEditor`.
- SC3 (unchanged) — the ✉ Messages composer stays an action-bar modal on the Service Order tab; no send
  behavior regresses.

DECISIONS (locked, from 63-CONTEXT.md / 63-UI-SPEC.md / 63-PATTERNS.md):
- Tab order is Service Order · Slides · Roles · **Messages** (append last; least disruption). The Messages
  button is gated `v-if="authStore.isEditor && isMessagingEnabled()"` — the Roles gate PLUS the messaging
  kill-switch. It copies the Roles button's class strings verbatim (no restyle; accepted deviations from
  Phases 58/59 — single-indigo accent, `font-medium`, `12px` spacing — must NOT be re-flagged).
- The move is byte-for-byte. Do NOT touch the messaging-defaults panel's internal
  `canEditService` / `isLocked` branch logic (its Draft-editable vs locked-read-only vs viewer structure is
  the shipped 58-05/62 behavior). The ONLY logic edit is the history's mount gate.
- R150 gate fix: history `v-if` becomes `isMessagingEnabled() && authStore.isEditor` — drop `canEditService`
  (removing the embedded `!isLocked` term), KEEP `authStore.isEditor`. Because the messages-panel is
  `v-show` (kept in DOM), the viewer-hidden invariant lives on the history's own `v-if`; a bare
  `isMessagingEnabled()` would leak the history to a viewer with messaging on. Do NOT re-introduce a lock
  term.

FORCED THIRD/FOURTH FILE (not scope creep — the type system requires it): widening `activeTab` to include
`'messages'` makes `buildActionBarItems(activeTab.value, …)` (:2399) pass a value the `ActionBarTab` param
(serviceEditorActionBar.ts:55) does not accept → TS2345. So `ActionBarTab` widens in lockstep and
`buildActionBarItems` returns `[]` for `'messages'` (the Messages tab exposes no action-bar items, exactly
like Roles). 63-PATTERNS.md Change 5 anticipated this ("may need 'messages' added there too").

Output: the restructured `ServiceEditorView.vue`, the widened `serviceEditorActionBar.ts`, and the extended
`ServiceEditorView.test.ts` + `serviceEditorActionBar.test.ts`. No component internals change, nothing
deployed, no `.env.local` needed.
</objective>
