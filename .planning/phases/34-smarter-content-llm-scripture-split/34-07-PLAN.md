<objective>
Build the mount seam and make the congregational-reading editor reachable from the product.

Purpose: this is the gap itself. `34-VERIFICATION.md` Truth 1 FAILED because
`CongregationalEditor.vue` has zero production mount points — no route, no parent import, no dynamic
import outside its own test. 34-PATTERNS.md § 1 confirmed the seam does not exist:
`handleNavigateToScriptureEditor` (`ServiceEditorView.vue:1499-1506`) is a tab-switch plus
scroll-to-row, not an editor mount.

Output: an explicit affordance on the Service Order tab's SCRIPTURE row that opens the editor for that
slot, and the write path from its emits onto the slot.

## Why a new affordance rather than repurposing the relay handler

The `edit-in-scripture` chain (`SlidesTab.vue:426-429,461-490` -> `ServiceEditorView.vue:1222` ->
`handleNavigateToScriptureEditor`) is live, tested, and carries its own WR-04 unsaved-drawer guard.
34-PATTERNS.md is explicit that the wiring should be reused and not re-invented. It already delivers
the user to the SCRIPTURE row — so the correct move is to put the affordance ON that row and leave the
handler's body alone. Making the handler auto-open the panel would change tested behaviour for plain
reference slides that have no congregational reading, for no benefit. The handler must stay byte-equal.

## The WR-04 contract is non-negotiable and gets its own task

`CongregationalEditor.vue` seeds its editable state ONCE at setup and is deliberately not reactive to
later prop changes (34-06 preserves this; the original contract comment lived at
`CongregationalEditor.vue:357-376` and is addressed by name to Phase 34). A parent that swaps which
slot the panel is showing without forcing a fresh instance will silently misattribute saves to the
first slot the instance ever saw. The mount is therefore keyed on `slot.id` — the stable slot identity
minted by Phase 24 D-01, already the anchor every `slideGroups/{slotId}` document uses — and Task 2
proves the swap really does produce a new instance.
