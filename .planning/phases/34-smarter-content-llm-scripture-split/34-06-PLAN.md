<objective>
Move `CongregationalEditor.vue` off the rejected separate-document persistence model and onto a
controlled prop/emit contract, so a parent can own the write.

Purpose: 34-PATTERNS.md § 2 confirmed by direct read that this component still imports
`useScriptureSlides` and calls `createReading`/`updateReading` against a separate `ScriptureReading`
Firestore document — the exact model R047 rejected (`3da5fe4` superseded by `5c531b1`). Its
persistence layer must change, not just its mount point. This is the largest single piece of the gap.

Output: a component that renders and edits a congregational reading and reports every change upward,
with no store of its own.

## What is deliberately removed, and why that is not a scope reduction

The component currently owns its own persistence stack: `useScriptureSlides`, the auto-save composable,
the shared save-status store, and a `SaveStatusIndicator` in its header, plus `currentReadingId` and
`surfaceId` derived from a `readingId` prop. Under slot-as-source-of-truth the component no longer
persists anything, so it has no save status of its own to report; keeping a second debounced
auto-save alongside `ServiceEditorView`'s existing one over `localService` would create two competing
save paths writing the same data — the defect shape Phase 28 removed when it collapsed two competing
`performanceOrder` fields.

Phase 32's R041 guarantee (a user always sees whether their work is saved) is preserved, not dropped —
but the mechanism changed with the 2026-08-03 owner decision on F1. The editor is now mounted as a
modal owned by `ServiceEditorView` (34-07), reached from the scripture SLIDE rather than from the
Service Order row, and a modal covers the page's sticky status bar. So 34-07's modal **header** renders
the shared `SaveStatusIndicator` bound to the SAME `service:{serviceId}` surface id the page already
uses. That is still one aggregator, one save path and one surface id — this component keeps no status
of its own, and the host supplies the visibility. Do not re-add a `SaveStatusIndicator` here; a second
one bound to a second surface id is exactly the drift Phase 32's single-aggregator design removed.

The tests being deleted here assert behaviour that genuinely ceases to exist; every test covering
behaviour that still exists must survive.

## Known, accepted consequence: AI split needs a fetch first

`rawText` is local state and is not persisted anywhere. Re-opening the editor on a slot that already
has sections therefore starts with `rawText` empty, so `canAiSplit` is false until the user clicks
Fetch Passage. This is deliberate: it avoids storing a second copy of the ESV passage alongside the
section text that already contains it, and the Fetch Passage control sits directly next to the split
control. Record it in the SUMMARY; do not work around it by persisting `rawText` onto the slot.
